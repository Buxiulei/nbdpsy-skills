# 轮播放映视频产线规格（第四内容形态 · tpl-slideshow）

> **定位**：把**已产出**的小红书轮播图当 PPT 逐张放映，配口播串联 + BGM，转成一条 3:4 竖版视频。
> 它不是「新做一条视频」，是**存量图文的分发形态转换**——图已经把话讲完了，视频只负责把它
> 送进视频流量池。跑通之后，所有达标的存量轮播都能低成本转视频。
>
> **边际成本 ≈ ¥0.54/条 + 本地渲染 ¥0**，出片墙钟 **4 分 10 秒**——
> 均为首片实测（H1 过度换气九页，口播 806 字 = 1535 计费字符，成片 181.3s / 40.8MB /
> 1080×1440 / 30fps / h264+aac；样片 `seo-geo/content/videos/slideshow-proto/slideshow-h1-test.mp4`）。
> 首版**无字幕**（老板 2026-08-14 定：字幕会挡住信息图本身的字）。

## ⛔ 上游闸门：R4 不达标的轮播不得进本产线

**图讲不清楚，口播救不回来。** 这是本形态与其它三种形态最不一样的地方——
字卡/微电影/播客的画面是为口播服务的，可以互相补位；放映形态里**画面是主体**，
口播只是导游。一张自己讲不清楚的图，配上再好的口播也只是「一张糊涂图 + 一段听不懂的话」，
而且观众的眼睛还被钉在那张图上出不来。

进产线前逐条核对（判据见 `nbdpsy-xiaohongshu-creator/references/illustration-spec.md` R4 节）：

| 闸门 | 判据 | 不过怎么办 |
|---|---|---|
| **有论点行** | 每页有一句话说清「这页要你信什么」，落在标题位**或收束位** | 回图文线补论点行，不要在口播里现编 |
| **图内自足** | 遮住口播，光看图能看懂这页；论点行不是单信息点（P8 的「期待摆正」半句是正例） | 回图文线改图 |
| **页序有推进** | 现象→机制→纠错→怎么办这类清晰递进，不是并列罗列 | 并列型轮播不适合放映，留在图文 |
| **文字量适中** | 一页的字，观众在该页放映时长内读得完 | 该页拆两页，或口播里放慢 |

**页时长节奏**：放映时长由口播长度反推，所以**口播稿的分页长度就是节奏控制器**。
首片实测九页落在 11.7–28.3 秒（中位 20.3s）。经验区间 **8–25 秒**：
低于 8 秒观众还没读完就翻页；**超过 25 秒同一张静图会开始发闷**（首片 P08 的 28.3s 已经偏长，
根因是那页口播写了 126 字——该拆成两页图，或把口播压到 100 字以内）。
⚠️ 这条只能在**写口播稿时**控制，脚本管不了。

⚠️ **闸门是硬的**：跑 `slideshow_video.py` 之前人工过一遍，脚本查不了「图讲没讲清楚」。
脚本能查的（页数对齐、时长漂移、分辨率）都已经做成拒跑，查不了的那部分靠这张表。

## 产线四步

```
① 论点行 → 口播稿（内容线供）：论点行串联扩写，讲故事线 + 解释每页里的小块含义。
   每页一节（`## P1`）。⚠️ 沿用微电影的审校纪律：外置审校，生产者自检不可信。
②③④ 一条命令收口：
   slideshow_video.py --images-dir <轮播图> --script-file <口播稿> --bgm auto --out <片子>
   ② 内部逐页调 MiniMax TTS（串行，带指纹缓存）
   ③ 内部 wav 域拼口播主轨，算出每页放映时长
   ④ 内部逐页出画布 + Ken Burns + 拼接 + 混 BGM + 收尾自检
```

口播已经录好（或来自别处）时，把 `--script-file` 换成 `--narration-dir <每页一段音频>`，
跳过 ② 直接进 ③。

## 工具与参数

`scripts/slideshow_video.py`（本形态唯一脚本；TTS 复用 `tts_gen.py`、BGM 复用 `gen_bgm.py`）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--images-dir` | 必填 | 轮播图目录，**文件名序 = 页序** |
| `--script-file` / `--narration-dir` | 二选一必填 | 分页口播稿（内部跑 TTS）／每页一段现成音频 |
| `--out` | 必填 | 成片 mp4；同时落 `<out>.meta.json` 产出凭证 |
| `--bgm` | 无 | `auto` = `gen_bgm.py` 纯合成（零版权）；也可给音频文件路径 |
| `--bgm-duck` | `18` | BGM 低于口播多少 dB（响度归一后压差） |
| `--canvas` | `1080x1440` | 3:4 竖版 |
| `--kenburns` | `0.03` | 缓放幅度 3%；`0` 关闭。**上界 = 贴合框，全程零裁切** |
| `--xfade` | `0`（简切） | 页间交叉淡化秒数，建议 ≤0.3 |
| `--head` / `--page-gap` / `--tail` | `0.3` / `0.35` / `1.2` | 片头静音／页间停顿／片尾留白（秒） |
| `--prescale` | `3` | Ken Burns 超采样倍数，压 zoompan 的整数取整抖动 |
| `--voice` | `Chinese (Mandarin)_Warm_Bestie` | 温暖闺蜜，现役口播音色 |
| `--dry-run` | — | 只校验页数/段数/字数，**不调 TTS 不花钱** |

**先跑 `--dry-run`**：稿子分页错了、图少一张，这一步就报出来，不用先花 TTS 的钱才发现。

## 三条规范（每条都对应一次本仓踩过的坑）

### 1. 🩸 wav 域拼接——本形态的命门

每页放映时长 = 该页口播的**实测样本数 ÷ 采样率**；多页音频在 **PCM 域按样本数**拼接。

⛔ **绝不逐段拼 mp3**：每段带 encoder delay，实测每段漂 ~46ms 且**随段数累积**
（8 段累计 0.41s）。字卡线 2026-08-11、播客线 2026-08-07 两次同因事故，都是「越到后面越对不上」。
放映形态里它的表现是**翻页越来越早于口播**——第 9 页的口播还在讲第 8 页的图。

**检验法（脚本自带，超差直接退出码 1）**：`ffprobe` 成片实长 vs 各页放映时长累计，
差 > **0.1s** 即拼接路径有漂移，别用这条片子。
理论残差只应来自帧取整（每页取整误差不累积，全片最大半帧 ≈ 17ms）。

### 2. 零裁切——信息图裁一条边就是裁一行字

画面一律 **contain 贴合**，⛔ 不许为了「满屏」改成 cover 裁切。

**轮播图的比例本来就不齐**：实测 H1 批封面 P01 是 3:4（876×1168）、正文 P02–P09 是 2:3
（876×1313）。在 3:4 画布上，2:3 的正文页两侧各留约 5.5% 的边——这是**正确行为**，
不是 bug；把它「修」成满屏就等于裁掉正文页左右两列。边由**同图的模糊放大版**填充
（信息图多是暖米底，模糊填充读起来就是一圈柔和同色边，不出戏）。

**Ken Burns 也不许把图推出画外**。做法（`_page_canvas` 的超尺寸画布法）：
把图铺到 `画面×(1+kb)` 的大画布上、贴合进中央的 `画面` 框，再让 zoompan 的 z 从 `1` 走到 `1+kb`——
对应图从 `1/(1+kb)`（97%）长到 `1.0`（100%），**缩放上界正好是贴合框**，任何时刻零裁切。
（zoompan 的 zoom 只能 ≥1，直接对贴合图 zoom-in 必然推出画外，所以要先做大一圈。）

**验证量具（可复现）**：取最大缩放帧 → 抠出贴合框（3:4 画布上的 2:3 页是 `crop=960:1440:60:0`）
→ 缩回原图尺寸 → 与原图算 PSNR。首片实测 **P02 33.5 dB / P07 31.5 dB**（另有开发期 P03 32.8 dB）——
30+ dB 这个量级只是重采样 + H.264 损失，内容一致；真被裁过会掉到 10–15 dB（整幅错位）。

方向按页序奇偶**交替**（偶数页推近、奇数页拉远），⛔ 不用随机——重渲染必须逐帧一致。

### 3. BGM 只用自产，⛔ 绝不下载来路不明的音乐

`--bgm auto` 走 `gen_bgm.py` **纯 Python 合成**（拨弦琶音 + 低音 pad，零版权零外部素材）。
一条商用短视频背一首侵权 BGM，赔的钱比整条产线省下来的多。

混音口径：先量口播的 integrated LUFS，BGM 用 `loudnorm` 归一到「口播 − 18 dB」，
`amix` 必须带 **`normalize=0`**（默认会按输入数分摊音量，把已经调准的口播再砍 6 dB）。
两端 1.5s 淡入淡出。

首片实测：口播 **−31.6 LUFS** → BGM 归一到 **−49.6 LUFS**；成片整体 **−31.63 LUFS**，
与「口播单轨」的 −31.6 只差 0.03 LU ⇒ **BGM 完全没有抬高整体响度，是床不是声部**。
⚠️ 别拿 RMS 当判据：同一条片子，纯 BGM 段 RMS −40.0 dB、口播段 RMS −32.8 dB，
看起来只差 7 dB「像是没压够」——那是因为 LUFS 带 K 计权（压低频，而这条 BGM 低频厚）
且带门控（跳过口播里的字间静音），两把尺子量的不是一回事。**认 LUFS，别认 RMS。**

**当前欠账**：包内**没有**授权的现成 BGM 音源，`--bgm` 因此是可选参数、默认不加。
自产 BGM 是能用的兜底，但它只有四和弦循环、无编曲变化，长片会显单调；
要更好的底乐得走**采购授权曲库**（老板拍板）。

## 对抗审查清单（出片后逐条核，⛔ 抽样不算）

脚本收尾自检已经把前四条做成硬闸门（不过就退出码 1、成片不算数）：

1. ✅ **时长对齐**：成片实长 vs 口播累计差 ≤ 0.1s；
2. ✅ **无字幕轨**：流构成必须恰好是 `['video','audio']`（首版规格无字幕）；
3. ✅ **画布**：1080×1440；
4. ✅ **页数** > 0，且页数 == 口播段数（对不上时**报出缺哪页**再拒跑）。

脚本查不了、必须人过的：

5. **逐页切点对齐**：至少抽 3 处页边界，在 `切点−0.05s` 与 `切点+0.05s` 抽帧，
   必须分别是前一页与后一页（`<out>.meta.json` 里每页的 `video_frames` 累加即切点时刻）；
6. **零裁切目视**：抽每页的**最大缩放帧**（偶数页看末帧、奇数页看首帧），
   四条边的内容都在，标题不切、注脚不切；
7. **口播与图对得上**：逐页听——第 N 段口播讲的是不是第 N 张图。
   ⚠️ 这是本形态最容易出错又最容易漏检的一条：页数校验只保证**数量**对，
   保证不了**内容**对（稿子第 5 节写的是第 6 页的事，脚本一点办法没有）；
8. **BGM 不抢话**：戴耳机整听一遍，人声始终在最前；
9. **合规**：图上已有的免责声明/热线在放映里仍然可读（末页停留时长够不够看完）。

### 三条纪律

**① 别把「没报错」当成「验过了」。** 自检打的四个 ✅ 只覆盖能量化的部分；
第 5–9 条没人替你做。本仓有一整条「绿必须是被验证过的绿」的教训线。

**② 改稿必须让缓存失效。** TTS 产物按 `(稿子, 引擎, 音色, 语速, 模型)` 的 sha256 存指纹，
任一变化即重合成、没变则复用（省钱）。旧的无指纹缓存踩过：改完稿子出来的还是老声音，
且完全无提示。⛔ 别为了省钱手动跳过重合成。

**③ TTS 失败不自动重试。** 按字符计费，重试＝重复扣费。脚本失败即抛、原文透出，
该不该再花钱由人决定。

## 与另外三种形态的选型与成本

| 形态 | 画面来源 | 边际成本 | 出片墙钟 | 什么时候选它 |
|---|---|---|---|---|
| **轮播放映**（本文档） | **存量轮播图**，零新画面 | **≈¥0.54/条** | 4 min（九页 181s） | 图文已经做好且 R4 达标，要低成本多占一个流量池 |
| 字卡短片 | GSAP 动效字卡 | ≈¥0.2/条 | ~1–5 min | 观点型短内容，没有现成图 |
| 播客 | HTML 播放器录屏 | ≈¥1.8/10min | 长 | 长对谈，听为主 |
| 微电影 | 即梦 Seedance 生成 | ≈26 分/秒 | 很长 | 品牌片、情绪叙事 |

**放映形态的性价比来自「画面白嫖存量」**：它是唯一一个新增成本里没有画面钱的形态，
所以只要图文本来就要做，转视频几乎是白给的第二个分发口。
代价是**画面质感受制于原图**——原图不好看，视频也不会好看，这也是上游闸门必须硬的原因。

## 交付与发布

- 成片同时落 **`<out>.meta.json` 产出凭证**（逐页图片路径/口播路径/放映时长/自检结果），
  这是「先落台账再发布」的那个台账；
- 发小红书**必经脚本层**：`nbdpsy-xiaohongshu-creator/scripts/publish_video.py`
  （落 job 行 = 台账先行，自动拆 `topics`）。⛔ 手搓 payload 直调 `POST /api/publish-jobs` 是禁令
  （job 337 就是这么发的，`#标签` 静默丢成正文纯文本无人发现）；
- **封面无旁路**：与另外三种形态共用 `nbdpsy-xiaohongshu-creator` 主流程第 ③ 步，
  凭证（`cover-*.meta.json`）在才准发。⛔ 抽帧不得当投放封面——
  本形态尤其容易犯这个错，因为「第一页本来就是封面图」看起来天经地义；
  但**放映片的第 0 帧是 97% 缩放状态的封面图**，不是封面成图本身。
