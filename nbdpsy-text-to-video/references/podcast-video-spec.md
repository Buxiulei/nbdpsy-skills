# 「长文播客」形态规格（长文 → 对谈播客视频）

> 2026-08-07 老板立项。参考形态：抖音「老徐的会客厅」（8.4 万赞样本）——**声音+字幕为主**，
> 画面是极简 HTML 播放器（黑底 + 期号标题 + 当前句大字幕 + 波形播放器图形 + 栏目名），
> 录屏成片。适合官网查证长文的深度内容二次分发；与「笔记微电影」互补（那个重画面，这个重内容密度）。

## 产线五步

```
长文 → ①对话逐字稿 → ②DeepSeek 三轮审校 → ③MiniMax 双声合成 → ④HTML 播放器页 → ⑤录屏+混音
```

### ① 对话逐字稿（一男一女对谈）

> **⚠ 生成过程 v2（2026-08-07 老板打回整稿后重建——此前的系统性缺陷：从长文提取句子
> 再口语化打磨，书面语 DNA 第一步就注入，后面全部审校都在给书面句子化妆）**：
>
> **A. 先「懂」再「说」，切断书面语血缘**。第一步把源文提炼成**知识底稿**（纯要点清单：
> 论断/数字/研究口径/限定语/安全红线，⛔不许成句成段）；第二步写稿人**只准看底稿、
> 禁止接触源文原句**，拿要点「转述给朋友听」——没见过的句子不可能漏进稿子。
> 事实核查环节改为「稿 vs 底稿」逐条对。
>
> **B. 正样本锚定**。写稿前先读下方「黄金样例」（老板亲手改定的首期冷开场），
> 写得像它；禁令清单（写稿守则）只作事后自查，不作生成引导——只给禁令，
> 模型必退回通用播音腔（封面字体 A3 实验同款教训）。
>
> **C. 首听测试是主质检**。稿子完成后交给一个**没读过源文、不知道主题**的代理只读稿，
> 逐行标「没听懂/这词卡住/不像人说话」并**复述每段大意**——复述错=理解断裂
> （能抓住指代丢失、因果压缩过头这类 DeepSeek 语感审抓不住的问题）。
> DeepSeek 三轮降为辅助，**取并集逐条人工裁决**（⛔不再取交集——交集会把只得一票的
> 真问题滤掉，首期「自责解释不了任何事」就是这么漏的）。
> 任何改稿/压缩/挪移后的新句，必须重过首听（首期「是我自己把它拉长的」就是
> 去接龙改稿时把因果压丢的）。
>
> **D. 按段生产质检，整篇交付**（2026-08-07 老板定案）。「段」是**内部**生产与质检单位
> （写一段→首听一段→过了再写下一段，避免整稿写完才发现开场就废）；**交付给老板的
> 永远是整篇**。文字稿送审只发生在**方法论校准期**（首期）；流程定型后**直接交成片终版**，
> 不再送审文字稿——质检责任完全由本流程的首听/审校/事实核查承担。
>
> **黄金样例**（首期冷开场，老板改定版——直接进场景不做声明、亲历者第一人称完整讲、
> 对方只做追问/猜测/反应、因果说破不留悬空指代）：
> ```
> F 我发条消息过去，他回两个字，在忙。我盯着那两个字看了很久，忍不住补一句，你是不是不想理我。
> M 他怎么回的。
> F 他回没有，后面带个句号。我心里那块反而更空，又追一句，那你到底怎么想的。这次他隔了四十分钟。
> M (chuckle) 那个句号我懂。那四十分钟，你手机是不是一直没放下？
> F 一次都没放下。最难受的是，我心里其实明白，他这四十分钟不回，就是被我一句句追出来的。
> M 你都知道，还是停不下来。咱们今天就聊这个，你越用力要爱，他越冷漠。
> ```

- **格式**：`podcast.json`
  ```json
  {
    "series": "栏目名",              // 如「NBDpsy 会客厅」，老板定
    "vol": 1,
    "title": "本期主题（两行内）",
    "source": "源长文 slug/路径",
    "lines": [
      {"speaker": "F", "text": "……", "emotion": null, "speed": 1.05, "pause_after": 0.3},
      {"speaker": "M", "text": "……"}
    ]
  }
  ```
- **角色分工**（对谈的骨架，不是两个人轮流念稿）：一个「引导者」（提问、追问、替观众说
  出困惑、偶尔抬杠），一个「阐述者」（专业输出、举例、纠正）。谁是 M 谁是 F 按内容定，
  别固定「男问女答」的套路。
- **语气语速规划写进每行**：`speed`（0.5–2.0，问句可稍快、共情句稍慢）、`pause_after`
  （行间停顿秒数，转折前 0.5–0.8）、句内用 `<#x#>` 与 `(sighs)(emm)` 等标签
  （纪律见 `narration-spec.md` 第五节；对谈里 `(emm)` `(chuckle)` 比微电影口播更常用——
  真人对话本来就有磕绊）。
- **标点即语气（2026-08-07 老板定案）**：**真问句必须用 ？**（含叙述里转述的问句——
  MiniMax 按 ？ 读升调、字幕层保留 ？！，句号会把问话读平，白扔表演力）；
  判定按语义不按句式（「我跟你说为什么。」是陈述，「那在哪？」是问句）。
- **逐行表演设计是定稿后的固定工序**：文字定稿后整稿过一遍，逐行决定
  `emotion`（只在方向明确处显式指定——低落/沉稳/明快等，其余留空让模型自动匹配，
  官方口径「一般无需手动指定」仍适用于无明确方向的行）、`speed`、`pause_after`；
  红线句/口径句一律 沉稳+放慢+句后停顿。审阅版导出须把这些标注可视化给老板。
- **写稿守则**：沿用 `narration-spec.md` 写稿六律，另加对谈四条——
  ⑴ 每轮发言 ≤3 句，超了拆成对方一句短接话（「嗯」「对」「等一下，你是说……」）；
  ⑵ 阐述者引用研究/数据须来自源长文（查证过的），对谈不新增事实主张；
  ⑶ 引语坑同样适用：转述不加引号；
  ⑷ **⛔ 不许相声式接龙**（2026-08-07 老板打回首期开场实翻车）：一个完整的思想/场景
  不拆给两个人轮流说。判据：把对方的行念出来，若它是在**替另一人叙述另一人自己的
  体验**（「你盯着那两个字看了很久」）或**补完对方没说完的句子**，就是接龙。
  正解=每人拥有自己的视角：亲历者把自己的经历**完整讲完**，另一人的接话必须是
  **对着她说的反应**——追问、猜测（我猜那四十分钟你手机就没放下）、共鸣、反驳、
  专业解释。两人是在对话，不是在合播一段旁白。
  ⑸ **承接词是对话感的零成本来源**（2026-08-07 老板定案，样例：「他怎么回的？」→
  「**那**他怎么回的？」——一个字就从审问变成聊天）。定稿后做一遍**承接词遍历**：
  逐行问「这句接得住上一句吗」，接不住的加承接（那/所以/也就是说）、应答（嗯/对/行）、
  转折（不过/可/话说回来）、补白（其实/说白了/我跟你说/诶）或反问软化（……吧？）。
  **纪律**：目标 30–45% 的行带承接（满篇「那、嗯、对」比一个都没有更假）；同一承接词
  不连续两行、全稿单词 ≤6 次；只加语气不改内容，红线句与事实句实质表述一字不动
  （最多句首加一个词）；CTA 两行不动。

### ② 质检（首听测试为主 + DeepSeek 为辅）

1. **首听测试（主）**：见 §① 生成过程 C。执行要点：首听代理的任务书里**不给源文、
   不给主题背景**，只给逐字稿；要求两份输出——逐行卡点标注 + 逐段大意复述；
   复述与原意不符处按理解断裂修稿，修完的行**再过一次首听**。
2. **DeepSeek 三轮（辅）**：3 轮 temperature 0.3，**取并集逐条人工裁决留痕**
   （⛔交集会滤掉真问题；播客稿审校口径与 `narration-spec.md` 第二节的「机器自动改稿
   取交集」场景不同——这里裁决人是 agent，噪声成本低、漏报成本高）。
   对谈稿额外审两项：**像不像真人对话**（播音腔/互相念稿感）、**角色一致性**
   （引导者不突然变专家、阐述者不突然装小白）。
3. **禁词表 grep（机械闸门）**：品性/构念/被试/基线/拒斥/负性/复现/可推广性/转引/
   施加/效应量/方法学（老板逐条毙过的书面词，随审片持续追加）——命中即改，
   专业术语确需保留时必须紧跟一句人话解释（如「横断面研究——测的是同一时间点的关联」）。

### ③ MiniMax 双声合成

- 逐行合成（`tts_gen.py --engine minimax --timed`），行间静音按 `pause_after` 用 ffmpeg
  anullsrc 垫；产出 `podcast.mp3` + 合并时间轴 `podcast.cues.json`
  （每行一条 cue：`{speaker, text, start, end}`——字幕与说话人高亮都靠它）。
- 音色：女声=温暖闺蜜（现役）；**男声待选**（候选：温润男声 `Chinese (Mandarin)_Gentleman`、
  电台男主播 `Chinese (Mandarin)_Radio_Host`、真诚青年 `Chinese (Mandarin)_Sincere_Adult`，
  试音后老板定）。
- 成本：对谈 10 分钟 ≈ 2600 字 ≈ ¥1.8（speech-2.8-hd），忽略不计。

### ④ HTML 播放器页（`assets/podcast_player.html` 模板）

参考截图的构图，竖屏 720×1280，从上到下（底色与配色随主题走，见下一节）：
1. **期号+标题**（两行内，白字，Vol.N：主题）；
2. **当前句大字幕**（画面视觉中心，随 cues 逐句切换；当前说话人可用颜色/前缀区分）；
3. **波形播放器图形**（居中：波形条 + 播放键造型 + 进度点——纯装饰，CSS/JS 动画随
   播放进度走，不必真实反映频谱；真实感优先级低于稳定性）；
4. **栏目名**（书法感字体或 logo 字，底部）。
- 全部资源内联（字体用系统 Noto，不依赖外网）。数据注入：模板顶部
  `<script id="podcast-data" type="application/json">` 占位，录屏脚本把 `{title,vol,series,cues}`
  写入后落临时 html 再打开（`file://` 下 fetch 本地 json 会被 CORS 拦，query 驱动走不通，
  2026-08-07 实现时定案）；音频固定同目录相对路径 `podcast.mp3`。页面暴露
  `window.__start()` / `window.__done` / `window.__t()` 供录屏脚本控制与检测结束。

### 播放器主题两档（2026-08-14 老板定案）

播放器**只有配色一个变量**——版式（期号+标题／大字幕／心电声纹播放器／栏目名）、字号、
心电图声纹的算法、字幕分页规则、录屏与混音流程**两档完全一致**，⛔ 不得为某一档另改版式。

| 档名 | 参数值 | 视觉 | 适用 |
|---|---|---|---|
| **深夜电台**（默认） | `shenye` | 黑底＋暖白/浅金字＋**金色**心电声纹 | 通用；夜里听的调子 |
| **纸上对谈** | `zhishang` | 暖米白 `#E8D8C4` 纸纹底＋深灰蓝 `#5A6B7B` 字＋**墨色** `#3A4A57` 声纹 | 与品牌图文同语言的轻议题 |

**默认档＝深夜电台＝现状**：历史全部已发期数（会客厅 Vol.1 起）都是这一档。
运营没点名主题时按 `shenye` 做。

**怎么用**：

```bash
python3 scripts/record_podcast.py <workdir>/podcast.json --theme zhishang --fade-out 1.5
```

`--theme` 只接受 `shenye` / `zhishang`，写别的**直接报错退出**（⛔ 不静默回落到默认——
静默回落会让人以为出了纸上对谈、实际拿到深夜电台）。成片回执里带 `"theme"` 字段，
台账按它核对。

**实现落点**（改主题只碰这两处，⛔ 别在别处再写颜色）：

| 落点 | 文件 | 说明 |
|---|---|---|
| **主题真源** | `assets/podcast_player.html` 的 `<html data-theme="…">` | 页面与 canvas 声纹的颜色**全部**从它选中的那组 CSS 变量派生 |
| 两组变量 | 同文件 `<style>` 顶部 `:root[data-theme="shenye"]` / `[data-theme="zhishang"]` | 底色/字色/声纹色/纸纹层各一组，**加新档＝加一组变量**，不动别的规则 |
| 写入 | `scripts/record_podcast.py` 的 `THEME_RE` | `build_page(..., theme=)` 把参数改写进 `data-theme` |

🔴 **canvas 的颜色也必须走变量**：心电声纹是 `<canvas>` 画的，JS 用 `cssVar()` 读
`--wave-played` / `--wave-unplayed` / `--wave-glow` / `--wave-head` / `--wave-base` 五个变量。
**在 JS 里写死颜色＝页面换了主题、波形还是老色**（半拉子主题，样图上一眼就能看出来）。

**验证过的切换**（2026-08-14 用会客厅 Vol.1 的真实音轨与 cues 空载渲染，播放到第 21s 取帧）：

取帧样图见 `nbdpsy-xiaohongshu-creator/assets/style-gallery/video/bokecast-{shenye,zhishang}-frame.jpg`。

### ⑤ 录屏 + 混音

- Playwright chromium 打开页面 → 720×1280 视口 → `page.video` 录制 → 播放到 `__done` →
  ffmpeg 把录屏视频与 `podcast.mp3` 混轨（录屏声道丢弃，用原始音频保音质）+ faststart。
- 片尾 `fade_out`。
- 🔴 **投放封面不在本文档做，一律回主流程③**（2026-08-14 删旁路）：封面是三形态（图文轮播／文字版／**视频·播客**）
  **共用的同一道必经步**——`nbdpsy-xiaohongshu-creator` 主流程第 **③ 步「封面」**（版式细则见其
  `references/illustration-spec.md` §2-b），出图后落**产出凭证** `cover-*.meta.json`，**无凭证拒发**。
  📌 **本行原写「封面沿用『封面首帧』能力（compose 的 `cover`）」——已删**：拿片子的帧当封面
  与 2026-08-13 事故里第一次绕规范（平台截第 0 帧、文字还没显出来的空白卡）**同型**，被老板打回
  （原话「你居然都没有做封面！！！」）。`compose` 的 `cover` 只够内部预览/自查用，**⛔ 不是投放封面**。
- ⚠️ **发小红书的封面图必须 3:4 竖版**（1080×1440），**不是** 9:16——信息流按 3:4 展示，
  传 9:16 会被上下裁切、标题字被切掉（2026-08-08 首批 8 条实翻车）。视频本身仍是 9:16 竖屏，
  封面是独立的图，两者比例不同是正常的。**发布前先把封面比例核对一遍**（发布时就传对，成本最低）。
- 🔴 **发布后补封面是主路径的第②步，不是"补救"**（2026-08-16 改口径；**旧写法「已发布笔记的封面改不了」
  与「这是补救不是流程」双双作废**）：**发布链那条设封面入口自上线起 31/31 全败**（xhs-server 2026-08-16 定性），
  所以每条播客笔记都要跑完**两段式四步**——
  ① `publish_video.py --note … --audio … --cover <③的封面>`（**`--cover` 照传**，闸门 A 靠它校验凭证；
  预期回执就是 `exit 3` + `cover=error`，⛔ 别当发布失败去重发）→
  ② `--fix-cover --job <发布job> --cover <同一张>`（内部走 `POST /api/accounts/{id}/note-components`，
  **该端点本身就建 job**；判据 `applied_cover=true` 且 exit 0）→
  ③ `--recheck <发布job>`（判据 exit 0、台账那行翻 `- [x]`）→ ④ `--ledger-check`（**exit 0 才准报完成**）。
  **实证**：2026-08-13/14 三条视频笔记均为**发布后补封面成功**（job `af53d3ca…` / `7e495f23…` / `ae679f87…`，
  三条 `applied.cover: true`，首批为人工逐条核对确认）；server 侧状态记的是「发布后补封面：可用（**仅视频笔记**）」。
  - ⚠️ **仅视频/播客笔记可用**：图文没有独立封面通道（首图即封面），传 `--cover` 当场 `ValueError`、直调 422——
    **图文封面发出去即定、事后无补救通道，首图发错只能删稿重发**。⛔ 别把这条绕行套到图文上。
  - ⚠️ **常规工序 ≠ 可以拖**：②③④ 必须紧跟着①在同一批次里跑完，⛔ 不许攒到"回头一起补"——
    会话一断那个"回头"就没了（2026-08-13 事故）。中间状态由**台账差集**盯着、⛔ 别靠记性。
- AI 标识：本形态**画面非 AI 生成**（HTML 排版），但**声音是 AI 合成**——发布时平台
  AIGC 声明照勾，角标按发布场景决定。

## 已定案（2026-08-07 老板逐项验收）

- **栏目名：「NBDpsy心理会客厅」**（podcast.json 的 series 字段统一用它）；
- **双声响度归一**：每行按 mean_volume 拉到 -22dB（±12dB 限幅），wav 阶段做（实测
  温暖闺蜜 -31dB vs 温润男声 -23.6dB 差 7.5dB，归一后逐行 -22.0dB 对齐）；
- **字幕规则与短视频一致**（2026-08-13 已升格为全形态铁律，正典与细则见 narration-spec.md §七：
  逗号换行/句号问号省略号翻页/每句独立成页禁多句连排/最短页 1.2s 并页/翻页背景空窗 ≤0.15s）——record_podcast
  注入前把行级 cues 用 compose_video 的分页管线变换成页级 cues，页时长按文字宽度比例分配；
- **波形=心电图式真实声纹**（三形态试到第三版定案）：离线预计算每 80ms 窗的有符号
  峰值对（真实波形上下包络），canvas 连续描线成过零摆动的心电轨迹，中心=当下（辉光
  播放头）、已播金色辉光/未播暗灰、亚像素平滑滚动、两侧渐隐窗口；
  ⛔ file:// 下 Web Audio AnalyserNode 全零、设 crossOrigin 音源直接被拒，都是死路；
- **音画同步=帧级标记**：预滚 0.8s 挂黑幕+品红块，audio playing 撤幕，录屏后逐帧扫描
  切齐（误差≤1帧）；load 后立刻开播标记一帧都录不到，预滚必不可少；
- **男声定案：温润男声 `Chinese (Mandarin)_Gentleman`**；
- **首期定案**：黄安麟《你越用力要爱，他越冷漠：投射性认同的怪圈》
  （slug yue-yao-ai-yue-lengmo，其署名文章阅读量第一）。
