# 声音验收清单（全形态通用）

> **适用**：轮播放映 / 字卡短片 / 播客视频 / 微电影 / 搬运重制——凡是本产线出的、带声音的成片。
> **定位**：画面有一整套零裁切、逐帧对齐的规范，声音以前只有零散口径。这份是**唯一真源**；
> 各形态 spec 的声音节只写「本形态特有项」，通用项一律引用本文件，⛔ 不要各写一份（会漂）。

## 这份清单是怎么来的

2026-08-16 老板实听首片轮播放映片，反馈**「背景音太小」**。查下来根因不是 BGM 压过头，
是**整条链路没有任何一处管绝对响度**：TTS 原始电平 −31.6 LUFS，比平台常态低 15 dB 以上；
BGM 按「口播 − 18 dB」算相对值，口播本身安静，BGM 就更安静（实测 −49.6 LUFS，约等于没有）。

**教训（会重复发生，所以写在最前面）**：相对量全部对得上，绝对量整体不合格——
每一项单看都「按规范做了」，合起来是一条手机外放听不清的片子。
⇒ 声音验收必须**同时**有一把绝对尺子（母带 LUFS）和一把相对尺子（BGM 压差），缺一个就会漏掉这类问题。

## 一、硬闸门（脚本自检，不过就退出码 1）

四条合成出口全部落地这三条，实现在 `scripts/audio_master.py`（**唯一真源**，
⛔ 任何出口都不许再抄一份自己的 loudnorm——「一处修了另几处没修」就是本文件的起因）。

| # | 判据 | 量具 | 不过会怎样 |
|---|---|---|---|
| A1 | **整体响度 −16 ±1 LUFS** | `loudnorm` 分析口的 `input_i` | 手机外放听不清；平台自动响度归一时被拉伸，动态被压扁 |
| A2 | **真峰 ≤ −1.5 dBTP**（成片实测容差 0.3，留给 AAC 编码） | 同上的 `input_tp` | 平台二次转码时削波爆音（尤其人声齿音） |
| A3 | **双声道 / 48 kHz / AAC** | `ffprobe` 流信息 | 单声道在手机外放上更闷；采样率漂移会让某些播放器变调 |

**量具命令（复制即用）**

```bash
# A1+A2：整片响度与真峰（认这一个，别的都是参考）
ffmpeg -hide_banner -nostats -i <片子.mp4> \
  -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null - 2>&1 | tail -20
# 读 "input_i"（整体 LUFS）与 "input_tp"（真峰 dBTP）

# A3：声道数 / 采样率 / 编码
ffprobe -v error -select_streams a:0 \
  -show_entries stream=codec_name,channels,sample_rate,bit_rate \
  -of default=nw=1 <片子.mp4>
```

### 🩸 认 LUFS，不认 RMS（本仓实证）

同一条片子，两把尺子给出的结论**方向相反**：

| 量法 | 纯 BGM 段 | 口播段 | 差值 | 会得出的结论 |
|---|---|---|---|---|
| RMS（`volumedetect` 的 mean_volume） | −40.0 dB | −32.8 dB | **7 dB** | 「BGM 才低 7 dB，压得不够」 |
| LUFS（`loudnorm` 的 integrated） | −49.6 | −31.6 | **18 LU** | 「BGM 已经低到基本听不见」 |

差在两处：LUFS 带 **K 计权**（压低频，而合成 BGM 低频厚）+ 带**门控**（跳过口播的字间静音，
RMS 会把静音也算进平均、把口播压低）。**两把尺子量的不是一回事**，混用必然误判。

⚠️ 播客线 spec 里的「逐行拉到 −22 dB（mean_volume）」是**说话人之间的相对对齐**（男女声差 7.5 dB），
用途不同、量的对象不同，它**不能**替代整片母带 LUFS，也不该被改成 LUFS——两件事都要有。

## 二、混音口径（做的时候按这个做）

| 项 | 口径 | 说明 |
|---|---|---|
| **母带归一** | 混音之后做一次，两遍法 `loudnorm`（先分析拿 `measured_*`，再线性归一） | ⛔ 单遍 loudnorm 是流式自适应的，开头几秒还没测准就在改增益，片头响度会飘 |
| **BGM 相对口播** | **−12 ~ −18 LU，默认 −14** | −12 = 音乐要被听见（情绪片、片头片尾）；−18 = 纯气氛垫底（信息密度高的讲解片）。老板 2026-08-16 实听把轮播放映线的默认从 −18 调到 −14 |
| **amix** | 必须带 `normalize=0` | 默认会按输入数分摊音量，把已经调准的口播再砍 6 dB |
| **淡入淡出** | 片头、片尾各 1.5 s | 硬切进/出音乐是「业余感」最明显的一处 |
| **重采样** | 母带 loudnorm 之后必须显式 `-ar 48000` | loudnorm 内部按 192 kHz 工作，不指定会把成片音轨留在 192 k |
| **拼接域** | 多段口播一律 **wav/PCM 域按样本数**拼接 | mp3 逐段拼每段漂 ~46 ms 且**累积**（8 段 0.41 s）。字卡线 2026-08-11、播客线 2026-08-07 两次同因事故。检验：成片实长 vs 各段累计差 > 0.1 s ＝有漂移，别用 |

**BGM 相对差怎么核**：读成片的 `<out>.meta.json` → 看 **`audio.bgm_actual_duck_db`**
（由归一后**回读实测**的 `bgm_measured_lufs` 反推），⛔ **不要看 `bgm_target_lufs`**——
那是「打算压到多少」，不是「实际压到了多少」。⛔ 也别用耳朵估——见上面 RMS 那张表。

### 🩸 分析域必须等于输出域（2026-08-16 实证，两层叠加共丢 3 dB）

同一次修声音，`--bgm-duck` 从 18 改到 14（BGM 应该抬 4 dB），回读实测却发现**只抬了 1 dB**。查下来是两处：

1. **单遍 loudnorm 不准**：流式自适应，开头还没测准就在改增益 ⇒ 一律两遍法；
2. **下混损失（主犯，−3 dB）**：BGM 源是宽立体声，`loudnorm` 在**立体声**上分析归一，
   输出时才 `-ac 1` 下混成单声道去和口播混。`(L+R)/2` 对不相关成分相消，能量掉约 3 dB——
   而口播本来就是单声道、没有这一刀。结果：参数写 −14，素材实际到 −17。

**通用规则**：**先把素材转成最终声道数/采样率，再分析，再归一。**
分析域与输出域之间任何一次声道数变化都会让归一失准，而且**不报错、成片能播**，
只有回读实测抓得到。⇒ 归一之后必须回读，脚本里做成闸门（差 > 1 LU 就拒跑）。

⚠️ 反向不成立：单声道**上混**成立体声（复制到两声道）LUFS 不变，实测 −31.88 → −31.86。
掉能量的是下混，不是上混。

### BGM 单调度（自产合成曲的已知边界）

`gen_bgm.py` 是纯合成（拨弦琶音 + 低音 pad，零版权），只有**四和弦循环、无编曲变化**。

- **≤ 2 分钟**：够用，听不出循环；
- **> 2 分钟**：会明显显单调，中段起会有「一直在响同一段」的感觉——
  这时要么把 BGM 压到 −18（退成纯气氛）、要么整片不加 BGM、要么走采购授权曲库（**老板拍板**的事，别自己下载）。
- ⛔ **绝不下载来路不明的音乐**：一条商用短视频背一首侵权 BGM，赔的钱比整条产线省下来的多。

## 三、静音空窗（听感上的「卡住了」）

| 位置 | 上限 | 备注 |
|---|---|---|
| 句间（页内） | 0.6 s | 本产线默认 0.45 s |
| 页间 / 段间 | 1.0 s | 本产线默认 0.35 s（停顿期间画面仍在屏，不是黑屏） |
| 片头 | 0.5 s | 超过这个数，观众以为没声音去点音量键 |
| 片尾 | 2.0 s | 末页要留够读完免责声明/热线的时间，但别拖到观众划走 |
| 任意位置的**无声段** | 1.5 s（无 BGM）／3.0 s（有 BGM 垫着） | 有 BGM 时整轨不会真静音，见下面的量具陷阱 |

```bash
# 量具：静音段检测（noise 阈值按素材调，人声片 -50dB 合适）
ffmpeg -v error -i <口播主轨.wav> -af "silencedetect=noise=-50dB:d=1.0" -f null - 2>&1 | grep silence_
```

⚠️ **量具陷阱**：对**成片**跑 silencedetect 基本什么都测不到——BGM 一直在响，整轨没有真静音。
要量的是**口播主轨**（`--keep-temp` 保留的 `narration_master.wav`）。
量错对象会得到「零静音段，通过」这种假绿。

## 四、必须人过的（脚本永远查不了）

**⛔ 别把「没报错」当成「验过了」。** 上面的自检只覆盖能量化的部分，下面这些没人替你做。

1. **三点抽听**：开头 0–15 s、中段（总时长一半处 ±15 s）、结尾最后 15 s，各完整听一遍。
   只听开头 = 只验了片头淡入。

   ```bash
   # 切三段出来听（不用整片来回拖进度条）
   D=$(ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 <片子.mp4>)
   ffmpeg -y -v error -i <片子.mp4> -ss 0                      -t 15 -vn /tmp/clip-head.mp3
   ffmpeg -y -v error -i <片子.mp4> -ss $(echo "$D/2" | bc -l) -t 15 -vn /tmp/clip-mid.mp3
   ffmpeg -y -v error -i <片子.mp4> -ss $(echo "$D-15" | bc -l) -t 15 -vn /tmp/clip-tail.mp3
   ```

2. **手机外放试听一遍**。⚠️ 这条不是可选的：**老板就是拿手机外放听的**，
   而手机外放没有低频、动态范围窄，耳机上「刚好」的 BGM 在外放上可能完全消失。
   耳机验过 ≠ 外放验过。
3. **BGM 不抢话**：人声任何时候都在最前，音乐是床不是声部。
4. **TTS 语速与停顿**：抽听 2–3 段，听有没有「赶」（该断的地方没断）、
   有没有把专有名词读错/读断（如「过度换气」被读成两个词）、有没有机械的等长停顿。
5. **口播与画面对得上**：第 N 段口播讲的是不是第 N 张图/第 N 个字卡。
   数量校验只保证数量对，保证不了内容对。

## 五、改动纪律

**改任何音频参数（duck / 母带目标 / 音色 / 语速 / 停顿 / BGM 源）之后，
必须重新出片并复核 `<out>.meta.json` 里的响度凭证段，⛔ 不能只看「命令跑完没报错」。**

```jsonc
"audio": {
  "narration_lufs_raw": -31.6,   // 口播原始电平（TTS 出来就这么安静，是常态不是故障）
  "bgm_duck_db": 14.0,           // 想要的相对压差（参数）
  "bgm_target_lufs": -45.6,      // = narration_lufs_raw - bgm_duck_db（目标，⛔ 不是实测）
  "bgm_measured_lufs": -45.6,    // ★ BGM 轨归一后回读实测
  "bgm_actual_duck_db": 14.0,    // ★ 实际压差，与 bgm_duck_db 差 >1 LU 即链路有隐性损失
  "bgm_in_film_lufs": -30.0,     // BGM 在成片里的绝对响度（= 实测 + 母带线性增益）
  "master": { "target_lufs": -16.0, "gain_db": 15.4 },
  "final_lufs": -16.05,          // ★ 成片实测，A1 判据认这个
  "final_tp_dbtp": -1.51,        // ★ 成片实测真峰，A2 判据认这个
  "final_lra": 8.3
}
```

`final_lufs` / `final_tp_dbtp` 是在**成片**上端到端量的（不是量中间文件报个好看的数）。
⇒ **证伪法**：把母带归一那段代码注释掉重跑，`final_lufs` 必须立刻偏离目标、自检必须变红。
如果注释掉了还是绿，说明这条闸门是摆设，先修闸门再谈成片。

## 六、各形态特有项（通用项看上面，别在各自 spec 里重写）

| 形态 | 特有项 |
|---|---|
| 轮播放映 | 页间停顿期间画面仍在屏（不是黑屏）；页数 == 口播段数 |
| 字卡短片 | 字幕/字卡与 cues 帧级对齐；kinetic 版需**词级** ASR 卡点 |
| 播客视频 | 双人声之间先做相对对齐（逐行 mean_volume −22 dB，男女声差 7.5 dB），**再**做整片母带；心电图声纹与音频帧级同步 |
| 微电影 | BGM 要有弧线（开场 −18 → 中段 −12 → 高潮前**全静默**）；生成素材必须强制静音去掉自带 BGM |
| 搬运重制 | 原声底噪与新配音的响度差；版权音乐必须换掉 |

### ✅ 欠账已清（2026-08-16 起账 → 2026-08-17 收编完毕）

**A1/A2 现在四条合成出口全部落成硬闸门**，实现只有一份：`scripts/audio_master.py`。

> 🩸 **起账时的形状值得记住**：2026-08-16 修的是「整片小声」这个 bug，但**只修了轮播放映线**，
> 另外三条出口原样留着。老板下次用默认形态（笔记微电影）出片必然重现同一个投诉，
> 而他会合理地认为这问题上次已经修过了。⇒ **同一个 bug 的兄弟出口必须一起修，
> 实现必须只有一份**——这就是抽 `audio_master.py` 的全部理由。

| 出口 | 形态 | 归一位置 | 成片实测（2026-08-17 验收） |
|---|---|---|---|
| `slideshow_video.py` | 轮播放映 | `mix_audio` → `master_audio` | **−16.02 LUFS** / −13.30 dBTP |
| `compose_video.py` | 笔记微电影（默认主线） | `compose` 末尾 `master_video` | **−16.03 LUFS** / −13.09 dBTP |
| `render_card.py` | 字卡短片 | `mux` 内联 loudnorm | **−16.06 LUFS** / −14.94 dBTP |
| `record_podcast.py` | 播客视频 | `mux` 内联 loudnorm | **−15.99 LUFS**（无淡出）/ −14.96 dBTP |

**不该归一的地方**（⛔ 别"顺手"补上去，会叠加两次）：`tts_gen.py`、`podcast_gen.py`、
`gen_bgm.py` 出的都是**中间件**，绝对响度由下游的合成出口统一负责；`video_pack.py` 是成片
之后的平台封装，重编码不改响度，也不该再归一一次。

**形态分档？不分（2026-08-17 调研裁决）。** 四个形态同为 −16。理由：Apple Podcasts 官方
播客指标本身就是 −16 LUFS ±1（依 ITU-R BS.1770），Spotify 对播客/音乐统一 −14，
AES TD1004 给流媒体的区间是 −20~−16；**没有任何一份规范按「内容时长」分档**，只按平台分档，
而播客视频是以 MP4 投视频平台的。分档位留在 `audio_master.FORM_TARGETS`，真要分改那一处。

### ⚠️ 已知边界：极短片 + BGM 会撞 BGM 回读闸门

`prepare_bgm` 给 BGM 两端各加 1.5s 淡化**之后**回读实测，超目标 1 LU 即拒跑。片子越短，
3 秒淡化占比越大，integrated 被拉得越低。实测（目标 −42.0）：

| 成片时长 | 5s | 8s | 12s | 20s | 40s |
|---|---|---|---|---|---|
| 回读偏差 | −1.53 ❌ | −1.06 ❌ | −0.66 ✅ | −0.43 ✅ | −0.15 ✅ |

拐点在 ~10s。本产线成片是 1–3 分钟量级，正常撞不到。**⛔ 不要为此放宽那个 1 LU 阈值**——
它是用来抓「分析域立体声、输出 -ac 1 白丢 3 dB」那类真隐性损失的。真要做 <10s 带 BGM 的
片子，改的是淡化时长，不是阈值。
