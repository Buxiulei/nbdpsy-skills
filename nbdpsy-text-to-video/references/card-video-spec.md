```

   句数由内容定——⛔ 别为了凑进区间而删论据或注水）→
② tts_gen --engine minimax --timed 口播+cues（★必须 2026-08-11 后版本：wav 域拼接）→

④ 选版式模板（assets/card-templates/）改卡片文案
```

## 五个版式模板（`assets/card-templates/`）

| 模板 | 概念 | 适用 | 已知代价 |
|---|---|---|---|
| **tpl-basic** | 品牌暖色+具象小动效（聊天气泡剧场/雷达扫描/下划线描画） | 默认；叙事场景类 | 最朴素 |
| **tpl-camera** | 一镜到底：八卡钉在大画布上摄像机运镜+景深换焦+电影遮幅 | 高级感/品牌片 | 渲染最慢（blur 负载，~4 min）；卡内断行手写、换字体会撑破 |
| **tpl-collage** | 心理手帐拼贴：纸片甩入/胶带/拍立得/印章「哐」盖章/信纸展开 | 温暖调性、贴手帐人群 | 码率最高（纸纹细节 ~18MB）；纸底色改动须同步印泥斑点色 |
| **tpl-kinetic** | 动力学文字：逐词砸屏/背景色情绪翻转/巨字滚屏/焦点句全片唯一红底 | 冲击力最强、观点型内容 | **必须走 ASR 词级卡点**（步骤③）；黑底强调块必须 inline-block 独立盒 |
| **tpl-oneline** | 一行字卡：全屏纸纹+手写体黑字白描边，**一屏只有一行、≤12 字**，念到哪句屏上就是哪句 | 减法到极限、要观众把注意力全押在当前这句；双画幅（3:4 小红书 / 16:9 视频号抖音） | **不能手改文案**（走 `build_oneline.py` 实例化）；句内翻屏点是按字数估算的（详见本节）；**⚠️ 12 字是排版拆屏的量具，⛔ 不是写稿字数上限**（见本节「写稿口径」） |

前四个模板=「可复制改造的参考实现」：**版式/动效层直接复用，内容层（各卡文案+强调词）按新笔记替换**。
换内容时守住各模板头部注释的硬契约（层级/字号收敛/安全区）。
**tpl-oneline 不走这条路**——它是脚本填的模子，文案由 cues 断句生成，见下文专节。

## tpl-oneline · 一行字卡专节（2026-08-16 立）

> **出处**：老板 2026-08-16 拿抖音「心理学永远爱你」的两张截图点名入库，原话
> 「这个不是要抄人家的书单，是抄人家的版式」「这种视觉更为集中的做法值得入库」。
> 拆解素材单：`NBDpsy/文档/2026-08-16-拆解素材单-抖音-一行字卡版式.md`。
> 样片（工程测试，四条）：`NBDpsy/seo-geo/content/videos/oneline-proto/`。

**版式定义**：全屏纸纹背景（静止）＋手写体黑字白描边＋**一屏只有一行、≤12 字、绝不折行**，
口播念到哪句屏上就是哪句。画面上除了正在说的那句话，什么都没有——无插画、无进度条、
无常驻落款（落款只在最后一屏浮出）。它是比其余四版式更极端的减法。
⚠️ **「一屏 ≤12 字」描述的是屏幕，不是稿子**——稿子该多长由内容定，见下「写稿口径」节。

### 产线（比通用五步多一步实例化）

```bash
# ⓪ 写稿（在这三步之前）：判据只有「把事说清楚」，⛔ 不拿 12 字裁句子——见下「写稿口径」节
# ① 口播 + 句级 cues（照常，⛔ 本版式不需要 kinetic 的 ASR 词级卡点）
python3 tts_gen.py --engine minimax --timed --voice "Chinese (Mandarin)_Warm_Bestie" \
        --text "$(cat narration.txt)" --out 工作目录/narration.mp3
# ② 断句分屏 + 实例化（双闸在这一步；不过闸不出文件）
python3 build_oneline.py --cues narration.mp3.cues.json --bg xianwen --canvas 3:4 --out 工作目录/
# ③ 照常渲染（画幅由模板里的 render-canvas meta 自己声明，render_card.py 不用传参）
cd 工作目录 && python3 render_card.py card-oneline.html out.mp4
```

`build_oneline.py` 会把 `gsap.min.js` 和字体一并拷进工作目录——**模板不内置 GSAP 只会静默超时**
（页面不报错，渲染器等 `window.SEEK` 等到死），所以这一步不能手工省略。

### 🩸 单行硬闸门（本版式的命门）

**字号是版式身份的一部分。装不下的唯一正解是改稿，⛔ 绝不缩字号、⛔ 绝不折行。**
缩字号能让任何句子"装下"，代价是这个版式的全部意义没了——所以闸门宁可拒绝出片。
三道闸各管一段，缺一不可：

| 闸 | 位置 | 判据 | 抓什么 |
|---|---|---|---|
| ① 字数闸 | `build_oneline.py` 断句 | 每屏 ≤12 字（ASCII 折 0.6）；`--max-line-chars 8–14` 可调（书名场景 13）——**整片**按「N 字装进安全区」反推统一字号（16:9 下 13 字≈121px），⛔ 按行缩字仍然绝对禁止，超上限照旧拒渲染（13 过/14 拒已实测 2026-08-16） | **某个片段断不开**（无标点又无软断点）——⚠️ 抓的是"断不开"，⛔ 不是"稿子太长" |
| ② 像素闸 | `--check`（默认开，真开 Chromium 量） | `offsetWidth + 2×描边 ≤ 安全区` | **闸①算错的情况**——换字体/改字号/改留白/回退字体的度量漂移 |
| ③ 画幅自洽闸 | `instantiate()` | `字号×12 + 2×描边 ≤ 安全区` | 有人调了画幅参数却没回头验算 |

### 🔴 专名屏例外（助理 2026-08-18 拍板 A，上面那句"绝不折行"的**唯一例外**）

一屏含**不可分割的英文专名**（期刊/量表/书名）且装不下时，允许**两行排版**，
并只把**这一屏**的字号缩到装得下（下限＝整片字号的 60%，再小就拒）。

| | 值 |
|---|---|
| **触发条件** | 🔴 **含不可分割专名**，⛔ **不是"装不下"** |
| **首选处置** | 两行排版（折点由 `proper_lines()` 算死后下发） |
| **次选处置** | 只缩这一屏的字号，⛔ 其余屏一个像素不动 |
| **预检口径** | ℹ️ **info，⛔ 不是 warn 也不是 fail**——它是**已处理好**的状态，无需改稿 |
| **兜不住时** | 两行仍超 ⇒ 拒，处置是「把专名单独说成一屏」，⛔ 不在专名内部补逗号 |

🔴 **为什么这个例外没有废掉"绝不折行"**：因为它由**内容性质**触发而非**排版结果**触发。
若由"装不下"触发，任何长句都能触发，契约当场失效；由"含专名"触发，
触发集是**封闭可枚举的**——就那几类专有名词。

🔴 **为什么两行同屏可以、两屏分时不可以**（同一个专名，两种切法后果完全不同）：
- 分**屏** = 时间上分离 ⇒ 第 2 屏单看是「and Psychosomatics」，**一个不存在的刊名**；
- 分**行** = 空间上同时可见 ⇒ 读者一眼看到完整刊名，只是排成两行。

🔴 **折点必须算死后下发，⛔ 绝不开 CSS 自动折行**：`Psychotherapy and Psychosomatics`
里有空格，浏览器会折在 `Psychotherapy` 后面——**所有折法里最坏的一个**（上行结尾正好是个假刊名）。
⚠️ 自动折行看着"能用"，出的正是要禁的那一屏。

🔴 **字号是两段算出来的，⛔ 别把它们当同一个数**：

| 段 | 谁算 | 是什么 |
|---|---|---|
| **估算下限** | `proper_font()`（Python） | ASCII 按 0.6 折算 ⇒ **偏保守** |
| **最终字号** | `refitProper()`（模板，浏览器端） | 按**实测宽度**回收余量，**只放大、封顶＝整片字号** |

**实测（2026-08-18，真开 Chromium，三条刊名）**：

| 估算 | refit 后 | 比例 |
|---|---|---|
| 57px | **62px** | 77% → **84%** |
| 58px | **66px** | 78% → **89%** |
| 53px | **63px** | 72% → **85%** |

⚠️ **refit 必须跑在 `window.SEEK` 挂出去之前**——渲染器只等 SEEK，**根本不知道页面还在变**；
跑晚了第一批帧就是 refit 前的字号，**而且没有任何东西会报错**。
⚠️ **refit 与 report 分开写**：一个是改、一个是量。量具和被量对象混在一起，量出来的永远是自己想要的数。

⚠️ **残余的保守没有一起放宽**：`proper_lines()` 的 `limit` 仍按估算算，
所以少数 refit 后其实能过的句子会在 build 阶段就被拒。**这是有意留的**——放宽它等于让
`--precheck`（离线、开不了浏览器）说能过、真跑却被像素闸拒，**预检与真闸当场不同源**。
⇒ 宁可多拒（代价：作者多断一句，且报得清楚），⛔ 不要假绿。

### ⚠️ 数量串走同一条规则（2026-08-18 扩全）

判据是**切开后数值就变了**，⛔ 不是"读着别扭"：

| 类 | 切开后 |
|---|---|
| 危机热线 `12356` | 「请打 123」「56」＝**一个错的号码** |
| 中文日期 `二〇二六年八月` | 「二〇二」「六年八月」＝**一个不存在的日期** |
| 金额区间 `四百到六百元` | 「四百」「到六百元」＝**另一个价** |
| 时长 `三分零五秒` | 「三分」「零五秒」 |
| 百分比/小数 `3.2` | 「下降了 3」「2 个百分点」 |
| 手机号／身份证／PMID／DOI | 同上 |

🩸 **本批 5 条科普的 12356 没被劈是侥幸**——它们恰好写成「热线，12356」让号码单独成屏。
⛔ 别拿"这批没出事"当"规则够用"。

🩸 **数字内部的 `.` `:` `/` 不当句读**（这是个**在产的坑**）：`HARD` 里就有 `.` `:`，
硬切根本轮不到保护区间，`display()` 还会把点整个丢掉 ⇒ `10.1001` → `101001`（**DOI 被改了**）。
⚠️ 只保护**数字参与**的那一侧，英文缩写里的点（`e.g.`）照旧当句读。

⚠️ **误伤面是有意压小的**：只保护 ≥2 字的串（「不一样」的「一」不算），
连接词只收「到/至/多/余」⛔ 不收「和/或」（那两个更常是并列连词）。
**29 份在产稿实测：断不开 63→63、软断 146→146、屏数 1971→1971，逐文件零差异**；
同一批里被新规则保护住的串 **425 处** ⇒ 零变化**不是规则没生效**，是这些串本来就没被切。
⚠️ 但这批稿里目标场景（热线/日期/金额）样本极少 ⇒ **它对"会不会引发假红"只是弱证据**。

---

断句规则：**标点（，。！？；：、…—）一律断屏且不上屏**（对标片屏显不带标点）；
段落仍超长时才启用**软断点**（认「下一段以 是/就/都/而是/所以/之后… 开头」或
「上一段以 了/着/过/时/后 结尾」，碎片不短于 3 字），动态规划取片数最少、长度最匀的切法。

🔴 **结构虚词（的地得把被在从对向给跟和与）前后都不断**（2026-08-18 两次拍板合成一张表）：

| 上屏结尾（第一次拍） | 下屏开头（第二次拍） |
|---|---|
| 「如果你正被持续的｜情绪困扰缠着」 | 「第一作者是我们｜的咨询师负责人李牧阳」 |
| 「练的就是怎么在难受的｜时候」 | 「把想来的人挡｜在门外」／「正念更关心你｜和自己感受之间的距离」 |

🩸 右列那三处是**左列规则上线之后**仍然照出不误的——**判据只看了断口的左边**。
根子在**两张登记表对同一批字给了相反的裁决**（`TAIL_BAN` 说不许做结尾，
`SOFT_HEAD` 却把「在/和/把/被…」列为合法开头）。⇒ 合成一张 `STRUCT_PARTICLES`，⛔ 别再分开维护。

⚠️ **jieba 词边界是必要条件，⛔ 不是充分条件**：「持续的」「情绪困扰」本来就是两个词，
在「的」后面切**确实是词边界**——词边界这一道拦不住它。

🔴 **虚词判的是「断口两侧的词」，⛔ 不是「两侧的字」**（2026-08-18 晚改）：
🩸 `向` 在表里 ⇒ 「证据**方向**｜是相反的」被当成"断在介词后"**整句拒渲染**，
**逼作者改一句本来没问题的话**。⚠️ 同一个字在不同词里角色不同，**单字黑名单永远分不出**。
升到词级后：`jieba` 把「方向」切成一个词 ≠「向」⇒ 放行；
「持续/的」「挡/在/门外」里那些虚词**本来就是独立的词** ⇒ 照禁。
**29 份在产稿实测：断不开 63→62、拦截零丢失。**
⚠️ jieba 不可用时**退回单字判据**（更严、多拒），⛔ 不是悄悄放行。

### ⚠️ 「三字孤悬」：报出来，⛔ 别靠提高 MIN_SOFT 治

**29 份在产稿实测**：

| | 断不开 | 软断 | ≤3 字屏 |
|---|---|---|---|
| `MIN_SOFT=3`（现行） | 62 | 147 | **122** |
| `MIN_SOFT=4` | **77**（+24%） | 132 | **107**（−15） |

🔴 **≤3 字屏有 122 个，提高 MIN_SOFT 只消掉 15 个（12%）**——因为**大头根本不来自软断，
来自作者自己用逗号句号断出来的短句**，而 `MIN_SOFT` 只管软断。
⇒ 代价（多拒 15 处、逼作者改稿）与收益（治好 12%）**完全不成比例**。
⇒ 改为给短屏一个独立记号 `[短屏]`（能数能 grep），**报出来让作者调标点**——
🩸 光有 `MIN_SEC` 那条时长警告不够：它跟软断警告混在一堆 `⚠️` 里，**warn 太弱、人不会逐条看**。
⚠️ 短屏是**报**不是**拒**——「够了」「不是的」这种三字屏是刻意的节奏，只有写稿人说了算。

### 🔴 已知缺口：断在名词短语中间（⛔ 现有工具做不到）

助理 2026-08-18 提的正向判据「每屏必须能独立成话」，**只落地了可计算的那部分**
（虚词两侧禁断／保护区间／词边界／短屏登记）。
⛔ **「断在名词短语中间」没有落地**——它要句法分析，`jieba` 的分词+词性给不出短语边界。
⚠️ **别以为这一版解决了它**：`目前这个领域的证据方向｜是相反的` 现在是**合法断点**，
读起来割裂与否归写稿人裁决。
软断**一定会登记出来**（`⚠️ 第 N 句在无标点处自动软断：…｜…`）——断点断得对不对只有写稿人说了算，
⛔ 不许静默。软断不开就拒绝出片，并报出是哪一句、哪个片段、以及三个「在这儿加个逗号就行」的位置。

**证伪记录（2026-08-16，三闸逐条实证）**：
- 闸①：`过度换气综合征患者常伴心慌手麻`（15 字、无任何软断点）→ 退出码 1，给出
  `过度换气综合征｜患者常伴心慌手麻` 等三条建议断点；
- 闸②：把 `units()` 打桩成少算一半（模拟闸①算错），14 字句子溜过闸①后
  → 闸② 实测 1006px > 安全区 960px，退出码 1；
- 闸③：把 `max_chars` 改到 20 → 「20 字需 1546px > 安全区 960px」，退出码 1。

### 🩸 写稿口径：12 字是**排版量具**，⛔ 不是写作阶段的字数上限（2026-08-17 老板令）

> 老板原话：「**口播稿我看了，没有把事情讲清楚。不要为了缩减字数而刻意删减。把事情说清楚
> 才是第一位**」。

事故形态是**顺序颠倒**：写稿人先看见「每屏 ≤12 字」，于是**先算字数、再想说什么**，交回来的是
一堆"排得下的短句"，不是把事说清楚的话。老板看到的结果就是「没把事情讲清楚」。
口径与封面工序**完全同源**：**先写内容 → 再排版**。

### 🎵 背景音（2026-08-18 老板：「都没有背景音，需要添加」）

🩸 **根因不是"没做过 BGM"**——轮播线（`slideshow_video`）与微电影线（`compose_video`）**一直有**，
`BGM_DUCK_LU=14` 还是老板 **2026-08-16** 对着成片实听调下来的。**只有字卡线漏接了。**
⚠️ 这是 `BGM_DUCK_LU` 注释里那条教训的**第二次现身**：**「修复只落在他点名的那个形态上」**
⇒ 同一个老板在另一个形态上又听到一次同样的问题。

| 开关 | 默认 | 说明 |
|---|---|---|
| `--bgm` | `auto` | `gen_bgm.py` **纯合成**（拨弦琶音＋低音 pad），零版权零外部素材；也可给音频文件路径 |
| `--no-bgm` | — | 出纯口播片 |
| `--bgm-duck` | `14` | BGM 低于口播多少 LU。⚠️ 改它要**重新实听**，⛔ 别凭「听起来应该」拧 |
| `--remux 源.mp4 输出.mp4` | — | **对已成片重混**，⛔ 不重渲帧 |

🔴 **⛔ 不下载来路不明的音乐**（本仓 2026-08-16 已拍）：**一条商用短视频背一首侵权 BGM，
赔的钱比整条产线省的多**。要用真实曲子就把文件路径传给 `--bgm`。
⛔ **也不用 CC BY**——署名要求意味着每条片子片尾都得加一行字幕，那会破坏本版式
「画面上除了正在说的那句什么都没有」的硬契约。

⚠️ **⛔ 没有 sidechain**：三条线用的都是**静态压 14 LU**，字卡线单独上 sidechain
＝ **三条线三个声音**。要加就三条线一起加。

**冒烟实测（kepu-a 成片，209.7s，2026-08-18）**：

| 量 | 原片 | 加 BGM | 判读 |
|---|---|---|---|
| 片长 | 209.733333s | **209.733333s** | ✅ TAIL 没被截 |
| 视频流 md5 | `e6a7e125…` | **`e6a7e125…`** | ✅ `-c:v copy` 真没重编码 |
| 句间静音 @95.9s | −91.0 dB | **−31.7 dB** | ✅ BGM 在这里是唯一声源、清晰可闻 |
| 人声段 60–70s | −18.4 dB | −18.3 dB | ✅ 人声不受影响 |
| 末屏 12356 段 | −17.9 dB | −17.8 dB | ✅ 清晰度没被盖 |
| 母带 | — | **−15.99 LUFS / −4.41 dBTP** | ✅ 达标 |
| 耗时 | 重渲 ~11 min | **41s** | |

🔴 **「BGM 在」与「BGM 听得见」是两件事**：压 14 LU 后，混合总能量只增加
`10·log₁₀(1+10^(−14/10)) = 0.17 dB` ⇒ **有人声时几乎量不出来**（实测 0.1 dB）。
⚠️ 所以验 BGM **要量句间静音段**，⛔ 量整片或人声段会得出「BGM 没进去」的错结论。

### 🔴 批量开跑前：先算「单条体积 × 条数」比可用磁盘

**2026-08-18 冒烟实证**：1080×1440 30fps 的 PNG **≈2.3MB/帧**，一条 3–6 分钟口播的帧目录
**12–25GB**；**12 条并存 ＝ 241GB**，而机器可用只有 248G——**还得减去别人正在用的**。

⚠️ **磁盘是共享的**：撑爆不是"本线这批失败"，是**连同时在出片的别条线一起死**。

⇒ **两条已落地的防护**：
- `render_card.py` **整片渲完后默认删帧目录**（`--keep-frames` 可留）。
  🔴 删的判据是 **`ffprobe` 读得出成片时长**，⛔ **不是「mp4 文件存在且非空」**——
  MP4 的 moov atom 在**末尾**写入，混音进行中的半成品同样存在、同样有几 MB
  （实测 3.8MB 的半成品报 `moov atom not found`，写完是 25MB）。
  **拿"存在"当"渲完了"去删帧，会把还在用的帧删掉。**
- ⚠️ **分片模式（`--shard`）不清帧**——帧还要给别的片与 `--mux-only` 收口用。

**⇒ 通则：批量 × 大产物开跑前，先把「单条体积 × 条数」和 `df -h` 摆在一起看。**
⛔ 别等跑到第 8 条才发现磁盘满了——那时前 7 条的算力和 TTS 配额已经花掉了。

#### 落款反差（加背景档时必量的一项）

`brand` 是半透明色（`rgba(...,.50)`）压在纹理底上，**换了底色它的实际反差就变了**——
沿用别档的 `brand` 值 ≠ 沿用了它的可读性，必须实测，⛔ 别靠推断。

量法：把 `#brand` 的 `opacity` 强制成 1（它初始是 0，靠 GSAP 补间才显形）、藏掉 `#stage`，
截图取 `#brand` 的 boundingBox 横向中段，Otsu 把区内像素分成字与底两簇，
**亮度差 = 底簇均值 − 字簇均值**（0–255）。

2026-08-17 三档实测（3:4，`brand_px=30`）：

| 档 | 亮度差（Otsu） | 峰谷差（最亮 − 最暗 1%） | WCAG |
|---|---|---|---|
| `liaoyu` | 53.1 | 76.0 | 1.87:1 |
| `kepu` | 60.3 | 90.0 | 1.97:1 |
| `miwen` | 56.0 | 88.0 | 1.91:1 |
| **`xianwen`** | **54.5** | **92.0** | **1.88:1** |

`miwen` 三种口径下都**高于 `liaoyu`**（底色更亮而落款色相同，绝对亮度差被拉开），
所以沿用的这个 `brand` 值够用，不动。WCAG 比值都远低于 AA 的 4.5:1——**这是有意为之**：
落款是装饰性水印不是正文，按正文标准拉高它会把视线从中间那行字上抢走。

⚠️ **`xianwen` 两个口径方向相反，别只看一个**：Otsu 口径比 `miwen` **降 1.5**（56.0→54.5），
峰谷差口径反而**升 4**（88→92）。原因是纸感层加大了落款区背景自身的起伏——
背景簇均值被拉低（200.34→198.62）所以 Otsu 差变小，而纹理让最亮点更亮所以峰谷差变大。
⇒ **判据仍是「高于 `liaoyu` 现状 53.1」，54.5 过线，`brand` 不动。**
但这条记下来：**往背景加纹理会轻微吃掉落款反差**，⛔ 以后再加纹理层必须重量这一项。

### 双画幅（`CANVAS` 表，同理加档）

| `--canvas` | 尺寸 | 字号 | 描边 | 安全区 | 12 字实占 | 用途 |
|---|---|---|---|---|---|---|
| `3:4` | 1080×1440 | 80px | 14px | 1000px | 988px | 小红书主战场 |

**上限 12 字两档相同**——它是版式规则不是画幅参数；字号由「12 个字必须装进安全区」反推。
描边固定 `round(字号 × 0.17)`，靠 `paint-order:stroke fill` 让描边只长在字外、不吃笔画
（Chromium 对 HTML 文本生效，实测通过，省掉双层结构）。

表里后三列**都是算出来的，改字号时请复算，⛔ 别手抄**（安全区 `W − 2·pad`；
**12 字实占 `字号 × 12 + 2 × 描边`**——描边只长在字外，两端各加一个描边宽）：

| | 安全区 | 12 字实占 | 余量 |
|---|---|---|---|
| `3:4` | 1080 − 2×40 = **1000** | 80×12 + 2×14 = **988** | 12px |
| `16:9` | 1920 − 2×150 = **1620** | 130×12 + 2×22 = **1604** | 16px |

🔴 **这个公式是补记的，因为旧表手抄错过**：旧 `16:9` 那行写「128px 字号 / 22px 描边 / 实占 1562」，
而 `128×12 + 2×22 = 1580` ——1562 是拿 `3:4` 的描边 13 去算 16:9 得到的，**两档串了行**。
⇒ **数字和它的算法必须一起存**：只存结果的表，漂了也看不出来。

  要用得先做子集化。**这是一笔登记在案的欠账**：若日后老板认为疗愈档需要更沉静的字，
  由主会话裁决是否做子集化引入。
- ⚠️ 字体没加载完就开渲＝第一批帧是回退字体。模板把 `window.SEEK` 挂在 `document.fonts.ready`
  之后，渲染器现成的 `wait_for_function` 就自然成了字体就绪闸门——**别把这段挪到前面去**。

### 与「屏显文字排版三铁律」的关系（登记）

本版式**严于**三铁律，不是豁免：逗号在别的版式是换行，在这里直接**翻屏**；句号照常翻页；
每句独立成屏。翻屏用同向上移交错（前一屏上移淡出与下一屏上浮同刻起手，视觉提前 0.07s），
**空窗 ≈ 0**。唯一放宽的是「最短页 1.2s」——单行字数上限决定了短屏并不进相邻屏，
所以短于 1.0s 只**告警**（`⚠️ 第 N 屏「…」仅 0.9s`），处置一律是改稿而不是并页。

### 已知代价（用之前先认）

1. **句内翻屏点是估算**。cues 是句级的，一句拆成多屏时按字数（逗号额外记 1.6 字的停顿）
   分配时间，误差量级 ±0.2s。**句边界＝屏边界这一层是精确的**。
   ⚠️ 句子短到不用拆屏时这项估算自然消失，但**⛔ 这不构成把句子写短的理由**——
   ±0.2s 的翻屏误差远不如「话没说清楚」贵（见上「写稿口径」节）。
2. **屏数由内容长度决定**。一句话拆几屏是排版的结果，⛔ 不是写稿要优化的指标；
   为了少几屏而删论据，是拿排版理由伤内容（2026-08-17 老板令，判据见上「写稿口径」节）。
3. **不能手改文案**。改字要改稿重跑 ②③ 两步，不能像前四个版式那样直接编辑 HTML。

## 渲染契约（每个模板必须满足，render_card.py 依赖）

- 画布默认 1080×1920，`html,body` 定死 overflow:hidden；要别的画幅就在 `<head>` 里声明
  `<meta name="render-canvas" content="1080x1440">`，render_card.py 读它定 viewport
  （**不声明＝1080×1920**，四个存量版式都没这行，逐字节走老路径）；
- 读 `const CUES = __CUES__;`（渲染器注入逐句 {text,start,end}）；kinetic 另读 `const WORDS = __WORDS__;`（无该占位的模板不受影响）；
- 主时间轴 `gsap.timeline({paused:true})`；暴露 `window.TOTAL` 与 `window.SEEK = t => tl.seek(t,false)`；
- **确定性**：⛔ Math.random/Date.now——一切"随机"用写死数组（重渲染必须逐帧一致）；
- 混音源优先 `narration.mp3.wav` sidecar（render_card.py 自动选）。
- **混音时做母带响度归一到 −16 LUFS**（口径见 `audio-checklist.md`），实现在 `scripts/audio_master.py`。
  ⚠️ 本脚本按契约是**被拷进工作目录**跑的，`audio_master.py` 不会跟着拷。它会按序找
  「同目录 → 往上找 skill 真源 → `~/.claude|.agents|.codex/skills/nbdpsy-text-to-video/scripts`」，
  **全找不到就拒绝出片**（⛔ 不静默跳过——静默跳过等于把「整片小声」那个 bug 放回来）。
  报错时按提示把 `audio_master.py` 拷到 `render_card.py` 同目录即可。

## 🩸 音画同步双层根因（2026-08-11 实战，全产线最重要的知识）

1. **mp3 逐段拼接漂移（全形态共性）**：每段拼接漂 ~46ms 随句数**累积**（8 句实测 0.41s，字卡越后越提前）。
   与播客线 2026-08-07 定性死路同因，tts_gen `--timed` 路径 2026-08-11 已根治：**wav/PCM 域按样本数拼接**，
   cues 按样本数构造，一次性编码输出（encoder delay 仅 ~43ms 且不累积），另出无损 `.wav` sidecar。
   **⛔ 检验法**：`ffprobe` 音频时长 vs cues 尾差 >0.1s ＝拼接路径有漂移，别用。
2. **词级卡点不能估算（kinetic 特有）**：句内按语速均匀分配＝必漂。正解＝faster-whisper 词级时间戳
   （`extract_word_timings.py`，三条坑见其文件头注释：wav 源/简体 prompt 不含正文/首字游标容错回退）。
   验证法：取一个关键词的 ASR 时刻抽帧，字应正在砸入瞬间。

## 工程坑清单（GSAP 逐帧渲染，全部实战踩过）

1. `gsap.fromTo` 一律 `immediateRender:false`——否则后段动画的 from 值提前渲染到开场（冲击环提前显形实例）；
2. 显隐 ⛔「CSS opacity:0 + tl.from({opacity:0})」——from 终值=当前 CSS 值=0 全程隐形；用 fromTo 显式终值或 tl.set；
3. **行内高亮块巨字必溢出**：`b { background:… }` 的 inline 背景盒跟不住大字号字形（笔画溢出块缘、两行咬合）——
   **必须 `display:inline-block` 独立盒**（padding 包字形+line-height 1.05+块间 margin）；
4. 绝对定位装饰层与文字分区布局，禁止重叠遮字；
5. 词组切换用 `duration:0` 的 fromTo 硬切（出场 to 与入场撞同帧时，普通补间在自身 start 渲染 progress 0 会出空帧）；
6. 渲染性能：多层 text-shadow/大面积 blur 拖慢逐帧截图（tpl-camera 251s vs tpl-kinetic 58s），量产优先轻负载模板；
   重负载模板走分片并行可把墙钟时间压回来（见下节「GPU 加速与分片渲染」）；
7. 双格式落盘防重（出图目录 png+jpg 同名会被发布脚本收两遍——publish_note 已去重，但落盘仍建议单格式）。

## GPU 加速与分片渲染

**提速主路是分片，不是 GPU。** 逐帧截图**默认 CPU 光栅**（SwiftShader）——与 2026-08-11 验收入库的
存量字卡片逐字节同一套参数（已实测校验：默认路径与改造前原始启动参数的 222 帧哈希同为
`0a5485a6…`）。GPU 要显式开，且**开了就整批开**（理由见纪律②）。

```bash
# 整片（默认 CPU，与存量批次像素一致）
python3 render_card.py tpl-basic.html out.mp4
# 分片并行：预清帧目录 → N 片并行 → 帧连续性校验 → 合帧混音，一条命令收口
bash render_sharded.sh tpl-camera.html out.mp4 4
# 逐字节可复现模式（跑验收闸门时用，见纪律①）
bash render_sharded.sh tpl-camera.html out.mp4 4 --deterministic
# 显式开 GPU（⚠️ 会改像素，整批统一才用）／vulkan 起不来的退路
python3 render_card.py tpl.html out.mp4 --angle vulkan
python3 render_card.py tpl.html out.mp4 --angle egl
```

`render_card.py` 启动后把实际后端打进 stderr：默认路径打一行中性说明
（`ℹ️ 当前 CPU 光栅（与存量批次一致）`）；**显式要了 GPU 却落回 SwiftShader 才打醒目警告**，
看到就别往下渲。⚠️ `--use-angle=egl` 不是 ANGLE 的合法取值、会**静默**回落 SwiftShader，
所以 `--angle egl` 内部映射成 `gl-egl`（2026-08-12 实测）。

**实测（本机 RTX 4090 + Playwright 1.58 headless，1080×1920，2026-08-12）**：

| 模板 | 帧数 | CPU 整片（默认） | CPU 4 片 | GPU 整片 | GPU 2 片 | GPU 4 片 |
|---|---|---|---|---|---|---|
| tpl-basic | 222 | 20s | 14s（2 片） | 11s（1.8×） | — | — |
| tpl-camera | 415 | 131s | **32-33s（4.0×）** | 83s（1.6×） | 43s | 28s |

**分片是提速主力，而且它零像素变化**：默认 CPU 路径上 camera **131s→33s（4.0×）**，全部来自分片。
在此之上再开 GPU 只多买到 33s→28s（约 1.15×）——用「与全部存量片字形不一致」换 15%，不划算，
所以默认关。GPU 单跑那 1.6-1.8× 在分片之后基本被吃掉了。
另注：GPU 提速比与模板负载**无正相关**——重负载的 camera 受益反而略小（1.6× vs basic 的 1.8×），
瓶颈在截图编码与 IPC，不在光栅。

⚠️ 上表分片数字**逐条复测过**：首测 GPU 4 片 38s 是单跑噪声，复跑两次稳定 28s。
分片耗时受同机其他负载影响明显，**要拿它做决策就跑两遍**（本节的教训之一）。

N 按内存定不按核数定：一路 Chromium 逐帧渲染峰值可吃到数 GB（EMDR 线 R15 有 7.1GB 被 OOM 杀的实例），
**2-4 是安全区**；4 片相对 2 片已进入争抢递减区。`--deterministic` 约慢 1.7×。

### 三条纪律

**① 换渲染后端必须双跑 md5 验确定性**——同模板同 cues 双跑，mp4 md5 一致才可用。
GSAP 渲染契约禁 `Math.random`/`Date.now` 正是为此服务。
🩸 **但双跑必须带 `--deterministic`**：不带它时逐帧截图**本来就不是**逐字节可复现的（seek 后不等合成器
提交就取图），实测同配置三跑出两三个不同 md5，CPU 与 GPU 都一样、和分片无关——
**这是 2026-08-12 之前就有的老毛病，不是 GPU 引进的**。差异 ≤6/255、落在 <0.4% 像素上，肉眼与成片无感，
但拿裸默认路径跑 md5 闸门＝闸门永远红，会把人引去查根本不存在的 bug。

口径按场景写死（2026-08-12 定）：

| 场景 | `--deterministic` |
|---|---|
| 验收、复现、换后端/换 N 前后对比 | **必须带**，否则闸门无意义 |
| 批量产线出片 | **建议带**——1.7× 代价用分片买回来（camera 4 片仍比 CPU 整片快 2 倍多） |
| 迭代调模板、预览看效果 | 不必带，默认路径快且与旧版逐字节兼容 |

**② 整批视频统一后端不得混用**——GPU/CPU 是两套字形抗锯齿实现，**差异远不止"亚像素"**：
实测 tpl-basic（`--deterministic`，同模板同 cues）CPU 与 GPU **222/222 帧全部不同**，
最严重一帧差 300804 个像素（占 14.5%），最大通道差 3-4/255，有差异帧的非零像素中位数 17186。
EMDR 线在带阴影合成的球体模板上量到更大：**44-49 万像素、最大通道差 35/255**。
混用＝同批的字看起来不是一套东西。

**分片数 N 同样算渲染配置的一部分**：实测（`--deterministic`，tpl-basic）整片 vs 2 片 vs 3 片三份 mp4
md5 各不相同，差在 1 帧、383 个像素、最大通道差 1——这个量级才叫看不出来，但同批混用仍是无谓的不一致。

**同一批：后端一致 + N 一致。**

⚠️ **正因为此，默认后端是 CPU**：2026-08-11 验收入库的首片与四版式样片都是 CPU 渲的，
默认开 GPU 等于让新片跟存量不是一套字。要用 GPU 就**整批都用**（含同批的补渲、返工重出），
别只给某几条开。EMDR 线基于同一条理由也把 GPU 关掉了，两线口径一致。

另：EMDR 线报告 vulkan 下 `page.screenshot` 会间歇性抛 `Unable to capture screenshot`
（本线 tpl-basic/tpl-camera 十余次整片与分片实跑未复现，但显式开 GPU 时要留意，遇到就退回默认 CPU）。

**③ 两个全量渲染撞同一帧目录＝后来者拒绝启动，绝不清对方的帧**。
帧目录里放 `.render.pid`（整片）/ `.render.pid.s{i}of{N}`（分片），首行是 pid。开渲前扫一遍：
凡是**会写到同一批帧**的活锁存在就 exit 1 并报出持锁 pid；只有「同一 N 的不同分片」算互不冲突，
其余组合（任一为整片 / 同一片重入 / N 不同）一律挡。锁主已死则打印接管说明后接管。
`render_sharded.sh` 在**预清帧目录之前**也做同一道检查——否则"先清后拒"照样把别人的活清光了。

> 事故由来（EMDR 线 R15/R16，2026-08-12）：两个渲染进程开在同一个工作目录，各自开渲前
> `unlink` 了对方的帧，成片音画混轨，而当时的 QA 量具查不出来——**帧目录被静默清空是最伤的失败模式，
> 因为它不报错**。归因还有一层：那两起"双渲"都是**自撞**（chain 已接管渲染，人又按派工单手跑了一遍），
> 所以自锁必须挡的是"任何会写同一批帧的第二个进程"，不分敌我。
