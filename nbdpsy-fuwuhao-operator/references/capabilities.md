## 能做什么（九项）

### 1. 排版发文
Markdown → 微信白名单内联样式 HTML。自动处理三件运营手动做很痛苦的事：正文图逐张传微信图床换 `mmbiz` 链接、封面传素材库拿 `thumb_media_id`、把不被微信支持的写法（class / `<style>` / `<script>` / iframe / position）在编译期就挡掉。
产物经真机核对：字号行距、二级标题左侧品牌红竖线、引用浅灰圆角卡片，与设计规格分毫不差。

### 2. 配图生成（gpt-image-2 锚点法）
与小红书轮播图**同一套服务、同一把凭据、同一个一致性机制**，只有三处按公众号场景改了：出**横版**（1536×1024）而非竖版、一篇是**1 封面 + 按正文字数配的插图（每 ~500 汉字一张，3500 字 → 7 张）**而非 6~9 页轮播、封面额外**居中裁成 2.35:1**（微信封面比例）。
一致性靠「锚点法」：先出封面 → 运营确认配色/风格 → 把这张当锚点喂给所有插图，整篇调性统一。**封面没确认就批量出图 = 风格跑偏后全废**。
提示词**不由生图脚本编**，来自稿件里的「## 配图」区块（写稿时一并产出）——图文才配套，而且改文字比重出图便宜得多。

### 3. 定时发布
微信**没有**定时发布 API，这能力是我方服务端队列到点执行实现的。所以：任务排在我们库里、能查能取消，公众平台后台看不到它们。

### 4. 群发（高危）
真正推送到粉丝对话框。**每自然月只有 4 次、发出去撤不回**。带月配额守卫与二次确认，且配额只统计经本系统发的——运营在公众平台后台手点过的次数我们数不到，复述剩余次数时必须把这句一并说出来。
**4 次限的是消息条数**：一条群发消息最多装 8 篇图文（第 1 篇是主图文），整条只算 1 次。运营要推多篇时先问「能不能打包成一条」，别一篇一次白烧配额。

### 5. 菜单装修
本地 JSON 是编辑真源，apply 前给 diff 念给运营确认。菜单有约 24 小时客户端缓存，改完粉丝不一定马上看到（取关重关可立即验证）。当前线上三栏：找咨询师 / 心理科普 / 我的。

### 6. 已发布文章查与删
台账（`--ledger`）是「线上有什么」的**唯一权威**——微信的列表接口查不到已群发的文章。
**微信没有「改」**：要改错别字只能删了重发，代价是换新链接、阅读/在看/分享数据清零。删除不可逆，必须先把代价讲清楚再动手。

### 7. 数据统计
涨粉、阅读、分享、单篇逐日曲线与阅读完成率。数据来自服务端每日 08:30 抓取的快照，可跨任意区间查（绕开了微信各接口 1~30 天不等的跨度限制）。**新口径数据从 2025-11-01 起**，更早的拿不到。当天数据要次日才稳。

### 8. 贴图（图片消息）——小红书笔记平移
「贴图」= 原「小绿书」2026 年升级版：图为主（≤20 张，首图即封面）+ 纯文本短文案，形态对标小红书，微信给独立分发位（公众号主页【贴图】栏、看一看、搜一搜「贴图号」分类）。现成小红书笔记一条命令平移：`--draft-add-newspic` 传图建稿一条龙。**标准流程是「skill 建稿 + 运营后台点发表」**——API 发表的内容不进主页（只得可分享链接），后台发表才进贴图栏与推荐池，且无次数限制、不占群发配额，适合高频更新（后台发表的内容台账不记，以后台发表记录为准）。贴图正文纯文本原样显示，不走 md2wechat；贴图草稿不支持字段级更新，改 = 重建。

### 9. 来访者即时回执推送（触达通道）
已关注服务号且完成身份绑定的来访者，会在五类事件发生时收到服务号消息：**预约已确认、咨询师回复留言、咨询师发来问卷、预约取消/改期、开通正式咨询预约通道**。
身份绑定三条路：专属二维码扫码关注（精确且确认已关注）、微信内打开官网时静默采集、UnionID 自动对号（老用户打开一次小程序即自动关联）。
引导入口：小程序（支付成功页/预约详情页/个人中心+独立页）、官网（支付成功页/账户页）、服务号菜单。

## 不能做什么（问了要直说，别硬凑）

| 运营可能会问 | 事实 |
|---|---|
| 「把已发的那篇改一下」 | 微信没有修改接口。只能删+重发，换链接、数据清零。后台那个「改错别字」是网页专属功能，没有 API |
| 「群发多发几次行吗」 | 每自然月 4 次是微信硬限，官方明确不支持增加。**但 4 次限的是消息条数**：一条里能放 8 篇图文、只算 1 次，要推多篇就打包成一条 |
| 「这个月还能发几篇文章」 | 这个问题问的其实是**群发**。走「发表」**没有次数限制**（官方口径：未开群发通知的内容，发表后仅在公众号主页展示，无次数限制）——想一周发三篇完全可以 |
| 「预约前 2 小时提醒也走服务号吧」 | **不行，这是合规红线**。微信《模板消息运营规范》明文禁止「课程提醒类/到期提醒类」定时催达，处罚阶梯到封号。服务号只做「刚发生的事的回执」。定时提醒继续走短信与小程序订阅消息 |
| 「催付款/催填问卷用服务号推」 | 同上，属禁区。代码层面也焊死了，加不进去 |
| 「给所有粉丝群发个活动」 | 技术上能（4 次/月），但内容规范禁止营销推广类模板消息；文章群发本身可以，注意别写成硬广 |
| 「菜单加个点击自动回复的按钮」 | 需要消息回调已配置（现已具备），但当前菜单按钮只用了跳网页/跳小程序两类；要加 click 类需要另外实现自动回复逻辑 |
| 「看看昨天发的那篇多少阅读」 | 要等次日快照；且只有走「发表」发布的文章有新口径数据 |
| 「帮我把公众号文章同步到小红书」 | 那是 `nbdpsy-xiaohongshu-creator` 的活，让它拆 |

## 三条最容易出事的纪律

1. **发布 ≠ 群发**。默认走「发布」（不打扰粉丝、次数不限，文章进发表记录与搜一搜）。运营说「推送给粉丝/群发」才走群发，且必须复述本月剩余次数并拿到明确确认。
   ⚠️ **但两者都不可逆**——区别只在**推不推送粉丝、占不占月配额**，⛔ 不在「能不能反悔」。已发布的文章微信没有「改」：要动一个字只能删了重发，代价是**换新链接、阅读/在看/分享清零、已经分享出去的旧链接全变死链**。
2. **不可逆动作失败时不要重试**。**发布、群发、删除**失败若拿到 `outcome: unknown`，意味着「可能已经生效」——先查台账核实，绝不盲目重跑。
3. **台账是唯一权威**。回答「发过什么/现在线上有什么」一律查 `--ledger`，不要凭对话记忆或微信侧列表作答。

### 🔴 不可逆动作清单（本节是清单，真源在代码）

**不可逆动作**本仓当前三样：**发布（freepublish，含定时发布）／群发（mass）／删除已发布**。

**真源是代码，⛔ 不是这段文字**——脚本里给 `wechat_api.request_json(...)` 传 `irreversible=True` 的那些调用点就是全集（`article_ops.py` 的发布/群发/删除、`schedule_ops.py` 的 `submit_job`，定时发布与定时群发都走它）。要判断某个动作算不算不可逆，**看它传没传这个参数**；两边对不上时以代码为准，并回头修这份清单（`tests/test_irreversible_scope.py` 会拦住漂移）。

**发布必带批复坐标**：`--publish` / `--submit-publish` 必须带 `--approval <件号>-<选项键>`（老板台批复件号 + `option_key`），**缺了一律 failed exit 1 且一个请求都不发**。做成**留痕式**而非拦截式是有意的——发布是日常高频动作，而**经常被正当操作触发的拦截闸迟早会被调松、且调松是一次性永久的**。⇒ 脚本只查坐标成不成形，**⛔ 不联网核实那个件真批没批**；真伪要人对台账，⛔ 别把命令跑通读成「已获批准」。（群发与删除走的仍是 `--confirm` 拦截式：它们低频，拦得起。）

⚠️ **视频号发布**同样不可逆，但**本仓没有实现面**——微信不给视频号内容发布 API（2026-08-07 实调：`errcode 48001`），只能人工发 ⇒ ⛔ 不进本清单，免得清单里躺一个脚本根本做不到的动作。
