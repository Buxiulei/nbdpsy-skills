# 公众号配图规格（横版 · 封面 2.35:1 + 正文插图 16:9）

> 面向**公众号长文**，不是小红书的 PPT 式轮播。两者共用同一个出图后端、同一把凭据、同一套
> 风格档案，但**版式逻辑完全相反**：小红书是"一套 6–9 页竖版信息海报，图本身就是内容"；
> 公众号是"一篇长文里配 1 张封面 + 按字数铺开的横版插图（每 ~500 汉字一张），图是**正文的呼吸口**，内容在文字里"。
>
> 出图脚本：`scripts/gen_gzh_images.py`。小红书那套的完整版式菜单见兄弟 skill 的
> `../nbdpsy-xiaohongshu-creator/references/illustration-spec.md`——**本文只写公众号的差异**，
> 风格基底、崩字防治、合规红线那些共通条款照那份执行，别在这里重复维护一份会漂的副本。

## 1. 一篇要几张图

| 位置 | 张数 | 比例 | 落盘 |
|---|---|---|---|
| **封面** | 1（必需） | 出图 16:9（标称 1536×1024）→ **居中裁 2.35:1** | `cover.jpg`（裁好的）+ `cover-raw.jpg`（未裁原图，便于重裁） |
| **正文插图** | **按正文汉字数：每 ~500 字一张** | 16:9，**不裁** | `illus-01.jpg` … |

> ⚠️ **别把 1536×654 当成固定尺寸**：服务端去水印工作流会对出图做**非整数等比缩小**
> （实测 ×0.855），所以到手常是 **1313×876**、裁后是 **1313×559**。
> 脚本按**实际拿到的宽度**现算 2.35:1 的高（`round(w / 2.35)`）——
> **比例恒定、绝对像素随实际宽度走**。验收时**看比例（宽/高 ≈ 2.35）不看绝对数字**。

**张数按正文汉字数算：每 ~500 字一张**（2026-08-04 老板定案，此前口径是「0~3 张，贵精不贵多」——
实测 3500 字只配 3 张，手机上整屏整屏都是字，太干）。算法与验收：

```
插图张数 = round(正文汉字数 / 500)，下限 2 张、上限 10 张（封面另算，不计入）
汉字数：grep -oP '[\x{4e00}-\x{9fa5}]' 稿子.md | wc -l
```

| 正文汉字 | 插图张数 |
|---|---|
| 1500 | 3 |
| 2500 | 5 |
| 3500 | **7** |
| 4500 | 9 |

- **张数是够了，但每张仍要有活干**。挨着小标题铺开，优先给这几类段落：能画成结构的
  （对比、流程、光谱、四象限）、数据段、读者最需要"喘口气"的长段。
  ⛔ 别为凑数塞纯装饰图——同一套配色的空景连出三张，读者只会觉得在灌水。
- **封面不能省**（信息流里读者先看到的就是它），且**不计入**上面的张数。
- 出图前先把张数算出来报给运营：「正文 3500 字 → 配 7 张插图」，别闷头出一批。

## 2. 封面规格（最需要小心的一张）

### 2.1 视觉重心必须居中——上下会被裁掉

微信封面官方比例是 **2.35:1**，而 gpt-image-2 出的横版是 **16:9**（标称 1536×1024，
经服务端缩图后实测 1313×876）。脚本下载后**居中裁**成 2.35:1，
也就是**上下各切掉约 18%的高度**（1024 高时各 185px、876 高时各 158px）。

所以写提示词时：

- 人物 / 主体 / 关键道具**全部落在画面正中的横向条带里**；
- 上方（天花板、天空）与下方（地板、桌面）留成**大面积干净留白**，被切掉不损失任何信息；
- ⛔ 别把主体贴到上边缘或下边缘——那正是会被裁掉的两条。

提示词里直接把这件事写给模型（照抄这段结构）：

```
横版 16:9 构图（1536×1024）：主体视觉重心**严格落在画面正中的水平带内**，
上方与下方都是大面积干净留白、可被裁掉而不损失信息；左右两侧留出呼吸空间。
负面提示：不要竖版构图、不要正方形构图、不要把主体贴到画面上边缘或下边缘、
不要额外边框、不要水印。
```

> **为什么负面提示是必需的**：扩散模型经常忽略"默认横版"自作主张出竖图或方图，
> 负面词是唯一可靠的兜底。这条与小红书那份规格同源，只是**禁的方向反过来**
> （小红书禁"横版/正方形"，公众号禁"竖版/正方形"）。

### 2.2 图内不要放大段文字

**这是与小红书最大的一条差异。** 小红书的封面靠图上的大标题抓人，公众号封面**不靠**：

- 信息流里公众号封面缩得很小，图上的字基本看不清；
- **标题由微信自己渲染**（建草稿时 `--title` 那一条），压在封面旁边或下面——
  图里再写一遍就是两份标题打架。

所以封面提示词固定收尾一句：**「画面中不出现任何文字或字母」**。
真要一两个字的点睛（极少数情况），也**只放一个词**、放在正中带内，别成句。

### 2.3 心理科普的视觉基调

- **温和、留白、非说教**。读者是带着"我是不是有问题"的忐忑点进来的，封面要让人**敢往下读**。
- ⛔ **不用刻板苦情图**：抱头痛哭、蜷缩在墙角、黑白色调、脸被阴影完全吞掉、
  雨中崩溃——这类图既是刻板印象，也在暗示"你完了"，与我们"这不是你的错、也有出路"的
  基调相反，还容易触到平台对**渲染负面情绪**的判定。
- **该怎么画**：把情绪落成**具体的日常场景**——窗边坐着喝茶、深夜台灯下合上的笔记本、
  两个人隔着一段距离并排走。有情绪、不惨烈，读者能对号入座又不被压住。
- 涉及具体人物时用当前运营风格档案里的**人物卡整句**（见第 4 节），一篇之内是同一个人。

## 3. 正文插图规格

- **横版 16:9，不裁**，原样嵌进正文（`![](images/<稿子名>/illus-01.jpg)`）。
- **承接小标题的概念图 / 氛围图**，不是小红书那种满版高密度信息海报——
  公众号正文的信息已经在文字里了，插图再堆一遍字只会重复。
- **能画结构关系就画结构**（对比、流程、光谱、因果链这类），
  版式菜单直接用小红书那份 `illustration-spec.md` 第 3 节的 17 种，
  **唯一要改的是把每条模板末尾那行「竖版 2:3（1024×1536）」换成横版比例行**（见 2.1）。
- **横版比竖版能放的纵向层级少**：竖版能排 5–6 行的流程图，横版排 3–4 步就满了。
  照搬竖版模板的信息点数会挤成一团——**横过来就要横着排**（左右并列、横向时间轴），
  别把竖排流程硬塞进横画布。
- 图内**可以**有短标注（≤6 字的点位标注、类型名），但仍**不放大段说明文字**——
  说明写在正文里，图旁边配一句图注即可。

## 4. 品牌视觉一致性：复用同一套风格档案

公众号**不另建风格档案**，直接读运营的**图文（carousel）那一套**：

```bash
python3 ../nbdpsy-xiaohongshu-creator/scripts/style_profile.py --get --kind carousel
```

> `../nbdpsy-xiaohongshu-creator/` 指安装后与本 skill 同级的兄弟 skill 目录
> （两个 skill 装在同一个 skills 根下，如 `.claude/skills/nbdpsy-fuwuhao-operator` 与
> `.claude/skills/nbdpsy-xiaohongshu-creator` 互为兄弟）。命令在本 skill 目录下执行，
> 或换算成绝对路径。⛔ **别用裸 `--get`**——多套时它给的是运营默认那一套，
> 可能是"文字版"，`visual` 段根本不存在，下面所有字段会一起取空。

**哪些字段照抄、哪些不适用**：

| 档案字段 | 公众号怎么用 |
|---|---|
| `visual.palette` | ✅ 照抄。配色行、"仅用品牌调色板"那句所指的就是它 |
| `visual.text_color` | ✅ 照抄（用在插图的短标注上；封面本来就不放字） |
| `visual.character_card` | ✅ **逐字照抄整句**。一篇之内、一个号之内都是同一个人 |
| `visual.texture` | ✅ 照抄。画风、肌理、光影那一段 |
| `visual.cover_layout` | ⚠️ **不适用**。它写的是竖版"标题压上 1/3、主体居中偏下"，公众号封面既不放标题、又要**居中避让上下裁切**——版式照本文第 2.1 节 |
| `visual.content_layout` | ⚠️ **只借"每条信息配一个具体场景小图"这半句**；"满版分 2–3 区块"是竖版信息海报的排法，横版插图不照搬（见第 3 节） |
| `density`（信息密度档位） | ⚠️ **不适用**。那是小红书"每页 200–400 字"的口径，公众号正文字数由长文本身决定，图上本来就不放大段字 |
| `tone` / `structure` | ⚠️ 与配图无关（管的是文案），排版发文时由长文 skill 负责 |
| **比例行（16:9 / 2.35:1）** | ⛔ **不归档案管**——出图后端的技术规格，任何档案都改不了 |

**留痕**：把 `--get` 输出里的 `trace_line` 原样写进稿子「## 配图」区块开头
（形如 `> 风格档案：图文 v1（本人档案，读取于 2026-08-04）`）。档案会改、还能回退，
拿新版配色去核对老批次的图必判不一致。

**读不到服务时**（没配 `NBDPSY_XHS_API_KEY` / API 不可达）：走小红书那份规格里的
**内置兜底默认配置**，但**必须显式告诉运营**「没连上风格档案服务，本次用内置默认风格继续，
等下次连上再核对」——⛔ 不许静默降级。

## 5. md 里「## 配图」区块的格式（写稿的 AI 照这个写）

`gen_gzh_images.py` **只认这一种格式**，判据与小红书 `### PN` 同源：
**行首 `### 封面` / `### 插图N` 定位，该标题到下一个标题之间的第一个完整 ``` 围栏块就是提示词。**

````markdown
## 配图

> 风格档案：图文 v1（本人档案，读取于 2026-08-04）

### 封面

```
<完整的封面提示词：风格基底 + 主体场景 + 横版 16:9 居中构图行 + 负面提示 + 「不出现任何文字」>
```

### 插图1 · 承接「什么是复杂性创伤」

```
<完整的插图提示词：同一套风格基底 + 该小节的概念/氛围画面 + 横版 16:9 构图行 + 负面提示>
```

### 插图2

```
<...>
```
````

规则：

- **`### 封面` 必需**，缺了脚本直接报错。
- **`### 插图N` 的 N 从 1 起、不重复**（脚本会拦重复编号）。
- 标题后可跟 `· 说明`（如 `### 插图1 · 承接第二个小标题`），不影响解析。
- 每个标题下**必须有一个 ``` 围栏**。缺围栏 → 脚本点名报错并拒绝出图
  （缺围栏会让服务端返回的图与提交顺序错位，宁可拦下）。
- 围栏可带语言标记（```` ```text ````），一个标题下**只取第一个围栏**。
- ⛔ **稿子里没有这个区块时，别让 agent 现编提示词**——提示词要按当前运营的风格档案写，
  编出来的图没人对过基底，出了也是废图，还白烧额度。脚本会直接报错并指回本文。

## 6. 出图纪律（锚点法，与小红书同源）

1. **先出封面过风格闸门**：`--cover-only`。
2. **运营确认**配色 / 人物 / 基调无误（**看裁好的 `cover.jpg`，不是 `cover-raw.jpg`**——
   运营最终看到的是裁后那张）。
3. 把回执里的 `anchor_url`（封面的公网 URL）当 `--anchor-url` 喂给插图，**再出插图**。
   每张独立锚定同一张封面，整篇调性统一。
4. 某张没出成 → `--pages <编号> --anchor-url <同一张>` 只重出那几张，**别整批重发**。

⛔ **封面没确认就把插图一起出** = 风格跑偏后整篇图全废、额度白烧。

## 7. 两条实测坑（踩过一次就够了）

### ① 提示词里的比例必须与真实画布一致，否则出"信箱图"

2026-08-04 实测：提示词写着"横版 16:9"、但实际画布是竖版时，模型**照 16:9 去构图、
把画面画在竖画布中间**，上下留出两条大片纯色空白——一张"信箱式（letterbox）"废图。

**声明的画布必须与真实出图一致。** 脚本恒传 `aspect_ratio: "16:9"` 就是为这件事；
拿到的图若是**竖的**（高 > 宽），先查服务端是不是没接住这个字段，**别去调提示词**——那是白调。
⚠️ 判据是**横竖方向**，不是精确的 1536×1024：去水印会等比缩小（实测到手 1313×876）。
2026-08-04 那次排查里，「API 收到了 `16:9`、出图仍是竖版」的真因是**执行任务的 worker 进程没重启**
（API 与 worker 是两个独立单元），不是提示词的问题。

### ② 落盘统一转 JPEG，因为微信正文图硬上限 1MB

gpt-image 原图是 PNG，1536×1024 常有 1.5~3MB，直接丢给 `md2wechat.py` 会在上传那一步失败。
脚本按质量阶梯（92→64）转 JPEG，第一档落在 1MB 内就停。若压到最低仍超，回执 `warnings`
会点名那张，**逐条念给运营**并手动压缩后再排版。

> 封面走的是**永久素材**（上限 10MB），比正文图宽松得多，所以封面一般不会卡这条；
> 但微信对 `type=thumb` 另有更老的规矩，真被拒时服务端会原样透出 errcode，按提示压缩即可。
