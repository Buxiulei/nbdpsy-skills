# Skill 编写与提示词工程原则（house style，写任何 skill/spec 前先读）

> 2026-08-12 立此存照。起因：微电影编剧规格首单 PK——同一个基座模型，在山音 skill 指导下写出
> 文学级台词，在我们规格指导下写出「拿走一点东西：先是指尖」这种病句。老板裁定：不是模型问题，
> 是 skill 设计问题。本文把教训升维成原则，每条都带本仓实证与可执行做法。

## 一、输出质量的分布 ≈ 文档的 token 分布（注意力预算是零和的）

模型读你的 skill 时在做一件事：分配注意力。你的文档 80% 讲流程，它就把 80% 的功夫花在流程上。
**你想让产出哪里好，token 就要花在哪里**——想要语言好，就写满语言示例；想要结构稳，就写结构契约。

- 实证：PK 中我们的规格赢下制作落地（36:16）与合规（9:5）——文档八成篇幅正是这两块；
  输掉语言（台词 6:9）——语言只占一节且例句稀薄。输出精确复刻了配比。
- 做法：动笔前先答一个问题：「这份 skill 的产出，哪个维度最不能砸？」那个维度的 token 占比
  必须与它的重要性匹配。**维度多到配比冲突时，拆成多个 pass（见原则四）**。

## 二、例句是转向器，规则只是围栏

「禁 AI 腔」是弱信号——抽象规则要模型自己解释，解释就有漂移。一对 ⛔/⭕ 例句是强信号——
直接锚定输出分布。规则告诉模型什么不行，例句告诉模型**往哪写**。

- 实证：山音每一节都是对错例句驱动（「我很害怕你也离开我」⛔ vs 「你走的时候把那件外套带上。
  ……外面冷」⭕），它的产出语言好不是巧合，是每个例句都在拉分布。
- 做法：**每条质量要求必须配至少一对具体到可抄的 ⛔/⭕ 例句**；真实事故句是最好的 ⛔ 例句
  （screenwriting-spec §5.4 把「拿走指尖」原句写进去了）。写不出例句的规则，先怀疑规则本身空洞。

## 三、自检必须可证伪——打勾清单拦不住任何东西

让模型「对照清单自检」，它产出的是一段全勾的自检文本，不是质量。自评永远通过，因为生成自检
的是同一个想交差的模型。有效自检=强迫执行一个**产生新证据**的动作。

- 实证（三条独立线同日）：①PK 乙案自检宣称「翻转由概念自身逻辑给出」，评委实测翻转恰恰是被
  台词点破的；②微电影 Opus/Sonnet 两组语言自检各打全勾，外置编辑各抓出 10-23 处「不通」
  （其中一组宣称"全文念过"实际只念了旁白）；③小红书 H1 红线自检写「隔了一段」，实际间隔 0 字。
  自称与事实相反，清单全绿——**无一例外**。
- 做法：把清单项改写成操作：「删掉翻转 beat 的旁白第一句，翻转仍成立吗」（删句检验）、
  「把句子按字面重读一遍，成立吗」（字面检验）、「出声念，有没有一句要回读」（朗读检验）、
  「声称的每个形式设计，对照分镜逐条指认写在第几镜」（核真检验）。判据：这条自检做完，
  会不会产生一段**可能推翻自己**的新文本？不会 → 它是装饰。

## 四、分身份分阶段——别让工程师人格污染编剧人格

「你是编剧」只在文档主体支撑这个身份时成立。若模型刚读完 200 行字段契约再来写台词，
它此刻是个填表工程师。身份由**当下活跃的上下文**决定，不由开头那句角色宣言决定。

- 实证：乙案的 shots.json 完美、台词平庸——同一个 agent 在同一次生成里，工程内容挤占了
  写作注意力。
- 做法（按代价递增）：① 步骤内加注意力指令（「此刻只做编剧，流程放下」——已用于 S5，属轻修）；
  ② **拆两个 pass**：创作 pass 只喂创作层章节，产纯剧本；装配 pass 只喂契约章节，把剧本
  装进 shots.json（互不见对方的重载内容）；③ 拆两个 agent（各配各的 spec 切片）。
  质量要求越高，越往后选。

## 五、约束写在使用点，作用域必须显式

长文档有位置效应：头尾权重高，中段稀释。更隐蔽的坑是**作用域默认**——你以为「全文适用」，
模型以为「本节适用」。

- 实证：写作红线实际只被应用于剧本正文，概念选型表成了免检区，病句从那里溜进交付物。
- 做法：关键约束在使用它的步骤旁**原地重复**（哪怕全文已写过）；每套检查显式声明作用域
  （「检查对象＝交付物里的每一句话，含 logline/表格/标题」）；内化型内容（写作时必须活跃的）
  与查表型内容（用时才查的）分节隔离，别混排。
- 引申（修稿指令同理）：**修改必须带连锁传播纪律**——每改一处，搜出该对象/状态的所有
  其他出现处一并改（实测点修必生新矛盾：钉死站姿漏改「并肩坐」）。这就是代码库
  「平行映射表」教训在文本修改里的等价物，修稿 prompt 里要原文写进去。

## 六、负面禁令必配正面替代

「不要 X」会先激活 X 的表征，且不给去处。禁令后面必须跟「改成什么」。

- 做法：「⛔ 旁白复述画面」必须跟着「⭕ 旁白只说画面外的三样：前史/机理/反差」。
  只有禁令没有去处的条目，模型会绕个姿势再犯。

## 七、每条规则过「动作测试」：模型拿这句话能做什么？

「要有画面感」「保持克制」——模型拿它做不了任何动作，只能生成一点风格化噪声。
可执行的版本永远指向一个可验收的具体行为。

- 实证：「每 beat 至少一个可见的抑制动作」是全 PK 被评委最高频表扬的纪律（11/11 兑现）——
  因为它可执行、可数、可验收。
- 做法：写完每条规则自问「模型读到这句，下一个 token 会因此不同吗？怎么不同？」答不上来就删或重写。

## 八、审查外置，且审查镜头本身也要设计

生产者不自审（本仓铁律）。但独立审查也只看得见你给它装的镜头——镜头缺一个维度，
那个维度就是盲区。

- 实证：三评委（故事/合规/落地）全部漏掉语言病句，老板一眼抓出——因为没有一个评委的
  职责里写着「逐句读语言」。
- 做法：审查配置=镜头清单，按「这类产物历史上在哪些维度翻过车」配齐；每次人工抓到
  审查漏掉的问题，第一动作是给审查加镜头，第二动作才是修产物。

## 九、设计 → 产出 → 盲评 → 回灌，闭环才算设计完成

Skill 写完不等于设计完成。没有对抗产出物检验过的规格只是假设。

- 实证：编剧规格 v1 自认完备，首次 PK 暴露九处短板+语言盲区，两轮回灌后才接近可用。
- 做法：新 skill/大改必须跑一次「同题产出+带镜头盲评」，评审意见逐条回灌（改成例句或
  可证伪自检，别改成新的空规则）；回灌后再验一轮才发版。

## 十、给执行模型分工时，把 skill 当成给"那个模型"写的

Opus 执行力强但同样吃注意力配比；Sonnet 适合大批量理解提炼但对弱信号规则服从率更低。
给谁执行，例句密度和作用域显式度就按谁的下限来写——**按最弱执行者标准写规格，
强执行者只会做得更好**。

---

**速查（写 skill 时贴在手边）**：
1. 最重要的维度拿最多 token 了吗？
2. 每条质量要求都有 ⛔/⭕ 例句吗？
3. 自检项是「产生新证据的动作」还是打勾？
4. 写作步和工程步分开了吗？
5. 每套检查的作用域写死了吗？关键约束在使用点重复了吗？
6. 每个 ⛔ 后面有 ⭕ 去处吗？
7. 每条规则过得了「动作测试」吗？
8. 审查镜头覆盖历史翻车维度了吗？
9. 发版前跑过对抗产出验证吗？
10. 按最弱执行者写的吗？
