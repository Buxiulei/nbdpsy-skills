# 视觉编排（每屏视觉由 LLM 按语义设计）· 设计稿

> 2026-08-18 · 起因：老板看四条 collage 成片后原话——
> 「**我看到动画与内容并无关联，节奏非常快。我希望动画都是与口播讲的东西有相关性的。
> 不能只是简单的套用模板。每一页是什么动画，什么特效，需要有 llm 来设计**」
> ＋「**必须引入单独的内容审稿 agent**」

## 一句话结论

**模板从「自带固定动效序列」退化为「渲染一份计划」**，计划由 LLM 按语义生成。
🔴 **但真正的难点不是让 LLM 生成计划，是让「相关」可被证伪**——
否则它会生成**看起来很合理、实际仍然无关**的计划，而人和审稿代理都只能点头。

---

## 一、🔴 先立判据：什么叫「动画与内容相关」

**判据（可机检）**：视觉计划里每一屏都要写一条 `why`，而

> **把这条 `why` 原样挪到别的屏，如果还成立，它就不算相关。**

落成两条硬检查：

1. **`why` 必须逐字引用本屏 `text` 里的片段**（≥2 字），⛔ 不许只说抽象理由。
2. **跨屏唯一性**：任意两屏的 `why` 去掉引用片段后，**主干不得完全相同**——
   全篇十屏写同一句「气氛转折所以用漂移」＝ 没有编排，只是换了个说法的套模板。

**例**：
- ⭕ 「本屏『**八个阶段**』是列举 → 逐项揭示（wipe），擦出的节奏对应"一项一项"」
- ⛔ 「本屏气氛转折 → 用漂移」（**放到任何一屏都成立**）

⚠️ **这条判据是整个设计的地基**。没有它，"LLM 设计"只是把套模板换成了套措辞。

---

## 二、数据流

```
cues.json（每句文本＋起止）          ┐
intent.json（hook/scene/closing）    ├→ ① 视觉编排 LLM →  plan.json  → ② 渲染 → 成片
第一反应判准.md（读者认知落差）      │                       ↓
账号/版式/语汇表                     ┘                  ③ 审稿代理
```

⛔ **模板不再自带动效序列**：`tpl-paragraph` 现在的 `MOTIFS` 库保留（那是**语汇层**），
但**哪一屏用哪个 motif 由 plan 指定**，⛔ 不再由 `motifFor(段号)` 轮转决定。
⇒ G13 的编排层＝**骨架**，语义计划＝**填充**。

---

## 三、`plan.json` schema

```jsonc
{
  "meta": {"cues": "narration.mp3.cues.json", "template": "paragraph",
           "account": "NBDpsy-好好生活", "generated_by": "llm", "model": "…"},
  "screens": [
    {
      "i": 0,
      "text": "感觉好了不代表能停药",     // 与 cues 逐字一致（闸门核）
      "start": 0.0, "end": 2.31,
      "semantic": "反驳",                 // 见下表，⛔ 闭集
      "motif": "wipe",                    // 见语汇表，⛔ 闭集
      "emphasis": "不代表",               // 本屏要强调的词（必须是 text 的子串）
      "elements": [],                     // SVG/贴纸；纯字屏为空数组
      "relation": "开场",                 // 延续/切换/呼应/开场/收口
      "why": "「不代表」是把前半句划掉再写新的，wipe 的擦出方向正好演这个动作"
    }
  ]
}
```

**`semantic` 闭集**（⛔ 不许自由发挥，否则无法统计与审）：
`断言｜反驳｜列举｜对比｜转折｜因果｜数据｜比喻｜场景｜提问｜收口｜留白`

**`motif` 闭集**＝ G13 语汇层现有六件：`rise｜wipe｜depth｜drift｜tilt｜still`
（⚠️ 扩语汇是另一件事，先用现有六件跑通，⛔ 别一次动两层）

**语义 → 手法的建议映射**（LLM 的先验，⛔ 不是硬绑定；偏离要在 `why` 里说明）：

| 语义 | 建议手法 | 理由 |
|---|---|---|
| 反驳／转折 | `wipe` | 擦出＝划掉重写 |
| 列举 | `wipe`（逐项）／`drift`（并置） | 节奏对应"一项一项" |
| 数据／断言 | `depth` | 从虚到实＝把结论"对上焦" |
| 比喻／场景 | `drift`／`tilt` | 横向或空间位移＝换一个看的角度 |
| 收口／留白 | `still` | **丰富 ≠ 一直在动**，收口要让人停一下 |

## 四、节奏

🔴 **老板说"节奏非常快"，但每屏停留时长 ⛔ 不由我们直接定** ——
它 ＝ `cue 时长 ÷ 该句拆出的屏数`，而 **cue 时长是 TTS 已经定死的**。

⇒ **能调的只有「一句拆几屏」**：

- **`hold_min = 3.5s`**（重点句 4.5s）作为**编排闸**：
  拆屏后若某屏 < `hold_min` → **报红，要求合并**（⛔ 不是警告）。
- collage 那批 **12 句 35 秒 ＝ 每句 2.9s**，⇒ **一句必须一屏**，⛔ 不能再拆。
- ⚠️ **若合并到"一句一屏"仍 < 3.5s**，那是**稿子/语速的问题**，
  ⇒ 出路是**重跑 TTS 放慢语速或加句间停顿**，⛔ 不是在排版层硬撑。
  **这条要在预检阶段就报出来**（`--precheck` 已能算屏数，加一个时长维度即可）。

**段落呼吸**：沿用 G13 的 `still` 留白件，但**触发改由 plan 指定**
（语义为 `收口/留白` 的屏用 `still`），⛔ 不再每 4 段机械插一次。

## 五、可审产物（给内容审稿 agent）

每条片子产出三样，**放同一目录**：

1. **`plan.json`** —— 机器读
2. **`plan.md`** —— 人读，**一屏一行**：
   ```
   #03  2.9–6.4s (3.5s)  列举  wipe   强调「八个阶段」
        「按创始人机构的描述，它有八个阶段」
        why: 「八个阶段」是列举 → 逐项擦出，节奏对应"一项一项"
   ```
3. **`frames/`** —— **每屏一帧**（抽在入场进行到 45% 处，**手法差异最明显**；
   ⚠️ 抽在停留期看不出手法——今天实测过，统一时刻抽的 12 格图**证明不了段间有变化**）

**审稿代理要能回答的三问**（⛔ 不是"好不好看"）：
- 每屏的 `why` **是否引用了本屏文本**？（机检已拦一遍，它复核语义是否真成立）
- 有没有**两屏 `why` 主干雷同**？（＝套模板的残留）
- **抽帧与 `plan` 是否对得上**？（说 wipe 的那屏，帧上是不是真在擦）

## 六、闸门（新增，随 plan 一起跑）

| 闸 | 判据 | 级别 |
|---|---|---|
| **文本一致** | `plan.screens[].text` 与 cues 逐字一致 | 拒渲染 |
| **闭集** | `semantic`/`motif`/`relation` 都在闭集内 | 拒渲染 |
| **强调词在文内** | `emphasis` 是 `text` 的子串 | 拒渲染 |
| **相关性** | `why` 逐字引用 `text` 片段（≥2 字） | 拒渲染 |
| **跨屏唯一性** | 去掉引用后的 `why` 主干不得完全重复 | **warn**（⚠️ 短片里少量重复可能合理） |
| **停留下限** | 每屏 ≥ `hold_min` | 拒渲染，并指出该合并哪两屏 |

⚠️ 全部 warn/fail 都要**指名到屏号**，⛔ 不报"整体不合格"。

## 八、⛔ 明确不做的

- **⛔ 不扩动效语汇**：先用现有六件跑通编排层。**一次只动一层**——
  语汇和编排同时改，出了问题分不清是哪层的。
- **⛔ 不让 LLM 决定分屏**：分屏是确定性闸门（`split_cue`）的事，
  LLM 只决定**每屏怎么演**。⇒ 两者混在一起会让"断不开"这类硬失败变得不可预测。
- **⛔ 不做「相关性评分」**：分数会诱人调阈值。判据是**二元的**：
  引用了本屏文本＝有依据，没引用＝没依据。
