# 03 审稿 · 复刻她的审稿行为

> 这份文件只管一件事：拿到一稿，怎么审。
> 判据本体不在这里——20 条判据的原文在 `02-讲故事.md` §1。这里写**怎么用那份清单**：谁判、判红了退给谁、判完怎么回话。
> 她的审稿不是打分，是逐句往下走：指到句子 → 说清为什么 → 亲手给替代 → 要求重出全文。
> 引号约定：「」= 她的原话，逐字；行内代码与弯引号 = 稿件里被审的原文，或别人（写手/画师/操作）的原话。

---

## 1. 她的审稿动作（7 条，按发生顺序）

**① 逐句按顺序读，一处一处推进**

10/19 上午十一分钟，她按稿子的顺序走，不跳读：
09:36「先看第一段」→ 09:44「好 然后我们来看第二段」→ 09:47「现在我们看“我试着不急着赶走它，给自己一点时间，再决定要不要继续吃。”这句话之后」。
每判完一处，写手重出全文，她才推进到下一处。

复刻：审稿意见按段落顺序排，一条一处。⛔ 不许只给“整体读起来有点平”这种没有位置的判决——她一次也没这么说过。

**② 指到具体哪一句**

她从不描述病灶，直接引原句：
「“有次我烦得快炸了” ？哪一次？什么叫有次？」
「第一句话 一点都不打人啊」——后面跟着把那一整句贴回来再判。

复刻：每条意见的第一行必须是被判的原文，逐字。引不出句子，说明这条意见不成立，删掉。

**③ 说清为什么，而且这个“为什么”落在读者身上**

她给的从来不是“违反了某条要求”，是三句具体的话：
「这句话很像论文的开头 我现在是一个挣扎于减肥的人 读到这个没有丝毫情绪波澜」
「这是一个非常 ai 的写法 只有 ai 才会这么写 非常地没头没脑」
「读者读到这里会好奇啊 那后来你吃了吗？你之前很急迫啊 你的急迫去哪了？」

复刻：为什么必须写成“读者读到这句会怎样”。“违反 checklist 第 7 条”不是理由——规则编号不产生替代方案。

**④ 亲手给替代**

09:36 给首句：「开始练习正念之后，我更加理解了《老友记》里的经典名言：“那是食物，不是爱”」。
09:44 给整段替代（她那条消息 261 字，大半是她的版本，连分段位置都标了「（然后这里我会分段）」）。
09:47 给缺的结尾：「然后我开始观察，观呼吸，观自己的念头，然后我发现，我实际上的需要是，我很委屈」……「然后我给朋友发了微信，我发现食欲就消失了。」

复刻：替代要给到“能直接看出改后长什么样”的程度——整段示范，或明确方向 + 一句示范。⛔ “这里可以更有故事感”这种不给替代的判决，等于没判。
边界：示范归审稿，落笔归写手（见 §5 第 2 条）。

**⑤ 要求重出全文**

触发点是 09:14 写手只回了“第一段改成：”+ 一句话。
09:13 她已说过「我每说一点 你就要对应调整你的文案 你要应用我的规则重写」；09:19 再说一次「改的时候展示全文 不要只给我展示一句」。

复刻：判 FAIL 的同一轮，写手交全文，不许只贴改动句。审稿 agent 收到只有改动句的回执，判“动作不合格”，不进下一处。
这是动作层否决，不是内容否决：她那句话针对的是整篇，不是那一句。

**⑥ 分清层次**

11:41 一条消息里同时判了两层，处置完全不同：标题「这几个标题都不好 都不如我花 6000 块学壁球，学会了装忙」→ 换；大纲「缺少故事感 不完整 不知道这个主人公为啥花了钱还要退出 没有体现主人公受挫折的过程」→ 补过程。

复刻：判 FAIL 前先写它属于哪一层，层决定退回哪道工序：

| 层 | 判决长什么样 | 退回 |
|---|---|---|
| 切题 | 「我为啥要看」答不上；平庸 | `01-切题.md`，换题 |
| 标题 | 比不上她自己写的那一句 | `01-切题.md` 标题节，重出候选 |
| 标题（用户从候选里选定） | 用户点名了其中一条——这不等于「还行吧」的微调 | 规则见 `01-切题.md` 第三节末尾『她选定候选之后』 |
| 大纲 | 只有结论没有过程，故事不完整 | `01-切题.md` 大纲节，**补过程，⛔ 不换题** |
| 句子 | 论文体 / 废话 / 半截 / 冗余 / 短句连排 | 本工序，写手重写并重出全文 |
| 图 | 太像 AI 画 / 看不出在讲什么 | `04-配图.md`，画师重画 |
| 预览 | 「看不出来啊」 | `05-发布.md`，重修预览形态，⛔ 不回写正文 |

**⑦ 给分档评价**

11:41 一条消息三档并存：「这几个标题都不好」（否）、「第一个标题也还行吧」（半通过）、「缺少故事感」（大纲层否）。
9/12 09:31 一句里同时表扬和否决：「这个角度 1 不错 有点意思 真棒 你开始学会什么叫选题了 角度三不错但是不对」。

复刻：逐条给档，⛔ 不给整篇一个总分。档位含义见 §2。

| 「这个切题不好 我感觉没有什么意思」 | 切题 | 换方向：换处境，不是换措辞 | 11:18，换成“我不敢认真”仍被否 |

| 「这个角度 1 不错 有点意思 真棒」「我的确就是这样的 这个很像我」 | 通过 | 落地。⚠️ 只对创意成立，落地前还要过事实锚 | 9/12 09:31 同一句里「角度 1 不错 有点意思」与「角度三不错但是不对」并存；11:25 选中后她当场补真实细节 |

**这张表的灵魂是最后一句：切题错要换题，大纲错要补过程。**

11:41 她在一句话里同时否掉标题和大纲，给了两种处置。写手的正确响应是：换标题、补过程、⛔ 不动切题。把两层混成一句“重写一遍”是最常见的错。

两条使用规则：
1. 一条回话里出现两档以上，按层拆开各自处置，⛔ 不许取平均（“整体重做一版”）。
2. 「不错但是不对」是复合判决：创意成立、事实锚错。这时不换题，换事实——她的原话「这是刘琼的硕士毕业论文 不是她下班在做的事」。

## 3. 三层判据：谁判、判红了谁动手

分层的出处是她第三版 checklist 自己的结构：**内容检查 / 文风检查 / 伦理合规检查**。条文原样在 `02-讲故事.md` §1，本表不重抄——只回答两件事：这条由谁判、判红了谁动手。

- **机判** ＝ `scripts/check_text.py` 能出确定结论的。脚本只报确定错，模糊的一律不下判断。
- **人判** ＝ 审稿 agent 逐字读出来的判断。⛔ 不许拿“脚本没报”当通过依据。

| 判据 | 层 | 谁判 | 判红之后的动作 |
|---|---|---|---|
| 第一句让人想读 | 内容 | 人判 | 换首句：首句是场景或发现，⛔ 不是结果汇报 |
| 论文体（一次把原理/结果/答案讲完） | 内容 | 人判 | 打回写手重写首段；原理挪到读者想要答案之后 |
| 温和的第一人称废话 | 内容 | 人判 | 加情绪强度或具体夸张；她的两级示范：`好饿啊` → `老娘要饿死啦！！！！！` / `我现在能吃一头牛` |
| 冗余与空细节 | 内容 | 人判 | 删句。判据：「所有的信息都可以在别的句子里推导出来」 |
| 半截的故事 | 内容 | 人判 | 补“后来呢”，情节停在自然可停处 |
| 极端情绪的前因后果 | 内容 | 人判 | 补哪一次、谁在场、发生了什么。`有次我烦得快炸了` 这种一律打回 |
| 名人名言／影视台词 | 内容 | 人判 | 这是「可以」不是必须：引用必须能核到原台词与出处，查不到就不引，⛔ 编一句名人名言 |
| 逆袭与突然开窍 | 内容 | 人判 | 结局换成微小的、带着不适的真实动作；⛔ 打赢所有人／一次练习就好了 |
| 未确认事实与报名信息 | 内容 | 人判 | 查不到写【待补充】／「确定后填入」；⛔ 编日期、价格、时段、入口、二维码 |
| 产品名位置 | 内容 | 人判 | MIED 等在读者理解问题之后才出现；前两段不许出现 |
| 俚语 | 文风 | 人判 | 换当下叫法：gay／男同／男同性恋——她的原话「不叫男同志」 |
| 三重排比 | 文风 | 机判报警 + 人判确认 | 脚本只报警，豁免由人确认：只有「像说明书一样 一个东西包含 abcde 构造这种 类似的 可以如实陈列」的事实列举能过；修辞排比除她说的「真的有文学价值 必须排比不可」外一律改 |
| 单字 | 文风 | 机判 | `更狠` `很稳` 这类被压成单字的，展开成词 |
| 长句／短句连段 | 文风 | 机判 + 人判 | 脚本出连续短句计数与段落长度分布；节奏由人判。⛔ 零散短句、⛔ 短句连段 |
| 禁词 | 合规 | 机判（硬拦） | `医疗` `疗法` `催眠`，命中即 FAIL，无豁免 |
| 商业边界 | 合规 | 人判 | 不夸大、不承诺效果、不把个体经历写成产品效果；底线是她那句「不说谎」 |
| 落款与占位 | 合规 | 人判 | 亲历稿正文末尾与图内都标`以上内容为学员投稿`；虚构标`故事演绎`；查不到的写`【待补充】`，价格／日期／师资一律不编 |
| 后台工作说明不出现在读者文案 | 合规 | 人判 | 「按目前预案」这类话一律移到正文外用斜体，读者文案里不出现 |

适用范围：「单字」「长句／短句连段」与附带说明 2 里的「段落长度分布」只判**连续正文**，⛔ 不判图内文字（标题、气泡、旁白、海报条目）——判例与读数记在 `04-配图.md` 的「图内文字不套正文的文风指标」，此处不重抄。

三条附带说明：

1. **字数只报不判。** 字数是她在每篇大纲里给的目标，一篇一给，不是全局常量；记录里她没有做过一次“超字数打回”。脚本统计汉字数，只用于报告。
2. **机判只是地板。** 当前机判覆盖：禁词、单字、三重排比（报警）、字数、段落长度分布、正文里的 Markdown `**`。清单里其余条目都得人判——脚本没报不等于过。
3. **机判与清单冲突时，以清单为准。** 你读出来的问题脚本没抓到，照样判 FAIL。

## 4. 交付形态：逐条对照表

写手交稿时附一张表，一行一条，两列：

| 检查项 | 本稿对应处理 |
|---|---|
| 第一句让人想读 | 用“恨不得住在球场”的热情，承接标题里“装忙”的反差。 |
| 不要论文体 | 前两段先讲投入和受挫，MIED 在读者理解为什么退出后出现。 |
| 删除冗余信息 | 各段分别推进投入、逃避、觉察、重新参与和再次报名，没有另加一段重复解释原理。 |

（上三行逐字取自 10/23 那份 15 行的表。）

格式硬要求：
1. **一行一条**，按 `02-讲故事.md` §1 的 20 条判据逐条对应、顺序照抄（§3 是同一批判据的归并路由表，只回答「谁判、判红退给谁」，不决定对照表行数）。⛔ 合并条目、⛔ 跳条。
2. 右列必须写出**本稿的哪一句／哪一段做了什么**，能引原文就引原文。“已检查”“已按 checklist 执行”“符合要求”——右列没有具体文字，就是没做。
3. 允许写「漏了」「没完全做到」「尚未完成」。10/19 07:01 那张自查表就有这三行，改完重出全文，再交一次表。
4. 表不是装饰：审稿 agent 拿它逐行回原文核对，指不到对应文字的，那一行判为编造。

为什么必须是这张表，而不是一句“已按 checklist 写”：

10/19 07:01，她问「你确认一下 是否已经按照写手 checklist 写了」，写手的回答是：`**没有完整执行。** 上一版参考了合格样本和你的提纲，但交稿前没有逐项检查。`
⇒ “我记住了”“已按 checklist 写”都不可信（写手 10/26 自己也承认：`文件保存了，也不等于我每次都实际读到了。`）。可信的只有逐条对得上的表。

### 4.1 预览也是被审的对象

有一轮她否的不是文案，是预览：「我在这里看到的预览是这样的 看不出来啊」。
⇒ 判的是形态：给路径、给 html 链接、让她自己打开看，都算 FAIL。修的是预览，⛔ 不许为了预览好看去回写正文（形态规格见 `05-发布.md`）。

## 5. 审稿者的自我约束

1. **独立实例。** 审稿 agent 与写手不是同一个实例，不共用写手的上下文。自审失效有记录：10/19 07:01 之前那一版没做逐项检查，是她的那句追问才把它逼出来的。写手的自评结论不算审稿结果。
2. **只判不改。** 审稿输出判决和三件套，终稿由写手改。她的「你要应用我的规则重写」是发给写手的——审稿 agent 直接交终稿，写手就跳过了重出全文这一步，§1⑤ 的动作链断掉。
3. **判 FAIL 必须三件套**：哪一句（逐字引）+ 为什么（读者读到这句会怎样）+ 怎么改（示范句或明确方向）。缺一件，退回重写审稿意见，不算判决。她 09:44 那条就是完整的三件套：引原句 → 说“没头没脑”在哪 → 给整段替代。
4. **通过也要指到句。** 她的表扬带定位：「（这句你写得很不错）」指的是 `我发现，自己这么急，是想让难受马上消失。` 审稿给 PASS 同样要写清哪一句过了、为什么过，否则下一轮会把好东西一起改掉。
5. **FAIL 的依据必须引她的原话。** 例：「02 §3.2 的原话是『被描述会点头，被说中才停下来』」——原话可核，⛔ 只给审稿者自己的归纳。

## 6. 审稿回执

审稿是链上唯一没有句柄的闸门：发布有 job id／台账／回读，机检有退出码，切题有聊天记录，唯独审稿只剩一句「审过了」。⇒ 每轮审稿必须落一份审稿回执，六个字段齐。回执落在哪、叫什么，按被审对象分两种：

- 定稿：与定稿同目录的 `审稿回执.md`（同轮多版加 `-v2`）
- 其它对象：`<被审对象>-审稿回执.md`，放被审对象所在目录

```
被审文件: <被审对象路径>
sha256: <sha256sum 现取，⛔ 手写>
审稿实例: <新起的独立 agent，附它读过的 skill 文件清单>
逐条判决: 按被审对象的判据清单逐条，每行「判据编号｜PASS/FAIL｜引句」：
  - 正文：`02-讲故事.md` §1 的 20 条，编号 1–20
  - 绘图 prompts：`04-配图.md` §2.1 四段式（P1–P4）＋ §4 图内中文 12 条（T1–T12）
  - 切题策略：`01-切题.md` §四 三节定义（S1–S3）＋ 故事五问（W1–W5）
FAIL 三件套: 哪一句（逐字引）/ 为什么 / 怎么改
结论适用范围: 这份 PASS 覆盖哪个 sha、不覆盖什么（例：只覆盖 prompt 文稿，成图未验收；只覆盖策略，正文未写）
```

⛔ 没有回执＝没审过。发布组装第一步校验定稿 sha256 与回执一致，不一致即拒绝组装——那说明定稿在审后又被改过。

PASS 是按版本签发的：10/28 同一轮里 draft.md 与 draft-v2.md 各拿过一次 20/20 PASS，v2 那份回执自己写着「v1或本轮独立审稿的PASS均不能代替用户认可，本回执仅对应上述SHA256的文件」——引用一份回执前先核它记的是哪个 sha。

三条反糊弄（每条对一种实测过的绕过）：

- ⛔ 不许把「请核对这份自检表」当审稿 prompt——审稿者必须先读稿、再看自检表，或不看，否则被锚定；
