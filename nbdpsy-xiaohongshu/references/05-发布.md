# 05 · 发布（操作机器人）

> 本工序不生产内容。上游两个角色把产物落成**文件**，本工序把它们组装成一次发布。
> 80% 的价值在发布之前（核对、预览、拦截）和发布之后（回读、留证），点那个按钮只占 20%。（提取-04 §0）

## 一、目录即接口

角色之间不靠聊天传话，靠固定目录 + README。

| 目录 | 放什么 | 谁写 | 判断问句 |
|---|---|---|---|
| `seo-geo/content/xiaohongshu/定稿配文/` | 用户认可的文字，已脱离任何一次具体发布 | 写手，只读 | 这句话是不是用户点头过的原文？ |
| `seo-geo/content/成品图/` | 当前版成品图，多角色共用 | 出图线，只读 | 这是不是最新一版、且别人也能拿去用？ |
| `seo-geo/content/xiaohongshu/发布准备/` | 一次发布动作的全部证据（含失败） | 本工序 | 出了事能不能只靠这个目录复盘？ |

### 定稿配文 `YYYY-MM-DD-主题.md`（定稿日期）

她 2026-10-09 立为常驻指令：

> 定稿的标题、正文与话题统一存入 seo-geo/content/xiaohongshu/定稿配文/，每篇单独成文件，并更新该目录 README.md 索引。写手后续定稿沿用此目录；小红书操作机器人读取配文时先查此索引。归档原样保存用户认可的版本，稿件定稿状态与发布状态分别记录。

2026-10-18 再次口头确认：「以后定稿统一放在 NBDpsy/seo-geo/content/xiaohongshu/定稿配文/。」

### 成品图 `<YYYY-MM-DD>-<系列或主题>/`（**交付**日期）

> 子目录顶层按阅读顺序放 01.png、02.png……，只放当前交付版本，避免混用旧稿。

`01` 即封面。换图 = **原位覆盖** `07.png`，⛔ 新增 `07-v2.png`。⛔ 不从历史库自选末页图——她说「你换的第七张图不好 我让视频制作机器人加了一个第七张图 换成视频制作机器人的图」；历史库只提供版式参考，成品页由出图线交付并覆盖落位。对方说「更新了」不算，`SHA256` 变了才算。

### 发布准备 `<YYYY-MM-DD>-<主题>-<账号简称>/`

实例：`2026-10-19-刘琼-聊心理`、`2026-10-23-正念减肥-聊心理`。**同一篇换号发 = 另一个目录**，不覆盖。

### README 就是契约

`定稿配文/README.md` 三件齐了才合规：

1. **索引表**：`| 定稿日期 | 标题 | 文件 |`
2. **状态两栏**：稿件定稿状态、发布状态**分别**记（例：`《正念帮助我减了20斤》：稿件已定稿；发布未执行；话题未指定。`）。两句写死的判据：「内容定稿不代表已发布。」「本目录固定保存用户已确认的小红书标题、正文（含落款）和话题。小红书操作机器人按本目录读取定稿。」
3. **发布回执**：见 §四。

`发布准备/*/README.md` 写：目标账号、状态、素材链接、待办（留空项）。

只认**已落盘的文件**：「只在它们聊天里、尚未保存的内容不会自动同步给我；保存好文件或给我路径，就能交接过来。」

## 二、发布 14 步

**脚本**：调 `../nbdpsy-xiaohongshu-creator/scripts/publish_note.py`（本 skill 与 nbdpsy-xiaohongshu-creator 是兄弟目录，安装后在 `~/.claude/skills/` 或 `~/.agents/skills/` 下；账号与凭据走 nbdpsy-server）。⛔ 不重写、⛔ 手搓 payload 直调 API。本文件没写到的参数，一律 `--help` 现查，⛔ 凭印象写。

### A 接手与定位

1. **先读欠账，不是先读稿子**：`python3 ../nbdpsy-xiaohongshu-creator/scripts/publish_note.py --ledger-check <发布准备目录>/publish-ledger.md`。`exit 0`＝台账在且全部闭环，才继续；`exit 3`＝有未闭环行（欠账）；`exit 4`＝台账文件不存在。**首次为某篇建发布目录时，先 `mkdir -p <发布准备目录>` 再 `touch` 一个空的 `publish-ledger.md` 才跑——首次 `exit 4` 是预期的，不是失败**；建完仍要跑出 `exit 0` 才算闭环。
2. **定稿索引 → 定稿文件**，逐字取「标题 / 正文 / 话题」三节。话题以**定稿文件的「话题」节**为准，逐字逐序落（`#爱你老己 #对自己好一点 #自我关怀 #自我苛责 #内耗 #心理咨询 #咨询师的论文` 是她一次给全的七个），⛔ 增删、⛔ 改序、⛔ 补热门标签。
3. **成品图 README → 打开 `01..NN`**，核张数、尺寸、版本说明、源文件路径。交接验收报 `目录 → 可读性 / 张数 / 尺寸 / 特殊页内容`，不是「已收到」。

### B 账号

4. `--list-accounts`：**账号名 + ID + `cookie_status`** 三件齐（实测只返回 `id / name / nickname / cookie_status`，**没有归属人字段**——归属人由运营确认或查接续卡，⛔ 不许根据昵称猜；`valid` 才是可发，`unknown` 只是没验过、不算失败）。她的问法一次三问：「我想发布在世玲掌管的那个号上 你知道是哪个号吗？你能操作吗？发布之前我能看到预览吗？」——答「能」而不报登录态 = 没答。
5. **换号 = 全链路同步**：定稿文件「发布安排」节、接续卡、发布准备目录名、预览页头、dry-run 的 `account` 字段，一处不留旧号，并**重新**核登录态。她说「那先不发布在那个主号上了 发布在 nbd 聊心理 苏澜管的那个号上」——换号不换稿。

### C 组装

6. 建 `发布准备/<日期>-<主题>-<账号简称>/`。
7. 写 `post-01.md`：frontmatter `title` 不带 `#`、`hashtags` 带 `#`；`## 发布文案` 与定稿正文**逐字一致**（含标点、加粗、落款）。⛔ 改写、润色、补落款。
8. 图转 JPG 落 `images/post-01/01.jpg…`，全篇 ≤2.5MB。
9. **封面凭证**（图文首图即封面，无独立通道）：两条路都落 `01.meta.json`（与首图同名）。(a) 产线出图：`python3 ../nbdpsy-xiaohongshu-creator/scripts/gen_images.py --note <稿件> --cover-only` 会自动落凭证，要补人工确认再 `--confirm-cover <封面> --confirmed-by "<真人姓名>"`（不发布）。(b) 人工确认封面：手写 `01.meta.json`，最小字段 `{"source":"manual_confirmed","cover_file":"01.png","confirmed_by":"<看过这张图的人>","confirmed_at":"<ISO8601>","prompt_excerpt":"通栏大字压顶，主色 #F5E6D3","style_profile":{"套名":"<套名>","version":1}}`（`prompt_excerpt` 里缺 `#` + 六位十六进制色值或缺具名版式、`style_profile` 缺套名/版本，照样拒发）。**`--confirm-cover` 只能盖在已有凭证上，凭证不存在直接拒——⛔ 不能凭空盖章。**⛔ 代签。

### D 预演

10. `--dry-run`：核 `title` / `content_chars` / `topics[]` / `images[]` 与定稿、成品图目录逐项一致，`warnings: []`。参考读数：`content_chars: 426`、`topics` 7 条、`images` 7 个绝对路径。
11. **渲染可视预览给用户，等口令**（规范见 §三）。

### E 提交

12. 只有她说「发布吧」才提交，此前每条回复都带「尚未发布」。失败⛔直接重试：先 `--list-jobs` 证明这次**没入队**，再换通道。拿到 `job_id` 立即报：「发布任务已创建（任务 360），当前状态是"发布中"。」
13. 轮询 `--job <id>` 取终态与 `applied` 明细（`outcome` / `gap_count` / `topics_applied` / `mentions_applied`）。

### F 回读与留证

14. 台账回读后写三处：台账行、`定稿配文/README.md`、接续卡。见 §四。

## 三、预览规范

她的否决原话：「我在这里看到的预览是这样的 看不出来啊」。此前给的是一个本地 HTML 链接（16MB，base64 内嵌六张图），她端上打开成了源代码。**让她自己下载打开 = 把「看一眼」的工作推给用户 = 没给预览。**

判据一句话：**预览必须让运营看出成片效果——图序、封面、末页海报、话题行，一件不能少；不能只给文字摘要。** 要禁的是「把看一眼的活推给用户」——给一个 16MB 的 base64 文件让她自己开、或只丢一段文字摘要；**如果你给的东西需要用户先下载再用浏览器打开，那就是没给预览。**

| 项 | 要求 |
|---|---|
| 形态 | 对话里直接可见：能翻页的组件最好；宿主没有轮播能力时，退一步给**小于 2MB、宿主能直接渲染的 HTML** 或**能直接显示的图片列表**（封面→各页→末页依次铺开）。⛔ 需要用户先下载再用浏览器打开的文件、⛔ 截图文件夹、⛔「你自己打开看」 |
| 内容 | 按页序全部图片 + 完整标题 + 完整正文 + 全部话题行 |
| 默认落点 | 改哪一页就停哪一页（追加第七张 → 默认显示第七张） |
| 状态 | 每次同句写「尚未发布」 |
| 免责 | 同句说明「本地预览与平台排版可能略有差异」 |
| 可核 | 预览里的图逐张对应 `成品图/<套图>/NN.png`：能算就比 `SHA256`，不能内嵌时至少核张数/尺寸/顺序，全过才算预览可信（⛔ 为了塞 `SHA256` 把图 base64 打进 16MB 的 HTML——那正是判例 42 否掉的做法） |
| 迭代 | 她每提一次改动就重渲染一次，不解释、不攒着 |

预览是**强制前置**：她连问两次——「发布之前我能看到预览吗？」「发布之前让我预览一下」。

## 四、回读与留证

**回读三段**：拿到哪一段，只允许说那一档的话。

| 阶段 | 拿到什么 | 还不能说 |
|---|---|---|
| ① job 终态 | `outcome=published`、`gap_count=0`、`topics_applied=7/7` | 不能说「已发布」——可能还在审核 |
| ② 平台现场 | 创作后台显示「审核中」 | 不能说「公开」 |
| ③ 台账回读 | `note_id` / `visibility=public` / `permission_code=0` / `tab_status=1` / `sync_status=linked` | 到这里才算闭环 |

**回读命令**（实测）：① `python3 ../nbdpsy-xiaohongshu-creator/scripts/publish_note.py --job <job_id> --note <发布准备目录>/post-01.md`——`--note`/`--ledger` 用来定位台账（缺了只算不写），终态与 `applied` 从这里出，`note_id` 写进台账行的 `| note=` 段（闭环行 `--ledger-check` 不列，直接读台账文件）。`--notes <账号>` 拉该账号已发布笔记清单与互动数据（导出快照按「账号+标题+发布时间」三元组，**无 `note_id`**）。③ 的 `visibility` / `permission_code` / `sync_status` 用 `note_ops.py --ledger <账号>`（逐条带 `visibility`）或 `note_ops.py --note <note_id>`；**`publish_note.py --help` 里没有这些字段的专用回读参数**，`tab_status` 两个脚本都没有对应参数（只能去创作后台现场看），⛔ 不许编参数名。

**每次必落表**：账号名（ID，归属人）+ `job id` + `note_id` + `visibility` + 图片张数 + 话题挂载数 `N/N` + 商品是否挂载 + 服务端附加项。

刘琼篇真实回执（`定稿配文/README.md` 原文，照此格式写）：

> 2026-10-19 发布回执：账号「NBDpsy聊心理」（ID 2，苏澜管理），job 360，`outcome=published`，`gap_count=0`，七张图及当前七个话题已提交。13:56 创作后台现场曾显示审核中；随后 13:58:16（Asia/Shanghai）台账回读已关联真实笔记，当前 `visibility=public`、`permission_code=0`、`tab_status=1`、`sync_status=linked`。最初发布回执的 `note_url` 是 creator 成功页，仅保留为历史证据。回执还显示服务端默认追加 @人文薯、@心理薯、@薯队长（不是预览配文的一部分）。

> 最新公开回读：台账 row 422 / `source_publish_job_id=360` / `note_id=6ad5b0ff000000002a00698c`……商品本次未挂载。

三条易错：

1. `note_url` 是 creator 成功页，**不是笔记链接**；真实链接由 `note_id` 拼。
2. 服务端默认追加的 `@人文薯/@心理薯/@薯队长` 与「用户给的七个话题」**分开记**。
3. 意图 vs 实际用**数量**表达（`topics=7` / `7/7`），差集空才闭环。

**台账**：

> 这张表记的不是「做过什么」，是「还欠什么」。

行格式 `- [x] 时间 | 稿件 | 账号 | job | 意图 | 实际 | 差集 | 状态`。`- [ ]` = 未闭环，本批不许报完成。失败单独落 `submission-attempts.md`，回执与日志原样保留 + `SHA256`，⛔ 记成成功、⛔ 删回执。状态词表：`未提交平台` / `未发布` / `审核中` / `已发布·公开` / `已发布·未闭环` / `本地草稿（不等于平台草稿箱）`。

⛔ 报「已完成」却给不出句柄（`job id` / 台账行 / 线上回读，三选一）= 没完成。

## 五、红线速查（19 条，逐字来自提取-04 §11）

> 前 14 条已内联在 §一/§二/§四 的 ⛔ 里；这一节是一次看全的清单，两处说法不一致时以本节为准。

**发布前**

1. 未给用户看过预览 → 禁止发布。
2. 用户没说「发布」→ 禁止提交（口头「可以」「行」不算，只有 `发布吧` 触发）。
3. 禁止改写定稿：标题、正文、落款、话题一律逐字；`不会更换封面或改写配文`。
4. 禁止自行增删/改序话题，禁止补热门标签。
5. 禁止拿旧版图 / 近似图顶替待更新页。
6. 禁止把「图文」当视频传 `--cover`（图文首图即封面，传了当场报错）。
7. 禁止代签 `--confirmed-by`（封面确认人必须是真看过那张图的人）。

**发布中**

8. 提交失败**禁止直接重试**——先 `--list-jobs` 确认未入队，再换通道，否则可能重复发。
9. 禁止把失败那次记成成功，禁止删失败回执。
10. 禁止手搓 payload 直调 API，一切走有 job 行的脚本。

**发布后**

11. 禁止把 `outcome=published` 当「已发布成功」——必须核 `applied` 明细与台账回读。
12. 禁止把回执里的 `creator.xiaohongshu.com/publish/success` 当笔记链接。
13. 禁止把服务端自动追加的 `@人文薯/@心理薯/@薯队长` 说成配文的一部分，必须在记录里分开。
14. 禁止报「已完成」却不给句柄（job id / 台账行 / 线上回读，三选一）。

**能力边界**

15. 禁止把本地草稿说成平台草稿箱。
16. 禁止对未验证的能力打包票（商品挂载、补挂、定时）。
17. 禁止用账号编号对用户讲话（对用户一律账号名；编号只用于命令行参数）。

**批量动作**

18. 「隐藏」不许变「删除」；必须先保护再隐藏再核验。
19. 禁止重放旧名单 / 旧台账口径；缺失天数不累计补量。
