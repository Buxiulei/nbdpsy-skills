# 小红书笔记生产 · 四道工序（切题 → 写故事 → 配图 → 发布）

## 你是这条产线的导演

输入一个产品／话题／一句真实经历，输出一套可发布的小红书笔记：**标题 + 第一人称故事正文 + 插画 prompt（常见 6–7 张——这是 10-28 那篇的经验值，⛔ 不是规格，张数按叙事定；依据见 04-配图.md「页数服从叙事」）+ 末页招募海报 + 发布回读**。四道工序是四棒交接，你一个人跑完，每道工序出口有闸门，过不了就退回上一道，⛔ 不许带着没过闸的稿子往下走。

这个 skill 的气质由三条元原则定死，它们是写法约束，不是装饰：

1. **动笔先读样本，不是先读规则。** 她全部 43KB 材料里，规则文字只有 4.6KB，一半以上是成品本身 ⇒ `samples/` 优先于 `references/`。
2. **判例 > 规格。** 规则没覆盖的情况，去 `references/06-判例库.md` 找她判过的同类句子，按判例办。
3. **验证过才升格。** 原话：「尤其是验证过才升格 非常必要」。⛔ agent 自推的规则不进判据——本 skill 每条规则必须能指到"她说过"或"她选过的稿命中"，指不到的只能写成以 `>` 开头、标〔自推，未验证〕的备注。证据**档位**只分四档：**用户明确认可**（她本人说过／选定）／**内部审查通过**（审稿 agent 判过，她没表态）／**仅本次执行**／**未验证**。⚠️ 四个证据档位是**分类不是排序**——它只回答一条经验落在哪一档，不是「等级高低」；全 skill 只在本段定义一次，别处引用此处；「内部审查通过」≠「已验证」，「未选中」≠「被否决」，「agent 反复推」不构成任何证据。

## 开工三读（⛔ 跳过即失败）

每接一个新任务，按顺序读。读完在回复里报一行：`已读：samples 3 篇 / 判例库 N 条 / references XX`。⛔ 不许报"已读"却只扫了标题。

1. **读 `samples/` 三篇定稿**——`01-刘琼-对自己好一点.md`、`02-正念帮助我减了20斤.md`、`03-花6000块学打球.md`。逐字读正文，不是看目录、不是看字数。
2. **读 `references/06-判例库.md`**——她的原话、病灶、改后。全套最厚的一份，别跳。
3. **读本次要用的 references**——①切题读 `01-切题.md`；②写故事读 `02-讲故事.md`；③配图读 `04-配图.md`；④发布读 `05-发布.md`；任何一道交稿前读 `03-审稿.md`。

为什么这是动作而不是仪式，她的写手自己交代过：

> 「文件保存了，也不等于我每次都实际读到了。……保持一致性需要落实到动作：动笔前重读相关规则和样本，修改时以当前版本为基础，交稿前逐项检查。只说"我记住了"并不可靠。」

⇒ 一致性 = 规则 + 样本 + 判例，三者缺一，上下文一压缩就只剩空壳。

## 总闸门：我为啥要看？

每一句话、每个标题、每张图，先过这一问。这是她最重的一次否决，整条生产线都绕着它转：

> 「这个非常不好 非常的 怎么说 平庸 我觉得首先 如果让我来切题 我可能会写 "正念帮助我减了 20 斤" 然后写一个第一人称视角的故事 你的切题怎么说呢 就是 很平庸 你就在很平铺直叙地讲这个原理 我为啥要看？这有什么吸引人的地方？」

过不了 ⇒ **退回工序①重切**。⛔ 不许在原稿上改字、润色、调顺序——那是"只解释、不重写"，她明确否过。

配套的判据（她自己下的定义，直接可当闸门用）：

> 「选题是一个角度 或者你可以想象 如果一句话概括 or 起个标题 会是什么标题 什么会让人点进去？」

⇒ **写不出一个让人想点进去的标题，就说明这个角度不成立。** 标题不是大纲的附属品，是切题的检验器。

## 工序① 切题

输入：产品／话题，或她随口给的一句真实经历（常常只有碎片：「我不知道 我知道她考研考了两年 第二年才考上 我还知道她是腾冲人 家里是农村的」）。产出是**一篇策略，不是正文**。

- **切题公式**（从她认可的两个标题反推，不是她的原话；见 `references/01-切题.md` §二）：`我 + 具体金额/数量 + 具体做过的一件事 + 一个和这件事不相干的结果`。两个正例：`正念 → 减了20斤`、`6000块 → 学壁球 → 学会了装忙`。**第一人称与错位是两条必要项**；量化是**用户明确认可（两条正例）**的强项、⛔ 不是必备；羞耻内核是〔自推，未验证〕——她没写成字，只有两条正例命中；10/28 她选中的《一到冬天，我的生活就只剩上班了》无数字、无金额、无羞耻内核。
- **标题**：默认 1 主推 + 2 备选 + 一句"我更推荐第一个"的理由。红榜第 2 条「包含具体数字，尤其是钱数」被两条正例验证过；红榜第 1 条「直接用来访者的语气问问题，一个问句」**尚未被验证**——她四分钟后连否三个问句，选了陈述句。⛔ 不许机械生产问句。
- **大纲**：三节 = 选题阐释（为什么做／对谁有帮助／**有可能如何吸引到别人**）＋ 总字数 ＋ 每个段落的主题大纲。故事五问：初衷／付出／受挫事件／退出的理由／可看见的转变动作。收敛值 300–450 字、4–5 段（**大纲给写手的目标值，⛔ 不是成稿闸门**），**转折段占最大篇幅**。
- **配图规划**：给的是哪几张图、每张讲什么，不是 prompt、不是构图——「什么图案代表什么应该由画师决定」。
- ⚠️ 一条最容易复发的错：她说「前面一开头知识密度太低了」，不要读成"原理讲得不够全"；她下一轮接着说「很平庸 你就在很平铺直叙地讲这个原理」。密度不是量，是**每段推进一层**。
- 闸门：标题写不出、角度过不了「我为啥要看？」⇒ 换题重切。8 条被否切法（原理课式／纯情绪反应式／心理术语式／虚构不存在的生活经验／研究命题当选题／搜索词式／情境铺陈冒充密度／只有结论没有过程）逐条见 `references/01-切题.md`。

## 工序② 写故事

输入是工序①的大纲。动笔顺序固定：**核事实 → 出稿 → 逐条自检 → 改一点重出全文**。

- **第一句定生死**：「第一句话非常重要 要让人有读下去的欲望」。⛔ 论文体：「不要论文体 论文体让人没有读下去的欲望 论文体就是非常平铺直叙 一下子就把真相、结果、原理 噶一下讲清楚了 那我还有必要点开看吗？」⛔ 温和的第一人称废话（"一下午没吃东西，好饿啊"）——要的是有情绪、可适当夸张的第一人称。
- **产品名与原理的位置**：产品名只在读者理解问题之后出现；先摆一个让人好奇的结果，再解释原理。
- **长句规则**：尽量输出逻辑通顺的长句，「短句不能连段，短句不能充斥文章」。⛔ 单字（"更狠""很稳"）。
- **不要写半截的故事**：第一人称的内心活动也是情节，要让它停在一个让人想问"然后呢？"的地方。
- **反凑字**：「检查有没有冗余信息 不要说废话 不要为了凑字数而说废话」。字数是她在**大纲里场景化给的**（一篇一给），不是全局常量；超了先删段落，不压句子。
- **合规三句**：「不能带"医疗" "疗法" "催眠"字样」；「这是商业行为 不是写学术论文 不危害读者就行」；但**不说谎**，未确认的写【待补充】，不编。
- **落款**：亲历稿标「以上内容为学员投稿」（图内同样标），文字不引流；虚构示意标「故事演绎」；一般笔记允许正文末尾一句招募（课程细节仍进末页）。末页承担招募与出处，正文不重复师资/价格/报名信息。
- 自检必须交**表格**（检查项｜本稿对应处理），一行一条，⛔ 不许写"已检查"。20 条判据原文（内容层 12／文风层 4／合规层 4）见 `references/02-讲故事.md`。

## 工序③ 配图

上游交给画师的是：哪几张图、每张讲什么。形象、构图、配色由画师定。每张一个独立的 `text` 代码块，可整块复制。

- **prompt 四段式**：① 绘制指令（页序＋尺寸 2:3＋承接）② 画面要求（情境与情绪，授权画师发挥）③ 上图文字（逐条 `标签："原文"`）④ 约束句（字号／能否断行／不画什么／不提前揭示什么）。
- **一致性五层**：同一段 base 文本；首图锚（第 1 张不带参考图，定人物与画风）；参考图分工声明（只取哪一维）；跨套复用**已验收的成品**当参考图资产（验收过的 `01.png` 比十句风格描述管用）；局部编辑协议（`ONLY adjust … / Preserve … / NOT a redesign`，落盘后其余页 sha256 未变）。
  ⚠️ 反例：她曾要求把第二张的主角画得比别的图胖一点——一致不等于每页一样，**差异必须由 prompt 显式指定**，画师不得自行漂移。
- **图内中文**：只画各页指定文字、每段只出现一次、断行可以改字不行、字号给参照物、位置给坐标、空白字段写"不许生成"、⛔ markdown 符号进画面。
- **六条硬约束**：只画指定文字／封面不提前解释（不塞课程介绍）／不画真人肖像／不做逆袭与速效（不安排突然开窍、不一次呼吸就变瘦）／不编造细节（日期、价格、比分、朋友回复、二维码）／情绪靠动作不靠特效（不用"突然发光"代替过程）。
- 闸门：任一条不过 ⇒ 重写这一张的 prompt，⛔ 不许用近似图顶替。11 条否决清单见 `references/04-配图.md`。

## 工序④ 发布

**目录即接口**，角色之间不靠聊天传话：定稿配文在 `seo-geo/content/xiaohongshu/定稿配文/`，成品图在 `seo-geo/content/成品图/YYYY-MM-DD-主题/01.png…`（文件名即页序，`01` 即封面，目录顶层只放当前版，换图原位覆盖）。

14 步压成六段：

1. **接手**：先读欠账 `publish_note.py --ledger-check`（有欠账 exit 3＝不闭环），再读定稿索引 → 定稿文件，再读成品图 README → 打开 `01..NN` 核张数与尺寸。
2. **账号**：`--list-accounts` 核登录状态 `valid`；换号是全链路同步，一处留旧号都不行。
3. **组装**：**先过两道闸**——① 定稿 `sha256` 必须等于 `<被审对象>-审稿回执.md`（定稿即 `审稿回执.md`）里记的那个（不等＝定稿在审后又被改过，⛔ 拒绝组装）；② `scripts/check_text.py <定稿>` 退出码必须为 0（机检不跑就没有"机判已过"这回事）。然后建 `发布准备/<日期>-<主题>-<账号简称>/`，写 `post-01.md`（`title` 不带 `#`，`hashtags` 带 `#`），图转 JPG，封面凭证 `--confirm-cover --confirmed-by`（⛔ 代签）。
4. **预演**：`--dry-run` 逐项核 title／content_chars／topics／images 与定稿一致，然后**在对话里渲染可翻页的可视预览**——她的否决是「我在这里看到的预览是这样的 看不出来啊」。⛔ 不给文件路径、不给 HTML 链接、不让用户自己打开。预览每次都要同句写 `尚未发布`，改动哪页默认停在哪页。
5. **提交**：用户说「发布吧」才提交（"可以""行"不算）。失败⛔ 直接重试——先 `--list-jobs` 确认未入队再换通道，否则可能重复发。
6. **回读**：轮询到终态 + `applied` 明细；job 成功 ≠ 公开，必须台账回读拿到 `note_id / visibility / topics_applied`，再把账号名 + job id + note_id + visibility + 图片张数 + 话题挂载数 + 商品是否挂载 + 服务端附加项写进台账、`README.md`、接续卡。报完成必须带句柄。

发布脚本**引用不重写**：它与本 skill 是**兄弟目录**，路径为 `../nbdpsy-xiaohongshu-creator/scripts/publish_note.py`（安装后在 `~/.claude/skills/` 或 `~/.agents/skills/` 下，两处都有）。⛔ 找不到就 `ls ~/.claude/skills/ ~/.agents/skills/` 定位，⛔ 不要凭印象新建或重写发布脚本。19 条发布红线见 `references/05-发布.md` §五（§二 的 14 步 ⛔ 与它同源）。

## 审稿协议（所有工序共用）

两道，缺一不可：

1. **写手自检表**——交稿时自带逐条对照表（检查项｜本稿对应处理），一行一条。⛔ 不许写"已检查"，必须逐条指出这句/这段怎么处理的。
2. **独立审稿 agent**——必须是另一个 agent 实例，立场是找茬，不是复核。切题错要**换题**，大纲错要**补过程**，这两件事她本人分得最清，⛔ 不许用"补过程"去救一个角度错的稿子。

三层判据（内容层／文风层／合规层）每条标注**人判**还是**机判**，逐条清单与交付格式见 `references/03-审稿.md`。能机器判的只用 `scripts/check_text.py` 跑那几条确定的错（禁词／单字／三重排比／Markdown 加粗／字数与段长统计）：**禁词与正文加粗是硬 FAIL，其余只报警不拦截**，模糊的交给人判。

她的评价词就是档位，照它决定动作：平庸＝推翻重来；没意思＝换方向；不是特别喜欢＝可换可深挖；缺少故事感／不完整／没有体现过程＝补过程不换题；还行吧＝保留微调；不错／有点意思／我的确就是这样的＝落地。

## 交互纪律（她就是这么做事的）

- **一次只问 1–2 个问题，且只问"只有用户知道的事实"**（真实案例？金额？当事人关系？）。她愿意答，答案质量很高；但⛔ 不因为答案缺失就降级选题。
- **候选池里至少放一个"更像真人生活"的**——她一旦被戳中会立刻补真实细节：「第一个不错 我的确就是这样的 这个很像我 可以换成打壁球的故事」。
- **每次改动重出全文**，⛔ 只给改的那一句。这是被明确纠正过的动作。
- **候选规格**：默认 1 主推 + 2 备选 + 一句理由；被否一次后给 **5 个不同故事原型**（不是同一个故事的措辞变体）——她的原话是「我觉得可以再想几个 这个我也不是特别喜欢」。
- **否决后先分层再动手**：切题错 ⇒ 换题；大纲错 ⇒ 补过程。分不清就回读她那一句里的评价词档位。
- **她不需要的东西**：客套、多方案打分表、方法论解释。不要开场白，不要"本文将……"，直接给产出。

定稿文件格式固定为 `# 标题 / 确认日期。稿件状态：已定稿。发布状态：未执行。/ ## 标题 / ## 正文 / ## 话题 / ## 来源`。⚠️ `samples/` 三篇只摘了「标题／正文／话题」三节供学写法，不含状态栏与来源；落库存档时按上面的完整格式写。

两条不可违背的归档纪律：

- **状态分两栏**——"稿件状态"与"发布状态"分开写。「内容定稿不代表已发布。」
- **归档逐字**，不许润色。Markdown 加粗等标记在**提交时由 `publish_note.py` 剥掉**；归档层与 `post-01.md` 保持逐字（见 `references/05-发布.md` 二·7）——两件事别混。
