# 笔记审查清单（小红书图文，逐篇审）

> 审查对象：nbdpsy-xiaohongshu-creator 产出的 post-*.md（一篇一审，一套笔记逐篇出结论，任一篇 FAIL 则该篇返工）。
> 立场：预设有问题，逐条找证据；不确定按 FAIL。

## 开审前 · 先认这批走的是哪条拆解路线（2026-07-28 定案，**比认档案更靠前**）

长文有两条上小红书的路，**判据完全不同**——路线判错，后面每一条都是假 FAIL。

```bash
grep -n "拆解路线" <note_dir>/00-overview.md
```

- 读到 `拆解路线：② 文字版` → **本清单的判据 6（密度）、页数 6–9、正文字数 210–450 三项全部不适用**，
  改按创作端 `references/longform-typeset-spec.md` §6 那张适用性对照表判；正文按 §5（引言 + 简短介绍 +
  危机声明 + 5–10 标签，**120–200 字**）判。
- 读到 `拆解路线：① 信息图轮播`、或**没有这一行**（存量批次） → 按本清单原样判，下面全部照旧。

⚠️ **路线② 的这三项"不适用"是豁免，不是放行**：标题口径（≤20 字、前 10 字含目标长尾词）、
合规扫描、危机声明、三条铁律、红线三层**一条不减**。而且路线② 的图里是**整篇长文**，
违禁词命中面比 300 字正文大得多——`check_compliance.py` 必须**对 `body.md` 本身也跑一遍**，
只扫发布文案就放行 = 漏审。

⚠️ **路线② 是系列篇时另判**（frontmatter 有 `series_index` / `series_total`，或标题带（上/中/下）、（一/二…））：

- **承接段**：第 2 篇起，开头必须有一两句说清上一篇讲到哪儿——没有 = **FAIL**（读者不知道自己捡到第几篇）。
  最后一篇之外，每篇结尾要有**预告段**。
- **TODO 残留**：`grep -n "TODO" <note_dir>/body-*.md` 有命中 = **FAIL**（占位没填就出图了）。
  ⚠️ 正常情况下 `typeset_longimage.py` 会拦住，命中说明有人绕过了脚本。
- **标题**：含系列标记后**总长仍 ≤20 字**（标记算字数，「（上）」占 3 字）。
- **每篇独立成立**：各自带齐标题 / 正文 / 危机声明 / 5–10 标签——**只有第一篇有 = FAIL**。
- **系列标签**：全系列共用一个贯穿标签，每篇都带。

⚠️ **挂了末页咨询师推介时另判**（`--counselor`）：推介信息**全部来自官网公开资料**，
一个字不许编（铁律 1 在这一页同样适用）；推介的必须是**运营点名的那位**。

⚠️ **路线② 独有的必查项**（源自"去引用"这道工序，做漏了就是一堆没出处的心理学断言）：

```bash
grep -nE "\[\[|\]\(http|参考文献|References" <note_dir>/body.md
```

有命中 = **FAIL**（引用标记/链接/参考文献区没剥干净）。反过来，**行内作者年份必须还在**
（`Linehan（1993）` 这类）——全文一个都找不到、而源长文里有，同样 FAIL（把出处一起删了）。

## 开审前 · 先认这批用的是哪一份、哪一版风格档案（2026-07-26 下午定案）

视觉与语气的默认口径（配色 / 人物卡 / emoji / 引号 / 密度）**不再是全站写死的常量，而是每个运营一份的「风格档案」**——本清单里写着的莫兰迪三色、固定人物卡、emoji 8–14、引号 >4 对等，都只是**默认配置那一份**的取值。拿它去判一个自带调性的运营（例：苏澜用她自己的配色），会把达标产出整批判成 FAIL。**所以开审前先认这批用的是哪一份、哪一版档案。**

1. **读留痕行**：`00-overview.md` 开头应有一行
   `风格档案：{套名} v{N}（本人档案 / 默认配置 / 内置兜底，读取于 {日期}）`。先跑一条命令确认它在不在：

   ```bash
   grep -n "风格档案" <note_dir>/00-overview.md
   ```

   以**有无输出**判，不看 exit code（grep 无命中时 exit 1 属正常）。
   **`{套名}` = 本批实际用的那一套的名字**（默认两套就是 `图文` / `文字版`；运营自定义命名的就写他起的名，如 `水墨风`），
   紧跟在 `风格档案：` 后面，与版本号之间一个半角空格——**套名与版本号两个都记下来，第 2 步两个都要用**。
   ⚠️ **旧写法兼容（两条，都绝不判成格式错误或漏填留痕行）**：
   - `管理员默认` 是 2026-07-26 之前的旧写法，等同于 `默认配置`——读到它**照常识别、按默认配置那一层处理**（存量批次全是这个写法）。
   - **整行没有套名**（`风格档案：v3（本人档案…）`）= 2026-07-28 之前的存量批次——**按「图文」判**（那时只有轮播这一条路线有档案）。

2. **按留痕行指定的那一套 + 那一版取回档案**（档案会改、还能回退，**拿当前最新版去判老批次必然错判**——用 v8 的口径去判 v3 时写的笔记，判出来的 FAIL 全是假的）：

   ```bash
   # 首选：版本 + 套名一起点名，取回的 profile 就是那一套（脚本已放开 --version 配 --profile）
   python3 ../nbdpsy-xiaohongshu-creator/scripts/style_profile.py --version {N} --profile {套名}
   # 老脚本不认这个组合（报"--profile 只能配 --get 用"）才退这条，然后自己从容器里挑（见下表）
   python3 ../nbdpsy-xiaohongshu-creator/scripts/style_profile.py --version {N}
   ```

   ⛔ **不要用 `--get` 代替**——那读的是"当前最新版"（而且是运营**当前默认那一套**），正是这一步要避开的东西。

   ⚠️ **取值路径按返回里有没有 `schema: "profiles-v1"` 分两种**（2026-07-28 多套化：`--version {N}` **不带** `--profile` 取回的是**整份容器**，不是某一套）：

   | 返回里 | 什么格式 | 判据从哪儿取 |
   |---|---|---|
   | 带了 `--profile` 且 `outcome: "ok"` | 脚本已把 `profile` 换成挑中的那一套 | 直接 `profile.*`，下文写法原样可用 |
   | 有 `schema: "profiles-v1"`（没带 `--profile`） | **多套容器** `{schema, active, profiles:{套名:{kind,…}}}` | `profile.profiles.{留痕行那个套名}.*`——⛔ **此时 `profile.visual` / `profile.tone` / `profile.density` 恒 `undefined`**，照老写法取会全部扑空、静默回落内置默认口径，**把自带调性的运营整批判成假 FAIL**（正是本节开宗明义要防的那件事） |
   | 没有 `schema` 键 | **老的平铺格式**（存量批次） | `profile.*`，照旧 |

   - ⛔ **别拿容器里的 `active` 那一套顶替留痕行的套名**：`active` 是"运营现在默认用哪套"、随时会变；留痕行点名的那一套才是这批当时真用的。
   - **留痕行的套名在那一版里找不到**（运营后来改名 / 删了；或带 `--profile` 取回的 `outcome` 不是 `ok`、`profile: null`）→ 按下面第 4 条当"那一版取不回来"处置，报告写明「留痕行的套名在该版档案里不存在」，**不据此单独判 FAIL**。

   **本清单下文一律写 `profile.visual.*` / `profile.tone.*` / `profile.density.*`——那是「取到那一套之后」的写法**；没带 `--profile`、自己从多套容器里挑时，同一字段的实际路径是 `profile.profiles.{套名}.visual.*`（`tone` / `density` 同理）。取到那一套后，里面三块与本清单相关：
   - `profile.visual.*`（`palette` / `text_color` / `character_card`）→ **判据 2**（每页提示词里的配色与人物卡）；
   - `profile.tone.*`（`emoji` 数量与款式 / `quotes` 引号口径 / `person` 人称 / `sentence_length` 句长 / `paragraph_rhythm` 段落节奏，对照表见创作端 `xiaohongshu-spec.md` §1.7 B；**该版档案里没有的字段就照 skill 默认判**）→ **判据 9**；
   - `profile.density.*`（密度五字段，**`信息密度档位` / `每页文字量` / `每页信息点` / `版式档` / `运营原话` 五个中文 key 原样，不是英文**）→ **判据 6**。

3. **三种来源怎么判**：

   | 留痕行写的来源 | 各判据对谁判 |
   |---|---|
   | `本人档案 v{N}` | `--version {N}` 取回那一版，按其 `profile.*` 判 |
   | `默认配置 v{N}`（旧写法 `管理员默认 v{N}`，同义） | **按该批次留痕行指定的那一版默认配置判**——同上用 `--version {N}` 取回那一版（取不回来时可退到本清单内置的默认值，报告写明） |
   | `内置兜底`（创作端当时没连上档案服务） | 版本号位写的是 `v—`（**没有服务端版本号是这一层的正常形态，不是漏填、更不是 FAIL**），**按本清单内置的默认值判** |

4. **留痕行缺失 / 那一版取不回来**（存量批次，写在本规范之前；或脚本不存在、**脚本 exit 2**＝没配 `NBDPSY_XHS_API_KEY`／API 不可达（stderr 写着"没连上风格档案服务"、stdout `layer: builtin_fallback`）、**exit 1**＝该版本不存在）→
   **按本清单内置的默认值判，并在报告里写明「本批次无风格档案留痕（或该版取不回），已按内置默认值判，请上游按新规范补留痕行」——不据此单独判 FAIL**
   （与 v1.37.0「密度五字段缺失」的处置同源：判松了最多漏一次风格偏差，判严了会把达标产出整批打回，返工成本远高）。

5. **优先级链（四层，与创作端同源，不得自行改序）**：
   **运营的显式口头指令 > 样本卡实测 > 风格档案 > skill 默认口径**。
   风格档案是**用户级、长期**的（一次显式固化动作才会变）；样本卡是**批次级、一次性**的。几层打架时按此序判，并在 issue 里写明是按哪一层判的。
   ⚠️ 本节与"有没有样本卡"**无关**：没有样本卡的批次照样要读留痕行、照样按档案判默认值。

6. ⛔ **档案管的是视觉与语气，管不到合规与选题**：判据 0 那条生死线（选题 / 主路径 / 三段式 / 全局硬闸 G1–G10）、
   **法律/执业级**（F1 公域冻结、G5 案例可反向识别）与**平台封号级**（站外导流，判据 8）**不因换了档案而变**——
   任何风格档案、任何样本卡都覆盖不了；档案里若写了要覆盖这两层，**这件事本身就是一条 blocker issue**（与样本卡 ⑤ 段同处置）。

## 确定性检查（先跑，JSON 输出与 exit code 原样记入报告）

路径说明：`../nbdpsy-xiaohongshu-creator/` 指安装后与 nbdpsy-content-reviewer 同级的兄弟 skill 目录；命令在本 skill 目录下执行，或换算为绝对路径。

| 命令 | 预期 | exit 语义 |
|------|------|-----------|
| `python3 ../nbdpsy-xiaohongshu-creator/scripts/count_xhs.py <post> --title-keyword "<该篇目标长尾词>"` | 正文字数、页数、标题字数达标 + **目标长尾词落在标题前 10 字内** | JSON 输出；不达标 exit 2，**失败原因逐个看 `ok_body` / `ok_pages` / `ok_title` 哪一项为 `false`**（同一个 exit 2 也可能由正文字数或页数触发；`title_reason` 只承载标题类原因，正文字数/页数不达标时它是空串，别据此当"标题没问题＝整体没问题"） |
| `python3 ../nbdpsy-xiaohongshu-creator/scripts/check_compliance.py <post>` | 无违禁词命中 + 危机声明在位 | JSON 输出；任一命中/缺失 exit 1 |
| `python3 ../nbdpsy-xiaohongshu-creator/scripts/count_xhs.py <post> --density-max <每页字数上限> --density-points <每页信息点上限>` | **仅「信息密度档位: 运营指定」时跑**：**逐内容页（P2…P(N-1)）**的「页面文字」字数与信息点数都不超过运营给的硬上限；`density_pages` 里 P1 与 PN 两行（`counted: false`）只作参考，**超限不判**（2026-07-26 决策 2：封面与末页不受密度档位管） | JSON 输出逐页给出实际字数/信息点；**exit 2 由字数/页数/标题/密度任一不达标触发**（脚本内是 `ok = ok_body and ok_pages and ok_title and ok_density`），**是否为密度问题只看 `ok_density` 与 `density_reason`，不看 exit code**（2026-07-26 实跑复现：正文字数不足也 exit 2、而 `ok_density: true`——把 exit 2 直接读成"密度超限"会误判） |

（两脚本内部口径以其自身实现为准，本清单只约定命令与 exit 语义，不复述内部规则。）

> **密度检查什么时候跑**（2026-07-26 老板定案）：**只在 `00-overview.md` / post frontmatter 的「信息密度档位」字段为 `运营指定` 时跑**，
> `--density-max` / `--density-points` 两个值**逐字取该篇声明的「每页文字量」「每页信息点」上限**（如声明 `≤100 字` / `2–3 个` → `--density-max 100 --density-points 3`）。
> **默认档不要跑**——默认档的 200–400 字 / 6–10 点是版式建议值、**没有硬上限**，跑了必然误判成假 FAIL（口径见判据 6）。
> **五个字段全部缺失（存量笔记，写在新规范之前）= 视同默认档，同样不跑**，并在 issue 里指出上游漏了新规范（口径见判据 6）。
> ⚠️ **只缺 `版式档` 一项时不适用本条**（2026-07-26 补）——其余四字段还在就说明这批是新规范产出：按判据 6 的兜底规则
> （按 `每页信息点` 的**下界**落档）定版式档，**密度检查仍按 `信息密度档位` 字段决定跑不跑（写着 `运营指定` 就照跑）**——
> 别因为少一个 `版式档` 就把它当默认档、放过运营给的硬上限，也别拿默认档的 6–10 点去判它密度不足。
>
> ⚠️ **`--density-points` 数出来的数是保守下界，别当精确值用**（2026-07-26 实测）：它按**非空行数**算，
> 一行里塞了 N 条信息也只记 1 条（实测范例 P2 目视 6–8 个信息点、脚本只记 3 点）；且**只数汉字**，
> `CPTSD`、`7.2%` 这类英文缩写/数字/标点**不计**。因此 **exit 0 不等于达标**——
> 实际信息点贴近运营给的上限时，以**人工目视逐页数**为准，脚本结果只作下界佐证。

> **目标长尾词从哪来**：`00-overview.md` 里该篇的 `目标长尾词` 字段（2026-07-26 起每篇必填 1–2 个）。
> **overview 里没有这一栏 = 上游漏了新规范**：在 issue 里直接指出，并按判据 0② 用标题里实际的议题词试判；
> 不传 `--title-keyword` 时脚本只校 20 字硬限、**不校关键词**（会漏掉"标题无关键词"这一类）。

> ⚠️ **咨询师推介笔记这两条命令都要换参数跑**（2026-07-27；篇型认定与判据见判据 4 的「咨询师推介笔记专属分支」）：
> `count_xhs.py <post> --body-min 400 --body-max 800 --page-min 4 --page-max 6`，且**不传 `--title-keyword`**
> （推介笔记不适用"目标长尾词前 10 字"那条，见推介分支 ③——传了就是拿科普规则套推介，必然假 FAIL）；
> `check_compliance.py <post> --no-crisis`（本场景不含 12356 声明，见判据 4）。
> **按默认参数跑推介篇必然假 FAIL**：脚本默认按科普的 6–9 页 / 210–450 字校验，而推介是 4–6 页 / 400–800 字
> （口径见 `../nbdpsy-xiaohongshu-creator/references/counselor-note-spec.md` §3、§5）。20 字标题硬限两种篇型同样照判。

> ⚠️ **批次目录有 `_shared/style-card.md`（参考样本卡）时，两处取值变了**（2026-07-26 参考样本模仿，口径见下方「判据前置」）：
> - **标题**：样本卡 `⑤` 段点名覆盖了「标题前 10 字必须含目标长尾词」时，`count_xhs.py` **仍照跑、输出原样记入报告**，
>   但 `ok_title: false` 且 `title_reason` 指向**关键词缺失/位置**的那一类**不判 FAIL**；标题超 20 字硬限这一类照判。⑤ 段没点名标题的，一切照旧。
> - **密度**：`--density-max` / `--density-points` 两个值**改从样本卡 `④` 段的 `每页文字量` / `每页信息点` 取**；
>   跑不跑仍只看 `信息密度档位` 字段——从参考样本实测出来的档位写的就是 `运营指定`，**照跑**
>   （例外：样本卡 ④ 注明「参考样本只含封面，内容页密度沿用默认档」时档位是 `默认`，**不跑**）。
>   ⚠️ **④ 段有「由运营口头指定覆盖样本实测值」注明行时**（场景四：运营既给图又开口），两个值**改取 `00-overview.md` /
>   frontmatter 的口头值**，不取 ④ 的实测值——口头 > 样本卡实测（优先级链见「判据前置」，取值口径见判据 6）。
