# 配图审查清单（轮播插图，逐张看图审）

> 审查对象：一篇笔记的成品配图目录（P01..PN）。
> 立场：预设有问题，逐张找证据；不确定按 FAIL。
> **铁律：判断性条目必须逐张打开图片查看**——不许只看文件名和尺寸就下结论；未打开图片得出的结论视为审查无效。

## 确定性检查（先跑，JSON 输出与 exit code 原样记入报告）

| 命令 | 预期 | exit 语义 |
|------|------|-----------|
| `python3 {SKILL_DIR}/scripts/check_images.py --dir <images> --pages <N>` | 页数齐全 + 尺寸合规 | JSON 输出；缺页或尺寸不合规 exit 1（尺寸判定见下） |
| `find <note_dir>/images -name .gen_images_state.json 2>/dev/null \| sort` | 有输出 = 该批次走过**路线 0**（后端一致性出图），锚点审计适用；无输出 = 非路线 0，下面两条**整体豁免** | 先跑这条定路线（见下方「路线判定」），再决定后两条是否适用；输出即"走了后端出图"的篇目清单，与 `post-*.md` 篇数比对可看出哪几篇没走 |
| `test -s <note_dir>/_shared/BATCH_ANCHOR.txt && echo ANCHOR_FILE_OK` | 输出 `ANCHOR_FILE_OK` | **无输出 = 锚点文件缺失或为空**，下一条比对根本不成立；**仅路线 0 批次**本项直接判不通过（路线判定与豁免见下方审计说明），**绝不当 PASS** |
| `ANCHOR=$(cat <note_dir>/_shared/BATCH_ANCHOR.txt) && [ -n "$ANCHOR" ] && grep -FL "\"anchor_url\": \"$ANCHOR\"" <note_dir>/images/post-*/.gen_images_state.json` | **无输出**（且上一条已输出 `ANCHOR_FILE_OK`） | 以**有无输出**判，不看 exit code（grep 无命中时 exit 1 属正常）；列出来的篇目即锚点对不上的，FAIL。⚠️ **只有上一条通过时，本条的"无输出"才等于 PASS** |
| `test -f <note_dir>/_shared/style-card.md && echo STYLE_CARD_FOUND` | 有输出 = 本批次吸收过运营给的**参考样本** | 定"按什么判版式"：有输出 → 判断性检查走下方**「有样本卡时的双重核对」**（判据 8 生效，判据 6 改按样本卡；**判据 7 图内引号不变**，样本卡覆盖不了）；无输出 → 照 `nbdpsy-xiaohongshu-creator/references/illustration-spec.md` 默认判，判据 8 不适用。**两种都不判 FAIL**（没有参考样本是常态）；判据 9 与本条结果无关，永远生效 |

`{SKILL_DIR}` = nbdpsy-content-reviewer 本 skill 目录；`<N>` = 该篇笔记规划的页数（对照 post-*.md 的 P 页标题数）。

**尺寸判定口径（2026-07-26 定案，对齐真实出图）**：宽高比命中 **2:3（0.6667，后端 `/api/op/consistent-images` 原生 1024×1536，主力）** 或 **3:4（0.75，运营自己用 Gemini/GPT 出的图、以及历史补边图）** 之一即合规，各容差 ±2%；最短边 ≥1024。两种比例都是合法交付，不因比例不同判 FAIL；JSON 的 `wrong_size` 会带 `ratio`（实际 w/h）与 `aspect`（命中的比例名，未命中为 null）便于取证。

**批次锚点审计（2026-07-26 定案）**：整批的一致性锚点只有一张 P1，其 URL 存在 `<note_dir>/_shared/BATCH_ANCHOR.txt`；每次出图 `gen_images.py` 会把本次实际所用锚点写进 `images/post-NN/.gen_images_state.json` 的 `anchor_url`。上表 `grep -FL` 那条命令逐篇比对两者：**对不上 = 该篇的风格基准漂了**，报告里列出对不上的篇目及其实际 `anchor_url`，该篇按 FAIL 处理（整篇的页都受影响）。理由见文末「FAIL 之后怎么改」，此处只做可审计的比对。

⚠️ **本项只适用于走路线 0（后端一致性出图）的批次**（2026-07-26 裁决 B）：宿主自出图 / 运营手工出图的批次**既无 `.gen_images_state.json` 也无锚点文件**，与下方 `.gen_images_state.json` 缺失同口径**不判 FAIL**，报告写明"非路线 0 交付，锚点无法自动审计"即可。**存量笔记（2026-07-26 新规范之前产出，那时还没有落盘锚点这一步）同样豁免**——它们多半"有 state 无锚点文件"，见下表第 2 行的分情况。先按下表定路线，再套用后面那条硬闸：

| 批次内有 `.gen_images_state.json`（上表 `find` 那条有输出） | 有 `_shared/BATCH_ANCHOR.txt` | 判定 |
|---|---|---|
| ✅ | ✅ | **路线 0**，照跑 `grep -FL` 逐篇比对 |
| ✅ | ❌ | **看这批图是不是本次新出的**：<br>· **本次出图流程内产出**（你审的就是刚跑完 `gen_images.py` 的图）→ 走了路线 0 却没存锚点 → **判不通过**（见下条），要求上游补存锚点后重跑<br>· **复审存量批次**（2026-07-26 新规范之前产出，那时还没有落盘这一步）→ **豁免**，报告写明"存量批次、新规范前产出，锚点无法审计"<br>· **拿不准是哪种 → 按豁免处理**，并在报告里问一句（宁可漏判不可误判） |
| ❌ | ❌ | **非路线 0**（手工 / 宿主 / 存量笔记）→ **豁免**，报告写明"非路线 0 交付，锚点无法自动审计" |
| ❌ | ✅ | 批次走了路线 0、但这几篇没走后端出图 → 该几篇按下方"某篇没有 `.gen_images_state.json`"条**豁免**，其余篇照常比对 |

⚠️ **路线 0 批次的 `_shared/BATCH_ANCHOR.txt` 不存在或为空 = 上游没按新规范存锚点**（2026-07-26 补，对抗验证 V2#1）：报告里写明"该批次锚点无法审计，根因是缺锚点文件"，本项**判不通过**，并要求上游补存锚点后重跑；**绝不当 PASS**。原因：缺文件时 `$ANCHOR` 是空串，`grep -FL ""` 会命中所有文件因而**零输出**——与"全部对得上"的成功输出长得一模一样，是一条永远给绿灯的伪检查，比不查更危险。所以先跑上表 `test -s` 存在性判断，通过了 `grep -FL` 的零输出才作数。

- 某篇没有 `.gen_images_state.json`：说明这篇不是走后端出图（手工路线不写 state），不判 FAIL，但报告须写明该篇锚点无法审计。
- 锚点文件**路径唯一为 `{note_dir}/_shared/BATCH_ANCHOR.txt`**（创作端 SKILL.md 的落盘步骤只写这一处），**不接受其它位置**——审查时不得因"文件可能在别处"而自我豁免，找不到就按上表定路线处理。
- **该篇挂了咨询师推介末页**（2026-07-26 补，对抗验证 V1#8）：末页是单独出的一批、锚点换成该咨询师头像直链，而 `gen_images.py` 的 `write_state()` 会用这一批的结果**覆盖同一个** `.gen_images_state.json`，于是 state 里的 `anchor_url` 是头像直链而非批次锚点——这是**末页推介的正常结果，不判 FAIL**。改为核对 P1–P(N-1) 的实际出图风格是否仍与批次锚点一致（逐张目视），并在报告里注明该篇 state 锚点被末页那批覆盖、故无法用命令自动比对。

## 有样本卡时的双重核对（2026-07-26 老板定案：**品牌资产保留、模仿其余**）

运营给了参考图文时，创作端会在 `<note_dir>/_shared/style-card.md` 留一张**样本卡**（结构与提取口径见创作端 `references/reference-mimicry-spec.md`）。**有样本卡的批次，视觉一致性一律双轴核对，两条并行、缺一不可**：

| 核对轴 | 对谁判 | 会不会因样本卡放松 |
|---|---|---|
| ① **配色 + 人物卡** | **品牌基底**——莫兰迪三色 #A8B5C4 / #E8D8C4 / #C9D6CE、文字色 #5A6B7B、固定人物卡（**圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫**） | ⛔ **绝不放松**。品牌资产保留是老板定案；样本卡里凡涉及配色/人物形象的都躺在「⛔ 记录但不采用」区，那是**记录**，不是要采用 |
| ② **版式 / 分区数 / 图文面积比 / 笔触质感 / 页角色分工** | **样本卡**——按 ① 段的提取结果与 ④ 段推导出的参数判；**没有样本卡则按 `illustration-spec.md` 默认判** | ✅ 按样本卡覆盖默认口径 |

**既有判据在有样本卡时怎么变**（没列出的一律不变）：

| 既有判据 | 有样本卡时 |
|---|---|
| 1 图内中文逐字一致 | 不变（与样本卡无关） |
| 2 莫兰迪基调无突兀撞色 | **不变**（轴 ①，不放松） |
| 3 人物与人物卡一致 | **不变**（轴 ①，不放松） |
| 4 构图完整无截断/畸变 | 不变 |
| 5 无二维码/联系方式/外链水印 | **不变**——站外导流属平台封号级，样本卡不可覆盖；参考样本自带水印 / logo / IP 形象也**一律不复刻** |
| 6 P1 单独看有封面吸引力 | 「P1 必须是钩子封面、不能是内容页版式」这条**不变**；标题占画面高比、有无人物、主视觉类型、封面文字量改按样本卡 ① 段的**封面卡**那几行判；**末页（PN）文字量**按 ① 段的**末页卡**判，但对齐的是「品牌锚句 + 12356 危机声明」**之外**的正文量（见下方 ★） |
| 7 图内引号收敛 | **不变**（2026-07-26 裁决，与创作端 `illustration-spec.md` 3-b ① 同源）——**图内引号是渲染问题、正文引号才是语气问题，两回事**：图上小标题 / 标签 / pill 带引号会把版面切碎。样本卡 ④ 段的 `引号口径` 是**正文侧**参数（由 `xiaohongshu-spec.md` 消费），**管不到图内文字**；⑤ 段即便点名了"引号"，放行的也只是正文，**图内引号照默认判** |
| 8 版式/质感对样本卡（新增） | **仅有样本卡时生效**，见下方判断性检查第 8 条 |
| 9 参考样本视觉污染（新增） | **永远生效**，见下方判断性检查第 9 条 |

- **密度按页角色分开判**：样本卡 ④ 段的密度五字段（`信息密度档位` / `每页文字量` / `每页信息点` / `版式档` / `运营原话`）**只约束内容页 P2…P(N-1)**，与 v1.37.0 口径一致；封面卡 / 末页卡的文字量单独记在样本卡 ① 段，**用那两行判，绝不拿内容页密度去套封面或末页**（反过来也一样）。
- ★ **末页文字量怎么对齐**（2026-07-26 补，与创作端 `illustration-spec.md` 3-b ④ 同源）：我们的末页**必带**品牌锚句「NBDpsy · 北大硕博纯线上心理咨询」与危机声明小字「心理科普，非诊断治疗 · 援助热线 12356」（两行合计约 40 字，前者是品牌资产、后者是执业级合规，**都不可被样本卡覆盖**），而参考样本没有这两行。所以样本卡 ① 的 `末页文字量` 对齐的是**这两行之外**的正文量——**绝不能拿末页总字数去比样本实测值**，那样我们的末页必然超标，是一条稳定的**假 FAIL**。
- **封面 / 末页文字量只在本清单（图审侧）判**：`checklist-note.md` 不判此项，见判据 6 / 8。
- 密度五字段的 `运营原话` 写成「按参考样本（N 张，形态 X）实测」是**合法值**，不是上游漏填。
- **样本卡试图覆盖法律/执业级或平台封号级 = 照判 FAIL 且升级 blocker**（图上的体现：二维码 / 微信号 / 外链水印、可反向识别的来访案例画面）。只有**产品判断级**（版式、密度、emoji、**正文**引号、封面结构）允许被样本卡覆盖；**图内引号不在可覆盖之列**（渲染问题，非语气问题，见上表判据 7 行）。
- **运营口头说过「照这张做」但没有 `style-card.md`** → 视为上游没落盘样本卡：报告写明「无样本卡可比对，本次版式按 illustration-spec 默认判」，判据 8 不适用，**判据 9 照常生效**（参考样本的配色/人物任何时候都不许出现在成图里）。

## 判断性检查（逐张打开图片，逐条 PASS/FAIL + 证据 + 页码）

1. **图内中文与该页「页面文字」逐字一致**：对照 post-*.md 每页的"页面文字"，逐字核对图上渲染出的中文——无错字/漏字/多字/乱码/繁简混杂。AI 出图最常见翻车点就是错字，小字和专业缩写（CPTSD、ICD-11）重点盯。任何一个字不对 = 该页 FAIL，报告里写明页码 + 错在哪个字。
2. **莫兰迪基调无突兀撞色**：整套图以品牌三色 **#A8B5C4（雾霾蓝灰）/ #E8D8C4（暖米白）/ #C9D6CE（鼠尾草绿）** 系为主，文字色为深灰蓝 **#5A6B7B**；出现高饱和红/亮黄/荧光色等突兀撞色，或某页明显偏离整套色调 = FAIL。
3. **人物与人物卡一致且跨页同一人**：出现人物的页，形象须符合人物卡「**圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫**」，且 P1→PN 看起来是同一个人（发型/脸型/衣着不跳变）。
4. **构图完整无截断/畸变**：主体不被边缘切掉，人物无畸变手指、多余肢体、崩坏五官；文字块不压主体、不出血到边缘外。
5. **无二维码/联系方式/外链水印**：任何页出现二维码、微信号、电话、网址水印、第三方平台 logo = 直接 FAIL（站外导流是限流封号红线）。
6. **首图（P1）单独看有封面吸引力**：把 P1 当作信息流里孤立的一张图来看——大标题是否一眼可读、钩子是否成立、视觉是否干净有点击欲。P1 是内容页版式（信息密集小字）而非钩子封面 = FAIL。⚠️ **有样本卡时**（2026-07-26 补）：标题占画面高比 / 有无人物 / 主视觉类型 / **封面文字量**改按样本卡 ① 段的**封面卡**判；**末页（PN）文字量**按 ① 段的**末页卡**判，且必须**先扣除**我们必带的「NBDpsy 品牌锚句 + 12356 危机声明」两行（约 40 字）再与样本实测值比——参考样本没有这两行，不扣就是稳定的假 FAIL（详见上方 ★）。封面 / 末页文字量**只在本清单判**，`checklist-note.md` 侧不判。
7. **图内引号收敛**（2026-07-26 老板口径，创作端规则见 `references/illustration-spec.md` 第 2 节）：只有**对话气泡里的原话 / 内心独白**可以带引号——那时引号是语义的一部分；**小标题、标签、pill 文字、区块标题、结论句带引号 = 该页返工（记 FAIL）**；一页图上**成对出现的引号 >2 处 = 返工**。层级本就该靠字号 / 位置 / 颜色去分，不靠引号。⚠️ 只看**图上真的画出来的**引号；提示词里用来包裹入图文字的那对引号不在此列（那是"这几个字要渲染进图"的语法标记，删了模型就不知道哪些字入图）。⚠️ **本条不因样本卡放松**（2026-07-26 裁决）：样本卡 ④ 的 `引号口径` 只是正文侧参数，**图内引号照本条判**——理由见上方「有样本卡时怎么变」表判据 7 行。
8. **版式 / 分区数 / 图文面积比 / 笔触质感与样本卡一致**（2026-07-26 新增，**仅当 `<note_dir>/_shared/style-card.md` 存在**；无样本卡时本条不适用，改按 `illustration-spec.md` 默认判）：逐张对照样本卡 ① 段——内容页的版式类型（对比 / 流程 / 象限 / 清单…）与分区数、格内小图与说明文字的图文面积比、笔触质感（扁平矢量 / 有无描边 / 噪点纸底…）、整套编排（总页数、内容页占比、页间靠什么维持一致）。**成套跑偏**（样本卡写"左右对比双栏、每栏 3 格"，成图却是通栏清单）= FAIL，报告写明是哪几页、样本卡那一行原文怎么写的、成图实际是什么。⚠️ 本条**只判版式与质感**——配色与人物形象不在本条内，那两项永远对品牌基底判（判据 2 / 3）。样本卡里置信度标「低」的条目（仅 1 张样本出现）**不单独判 FAIL**，只在报告里提示偏差。
9. **参考样本的配色或人物形象出现在我们的成图里 = FAIL**（2026-07-26 老板定案「品牌资产保留」的直接推论，**永远生效**，不看有没有样本卡）：成图里出现样本卡「⛔ 记录但不采用」区写明的配色（例：参考样本的米黄 + 砖红双主色）、参考样本的人物形象（例：短发戴眼镜男性），或参考样本的 IP 形象 / logo / 字体标识 / 水印 = **FAIL**。判据是目视认出成图带着**参考样本的视觉身份**，不以样本卡有没有列全为准。报告里**必须写明是下面哪一种根因**——两种改法完全不同：
   - **(a) 误把参考图当了整批 anchor**：取证 = `_shared/BATCH_ANCHOR.txt` 的 URL、或某篇 `.gen_images_state.json` 的 `anchor_url`，指向的是**运营给的参考图**而不是我们自己确认的 P1。表现通常是**整批**都染上参考样本的配色/人物。→ 处置：参考图**永远不进 `BATCH_ANCHOR.txt`**；须先按流程做出我们自己的 P1（配色与人物用品牌资产、版式与密度模仿样本卡）、经运营确认后落盘为锚点，再用**新锚点**整批重出。
   - **(b) 把样本卡「⛔ 记录但不采用」区当成了要采用的**：取证 = 锚点链路正常（`anchor_url` 就是我们的 P1），但**个别页 / 局部**仍带参考样本的配色或人物 → 根因在提示词，有人把不采用区的描述抄进了页面提示词。→ 处置：删掉提示词里从不采用区抄来的配色 / 人物描述，按判据 2 / 3 的品牌基底改回，用**原锚点** `--anchor-url` 整页重出。
   - **两种都取不到证**（看不到锚点链路，也分不清是整批还是局部）→ **按 (a) 报**（整批污染是更坏的一种，先按坏的报），并在报告里注明取证不足、要求上游补出锚点落盘记录。

## FAIL 之后怎么改（报告里必须写明，2026-07-25 老板定案）

判 FAIL 时，issue 的处置建议**只能是「改初始提示词 + 用原锚点图整页重出」**：

```
修 post-NN.md 里该页的提示词 → gen_images.py --pages N --anchor-url <原来那个 anchor_url>
```

⛔ **绝不能建议**「把这张图作为参考图再喂回去修」「追加一句提示词让它把第 3 行改掉」这类**在错图上迭代**的做法。三条理由：

1. 一致性锚的是**那一张已确认的 P1**；把成图换作 anchor 会让整套风格基准漂掉，越修越偏。
2. 模型会继承错图里的错误特征——在错的基础上改只会**固化错误**，而不是修掉。
3. 成图带着已渲染的中文与版式，作为 anchor 会把这些「已定死的排版」当成风格基准传给后续页。

**锚点图自始至终只有一张**：第 1 步确认通过的那张 P1，整套所有页、所有次重出都用它。是否真做到了，跑确定性检查区的**批次锚点审计**命令逐篇比对即可。

**唯一例外：判据 9(a) 那种「锚点本身就是错的」**（2026-07-26 补）——参考图被当成了整批 anchor 时，照上面的 `--anchor-url <原来那个 anchor_url>` 重出只会把污染再打一遍。此时的处置是**先重建锚点**：按品牌基底 + 样本卡版式做出我们自己的 P1 → 运营确认 → 落盘 `_shared/BATCH_ANCHOR.txt` → 用**新锚点**整批重出。这不违反"只有一张锚点"——参考图**从来就不是合法锚点**（它带着别人的文字、版式与配色，当 anchor 会把对方的内容特征传染到每一页，还会盖掉品牌基底）。除这一种情况外，「改初始提示词 + 用原锚点整页重出」的纪律不变。
