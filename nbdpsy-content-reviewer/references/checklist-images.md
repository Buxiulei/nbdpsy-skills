# 配图审查清单（轮播插图，逐张看图审）

> 审查对象：一篇笔记的成品配图目录（P01..PN）。
> 立场：预设有问题，逐张找证据；不确定按 FAIL。
> **铁律：判断性条目必须逐张打开图片查看**——不许只看文件名和尺寸就下结论；未打开图片得出的结论视为审查无效。

## 开审前 · 先认这批走的是哪条拆解路线（2026-07-28 定案，**比认档案更靠前**）

```bash
grep -n "拆解路线" <note_dir>/00-overview.md
```

读到 `拆解路线：② 文本排版长图` → **这批图不是 AI 画的，是脚本把长文正文排版渲染出来的**
（`typeset_longimage.py`，1440×2400）。本清单里**关于配色 / 人物卡 / 质感 / 版式 / 图内文字提示词 /
2:3 比例 / 信息密度的判据全部不适用**——图里没有插画、没有人物、没有提示词，硬判必然整批假 FAIL。

**路线② 只审这七条**（仍须**逐张打开图片**，这条铁律不豁免）：

1. **首页**：大标题完整不折断、`全文N字｜阅读需M分钟`在位、标题没被裁在版心外
2. **切页**：没有半行文字被横切；表格没被切开；标题没有孤零零留在页底
3. **正文**：段落 3–5 行、没有整页密文；红色/强调句每页 ≤2 处
4. **引用已剥净**：图上找不到 `[[1]]`、URL、「参考文献」；**行内作者年份（`Linehan（1993）`）还在**
5. **图内 0 个 emoji**、0 处站外导流（微信/二维码/外链）
6. **页脚小红书号**是这个账号的（不确定就问，别猜）
7. **错字**：这条路线的字全部来自输入文件，**出现错字 = 源 `body.md` 就有错**，回改文件重渲染，
   不是改图

读到 `拆解路线：① 信息图轮播`、或**没有这一行**（存量批次）→ 按本清单原样判，下面全部照旧。

## 开审前 · 先认这批用的是哪一份、哪一版风格档案（2026-07-26 下午定案）

视觉调性（配色 / 文字色 / 人物卡 / 质感 / 版式）**不再是全站写死的常量，而是每个运营一份的「风格档案」**——本清单里的莫兰迪三色 + 固定人物卡只是**默认配置的那一份**。拿它去判一个自带配色的运营（例：苏澜用她自己的配色），会把达标产出整批判成 FAIL。**所以判视觉之前，先认这批用的是哪一份、哪一版档案。**

1. **读留痕行**：`<note_dir>/00-overview.md` 开头应有一行
   `风格档案：v{N}（本人档案 / 默认配置 / 内置兜底，读取于 {日期}）`。
   ⚠️ **旧写法兼容**：`管理员默认` 是 2026-07-26 之前的旧写法，等同于 `默认配置`——读到它**照常识别、按默认配置那一层处理**，**绝不判成格式错误或漏填留痕行**（存量批次全是这个写法）。
2. **按留痕行指定的那一版取回档案**（档案会改、还能回退，**拿当前最新版去判老批次必然错判**——用 v8 的配色去判 v3 时做的图，判出来的 FAIL 全是假的）：

   ```bash
   python3 ../nbdpsy-xiaohongshu-creator/scripts/style_profile.py --version {N}
   ```

   （`../nbdpsy-xiaohongshu-creator/` 指安装后与本 skill 同级的兄弟 skill 目录，口径见 SKILL.md §3；命令在本 skill 目录下执行或换算成绝对路径。）
   输出 JSON 里的 `profile.visual.*` 就是本次判**判据 2 / 3**（以及下方双重核对轴 ①）的依据：
   `palette`（配色）/ `text_color`（文字色）/ `character_card`（人物卡整句）/ `texture`（质感）/ `cover_layout`、`content_layout`（封面与内容页版式）。
   ⛔ **不要用 `--get` 代替**——那读的是"当前最新版"，正是这一步要避开的东西。

3. **三种来源怎么判**：

   | 留痕行写的来源 | 判据 2 / 3 对谁判 |
   |---|---|
   | `本人档案 v{N}` | `--version {N}` 取回那一版，按其 `profile.visual.*` 判 |
   | `默认配置 v{N}`（旧写法 `管理员默认 v{N}`，同义） | **按该批次留痕行指定的那一版默认配置判**——同上用 `--version {N}` 取回那一版（取不回来时可退到本清单内置的默认配置示例值，报告写明） |
   | `内置兜底`（创作端当时没连上档案服务） | 版本号位写的是 `v—`（**没有服务端版本号是这一层的正常形态，不是漏填、更不是 FAIL**），**按本清单内置的默认配置示例值判** |

4. **留痕行缺失 / 那一版取不回来**（存量批次，写在本规范之前；或脚本不存在、**脚本 exit 2**＝没配 `NBDPSY_XHS_API_KEY`／API 不可达（stderr 写着"没连上风格档案服务"、stdout `layer: builtin_fallback`）、**exit 1**＝该版本不存在）→
   **按本清单内置的默认配置示例值判，并在报告里写明「本批次无风格档案留痕（或该版取不回），已按内置默认值判，请上游按新规范补留痕行」——不据此单独判 FAIL**
   （与 v1.37.0「密度五字段缺失」的处置同源：判松了最多漏一次风格偏差，判严了会把达标产出整批打回，返工成本远高）。
5. ⚠️ **档案管的是视觉与语气，管不到合规**：判据 5（二维码 / 联系方式 / 外链水印 = 站外导流）与可反向识别的来访画面属**平台封号级 / 法律执业级**，**任何风格档案、任何样本卡都覆盖不了**，不因换档案而放松。
6. ⚠️ **尺寸与画布比例是出图的技术规格、不是风格**（2:3 / 3:4、最短边 ≥1024，口径见下方「尺寸判定口径」），**不随风格档案变**——别把它当成档案里的可调项。

## 确定性检查（先跑，JSON 输出与 exit code 原样记入报告）

`{SKILL_DIR}` = nbdpsy-content-reviewer 本 skill 目录；`<N>` = 该篇笔记规划的页数（对照 post-*.md 的 P 页标题数）。

**尺寸判定口径（2026-07-26 定案，对齐真实出图）**：宽高比命中 **2:3（0.6667，后端 `/api/op/consistent-images` 原生 1024×1536，主力）** 或 **3:4（0.75，运营自己用 Gemini/GPT 出的图、以及历史补边图）** 之一即合规，各容差 ±2%；最短边 ≥1024。两种比例都是合法交付，不因比例不同判 FAIL；JSON 的 `wrong_size` 会带 `ratio`（实际 w/h）与 `aspect`（命中的比例名，未命中为 null）便于取证。

**批次锚点审计（2026-07-26 定案）**：整批的一致性锚点只有一张 P1，其 URL 存在 `<note_dir>/_shared/BATCH_ANCHOR.txt`；每次出图 `gen_images.py` 会把本次实际所用锚点写进 `images/post-NN/.gen_images_state.json` 的 `anchor_url`。上表 `grep -FL` 那条命令逐篇比对两者：**对不上 = 该篇的风格基准漂了**，报告里列出对不上的篇目及其实际 `anchor_url`，该篇按 FAIL 处理（整篇的页都受影响）。理由见文末「FAIL 之后怎么改」，此处只做可审计的比对。

⚠️ **本项只适用于走路线 0（后端一致性出图）的批次**（2026-07-26 裁决 B）：宿主自出图 / 运营手工出图的批次**既无 `.gen_images_state.json` 也无锚点文件**，与下方 `.gen_images_state.json` 缺失同口径**不判 FAIL**，报告写明"非路线 0 交付，锚点无法自动审计"即可。**存量笔记（2026-07-26 新规范之前产出，那时还没有落盘锚点这一步）同样豁免**——它们多半"有 state 无锚点文件"，见下表第 2 行的分情况。先按下表定路线，再套用后面那条硬闸：

| 批次内有 `.gen_images_state.json`（上表 `find` 那条有输出） | 有 `_shared/BATCH_ANCHOR.txt` | 判定 |
|---|---|---|
| ✅ | ✅ | **路线 0**，照跑 `grep -FL` 逐篇比对 |
| ✅ | ❌ | **看这批图是不是本次新出的**：<br>· **本次出图流程内产出**（你审的就是刚跑完 `gen_images.py` 的图）→ 走了路线 0 却没存锚点 → **判不通过**（见下条），要求上游补存锚点后重跑<br>· **复审存量批次**（2026-07-26 新规范之前产出，那时还没有落盘这一步）→ **豁免**，报告写明"存量批次、新规范前产出，锚点无法审计"<br>· **拿不准是哪种 → 按豁免处理**，并在报告里问一句（宁可漏判不可误判） |
| ❌ | ❌ | **非路线 0**（手工 / 宿主 / 存量笔记）→ **豁免**，报告写明"非路线 0 交付，锚点无法自动审计" |
| ❌ | ✅ | 批次走了路线 0、但这几篇没走后端出图 → 该几篇按下方"某篇没有 `.gen_images_state.json`"条**豁免**，其余篇照常比对 |

⚠️ **路线 0 批次的 `_shared/BATCH_ANCHOR.txt` 不存在或为空 = 上游没按新规范存锚点**（2026-07-26 补，对抗验证 V2#1）：报告里写明"该批次锚点无法审计，根因是缺锚点文件"，本项**判不通过**，并要求上游补存锚点后重跑；**绝不当 PASS**。原因：缺文件时 `$ANCHOR` 是空串，`grep -FL ""` 会命中所有文件因而**零输出**——与"全部对得上"的成功输出长得一模一样，是一条永远给绿灯的伪检查，比不查更危险。所以先跑上表 `test -s` 存在性判断，通过了 `grep -FL` 的零输出才作数。

- 某篇没有 `.gen_images_state.json`：说明这篇不是走后端出图（手工路线不写 state），不判 FAIL，但报告须写明该篇锚点无法审计。
- 锚点文件**路径唯一为 `{note_dir}/_shared/BATCH_ANCHOR.txt`**（创作端 SKILL.md 的落盘步骤只写这一处），**不接受其它位置**——审查时不得因"文件可能在别处"而自我豁免，找不到就按上表定路线处理。
- **该篇挂了咨询师推介末页**（2026-07-26 补，对抗验证 V1#8）：末页是单独出的一批、锚点换成该咨询师头像直链，而 `gen_images.py` 的 `write_state()` 会用这一批的结果**覆盖同一个** `.gen_images_state.json`，于是 state 里的 `anchor_url` 是头像直链而非批次锚点——这是**末页推介的正常结果，不判 FAIL**。改为核对 P1–P(N-1) 的实际出图风格是否仍与批次锚点一致（逐张目视），并在报告里注明该篇 state 锚点被末页那批覆盖、故无法用命令自动比对。

## 有样本卡时的双重核对（2026-07-26 老板定案，下午修订：**当前用户的风格档案保留、模仿其余**）

运营给了参考图文时，创作端会在 `<note_dir>/_shared/style-card.md` 留一张**样本卡**（结构与提取口径见创作端 `references/reference-mimicry-spec.md`）。**有样本卡的批次，视觉一致性一律双轴核对，两条并行、缺一不可**：

| 核对轴 | 对谁判 | 会不会因样本卡放松 |
|---|---|---|
| ① **配色 + 人物卡** | **该批次留痕行指定的那一版风格档案**——`profile.visual.palette` / `text_color` / `character_card`（默认配置的示例取值：莫兰迪三色 #A8B5C4 / #E8D8C4 / #C9D6CE、文字色 #5A6B7B、人物卡「圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫」；**是示例不是常量**，留痕行写「本人档案」时一律按那一版的取值判） | ⛔ **不因样本卡放松**。样本卡里凡涉及配色/人物形象的条目都躺在「⚠️ 待定：是否更新进风格档案」区，**在运营拍板固化进档案之前那是待定项、不是要采用的清单**；运营拍板"更新"后档案本身变了（新版本号），本轴改按**新版档案**判——判的对象永远是"留痕行指定的那一版" |
| ② **版式 / 分区数 / 图文面积比 / 笔触质感 / 页角色分工** | **样本卡**——按 ① 段的提取结果与 ④ 段推导出的参数判；**没有样本卡则按档案的 `profile.visual.texture` / `cover_layout` / `content_layout` 判，档案没写这几项才回落 `illustration-spec.md` 默认** | ✅ 按样本卡覆盖默认口径（样本卡是批次级，压过档案） |

- ★ **末页文字量怎么对齐**（2026-07-26 补，与创作端 `illustration-spec.md` 3-b ④ 同源）：我们的末页**必带**品牌锚句「NBDpsy · 北大硕博纯线上心理咨询」与危机声明小字「心理科普，非诊断治疗 · 援助热线 12356」（两行合计约 40 字，前者是品牌资产、后者是执业级合规，**都不可被样本卡覆盖**），而参考样本没有这两行。所以样本卡 ① 的 `末页文字量` 对齐的是**这两行之外**的正文量——**绝不能拿末页总字数去比样本实测值**，那样我们的末页必然超标，是一条稳定的**假 FAIL**。
- **封面 / 末页文字量只在本清单（图审侧）判**：`checklist-note.md` 不判此项，见判据 6 / 8。
- 密度五字段的 `运营原话` 写成「按参考样本（N 张，形态 X）实测」是**合法值**，不是上游漏填。
- **样本卡试图覆盖法律/执业级或平台封号级 = 照判 FAIL 且升级 blocker**（图上的体现：二维码 / 微信号 / 外链水印、可反向识别的来访案例画面）。只有**产品判断级**（版式、密度、emoji、**正文**引号、封面结构）允许被样本卡覆盖；**图内引号不在可覆盖之列**（渲染问题，非语气问题，见上表判据 7 行）。
- **运营口头说过「照这张做」但没有 `style-card.md`** → 视为上游没落盘样本卡：报告写明「无样本卡可比对，本次版式按 illustration-spec 默认判」，判据 8 不适用，**判据 9 照常生效**（参考样本的配色/人物，只要没被固化进当前风格档案，任何时候都不许出现在成图里）。

## 判断性检查（逐张打开图片，逐条 PASS/FAIL + 证据 + 页码）

1. **图内中文与该页「页面文字」逐字一致**：对照 post-*.md 每页的"页面文字"，逐字核对图上渲染出的中文——无错字/漏字/多字/乱码/繁简混杂。AI 出图最常见翻车点就是错字，小字和专业缩写（CPTSD、ICD-11）重点盯。任何一个字不对 = 该页 FAIL，报告里写明页码 + 错在哪个字。
2. **配色与本批次风格档案一致、无突兀撞色**（2026-07-26 下午改：比对基准从写死的品牌三色改为**当前用户的风格档案**）：整套图以该批次档案 `profile.visual.palette` 的色系为主，文字色为 `profile.visual.text_color`；出现**档案色系之外**的高饱和红/亮黄/荧光色等突兀撞色，或某页明显偏离整套色调 = FAIL。
   - ⚠️ **"无突兀撞色 / 整套色调统一"这一层语义完全不变**——变的只是"对谁比"。
   - **默认配置的取值（示例，不是常量）**：主色 **#A8B5C4（雾霾蓝灰）/ #E8D8C4（暖米白）/ #C9D6CE（鼠尾草绿）**、文字色深灰蓝 **#5A6B7B**。留痕行写「默认配置」（含旧写法「管理员默认」）「内置兜底」或留痕行缺失时按这组判；**留痕行写「本人档案」时一律按那一版档案里的色值判——拿这组去判自带配色的运营，会把达标产出整批判成假 FAIL**。
3. **人物与人物卡一致且跨页同一人**：出现人物的页，形象须符合该批次档案 `profile.visual.character_card` 那一句人物卡，且 P1→PN 看起来是同一个人（发型/脸型/衣着不跳变）。
   - ⚠️ **"跨页同一人、不跳变"这一层语义完全不变**——变的只是"对谁比"。
   - **默认配置的人物卡（示例，不是常量）**：「**圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫**」。取值来源与判据 2 同规则。
   - 该版档案的 `character_card` 为空 / 明确写着"不固定人物"时：**只判"跨页同一人不跳变"，不拿默认配置那句人物卡去判形象** = 达标（拿它去判就是假 FAIL）。
4. **构图完整无截断/畸变**：主体不被边缘切掉，人物无畸变手指、多余肢体、崩坏五官；文字块不压主体、不出血到边缘外。
5. **无二维码/联系方式/外链水印**：任何页出现二维码、微信号、电话、网址水印、第三方平台 logo = 直接 FAIL（站外导流是限流封号红线）。
6. **首图（P1）单独看有封面吸引力**：⚠️ **咨询师推介笔记的封面按 `counselor-note-spec.md` §4 判**（2026-07-27）：照片主体 + 大字姓名 + **副题两行**（职称一行 + 能力/画像钩子一行 ≤14 字），**第二行钩子须与发布标题的能力短语同源**——缺第二行钩子 = FAIL（那是标题三要素在封面上的落点）；科普封面的"主标题=议题词"分工对推介不适用。其余照下述判：把 P1 当作信息流里孤立的一张图来看——大标题是否一眼可读、钩子是否成立、视觉是否干净有点击欲。P1 是内容页版式（信息密集小字）而非钩子封面 = FAIL。⚠️ **有样本卡时**（2026-07-26 补）：标题占画面高比 / 有无人物 / 主视觉类型 / **封面文字量**改按样本卡 ① 段的**封面卡**判；**末页（PN）文字量**按 ① 段的**末页卡**判，且必须**先扣除**我们必带的「NBDpsy 品牌锚句 + 12356 危机声明」两行（约 40 字）再与样本实测值比——参考样本没有这两行，不扣就是稳定的假 FAIL（详见上方 ★）。封面 / 末页文字量**只在本清单判**，`checklist-note.md` 侧不判。
7. **图内引号收敛**（2026-07-26 老板口径，创作端规则见 `references/illustration-spec.md` 第 2 节）：只有**对话气泡里的原话 / 内心独白**可以带引号——那时引号是语义的一部分；**小标题、标签、pill 文字、区块标题、结论句带引号 = 该页返工（记 FAIL）**；一页图上**成对出现的引号 >2 处 = 返工**。层级本就该靠字号 / 位置 / 颜色去分，不靠引号。⚠️ 只看**图上真的画出来的**引号；提示词里用来包裹入图文字的那对引号不在此列（那是"这几个字要渲染进图"的语法标记，删了模型就不知道哪些字入图）。⚠️ **本条不因样本卡放松**（2026-07-26 裁决）：样本卡 ④ 的 `引号口径` 只是正文侧参数，**图内引号照本条判**——理由见上方「有样本卡时怎么变」表判据 7 行。
8. **版式 / 分区数 / 图文面积比 / 笔触质感与样本卡一致**（2026-07-26 新增，**仅当 `<note_dir>/_shared/style-card.md` 存在**；无样本卡时本条不适用，改按 `illustration-spec.md` 默认判）：逐张对照样本卡 ① 段——内容页的版式类型（对比 / 流程 / 象限 / 清单…）与分区数、格内小图与说明文字的图文面积比、笔触质感（扁平矢量 / 有无描边 / 噪点纸底…）、整套编排（总页数、内容页占比、页间靠什么维持一致）。**成套跑偏**（样本卡写"左右对比双栏、每栏 3 格"，成图却是通栏清单）= FAIL，报告写明是哪几页、样本卡那一行原文怎么写的、成图实际是什么。⚠️ 本条**只判版式与质感**——配色与人物形象不在本条内，那两项永远对**该批次的风格档案**判（判据 2 / 3）。样本卡里置信度标「低」的条目（仅 1 张样本出现）**不单独判 FAIL**，只在报告里提示偏差。
9. **参考样本的配色或人物形象「未经固化」就出现在我们的成图里 = FAIL**（2026-07-26 下午定案「当前用户的风格档案保留」的直接推论，**永远生效**，不看有没有样本卡）：成图里出现样本卡「⚠️ 待定：是否更新进风格档案」区写明的配色（例：参考样本的米黄 + 砖红双主色）、参考样本的人物形象（例：短发戴眼镜男性），或参考样本的 IP 形象 / logo / 字体标识 / 水印 = **FAIL**。判据是目视认出成图带着**当前风格档案之外的、属于参考样本的视觉身份**，不以样本卡有没有列全为准。
   - ⚠️ **先看它是不是已经被固化进档案了**（2026-07-26 下午新增，**判 FAIL 之前必做**）：运营有权拍板把参考图的配色 / 人物**更新进自己的风格档案**（走 `PUT` 存一个新版本）。若留痕行指向的那一版档案里，`profile.visual.palette` / `character_card` **就是**这套配色/人物，那它已经是**合法的当前档案值**，按判据 2 / 3 判**达标，不判 FAIL**。只有**运营选了"不更新"、或还没拍板（仍躺在「⚠️ 待定」区）**时，它出现在成图里才是 FAIL。取证写明：留痕行的版本号 + 该版档案里那两个字段的实际值。

   - **(b) 把样本卡「⚠️ 待定：是否更新进风格档案」区当成了已拍板要采用的**：取证 = 锚点链路正常（`anchor_url` 就是我们的 P1）、且留痕行那一版档案里并没有这套配色/人物，但**个别页 / 局部**仍带参考样本的配色或人物 → 根因在提示词，有人把待定区的描述抄进了页面提示词。→ 处置：删掉提示词里从待定区抄来的配色 / 人物描述，按判据 2 / 3 的**当前风格档案**改回，用**原锚点** `--anchor-url` 整页重出；运营若确实想要这套配色，正确做法是先把它固化进档案（存新版本）再整批重出，而不是在单页提示词里夹带。
   - **两种都取不到证**（看不到锚点链路，也分不清是整批还是局部）→ **按 (a) 报**（整批污染是更坏的一种，先按坏的报），并在报告里注明取证不足、要求上游补出锚点落盘记录。

## FAIL 之后怎么改（报告里必须写明，2026-07-25 老板定案）

判 FAIL 时，issue 的处置建议**只能是「改初始提示词 + 用原锚点图整页重出」**：

```
修 post-NN.md 里该页的提示词 → gen_images.py --pages N --anchor-url <原来那个 anchor_url>
```

⛔ **绝不能建议**「把这张图作为参考图再喂回去修」「追加一句提示词让它把第 3 行改掉」这类**在错图上迭代**的做法。三条理由：

1. 一致性锚的是**那一张已确认的 P1**；把成图换作 anchor 会让整套风格基准漂掉，越修越偏。
2. 模型会继承错图里的错误特征——在错的基础上改只会**固化错误**，而不是修掉。
3. 成图带着已渲染的中文与版式，作为 anchor 会把这些「已定死的排版」当成风格基准传给后续页。

**锚点图自始至终只有一张**：第 1 步确认通过的那张 P1，整套所有页、所有次重出都用它。是否真做到了，跑确定性检查区的**批次锚点审计**命令逐篇比对即可。

**唯一例外：判据 9(a) 那种「锚点本身就是错的」**（2026-07-26 补）——参考图被当成了整批 anchor 时，照上面的 `--anchor-url <原来那个 anchor_url>` 重出只会把污染再打一遍。此时的处置是**先重建锚点**：按**当前风格档案**（留痕行那一版的 `profile.visual.*`）+ 样本卡版式做出我们自己的 P1 → 运营确认 → 落盘 `_shared/BATCH_ANCHOR.txt` → 用**新锚点**整批重出。这不违反"只有一张锚点"——参考图**从来就不是合法锚点**（它带着别人的文字、版式与配色，当 anchor 会把对方的内容特征传染到每一页，还会盖掉运营自己档案里的视觉设定）。除这一种情况外，「改初始提示词 + 用原锚点整页重出」的纪律不变。
