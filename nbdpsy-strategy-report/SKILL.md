# NBDpsy 月度战略报告生产线

一句「出 7 月战略报告」进来，产出一份发布在管理后台 /strategy 的自包含 HTML 战略报告 + 一份归档进
`docs/` 的 markdown 底稿。整条线六步：**定周期 → 并行采集 → KPI 复刻与复核 → 麦肯锡正文 → HTML 与发布 → 归档收尾**。

2026 年 7 月报告（slug=`strategy-202607`）是本流程的完整实例，其底稿在 NBDpsy 仓库
`docs/战略报告-2026年7月-底稿.md`——写新一期前先通读上一期底稿，结构直接沿用、数字做环比基线。

## 前置条件（先检查，缺任何一项就停下告知用户）

1. 工作区是 NBDpsy 主仓库（默认 `/home/roots/NBDpsy`），能读 `docs/` 与 git 历史；
2. `ssh nbdpsy` 可达生产库（`ssh nbdpsy "echo ok"` 验证）——生产库是唯一数据真源，本地库只是旧快照，**绝不可用本地库数字写报告**；
3. 发布需要铸 admin JWT（读生产 `.env` 的 `JWT_SECRET`）——运营账号做不到这一步。

不满足时直接说明「本 skill 需要管理员主环境」，不要降级硬跑。

## 流程总控

### 第 1 步 · 定周期与基线

- 从用户话里定报告月（「出 7 月报告」→ 窗口 `2026-07-01 00:00 +08` ~ `2026-08-01 00:00 +08`，环比基期为上一个月同窗口）。
- 查生产库 `strategy_reports` 表已有报告（避免撞 slug、了解已有版本）：
  `SELECT id, slug, title, version_label FROM strategy_reports ORDER BY id;`
- 找上一期底稿 `docs/战略报告-*-底稿.md` 通读：它是结构模板、KPI 基线（环比来源）与口径手册的载体。
- 报告类型询问或默认：战略报告（strategy，仅 admin 可见）；若用户点名「运营报告」则 operation。

### 第 2 步 · 并行采集（六路，全部只读）

读 `references/data-collection.md`——里面是六路采集任务的完整提示词模板与**口径手册**（表名/字段/
状态过滤/已知的坑）。用子代理或 Workflow 并行跑六路：

1. 预约与会话（交付量、取消爽约、循环占位、排队）
2. 财务（毛额/净收/退款/渠道/咨询师贡献/优惠券/分成/LLM 成本）
3. 增长转化（注册、线索台账、预沟通转化、埋点渠道、脱落回流）
4. 小红书双账号（台账篇数口径 + 笔记级指标 + 与上期诊断对比）
5. SEO/公众号（GSC/Bing/AI 爬虫 CSV + 博客 + 服务号）
6. 战略基线提炼（读战略文档，列出「本期报告应回答的问题」清单）

给每路代理的三条铁律必须写进提示词：**只允许 SELECT**；**不许 sleep 死等**；**查不到就如实说，绝不编数**。

### 第 3 步 · KPI 复刻、对抗复核、行动项取证（并行三路）

读 `references/kpi-definitions.md`——北极星与分层 KPI 的判据出处和复刻铁律。三路并行：

1. **KPI 复刻**：长期稳定客户五分层、新客首月 ≥3 次达标率（按队列月）、客位利用率、月留存率、
   预沟通→正式 D3 转化率。**铁律：先用同一套判据回算历史月份、与已发布基线逐格比对命中，才允许产出当月值**——
   复刻不中说明判据理解错了，此时修判据而不是解释差异。
2. **对抗复核**：把即将进报告的 15-20 个头条数字交给一个独立代理，要求它不看原查询、从表结构出发
   重写 SQL 重新推导，逐项判定 CONFIRMED / MISMATCH。有 MISMATCH 就查到根因才继续。
3. **战略行动项取证**：`git log --since=<月初> --until=<今天>` 全量过目 + `docs/` 交付文档 + 生产库实查，
   对照战略排期表逐项判定「已上线/部分/未见痕迹」，每项附 commit hash 或代码路径。

### 第 4 步 · 麦肯锡正文（主会话亲自写，不外包）

读 `references/mckinsey-style.md`——报告的写作范式与结构模板。核心要求：

- **SCQA 摘要**（现状-冲突-问题-答案，答案最重）+「一页答案」三支柱 + 关键数字卡片；
- **行动标题**：每个章节标题是完整结论句，只读标题能读完整个故事；
- **每张图配一行 so what**；行动清单表格化（动作/归属/时限/检验标准，分 P0/P1/P2）；
- **严禁过程叙述**：「复核成立/修正/翻案撤回/我先算了X后来发现Y」一类分析师工作底稿语言一个字不能进正文，
  结论直接陈述、证据跟在后面，口径折衷收进附录一句话带过。

正文写成 markdown 定稿（数字一律照抄采集结果，环比对照上一期底稿）。

### 第 5 步 · HTML 转换与发布

读 `references/publish.md`——自包含 HTML 的硬性要求、设计体系基准、发布 API 与铸 JWT 细节、
目视验证清单。要点：正文定稿交给执行代理转 HTML（设计体系沿用库内已有战略报告的 CSS），
你自己做数字抽查（grep 15+ 个关键数字）、本地 Playwright 双端目视（390 与 1440 宽、无横向溢出）、
再铸 admin JWT POST 发布，最后到生产后台注 token 目视确认。

### 第 6 步 · 归档收尾

- 底稿（markdown 定稿，去掉「给转换者」的过程注记）写入 NBDpsy 仓库
  `docs/战略报告-<年月>-底稿.md`，commit + push（下一期报告靠它做基线）；
- 检查远程部署日志确认 push 正常（docs-only 变更不会触发重建，属预期）；
- 收尾时向用户汇报：报告地址（后台 /strategy）、版本号、核心结论三句话、遗留观察项（如「X 月队列
  观察未满需月底回算」）。

## 红线（每一条都有事故背书）

1. **生产库只读**——任何一路采集/复核代理都不许写库；
2. **数字零改动**——HTML 转换与改版时数字照抄，四舍五入不得变位；
3. **口径先复刻再产出**——KPI 没在历史月份上回算命中前，当月值不可写进报告；
4. **过程叙述不入文**——推翻旧判断可以（那是业务更新），同一份报告里不许出现自我辩论痕迹；
5. **发布前双端目视**——iframe 里排版崩了，老板第一眼看到的就是事故；
6. **同 slug 覆盖发布是安全的**（upsert 保留划线批注），但 slug 打错会新建一份——发布后必查
   `strategy_reports` 表确认 id 未变、version_label 正确。
