# 插图提示词体系（PPT 式轮播 · 风格基底取自当前用户的风格档案）

> 目标：一条笔记的 6–9 张图，看起来像同一个号、同一个设计师做的。做法 = **锁住风格基底，只换主体画面与文字**。本项目用 **Gemini / GPT 出图**，二者能把中文文字渲染进图，所以提示词把"要显示在图上的中文"直接写进去。

> ⚠️ **v1.39.0 起：风格基底不是全局常量，而是「当前用户的风格档案」**。本文里出现的全部具体色值（#A8B5C4 / #E8D8C4 / #C9D6CE / #A34B3A / #2B3A4A / #5A6B7B）与那句人物卡原文（"圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫"）**都是「默认配置」的取值，是示例不是常量**——当前用户的档案不同，就按他自己档案里的对应字段写提示词。字段怎么对应见**第 1 节的字段映射表**；档案怎么读（三层降级 + `00-overview.md` 留痕行）见 `SKILL.md` 开工前那一步「先读风格档案」。
>
> ⚠️ **画布 2:3（1024×1536）与那行负面提示不随档案变**：它是出图后端 `/api/op/consistent-images` 的**技术规格，不是风格**。风格档案管的是配色 / 文字色 / 人物 / 质感 / 版式，**管不到画布**——任何档案、任何样本卡都改不了这一行。

> ⚠️ **本批若存在 `_shared/style-card.md`**（运营给了参考图文、要"照着做"）：写提示词前先读 **第 3-b 节「有样本卡时怎么写提示词」**——版式 / 分区数 / 图文比 / 笔触质感**照样本卡**，而**配色与人物卡照当前用户的风格档案、2:3 画布照本文（技术规格）**（2026-07-26 v1.38.0 定案，v1.39.0 把"品牌基底"改述为"当前用户的风格档案"）。没有这个文件则整节跳过，本文默认口径照常走。

## 1. 风格基底 · 取自当前用户的风格档案（每页提示词都以它开头）

> **v1.39.0 起，风格基底不是写死在本文里的全局常量，而是「当前批次所用那一套 + 那一版风格档案」里的字段。**
> 开工前按 `SKILL.md` 那一步「先读风格档案」跑 `python3 {SKILL_DIR}/scripts/style_profile.py --get --kind carousel` 读档案，并把
> `风格档案：{套名} v{N}（本人档案 / 默认配置 / 内置兜底，读取于 {日期}）` 这一行写进 `00-overview.md`
> （`--get` 输出的 `trace_line` 就是填好的这一行、套名已带好，直接抄，别自己拼）；
> ⛔ **别用裸 `--get`**——多套时它给的是**运营默认那一套**，可能是文字版，`visual` 段根本不存在，
> 本文下面全部 `profile.visual.*` 会一起取空。本文管的是图文轮播这条路线，**一律 `--kind carousel`**；
> 运营点名了用他哪一套图文风格（「用我那套水墨风」）→ 改用 `--get --profile <套名>`。
> **写提示词前先回读那一行**，用它指定的那一版档案的字段值，别凭记忆用默认值（档案会改、还能回退，
> 拿新版的配色去做老批次的图，审查端按留痕行那一版判，必判不一致）。
> API 不可达 / 没配 key 时走**内置兜底 = 本节下面这套默认配置取值**，但**必须显式告诉运营**
> 「没连上风格档案服务，本次用 skill 内置的默认风格（默认配置）继续；等下次连上再核对」——**不许静默降级**。

**字段映射表（档案字段 → 提示词里的哪一处）**：

| 档案字段 | 落到提示词的哪一处 | 本文里的**默认配置示例值**（不是常量） |
|---|---|---|
| `profile.visual.palette` | 每条提示词的**配色行**，以及"仅用品牌调色板 / 仅用品牌基底配色"这句话所指的那套色 | 雾霾蓝灰 #A8B5C4（主色）/ 暖米白 #E8D8C4（背景）/ 鼠尾草绿 #C9D6CE（辅助）/ 赭砖红 #A34B3A（可选强调） |
| `profile.visual.text_color` | **文字色**：大标题、正文说明、强调字的颜色 | 深灰蓝 #5A6B7B（正文与默认标题）、深钢蓝黑 #2B3A4A（可选加粗标题）、赭砖红 #A34B3A（可选点睛） |
| `profile.visual.character_card` | **人物卡整句**：出现人物时逐字照抄这一句，保证全套是"同一个人" | "圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫，神情温和平静。" |
| `profile.visual.texture` | **质感描述**：画风、肌理、光影那一段 | 柔和扁平矢量插画风、细腻颗粒 / 纸质肌理、柔光无强烈阴影、圆润柔和形体 |
| `profile.visual.cover_layout` | **封面页 / 末页版式**：第 3 节三层组件模板的**文字层 + 元素层**怎么排 | 标题压上 1/3、主体居中或偏下、治愈系小道具环绕 |
| `profile.visual.content_layout` | **内容页版式**：第 3 节版式菜单里默认偏好哪一类排布 | 满版铺陈、分 2–3 区块、图文双通道 |
| ⛔ **画布 2:3（1024×1536）+ 那行负面提示** | **不归档案管** —— 出图后端的技术规格 | 恒为 2:3，任何档案、任何样本卡都改不了 |

- **字段缺了就回落，别空着**：当前档案只写了 `palette` 没写 `texture`，那一项就照本节的默认配置示例值做。
- **取值形态以 `--get` 读到的为准**：本表只定"哪个字段管哪一处"，不规定它长什么样（是一串 HEX 还是一句描述）——`profile` 由 server 原样存取、不校验语义。
- **档案管的是视觉与语气，不是合规**：末页品牌锚句 / 危机声明、图内不得站外导流、简体硬要求、崩字防治，任何档案都覆盖不了（见 3-b ④）。

一套笔记里有两类页面，**共用同一套调色板与人物卡**，只是构图密度不同：

- **情绪页**（封面 P1 / 末页 PN / 隐喻页）：柔和治愈单主体，留白勾人。
- **信息海报页**（中间的内容页）：满版高密度，核心是**图文双通道**——每条信息配一个能解码的具体场景小图/简笔小人（见第 3 节「内容页核心：图文双通道」）。

**调色板（取自 `profile.visual.palette` + `profile.visual.text_color`）**——下表 HEX 是**默认配置的示例值、不是常量**，当前用户档案不同就整表替换：

| 用途 | 颜色 | HEX |
|------|------|-----|
| 主色调（画面/图标基调） | 雾霾蓝灰 | #A8B5C4 |
| 背景 / 暖调（纸质） | 暖米白 | #E8D8C4 |
| 辅助色 | 鼠尾草绿 | #C9D6CE |
| 强调 / 高亮（**可选**：标题关键词、结论红字点睛） | 赭砖红 | #A34B3A |
| 标题主字（默认用下方深灰蓝；想加粗更醒目可选此深色） | 深钢蓝黑 | #2B3A4A |
| 正文 / 说明 | 深灰蓝 | #5A6B7B |

> **情绪页基底**（封面/末页/隐喻页用；配色照 `palette`、质感照 `texture`、构图照 `cover_layout`，下面这句是**默认配置的示例写法**）：柔和扁平矢量插画风（soft flat illustration），莫兰迪低饱和配色——以雾霾蓝灰 #A8B5C4、暖米白 #E8D8C4、鼠尾草绿 #C9D6CE 为主，背景暖白；圆润柔和的形体，细腻颗粒/纸质肌理，柔光、无强烈阴影，整体平静治愈；竖版 2:3 构图（1024×1536），主体居中或偏下，**顶部留约 1/3 空白放标题**。信息海报页的构图另见第 3 节「内容页核心」（满版、图文双通道、不留大空白）。
> ⚠️ 这句里唯独 **「竖版 2:3 构图（1024×1536）」不随档案变**——技术规格，照写。

**人物卡（取自 `profile.visual.character_card`；出现人物时统一这一个形象，保证全套是"同一个人"）**：

> 圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫，神情温和平静。
>
> ⚠️ 上面这一句是**默认配置的示例值**，不是全局常量。当前用户档案里的 `character_card` 是什么，就逐字写什么。
>
> ⚠️ **本文其余各处写的「固定人物卡」= 当前档案的 `character_card`**（"固定"指的是**同一批次内跨页固定**，不是跨用户固定）——版式模板与白名单里那个词一律这么读，不必逐条改写。

> 风格基底与人物卡是**当前用户的风格档案资产**：同一个运营的所有笔记复用他自己那一套（跨页不漂移），不同运营之间**可以完全不同**。要换风格**不是改这份文档**，而是更新他的档案——先 `--get` 拿全量、改完**整份 PUT**（必须带读到的 `base_version`）；收到 409 别重试同一份 body，按 `detail.current_version` 重新 `--get` 再改。

## 1-b. R4「图要把事讲清楚」结构规范（2026-08-14 老板定案 · **先于一切数量约束**）

> **为什么单立一节、还放在密度五字段前面**：老板原话——「信息图我还有一点不满，我感觉没有真的通过图文的形式，把事情讲清楚。我看的都是云里雾里的」。病根不是排版，是**现行密度五字段（第 2 节）全是数量约束**——每页几个字、几个信息点、哪一档版式，**没有任何一条管「这些点连不连得成一条线」**。生产者在纯数量约束下的最优解就是**往版式模板里填满 N 个点**：版式从「表达论点的手段」退化成「填页的容器」，点越满越云里雾里。所以本节各条都是**结构约束**，第 2 节的密度五字段**降级为「论点行定了之后的填充上限」**，不再是驱动性指标。
> 这条与封面 hero 的「说『啊？』还是说『哦』」判据（§2-b）同构：都是逼生产者**先回答「你到底想说什么」**，再谈怎么排。
>
> 📌 **2026-08-16 补三条（⑥⑦⑧）**：老板令三条写作方法论必须**被执行**、不是**被写下**——「不要是死链，永远闲置不被调用」。
> 验收口径是**「如果下一个执行者完全不看这段规格，他会不会被拦住？」**——所以三条全部挂进同一个 `validate_structure()`，
> 而**不是**再加三段"参考资料"。①「术语只能定义或删除」②「不要从卖方/知识体系视角写」③「下笔前先钉死读者是谁」
> 分别落成 **⑦ / ⑧ / ⑥** 三道闸。

**本节共八小节（① 至 ⑧），其中五条是代码闸门，⛔ 不是建议**——写在 `scripts/gen_images.py::validate_structure()`，出图前跑，任一不过即**拒跑**（不出图、不烧额度）：

| 小节 | 内容 | 形态 | 凭证里的 `gates` 键 |
|---|---|---|---|
| **①** 论点行先行 | 每页块首行 `**论点行**：…` | 🔒 **代码闸门**（只查有没有） | —（不进 gates） |
| **②** 图内自足 | 论点行落在图面上、每块都为它服务 | 人工判据 | — |
| **③** 整组一条故事线 | frontmatter `故事线` | 🔒 **代码闸门**（只查有没有） | —（不进 gates） |
| **④** 三元组必填 | 观点 / 证据（机制）/ 落点 | 人工判据 | — |
| **⑤** 适用范围与闸门形态 | 三种页型各判什么 | — | — |
| **⑥** **读者三段式** | frontmatter `读者`（2026-08-16 立） | 🔒 **代码闸门** | `reader` |
| **⑦** **术语只能定义或删除** | 页面文字里的术语首现处必须有人话定义（2026-08-16 立） | 🔒 **代码闸门**（逃生口 `--skip-term-gate`） | `term` |
| **⑧** **论点行禁卖方视角** | 主语必须是读者或他身上的事（2026-08-16 立） | 🔒 **代码闸门** | `seller_view` |

⛔ **别拿「脚本没报错」当这八条都过了**：代码闸门挡的是**有没有 / 是不是明显不合格**，挡不住**够不够**（②④ 的成色、①⑥⑧ 是不是充数）——那些仍由出图步人工核 + 审查端复核双人执行（判据见 ⑤ 末尾与 `checklist-note.md` 判据 6-R4 的 ⑤⑥⑦）。**⑥⑦⑧ 各自漏掉的那一半在下面各节的「代码查不到的那一半」里逐条点了名。**

**填写顺序（顺序本身就是规范，⛔ 不许颠倒；这一串就是代码报错末行原样打出来的那句）**：

```
①读者 → ②故事线 → ③逐页论点行 → ④版式序列 → ⑤按版式填点
```

⚠️ **这五个步号与上表的小节号 ①–⑧ 不是一回事**（小节号是这份文档的编号，步号是动笔顺序）——⛔ 别把「第 3 步逐页论点行」读成「小节 ③故事线」。
⚠️ **读者排在第 1 步不是排版好看**：收到写作请求**不许立刻动笔**，先答「谁会看到这篇（身份/阶段）／他最痛的是什么／他最容易误解、忽略或焦虑的是什么」。读者没钉死就先写故事线，写出来的必然是**我们想讲的顺序**，不是**他想知道的顺序**——这正是 ⑧ 那条卖方视角在结构层的源头。
⚠️ **⑦ 术语闸与 ⑧ 视角闸是横切的**：不属于顺序里的某一步，而是**这五步里写下的每一行字**都要过——术语一出现就得当场落地，论点行一写下就得是读者的处境。

⚠️ **版式序列（第 4 步）必须在逐页论点行（第 3 步）之后才填**：现行 frontmatter 的 `版式序列`（`P2 ⑩自查清单 / P3 ⑧因果链 / …`）是**先于内容预排**的——先挑好框再找话填，正是上面那条病根在 frontmatter 层的形态。R4 之后，**版式是论点行选出来的**（这页的论点是"两件事怎么不一样"→②对比表；是"一步一步该怎么做"→③流程图），不是先定了框再找点。选版式的映射表见第 3 节「选型第一问」。

### ① 论点行先行（写不出 = 这页不该存在）

每张图动笔前，先写一行「**这张图要让读者带走的那句话**」。写不出来的页**直接毙掉**，⛔ 不许"先占个位后面再想"、也不许拿页标题充数。

- **落点**：`post-NN.md`「## 配图轮播」里每个 `### PN` 块的**第一行**，格式 `**论点行**：…`——写在绘图提示词围栏**之外**、页标题正下方（围栏内是喂模型的提示词，`gen_images.py` 只取页内第一个围栏，论点行放围栏外不影响出图）。
- 论点行是**一句能独立成立的话**（有主语有谓语有主张），不是标题、不是话题词、不是版式名。
- **审查端逐页核对「图面有没有兑现这句论点行」**——图上读不出这句话的意思 = FAIL。
- 🔴 **P1 封面这一页：论点行 ＝ 文案步的金句，同一句话的两个名字**（2026-08-17 合流，⛔ 别为了填闸门另写一句应付）。
  两套系统要的本来就是同一个东西：本条要「读者带走的那句话」，文案步判据甲要「自己就是一段完整的话」——**金句是论点行的更强形态**（多了张力与可转发）。
  - ⚠️ **反过来不成立**：内容页的论点行**不必是金句**，那是 P1 专属的更高一档，⛔ 别拿金句标准去要求内页；
  - ⚠️ **排版步改了金句，P1 论点行必须跟着回写**——`gates.seller_view` 扫的是**论点行 + P1 页面文字**两处，只改一处＝闸门扫的是旧字；
  - 📌 **旧写法作废留痕**：`example-xhs-note.md` 原写「**封面的论点行＝hero**」——**hero 现在是排版步从金句里截的片段**，比论点行短、常常不成句，⛔ 不能再拿它当论点行。已改为「论点行＝金句、hero＝金句的片段」。

| 判 | 例句（题材取自已发的过度换气 H1 批次；⛔ 三条是同题材构造的对照） |
|---|---|
| ⛔ 话题词充数 | 「过度换气是怎么回事」——这是**页标题**，读者带不走任何东西 |
| ⛔ 版式名充数 | 「这页用因果链讲成因」——描述的是我们怎么排版，不是读者读到什么 |
| ⛔ 半句话 | 「二氧化碳」——名词不是论点，没有谓语就没有主张 |
| ⭕ | 「越深呼吸越晕：你不是缺氧，是二氧化碳被吐太多了」 |
| ⭕ | 「连纸袋都被急救指南划掉了——别再教人捂纸袋」 |

### ② 图内自足（单独看这一张，也知道它在说什么）

判据两条，都能一眼验：

1. **论点行出现在图面上**——落在**标题位或结论位**，在提示词里用「逐字写出这行字：…」写死（措辞可精简，意思不许打折）；
2. **图上每个信息块都在为这句话服务**——随便挑一个块问「它是这句话的什么」，答不上「观点 / 证据 / 落点」三者之一 = 这块是装饰，删掉或改掉。

⛔ 反例就在本文第 5 节那条低密度原稿：「抑郁症＝一场雨」一朵雨云 +「成组出现／至少两周／有周期」三个抽象标签——脱离正文，读者从这一页拿不走一句完整的话。

### ③ 整组是一条故事线（每页论点行串起来读得通）

- **落点（唯一真源）**：**每篇 post 的 frontmatter 字段 `故事线`，与 `版式序列` 并排**——一句话写清这一篇 6–9 页在论证什么（现象→机制→纠错→怎么办 这类推进）。
  **一篇一条，半角冒号**（`故事线: …`，与 frontmatter 其余字段同）。
  📌 **2026-08-14 口径裁决**：本行原写「`00-overview.md` **与**每篇 post 的 frontmatter」都写——**含糊已删**。
  两处写就会漂（改了一处忘另一处，审查端不知道该信哪个），且自检期望值也说不清是 1 还是 N。
  **现行：只写进每篇 post，自检期望数 = 篇数**（`grep -l '^故事线: ' post-*.md | wc -l`）。
  `00-overview.md` 想写一句整批总述**不禁止**，但它是给人读的说明、**不是判据落点**。
- **自检（可证伪）**：把 P2…P(N-1) 的论点行**按页序抄成一段话**读一遍——读出来是一段通顺的论证 = 过；读出来是几条互不相干的知识点 = 这篇没有故事线，回去重排页序或重选内容。
- 审查端新增此项（与逐页论点行核对并列）。

frontmatter 写法（**三行并排**，示例取材 H1 过度换气批次的实际内容）：

```yaml
读者: 身份阶段（刚在地铁上手麻头晕过一次、还没去过医院的人）｜痛点（当时以为自己要死了，事后不敢一个人坐地铁）｜最容易误解或焦虑的点（以为是缺氧，下次还会更用力地深呼吸）   # ⚠️ 这一行最先写，格式见 ⑥（分隔符是 ｜）
故事线: 现象（那十分钟身体在干什么）→ 机制（不是缺氧，是 CO₂ 被吐太低）→ 纠错（深呼吸、纸袋都是帮倒忙）→ 怎么办（呼气比吸气长 + 五种情况必须去医院）
版式序列: P2 ⑬身体地图 / P3 ⑧因果链 / P4 ⑭误区纠错卡 / P5 ③流程步骤图   # ⚠️ 论点行写完之后才填
```

📌 **`读者` 第三段「最容易误解或焦虑的点」直接决定 `故事线` 从哪拐弯**：上例的误解是"以为缺氧、会更用力深呼吸"，故事线才有"纠错"那一段——⛔ 读者没钉死就写故事线，写出来的是我们想讲的顺序，不是他想知道的顺序。

### ④ 每页三元组「观点 / 证据（机制）/ 落点」必填

**老板口径 B（2026-08-14 定案）**：「每一篇小红书都是一个小的文章，**每页表达的信息稿都应该 400 字左右**」——即**每页 = 对标一篇 400 字小文里的一小节**：有观点、有把观点撑住的证据或机制、有读者能带走的落点。**图内落字 150–250 汉字**（400 字是内容分量的尺子，不是图上要写 400 字；压缩的是措辞，⛔ 不是砍掉证据或落点）。

- **落点**：论点行下面一行写 `**三元组**：观点=… ／ 证据（机制）=… ／ 落点=…`，三样都必须能在图上找到落地物（证据/机制那一样要落成**能解码的具体画面、对照、日历、曲线或数字**，不是又一个抽象标签）。
- **数字达标也可能返工**：三元组填不出、或图上只有观点没有机制，字数再够也是 FAIL。
- ⛔ **实证（这条规范就是被它逼出来的）**：2026-08-14 五篇实测**每页只有 66–73 字**，按"配图"思维做成了「标题 + 几条短条」，比规范薄 5 倍——数量指标写着 200–400 字，照样交出这种页，因为**没有一条规矩要求这页得讲清一件事**。

**三元组示例**（按已发 H1 · P2「那一刻身体里发生了什么」的实际内容补写这两行）：

```
**论点行**：越深呼吸越晕：你不是缺氧，是二氧化碳被吐太多了
**三元组**：观点=手麻头晕不是缺氧 ／ 证据（机制）=呼吸过快→血里 CO₂ 掉低→脑血管收缩→手麻、头晕→更慌→吸得更快（画成闭环箭头图，每环一个具体小画面）／ 落点=所以「再多吸两口」是帮倒忙，要让呼气比吸气长
```

### ⑤ 适用范围与闸门形态（结构性，不是提醒）

**适用范围**（与「密度档位只约束内容页」那条口径对齐，别互相打架）：

| 页 | 论点行 | 三元组 + 图内 150–250 字 |
|---|---|---|
| **P1 封面** | **必填**——封面的论点行**就是 hero**，判据走 §2-b 的选句判据 +「**hero 四判据**」（张力/事实边界/自明性/信息量下限），本节不重复判 | **不适用**（封面走 §2-a 自己那一档：12–45 字、下限＝**三层信息齐**，⛔ 不是"没有下限"） |
| **内容页 P2…P(N-1)** | **必填** | **必填**（下限＝ <150 字且三元组填不出即 FAIL，见 §2-a） |
| **PN 末页** | **必填**（一句话写清"看完该带走什么/下一步"） | **不适用**（末页走 §2-a 自己那一档：40–90 字、下限＝**行动建议 + 品牌锚句 + 危机声明三件齐**） |

- **frontmatter 的 `读者`、`故事线` 与每页的「论点行」都是必填**，缺一即**不许开始出图**；
- ✅ **脚本层强制已上线（2026-08-14 起 `gen_images.py::validate_structure`，2026-08-16 并入 ⑥⑦⑧）**：frontmatter 缺 `故事线` / 缺合格的 `读者` 三段式、任一 `### PN` 页缺论点行、页面文字里术语悬空、论点行或封面文字是卖方腔 → **拒跑**（⛔ 不出图、不烧额度），报错逐条点名缺的是哪几页、哪个词、哪一行。**半角/全角冒号都认**，但模板一律写半角（frontmatter 要是合法 YAML）。
- ⚠️ **闸门只挡"有没有 / 明不明显"，挡不住"够不够"**：**三元组填没填、论点行是不是话题词/版式名/半句话充数、整组连读通不通、读者三段式是不是"换篇也成立"、「六个成分」这类自造结构名词、「自我关怀的六个成分不是齐步走的」这类知识体系视角**——脚本一概不判，仍由**出图步逐页人工核 + 审查端复核**（`checklist-note.md` 判据 6-R4 / `checklist-images.md` 判据 10）双人执行。⛔ **不许拿「脚本没报错」当这几项通过。**

### ⑥ 读者三段式必填（🔒 代码闸门 · 下笔前先钉死读者是谁）

> **老板原话（2026-08-16 定案）**：收到写作请求**不许立刻动笔**，先答——**谁会看到这篇（身份／阶段／痛点）？他们最容易误解、忽略或焦虑的点是什么？**
> **为什么写成闸门而不是提醒**：读者没钉死时，人写出来的是**我们想讲的顺序**（先讲概念、再讲分类、最后给方法），而不是**他想知道的顺序**（我现在这样是怎么回事 → 我是不是搞错了什么 → 我今天能做什么）。⑧ 那条卖方视角的病灶，八成在这一步就已经种下了。

**落点**：每篇 post 的 frontmatter，**在 `故事线` 之前**（顺序即规范），一篇一条：

```yaml
读者: 身份阶段（…）｜痛点（…）｜最容易误解或焦虑的点（…）
```

**格式硬要求（代码 `check_reader()` 逐条查，⛔ 以代码为准）**：

| 项 | 规则 |
|---|---|
| **分隔符** | 全角 `｜`（半角 `|` 也认）。⛔ **不是** `／`、不是逗号、不是换行 |
| **段数** | **恰好三段**（切出 2 段或 4 段都拒跑，报错会把现有值原样贴回来） |
| **每段的"答案"** | 括号里的内容；**没写括号**时＝去掉 `身份阶段`/`痛点`/`最容易误解或焦虑的点` 这些标签前缀后剩下的字 |
| **答案长度** | **每段答案 ≥6 个字**（去空白后数）。⚠️ **标签本身不算答案**——`身份阶段（他）` 整段 6 字、答案只有 1 字，判不过 |
| **空泛值** | **只判第 1 段（身份阶段），且只在答案 ≤14 字时判**（见下面「为什么只判第一段」） |
| **行尾注释** | frontmatter 行尾的 `   # …` 会被剥掉，可以照常挂注释 |

**⚠️ 为什么空泛值只判第 1 段、只判短答案（这两条误伤控制是被真实句子逼出来的，⛔ 别以为闸门漏判了）**：

1. **只判第 1 段**——「所有人都在评价我」放在 `痛点` 或 `焦虑点` 里是**读者的真实原话**，拦它就是拦对的东西；
2. **只判短答案**——黄金范例首版写「刚被上级随口批评、还没跟**任何人**说起这事的 28 岁职场女性」被误拦过，而这恰恰是全仓最具体的一个读者定义。**空泛词出现在一句长描述里面是正常中文**，只有当它**本身就是那个答案**（短到只剩这个词）时才叫"没定义读者"。

**空泛值词表在代码里**（`_READER_VAGUE`，唯一真源；这里只举例、⛔ 不抄全表——两处抄必漂）：所有人 / 任何人 / 每个人 / 人人 / 大众 / 公众 / 普通人 / 广大网友 / 对心理感兴趣 / 心理爱好者 / 关注心理健康的人 / 所有读者 / 泛人群 / 通用人群 / 男女老少 / 不限。

**主判据（人判，⛔ 代码判不出来）**：**把这三段原样抄到另一个选题上还成立 → 空泛 → 重写。**

| 判 | 例 |
|---|---|
| ⛔ 词表级空泛（**代码能拦**） | `读者: 身份阶段（所有人）｜痛点（压力大）｜最容易误解或焦虑的点（不了解）` |
| ⛔ **换篇也成立**（**代码拦不住，必须人判**） | `读者: 身份阶段（关注心理健康的年轻人）｜痛点（最近压力比较大）｜最容易误解或焦虑的点（对心理咨询有误解）` —— 每段都超 6 字、身份那段 10 字未触发短答案判，但抄到"职场倦怠""留学生适应"任何一篇上都照样成立 |
| ⛔ **我方视角**（**代码拦不住**） | `读者: 身份阶段（潜在来访者）｜痛点（需要专业帮助）｜最容易误解或焦虑的点（不知道我们能提供什么）` —— 写的是转化漏斗上的一个位置，不是他眼里的自己 |
| ⭕ | `读者: 身份阶段（刚被上级随口批评、还没跟任何人说起这事的 28 岁职场女性）｜痛点（一句话就在工位上僵住、事后反复回放，骂自己玻璃心）｜最容易误解或焦虑的点（以为这是性格缺陷、怕被说矫情所以更晚开口）` |

（⭕ 那条就是黄金范例 `assets/example-xhs-note.md` 的现行值，可直接对照结构、⛔ 别照抄内容。）

**与 frontmatter 既有 `scene_5q` 的分工（⛔ 别互抄一遍）**：`scene_5q` 是工序①-4 的产物，五问全在描述**场景本身**，写给我们排篇目用；`读者` 答的是**这一篇写给谁看、他会怎么读错**。前两段可以从 `scene_5q` 提炼（压成一句他会说出口的话，别粘一大段）；**第三段「最容易误解或焦虑的点」`scene_5q` 里没有、必须新答**——它是三段里唯一决定「故事线从哪拐弯」的那一项，也是最容易被糊弄成"对心理咨询有误解"的那一项。

### ⑦ 术语只能定义或删除，不许悬空（🔒 代码闸门，有逃生口 `--skip-term-gate`）

> **判断句（老板原话，逐字记死）**：**「删掉这句，读者会少一个事实还是少一个论据？都不是，那它就是废话。」**

**代码判据（`find_undefined_terms()` + `_defined_at()`，⛔ 以代码为准）**：

- **扫哪儿**：每页的 **`**页面文字**` 块**——也就是**要画进图、读者真会看到的那几行**。
  ⛔ **不扫绘图提示词围栏**（那是喂模型的）、⛔ **不扫 `>` 引用块**（那是写给人看的判断与理由）、⛔ **不扫发布文案**。
- **判谁**：术语表 `DOMAIN_TERMS` 里的词，**只判它首次出现的那一页**；后面几页照常用、不再拦。
- **定义窗口 60 字**，四种句式任一算数：术语后**紧跟** `（…）`（括号内 ≥4 字）／**紧跟** `：…`（冒号后 ≥4 字）／窗口内出现 **「就是 / 指的是 / 说白了 / 也就是 / 换句话说 / 意思是」**。
  ⚠️ 窗口只有 60 字**是故意的**——不许"这一页某处有个冒号"就算定义过了，那样闸门恒真＝等于没有。
- **豁免**：`《…》` 文献名内、以及含「数据来源 / 参考文献 / 文献 / 出处 / 数据口径」的行——那是引用，不是拿黑话砸读者。

**术语表在代码里**（`DOMAIN_TERMS`，唯一真源；这里只举例）：解离 / 内感受 / 述情障碍 / 认知重构 / 暴露疗法 / 心理弹性 / 共情疲劳 / 边缘型 / 双相 / 躯体化 / 闪回 / 过度警觉 / 依恋回避 / 情绪粒度 / 元认知 / 接纳承诺 / 图式 / 投射性认同。
⚠️ **表是窄的、也必须窄**：⛔ 别把「情绪」「焦虑」「压力」这类读者自己天天说的词加进去——那不是术语，加进去闸门就开始误伤，而**恒报红的闸门等于没报**。要增补，每加一个词都得先过一遍「读者不查就不懂吗」。

**没过怎么办 —— 两条出路，⛔ 没有第三条**（"读者应该能猜到"不是出路）：

1. **在同页加一句人话定义**——术语后紧跟 `（…）` 或 `：…`，或用「就是 / 指的是 / 说白了 / 换句话说」讲开。
   ⛔ **不许用另一个术语解释这个术语**（「过度认同就是自我关怀的反面」＝把一个悬空的词换成另一个悬空的词）。⚠️ 这一条**代码查不出来**，靠审查端。
   - ⭕ 「闪回（那个画面毫无预警地重播）」——黄金范例 P3 的实际改法。
2. **换成读者自己会说的词 / 整句删掉**——他不会说「解离」，他会说「像是从自己身体里飘出去了」。删不删用上面那句判断句裁：删掉之后读者**既不少一个事实、也不少一个论据** → 它本来就是废话。

**🔴 代码查不到的那一半（⛔ 别以为闸门绿了就没问题）**：

- **自造结构名词**——「**六个成分**」「三个维度」「四种模式」。**四个字全是常用字、字面难度为零，读者照样接不住**，因为它指的是一套他没见过的分类体系。**这正是老板点名的那一类**（「自我关怀的六个成分不是齐步走的」），而它**不在 `DOMAIN_TERMS` 里、代码放行**——只能靠审查端 `checklist-note.md` 判据 6-R4⑥ 人工判。
- ⛔ **别把这条理解成"通用可读性扫描"**：中文没有可靠的"说人话"量具——唯一在维护的那个测的是**字面难度**（甲乙丙丁词表），「六个成分」在它眼里满分。**问题在语义脱离处境，不在字面难度。** 所以本闸只做**窄而准**的流程闸，剩下的必须人判。

**逃生口 `--skip-term-gate`**（默认关闭）：确有正当理由（该术语就是本篇标题要科普的对象、整页在展开定义）时可跳过。跳过后凭证里记 `term_gate_skipped: true` + 一句**固定文案**的 `term_gate_skip_reason`。
🔴 **注意：凭证里那句 reason 是代码写死的固定文案，不是你填的理由**——**所以理由必须由你写在交付说明里**（哪个词、为什么这篇不需要就地定义）。凭证只能证明"跳过了"，证明不了"跳得有道理"。⛔ **静默使用 = 绕过闸门 = 不合格**（红线速记第 15 条）。

### ⑧ 论点行禁卖方视角（🔒 代码闸门）

> **老板原话**：**「用户不关心你提供什么，用户关心我的问题有没有被看见。」**

**代码判据（`find_seller_voice()`，⛔ 以代码为准）**：

- **扫哪儿**：**每页的论点行** ＋ **P1 封面的 `**页面文字**` 块**（hero 所在处）。
- **拦什么**：卖方腔词表 `_SELLER_PHRASES`（唯一真源在代码，举例）：我们提供 / 我们的服务 / 我们的课程 / 我们的方法 / 我们的咨询师 / 我们专注于 / 我们致力于 / 本文将介绍 / 本篇将介绍 / 本篇带你 / 本文带你 / 这篇带你 / 带你了解。
- **带守卫的两个词** `_SELLER_GUARDED`：「教你」「让你学会」——**前 8 字里有否定词**（没 / 谁 / 未 / 无人 / 从来 / 不曾）时**放行**，因为「没人教你怎么拒绝」是**读者的处境**，不是卖方腔。

**人判的主判据**：**这句话的主语是谁？** 必须是**读者、或读者身上正在发生的事**。三类主语都不合格：

| 主语 | ⛔ 例 | 代码拦不拦 |
|---|---|---|

### 2-1. 确定了「要有字」之后，怎么把字写进提示词

- **把要显示的中文用引号写进提示词**，并指定位置与层级（大标题 / 小标题 / 说明）。例：`在图片上方留白处写中文大标题"别再说自己想太多"`。
- **提示词里的引号是"语法标记"，不是要画上去的字符**：`写中文大标题"别再说自己想太多"` 里的那对引号只是**告诉模型哪几个字要渲染进图**，图上不应该出现引号本身。若成图把引号也画了出来，在该页提示词补一句负面提示「图中不出现引号等标点符号（气泡原话除外）」。
- **图内引号要收敛**（2026-07-26 老板口径：双引号用得太多）：只有**真的是某个人说出口 / 心里那句原话**时才保留引号（对话气泡、内心独白），此时引号是语义的一部分；**小标题、标签、说明句、pill 文字、区块标题、结论句一律不加引号**，层级靠字号 / 位置 / 颜色去分。一页图上成对出现的引号**不超过 2 处**为宜。⚠️ 这条只管"页面文字内容本身带不带引号"，**绝不动提示词里用来包裹入图文字的那对引号**——删了模型就不知道哪些字要入图。
- **信息密度 = 图文共同表达的信息量，不是字数**：封面页(P1)、末页(PN)保持精简（大标题 + 一句副标题即可，**封面主/副标题的分工见第 3 节「封面页 / 末页 —— 三层组件模板」的文字层**：主标题 = 核心议题词、副标题 = 场景钩子）；**中间的内容页要让"图+文一起读"就获取一个完整认知**——每个视觉元素都承载具体信息（叙事不装饰）、抽象点落成具体场景、按档位取值的信息点有结构地铺满（详见第 3 节「内容页核心」①）。

  - **要点卡（信息卡）**：并列 3–6 个平行要点时用（大标题 + 4–6 条「加粗小标题≤10字 + 一行说明≤28字」）。
  - **信息图（图文一体，密度更高、更有干货感）**：当内容有"结构关系"时，别硬塞成要点列表，改用信息图把关系画出来——**对比图**（X vs Y）、**流程/步骤图**（自救 N 步、成因链）、**象限/坐标图**（两维度分类，如依恋四象限）、**隐喻图**（抽象概念可视化，如"冰山下的情绪"）、**数据图**（占比/统计，如"约 6.8%"用圆环或人形阵列）、**拆解/结构图**（一个概念的几根支柱）。信息图靠"图形承载结构 + 短标注承载信息"，同样的干货比纯文字列表更好懂、更耐看。
- **整页信息多、但每个文字块仍短**：无论要点卡还是信息图，每个文字块（标题/标注/说明）都短、各自独立——这样 Gemini/GPT 渲染中文更准，读者也更好扫。**信息图的文字风险更高**（标注点位多）：**"≤6 字"仅指点位式短标注（如隐喻图/象限轴标）**；对比句、类型名、数据说明等各版式已在第 3 节模板里各自给了字数上限，以模板内数字为准。关键专业名词单独放大；出图后**逐字核对**；某工具长文老渲染出错，就精简标注或拆成两页。
- **崩字的真规律 = 单个文字块被迫折行**（2026-07-26 实测，同一页同一次生成内对照）：崩字与"整页文字总量"**无关**（"高密度必崩"已于 2026-07-25 实测证伪，那条结论继续有效、别再拿总量当理由），与**单个文字块是否被容器逼着折行**强相关。宽容器里能断成自然词组的 pill（「身体在说什么」3+3、「心里那句话」3+2）两轮重掷都正确；被塞进**窄竖色带**、强行折成 3×2 网格的 pill（「凌晨的那一幕」「白天的那一套」）两轮分别在不同位置崩。**宽的对、窄的错。**
  - **高危形态**：窄竖 pill / 窄色带 / 小徽章里放 **≥5 字**的词组。图内每一个文字块都应能在它的容器里**单行排下**。
  - **做法**：把该处文字**缩到 4 字以内**，或把容器改成**横贯的单行标签**。
  - **同一处反复崩字时不要重掷**——那是版式在逼模型出错，改版式才收敛。三招消因（按实测有效性排序）：① **换掉反复出错的那几个字**（等义改写，让崩点连同那个字一起消失——最有效，一次即净）；② **消除强制折行**（缩短该处文字，或把容器改宽改横）；③ **消除挤压**（把被相邻图形夹住的窄横带**整条移走**，而不是给它腾地方——实测"腾地方"无效，崩点坐标依然崩）。
- **全局硬要求：图中全部文字使用简体中文，不得出现繁体或异体字**（2026-07-26 本批出现过 數 / 軟）。每条提示词的「要求」行都带上这一句，出图后按此逐字核对。
- **N 步 / N 条清单类内容**（如"自救几步"）的取舍：**只需让读者看清步骤顺序/概览 → 用第 3 节③流程图，一页画完**（干货感强、省页数）；**每一步都要展开细节（做什么/为什么/小提示）→ 一步一卡**，每卡 ≥3 个子点把单步讲透。无论哪种，**避免只有 1–2 点的稀页**夹在足量页之间，整本密度才一致（本条约束的是"整本不齐"；大字报档下整本每页都是 1–2 点，本身就是齐的，不算稀页）。
- **指定字体气质**而非具体商用字体名：如"圆润无衬线体""温柔手写体"，颜色用当前档案的 `profile.visual.text_color`（默认配置示例：深灰蓝 #5A6B7B）。
- **易错专业名词的退路**：若某页必须出现 `CPTSD` `ICD-11` 等模型易渲染错的拼写/缩写，要么放大字号单独成行让模型更易写对，要么在该页提示词标注"该缩写如渲染错误请后期排版叠加"，并在"页面文字"里照常给出正确文本供人工兜底。
- 出图后**务必人工核对图上每个字**——错字是 AI 出图最常见翻车点。

## 2-a. 密度按页型分档（**三档各有下限**，2026-08-16 立 · ⛔ 不许拿封面的短促当内容页标准）

> **为什么单立一节**：§1-b 的三元组已经把"内容页要讲清一件事"说透了，但**下限此前只写在审查端**（`checklist-note.md` 判据 6 的不对称表），生产端读到的一直只有"别太长"。
> ⛔ **实证（2026-08-14 五篇首版）**：执行者把**封面页的短促**当成了**内容页的标准**，25 页全部做成「标题 + 几条短条」、每页 **66–73 字**——交出去的是"标题的堆叠"而不是"文章的分页"。老板打回原话：「每一篇小红书都是一个小的文章，每页表达的信息量都应该 400 字左右」。确认口径 B 后 25 页全部重建到 **151–253 字**。
> **病根是分档缺失**：三种页型本来就是三把不同的尺子，只给一把必然一头被灌满、一头被掏空。这与 `reference-mimicry-spec.md` §2.2「**密度实测必须分角色统计，绝不可把封面的 15 字与内容页的 300 字平均**」是**同一条道理的两面**——那边讲读参考图时怎么分角色统计，这边讲自己出稿时怎么分页型定档。

| 页型 | 图内汉字 | 信息点 | **下限判据（缺了就返工）** | 上限判据 |
|---|---|---|---|---|
| **P1 封面** | **12–45 字**（hero ≤8 + 副题 ≤18 + 辅句/落款）⚠️ **这一格是排版步的量具，⛔ 不前置给文案步**（2026-08-17，见 §2-c 开头） | 不适用 | **三层信息齐**（**文案步 的内容判据**）——hero 打翻认知 / 副题给结果 / 辅句或小字加码；**缺一层 = 信息量不足**，判据走 §2-b「hero 四判据 ④ 信息量下限」 | hero+support 合计 16 字是参考值不是硬闸；唯一硬闸是缩略图验收（§2-b 硬闸 4） |
| **内容页 P2…P(N-1)** | **150–250 字（150 是下限，不是"起步就够"）** | **6–10 个** | **图内 < 150 字 _且_ 三元组（观点／证据（机制）／落点）填不出 = FAIL**；三元组齐、图上确实讲清了一件事，150 字上下**不判** | 250 是建议值、默认档下超了不判错；**运营指定档的数是硬上限**，超了＝没执行运营指令 |
| **PN 末页** | **40–90 字**（其中品牌锚句 + 危机声明固定占约 40 字） | 不适用 | **三件齐**：行动建议 + 品牌锚句「NBDpsy · 北大硕博纯线上心理咨询」+ 危机声明小字，**缺一件 = FAIL** | 不设 |

**怎么自检（可证伪，⛔ 别靠目测）**：

```bash
python3 {SKILL_DIR}/scripts/count_xhs.py <post.md>   # 不传 --density-* 也恒输出 density_pages / density_report
```

`density_pages` 逐页给实测汉字数与信息点，越界的页带 `warn: "low"`（<150＝页太薄）或 `warn: "high"`（>250＝撑爆版面）；表里 **P1 与 PN 两行是 `counted: false`**——它们走上表自己那一档，⛔ 不拿内容页区间去量。

- **`warn: low` 不是判决，是点名**：拿它去逐页对三元组——三元组填不出＝真薄页，回 §1-b 重写；三元组齐全＝放行。
- ⛔ **反过来也不成立**：脚本 exit 0 **不代表密度没问题**（默认档它压根不裁决，只当量具）。**判够不够的永远是三元组，不是字数。**

**四条口径边界（最容易搞混，逐条记死）**：

1. ⛔ **封面页的短促 ≠ 内容页的标准**——封面十几个字是它那一档的达标形态；把这套手感带到内容页，就是 2026-08-14 那一整批的错法；
2. ⛔ **也不许倒过来**——拿 150–250 去量封面 / 末页同样是误判（与 `checklist-note.md` 判据 6「密度三字段只约束内容页」同源）；
3. **运营指定档只改内容页那一行**：运营说「每页不超过 100 字」时，内容页按 100 判硬上限，**封面与末页仍走各自那一档**，⛔ 不跟着一起改；
4. **走「材料让步方式 B」（减密度）的页**：信息点降到 **4–6 个**，**字数仍 150–250 不动**——B 让的是"这一页讲几件事"，不是"这一页写多少字"；跟着把字数也降下去，就退回薄页病根。**三元组在 B 之下一条都不许少。**

## 2-b. 封面版式工程（P1 专属 · 2026-08-10 立，四版实战对照+三路调研定案）

> **为什么单立一节**：封面好不好看、点不点得动，由版面决定（字号级差/焦点归属/留白分组/卖点面积），此前这层知识空白、每批现场发挥。本节全部条目要么有同文案四版对照实证（v1 字墙/v2 焦点错对象/v3 分栏限宽/v4 通栏过审），要么有外源逐字原文；未经自证的单独标注。

### 层级三层制（**排版步**逐行标层；⛔ 文案步不标层、不受字数约束）

> 🔴 **标层是排版动作，不是写作动作**（2026-08-17 倒置后的定位，见 §2-c 开头）：文案步 交出的是**一段完整的封面文案**（金句 + 结果 + 加码），
> **由 排版步 把它切成三层**并挑出 hero 片段。**下表的字数是 排版步 切分时的量具，⛔ 不许前置给写文案的人**——
> 拿 ≤8 字去要求作者，他交回来的会是短标题不是金句（老板 2026-08-17：「先写封面内容，然后再让一个 agent 进行排版设计」）。

| 层 | 是什么 | 数量 | 缩略图可见性 |
|---|---|---|---|
| **[hero]** | **打翻读者已有认知的那句**（**排版步 切出的片段**，≤8 字、4-6 最佳；**选句判据（内容层）见下「hero 选句」，那部分归 文案步**） | 恰好 1 个 | 必须可读 |
| [support] | 辅助句（**转折句永远在这层**）、副标题、场景引子 | 1-2 组 | 应可辨认 |
| [detail] | 落款/角标/账号名 | ≤2 处 | **默认不可见档** |

> 🔴 **以下「hero 选句 / 三问 / 四判据 / 副题回答『然后呢』」全部是内容判据 ＝ 文案步的验收标准，2026-08-17 倒置后原样保留、一条不撤。**
> ⚠️ 文案步还没有"hero"（hero 是 排版步 从金句里截的片段）——**此时这些判据判的是那句金句本身**：
> ①张力 ②事实边界 ③自明性 判**金句**；④信息量下限 判**整张封面文案三层齐不齐**。金句过了，截出来的片段才可能过。
> 验收步 验收时**对着缩略图再逐条打勾一遍**（排版步 动过文案，文案步 的结论可能已不成立，见 §2-c 验收闸第 7 条）。

- 🔴 **hero 选句判据（2026-08-12 老板定案+验收）**：「让人共鸣、让人感兴趣、让人震惊、营造反直觉的点，才需要放大」——判定问题：**读者扫到这句会说「啊？！」还是「哦」？说「哦」的都不配当 hero**。四类冒牌 hero（本周实战全部过了机检、全被老板肉眼打回）：

  | 冒牌 hero | 为什么不行 | 实战反例 |
  |---|---|---|
  | 话题词 | 只告知"讲什么"，零张力 | 「过度换气」（长尾词该在 title，不该占最大字） |
  | 答案 | 剧透——答案是读完才该拿到的 | 「是气吸太多了」（老板：肯定不是这句） |
  | 转折句 | 论证里最聪明的一句 ≠ 封面最该放大的一句 | 「但文凭只是我们的第一道筛子」 |
  | 纯共鸣句 | 能认领但不震惊，缺"难道我错了？"的钩 | 「你以为自己缺氧了」（比答案好，仍差一档） |

  正版实例：「深呼吸 是帮倒忙」（打翻全民共识动作）✅ 验收、「只招北大」✅。
  验收版四层结构模板：引子=共鸣（场景认领）→ hero=震惊/反直觉（最大字）→ 副题=悬念/半个答案 → 小字=加码+导流。

- 🔴 **hero 三问自检（2026-08-14 老板两轮打回实录立；与「啊？/哦」判据互补，两套都过才算过）**：hero 选定后，必须能当场答上老板这三问——

  > **① 这是什么意思？　② 要传达什么？　③ 凭什么吸引人点进去？**

  两套判据分工别混：**「啊？/哦」判的是张力**（值不值得放大），**三问判的是信息完整性**（放大了读者看不看得懂）。**无主语 / 不自明 / 只是答案碎片 = 第①问就答不上，直接不过。**
  📌 **三问是口头速查版；可打勾的完整形态是下面那张「hero 四判据」表**（2026-08-16 补齐）——**三问覆盖不到「事实边界」**：一句话完全自明、三问全答得上，照样可能是**越界**的（说得越清楚、被当成服务承诺传播的风险越大）。**两处不是两套标准，是同一套的速查版与逐条版。**

- 🔴 **hero 四判据 · 逐条打勾（2026-08-14 立①②、2026-08-16 补齐③④；⛔ 四条全打上勾才算过，答不上就是没过、不许"先出图看看效果"）**：

  | # | 判据 | 一问（必须当场答上，答案写进出图前的系统声明） | ⛔ 打不上勾的实证 |
  |---|---|---|---|
  | ① | **张力** | 读者扫到这句会说「啊？」还是「哦」？ | 「你以为自己缺氧了」——纯共鸣句，读者说「哦」（四类冒牌 hero 见上表） |
  | ② | **事实边界** | 这句话被截图**单独传播**，我们敢不敢认它是**对所有来访者的承诺**？ | 「摄像头 可以不开」——研究里对**特定参与者**的个别安排，放到封面最大字上会被读成团体通用规范／我们的服务承诺 |
  | ③ | **自明性** | 把正文、副题、账号名**全遮住**，只留这一句——读者读得懂吗？ | 「一节没落」（谁一节没落？什么课？＝答案碎片）；「敢不敢承认疼」（术语腔／文艺腔，老板：「说得都不吸引人」→ 改口后又「看不懂」） |
  | ④ | **信息量下限** | 只看这一张封面，能不能**一句话复述"这篇要说啥"**？ | v6：头像放大到画面宽 36% 之后被否——「封面里表述太少，看不懂到底要说啥」。**元素占面积 ≠ 传递信息** |

  - **② 事实边界**（原独立条目，2026-08-16 收进本表，内容一字未改）：**特殊人群的特殊安排，不得放大成封面通用承诺**——**事实越界**，比"不好看"严重得多（不好看是转化问题，越界是事实问题）。同源教训见记忆 `feedback_cover_counselor_avatar`「研究里的特殊安排勿放大成规范」。
  - ⚠️ **咨询师推介笔记例外**：那类封面的 hero **就是咨询师姓名**（分工见 `counselor-note-spec.md` §4「P1 · 照片封面」），⛔ 别拿判据①「打不打翻认知」去要求姓名；**②③④ 与「副题回答然后呢」照走**——推介封面同样得让人一句话说清"这是谁、能帮你什么"。
  - **③ 自明性的可判定形态**：hero **无主语 / 是答案碎片 / 含只能靠正文补全的指代**（"一节""这件事""那种感觉"）= 不自明。与 `checklist-note.md` 判据 4.5「标题场景自足」同族——那边判发布标题、这边判封面大字，**两处都判，谁也不顶替谁**。
  - **④ 信息量下限 ＝ 封面三层信息齐**（v6 逼出来的下限，⛔ 只放大一句 hero 不算一张封面）：

    | 层 | 必须承载 | 缺了会怎样 |
    |---|---|---|
    | **hero** | 打翻认知的那一句 | 没有钩子，无人点进 |
    | **副题** | **结果 / 利益点**（见下条「副题必须回答『然后呢』」） | 读者问"然后呢"，判断不出值不值得读 |
    | **辅句或小字** | 加码：出处 / 场景 / 身份行 / 落款 | 只剩一句口号，看不懂"这篇要说啥" |

    - **判据（一眼验）**：遮住正文与账号名，只看封面，**用一句话复述这篇讲什么**——复述不出 = 信息量不足；**处置＝把缺的那一层文字补写回来**（补副题给结果、或补一行辅句加码，仍受 hero ≤8 / 副题 ≤18 与三档字号约束），⛔ **不许靠放大插画 / 头像来"填满"封面**（面积不是信息，v6 就是这么栽的）。
    - ⚠️ 与「封面始终精简」不冲突：精简说的是**每层都短**（hero ≤8 字、副题 ≤18 字——**这两个数是 排版步 切层时的量具**），**不是层数可以少**（**层数齐是 文案步 的内容判据**）。封面页自己的字数档（12–45 字）见 **§2-a** 那张分档表，⛔ 别拿内容页的 150–250 去量封面。
    - 🔴 **⛔ 不许拿「每层都短」去要求 文案步**：三层信息齐是**内容要求**（说完整），字数是**排版量具**。文案步 交一段完整的话，排版步 负责把它切短切匀——**反过来先让作者按 8/18 字写，交回来的就是三行短标题**。

### 排印参数（公式不枚举）

- **三档字号上限**：全图只许 hero/support/detail 三档，第 4 条信息并档或删（「三级是普通人能分辨的上限」）；
- 🔴 **三级字重＝一套系数，照抄不猜**（2026-08-14 两处口径合一定案；系数以 hero 为 1，**分母是画面高**）：

  | 档 | 字高 | 写进提示词的说法 |
  |---|---|---|
  | **hero**（主标题） | **≈ 画面高 13%**（实产区间 9–13%，hero 越短取越大；单行撑满两侧页边距之间的全宽、不折行） | 「字高约为画面高度的 13%」 |
  | **support**（引子 / 副题） | **= hero × 0.34** | 「字号约为主标题的 0.34 倍」 |
  | **detail**（小字 / 落款） | **= hero × 0.22** | 「字号约为主标题的 0.22 倍」 |

  推出来的级差正是「hero＝基准 ×2.5 起、可到 4 倍」那一档：hero:support ≈ 2.9:1、hero:detail ≈ 4.5:1，**hero:support ≥2.5:1 这条硬下限继续成立**。⚠️ **1.6 倍「只差一级」在密排多行下完全无感（v1 实证）——焦点必须跳级**，所以本表不给 1.6 这一档留位置。
  📌 **两处旧口径已作废、此处留痕**：① 本节原写「字高约 7.5-11% **画布宽**」——分母写成了画布宽，换算成画面高只有 5–7.3%，比实产配方小一半；② 第 3 节文字层原写「第一级字号约为其余行 **1.6 倍**」——就是上面实证判死的那一档。**依据**：近两周实产且老板验收过的封面批次（H1 过度换气、W1–W5）稳定用「主标题字高 = 画面高 9–13% + 副题 0.34 + 小字 0.20–0.22」这一套，本表即该配方本体，**只把倍率区间收成系数，不给生产者留猜的余地**；
- **五杠杆核对**（字号/字重/颜色/位置/留白）：hero 同时占「最大字号+最粗字重+唯一强调色」三项；support 最多一项；detail 零项；
- **焦点成块**：hero 多行时特粗+行距 1.0-1.1 字高+字距 0 至微负，紧凑成矩形字块；**焦点四周留 ≥1 个 hero 字高的空白隔离带**，任何元素不得进入；

- 文字总量：hero+support 合计 16 字是**参考值不是硬闸**（2026-08-10 五样本 28-38 字全过缩略图验收证伪了硬上限）——**唯一硬闸是缩略图验收**（见下）；行数默认 2 排、第 3 排只做装饰。

### 画布与安全区

- 画布仍为 2:3（1024×1536，生图模型档位）；**信息流展示为 3:4，2:3 会被上下各裁约 5.6%**（✅ 2026-08-12 老板真机实证确会裁）——**硬约束：全部文字与卖点收进画面中央 3:4 等效区，上下各 5.5% 牺牲带只放纯背景**；
- **标准做法（封面要出正 3:4 时）**：`gen_images` 只能出 2:3（876×1313）无比例参数——提示词里写死「上下各 11% 为牺牲带只留纯背景色，所有文字与插画落在 11%–89% 中央带」，出图后本地裁成 876×1168（3:4）。内容线 2026-08-12 实测 5 张：4 张零损失、1 张仅切底部可牺牲页脚；
- **封面 3:4 的两条落地路径（别混）**：①**图文笔记没有独立封面通道**（封面恒=第一张图，`--cover` 对图文无效）→ 3:4 封面 = 把 P01 按上法做成 3:4，内页保持 2:3（混比例已获老板确认）；②**视频/播客笔记支持 `--cover` 单独传 3:4 封面**，与正片比例无关；
- 四边安全边距＝画面宽 6-9%；**底部 10-15% 禁放关键文字**（信息流被笔记标题/昵称遮挡，知识类封面头号翻车点）；
- hero 垂直位置＝上 1/3 至中上（高处感知更重+压上三分线）。

### 🔴 本节全文 ＝ 排版步的手册（2026-08-17 老板定案：**文案先行、规格后置**）

**老板原话**：

> **「规格实测，不要先给那么细的规格再写作，最好是反过来，先写封面内容，然后再让一个 agent 进行排版设计，可以一定程度上的改文案，但需要表达清晰」**

**病根**：此前把 hero ≤6 字、字高 9–13%、hero:副题 ≥2.5:1 这些数**扔给写文案的人**，他戴着镣铐写——先算字数、再想说什么，写出来的是"能排得下的短句"而不是"打得动人的话"。

**改法：规格从写作阶段撤到排版阶段。⛔ 一个数都没删，全部变成排版阶段的内部量具。**

```
文案步（文案先行）        ⛔ 此时不给任何字数/字高/比例约束，只给内容判据
   ↓  交付物：post-NN.md 的 P1 封面块（金句 + 结果层 + 加码层 + 四判据答案）
排版步（本节）            持有全部量具；渲染是它的量具不是它的裁判；**有限改文案权**
   ↓  交付物：cover.json（+ 改动回写 P1 块 + 00-overview.md 留痕）
验收步                    缩略图验收 + 四判据复打勾 + 落 cover-*.meta.json
```

**⑧ 论点行禁卖方视角**（该闸明确扫「每页论点行 ＋ **P1 封面页面文字**」）扫到。
**排版步 改完文案必须把定稿回写这个块**，否则合规扫的是旧字。

#### 🔴 风格档案校验（v2.28.0 起，**会拒渲**）

**为什么有这道闸**：凭证里一直同时躺着 `style_profile`（声明用了哪套）与 `palette`（实际渲出什么色），
而**从来没人把这两个数相减**——字段在、判据在、每次都过。
🩸 **实证**：2026-08-21 有 13 份凭证标着 `图文 v3` 一路绿灯到发布前才被人肉发现，
而档案库里**「图文」只有 v2**（v3 是「暖米大字」的）。**错标比缺失更毒**：
缺失会被闸门 A 拒（有声音），错标畅通无阻，而**凭证的意义就是溯源，错标＝溯源断**。

出图**之前**核一次「这个套名 + 这一版在不在档案库里」，出图**之后**核一次「档案声明的色是不是真渲出来了」：

| 情形 | 凭证 `style_profile_check.verified` | 行为 |
|---|---|---|
| 档案库里有这一版 | `true` | 正常渲 |
| 档案库明确说没有（**只有 404**） | `false` | 🔴 **拒渲**（在起浏览器之前），exit 2 |
| 没配 key / 连不上 / 超时 / 服务端没答上来（含 5xx） | `null` | ⚠️ warn 放行，**凭证如实记「没核过」** |

🔴 **`null` 与 `false` 是两件事，⛔ 不许塌成一个**：把「这次没核成」记成「档案是错的」，
会拒掉一张好图、而且红灯指向错的地方（🩸 实测撞过：源站抖一下回 **HTTP 530**，
首版把它当成「档案对不上」，照那个红去查会去改留痕行，**真正的问题是源站挂了**）。

**色值判据的方向是「档案声明的 ⊆ 实际渲出的」**，⛔ 不是反过来：
模板里有正当的中性色（如 jinjin 的墨蓝 `#2B3A4A`）档案根本没记，
写成「实测 ⊆ 声明」就恒红，而**恒红的闸门等于没有闸门**。
色值对不上**不拒渲**（图已经在磁盘上了），但会进 `warnings` 且凭证记 `palette_ok: false`。
⚠️ 量不出实测调色板时（如 still-life 的 `:root` 里一个 hex 都没有）记 `null` **不记 `false`**——
把"没量到"说成"不匹配"是在自造假红。

⛔ **没有 `--skip-style-check` 这种逃生门**：开一个就会变成默认习惯，闸门当场作废。
离线自动放行已经是唯一的洞，而它**在凭证里留了痕**。

**顺带产出四件**：`<out>.png|jpg` 成图、`<out>.thumb220.*` 缩略图、`<out>.html` 排版 HTML（浏览器直接打开就是成图的样子）、`<out>.meta.json` **产出凭证**。

### 🔴 封面文案口径：金句，不是标题（2026-08-17 老板定案 · CTR 优先）

老板原话：**「我希望封面不仅仅是标题，应该是金句，可以 10～30 字，小红书的封面，我发觉不一定需要多好看，但一定要金句才能提高 CTR」**

**两层口径并存，别混为一谈**（它们字面看着冲突，其实管的是两件事，**而且分属两个阶段**）：

| 口径 | 属哪一阶段 | 管什么 | 判据 |
|---|---|---|---|
| **金句 10–30 字**（内容层） | **文案步 写文案** | 封面上**必须有一句金句**，不是标题复读；金句**一字不少**地呈现在封面上 | **10–30 是长度感，⛔ 不是闸**：少于 10 字多半是标题不是金句；超过 30 字读者在信息流里读不完。**判金句的是「说的是不是我」，不是字数** |
| **hero ≤6 字**（视觉层） | **排版步 排版** | 金句里**最扎心的那 4–6 字放大**成大字（≥9% 字高），其余部分以**副题**承载 | 见下「版式适用范围硬判据」 |

**合起来＝金句完整在封面上，其中最狠的片段被放大。** ⛔ 别为守字高把金句砍成 4 字（老板明确 CTR 优先于美观）；⛔ 也别把 10–30 字全塞进大字（30 字全大字时字高 <3%，等于没有焦点）。

### 🔴 版式适用范围硬判据（本轮最贵的教训）

**「通栏大字压顶」要求 hero ≤6 字。**

> 🗑️ **原先这里还有一张表（4字12.4% / 5字9.9% / 6字8.3% / 7字7.1% / 8字6.2% / 10字5.0%），2026-08-17 已删。**
> 它是按「**字高＝字号×0.86**」**推算**出来的，而 0.86 这个经验常数本身是错的——实测中文 900 字重的真实墨迹比是
> **0.955～0.982**（带引号 0.969、纯拉丁只有 0.767）。⇒ **那张表全线偏低约 11%**。

### 🔴 排版步 的改文案权（老板授权，但有边界：**界线是「表达清晰」且意思不变**）

老板原话里那半句是授权：**「可以一定程度上的改文案，但需要表达清晰」**。
授权不等于重写——**排版步 是排版师不是作者**。边界逐条写死：

| | 能改（⭕ 排版权限内） | ⛔ 不能改（越界，必须回 文案步） |
|---|---|---|
| **句子形状** | 断句、换行点、把一句长句拆成 hero + 副题（**原句一字不少地落在副题**） | 把两句合成一句、把一句拆成两个不同的意思 |
| **字** | 删可省的**虚词**（的／了／其实／真的／一个／就是）；**同义替换更短的词**（同强度同语义，如「不对劲」换「有问题」） | 换掉承载语义强度的词（「崩溃」→「难受」是**改结论**不是改字数） |
| **hero** | 从金句里**截片段**当 hero；hero 太短（≤4 字）时**从原金句里多截两个字**补到 5–6 字 | 为凑字数**新造**原金句里没有的字词 |
| **标点** | 为让引号成对、为断句而调标点（老板 2026-08-17 明确不算改文案） | 用标点改变语气归属（陈述改反问、去掉限定号） |
| **层的归属** | 把某一层的内容挪到另一层（辅句降小字、副题升 hero 片段） | 删掉整整一层（三层信息齐是 文案步 的内容判据，⛔ 排版不许为了好看砍掉一层） |
| **论点** | — | **论点本身**（这张封面在说什么）、**事实与数字**（人群限定、比例、时间、出处）、**金句最扎心的那半句**（一字不许换）、**专业术语的准确性**（⛔ 别为省字把「复杂性创伤」写成「创伤」）、**合规文字**（危机声明、免责） |

**两句自查（改完逐句核，⛔ 不许只凭"我觉得意思没变"）**：

1. 🔴 **并排读测试**：把**改前**与**改后**两句并排读给**一个没看过这篇稿子的人**——
   **他会不会得出不同的结论？** 会 → 越界，退回原文案重排；不会 → 通过。
2. 🔴 **事实成分逐字回溯**：改后那句里的**每一个事实性成分**（人群、数字、时间、程度词、限定词），
   **都能在改前那句里逐字找到**。找不到 = 你新增了一个事实（违反本 skill 铁律 1「不新增未验证事实」），
   哪怕它看起来无害。⚠️ 这一条抓的是最隐蔽的一类越界：**删限定词**。
   ⛔「**部分**来访者六周后改善」删成「六周后改善」——字少了、读着更顺、**事实被放大成承诺**（同 §2-b 判据② 事实边界）。

**改完两件事，缺一不可**：

1. 🔴 **把定稿回写 `post-NN.md` 的 P1 封面块**——post 是封面文案的真源，`check_compliance.py` 与卖方视角闸门扫的都是它。
   ⛔ **只改 `cover.json` 就走 = 合规扫的是旧字、审查端看的是旧字、下一个接手的人拿到的也是旧字**。
   回写后**重跑一遍 `check_compliance.py`**（封面文字动了就得重扫广告法与平台词表）。
   **可核判据（2026-08-17 订正）**：P1 块 `**页面文字**` 里的每一行 ≡ `cover.json` 的
   **`hero` + `subtitle` + `steps` + `footer`**（逐字比，⛔ 别凭印象）。
   ⚠️ **`footer` 此前漏在等式外**——黄金范例的 `[detail]「NBDpsy 心理科普」` 走的就是 `footer`，
   照旧等式逐字比必然对不上，会把「其实没改」误判成「改了没回写」。
   ⚠️ **`avatar` / `identity` ⛔ 不进这个等式**：它们是元素层不是页面文字（`identity` 的字虽然会渲进图，但不写在 `**页面文字**` 块里）；
   横版下第 ④ 层整层收起，更谈不上比对。逐层对应关系见上面「黄金范例的 `[层]` ↔ `cover.json` 字段映射」。
2. 🔴 **留痕（⛔ 不留痕 = 这次改动不成立）**：排版步 改动的每一处都写进 `{note_dir}/00-overview.md` 的
   **「封面改文案留痕」** 一节，一篇一块、一改一行，三列：**原句 ｜ 改后 ｜ 为什么（哪条量具逼的）**。

```markdown
## 封面改文案留痕

### post-01
| 原句 | 改后 | 为什么 |
|---|---|---|
| 你以为自己是玻璃心，其实是身体在替你记着 | hero「不是玻璃心」／副题「你以为自己是玻璃心，其实是身体在替你记着」 | 从金句截 4 字片段当 hero，原句一字不少落副题（截片段不算改文案） |
| （hero）不是玻璃心 | （hero）这不是玻璃心 | hero 4 字字高 13.7% 冲破上限，从原句里补一个「这」字落回甜区 |
```

- **为什么必须留痕**：不留痕，文案作者**不知道自己的话被动过**，下一批还会照原样写；审查端也无从判断"这句不地道"是作者写的还是排版改的。
- **留痕之后回读一次**：把改动清单回给文案作者/运营看一眼（⛔ 不是审批，是告知——**除非**自查句 1 判定为"会得出不同结论"，那种情况本就该退回重排，不该拿去问)。
- ⚠️ **本条目前没有代码闸门**——`render_cover.py` 不检查留痕、`--check-cover` 也不检查。**它靠自觉与审查端**（`checklist-note.md` 走成图审时对着 `00-overview.md` 核）。⛔ 别以为脚本会替你拦。

### 🔴 红灯循环与打回界线（**红灯是排版的活，不是打回文案的理由**）

`render_cover.py` 报红（字高越界／hero:副题比不足／溢出／3:4 安全区／折行触底）时，**排版步 的正确反应是自己解掉再渲一次**，⛔ 不是把稿子扔回 文案步。**处置按顺序试，试到绿为止**：

```
① 调排版：换版式（通栏大字压顶 → 左字右图分栏／留白场／色块压条）、改换行点、调留白、改 hero 截取的片段
   ↓ 还红
② 行使改文案权：删虚词 → 同义替换更短的词 → 拆句（长句降副题）→ hero 补字/减字
   ↓ 还红，且已到「再删就伤意思」
③ 才准打回 文案步
```

**两个打回口，性质完全不同，别混**：

| 打回口 | 触发 | 谁发现 | 打回时必须带什么 |
|---|---|---|---|
| **A · 装不下**（排版走投无路） | ①②都试过、**再删就伤意思**——即自查句 1 判定"并排读会得出不同结论" | 排版步 | **试过哪几个版式**、**改过哪几处**（贴留痕表）、**卡在哪条量具上的多少**——🔴 **数字必须是你这一张实测出来的**（`render_cover.py` 交回的 `hero_glyph_pct_of_h` / `hero_fs` / `warnings` 原文），⛔ **不许从规格表里抄一个**（本节原先那句"压到 7.1%"就是从已删的旧推算表里抄的，对不上任何一次真实渲染）。格式照这个写：**"副题 87 字，递进行降到下限仍塞不下，已回头压 hero 到 128.7px＝9.37%"**（2026-08-17 实测样例，形态：876×1313＋avatar/identity/footer＋2 条 steps）。⛔ 只说"排不下"不算打回，那是甩锅 |
| **B · 内容不过**（判据层） | hero 四判据任一答不上／事实边界越界／触广告法与平台词表／三层信息缺一层 | 排版步 或 验收步 | 点名**哪一条判据**、**为什么**。🔴 **这一类 ⛔ 不许 排版步 自己改内容去救**——改内容救判据就是重写，越权 |

🔴 **一句话判据**：**「删到伤意思」才回 文案步；「排不下」不回。**
⛔ **反面**：拿"hero 超 6 字"「字高不够」当打回理由 = 把量具当闸门用回写作阶段，整套倒置白做。

⚠️ **打回 文案步 时，⛔ 仍然不许把量具当需求提过去**（最容易复发的地方）：
正确提法是**「这句放不进封面，最狠的是哪半句？能不能换个说法把同一件事说完整」**——把**问题**交回去；
⛔ 错误提法是「请写一个 6 字以内的 hero」——那是把镣铐又戴回作者手上，等于这次改造没发生。

### 验收闸（逐条可核 · **验收步**）

> 🔴 **先说怎么读脚本的结论：判 `gates_ok`，⛔ 不判退出码、⛔ 不判 `ok`**（2026-08-17 零上下文干跑抓出来的坑，**现状登记**）。
>
> | 读什么 | jinjin（小红书竖版/横版）这条路的实际行为 | 能不能当验收依据 |
> |---|---|---|
> | **`gates_ok`** | `true` = 一条 🔴 都没有；`false` = 有红字 | ✅ **唯一该判的** |
> | 退出码 | 🔴 **恒 0**——**一张缺头像（`gates_ok:false`）、一张全绿，退出码都是 0**（2026-08-17 实跑复核） | ❌ ⛔ 判了等于没判 |
> | `ok` | 🔴 jinjin 路**恒 `true`**（与 `gates_ok` 不同源）；still-life 路才 `= not red` | ❌ ⛔ 写 `if payload["ok"]` 会把红灯渲染当成功收下 |
> | `warnings` | 全部告警原文，`🔴` 开头的是红字、`⚠️` 开头的只是提示 | ✅ 判完 `gates_ok` 之后**逐条读**，红字告诉你怎么处置 |
>

## 3. 单页提示词模板

> **房规：宁详勿略，把提示词当"施工图"写。** 内容页的每一条提示词都要把「整体结构 + 每个元素画成什么具体画面 + 所有图上文字逐字」写全——**详细提示词能锁死模型的随机性，让整套 6–9 张风格统一**；松散描述靠模型即兴发挥，套图之间必然漂移。下面模板给的就是这个详写颗粒度，照着填、别偷懒简写。可选设计项（粗黑标题/赭红/纸质框）不一定用，但"结构 + 具体画面 + 文字"这三样必须写透。

**封面页 / 末页 —— 三层组件模板（背景层 + 文字层 + 元素层）**

> **为什么分层**：封面是决定点击率的门面，也是**产出量最大、最需要批量复用**的一页。把它拆成三个可独立替换的"组件"后，做新一篇笔记只需换文字层（标题/副标题）与元素层（主体道具），背景层原样复用——**风格自动统一、产出速度翻倍**，还能一套素材跨平台适配（小红书 2:3 / Instagram 1:1，见下方「比例参数」）。

```
【风格基底 · 取自当前用户的风格档案】

■ 背景层（取自当前档案的 `visual.palette` + `visual.texture`，同一运营的所有笔记原样复用）：
暖米白 #E8D8C4 纸质肌理底，细腻颗粒感；柔光、无强烈阴影；
四角留空，画面整体平静治愈；不出现品牌调色板（#A8B5C4 / #E8D8C4 / #C9D6CE / 可选 #A34B3A / #2B3A4A）以外的颜色。

■ 文字层（每篇替换，写清位置与层级）——**字重三级层级，取自 `visual.cover_typography`；字号系数唯一真源在 §2-b「排印参数」那张表，此处只做展开，⛔ 别在这里另立一套数**：
在【上方留白区 / 正方形版则为上 1/4 区】写中文主标题（可折 2–3 行，**不受 20 字限制**，见 `xiaohongshu-spec.md`「标题」节的解耦规则），其下一行副标题。三级层级写死在提示词里：
- **第一级＝ hero**（§2-b「hero 选句判据」选出来的那一句，**不是论证里的转折句**）：超粗 Heavy/Black 字重、**字高约为画面高度的 13%**、通栏撑满不折行（必须折时各行同字号同色、行距 1.0–1.1 紧贴读成一个整体）、字色**强调色赭红 `visual.accent_color`（默认配置 #A34B3A）**，是全图视觉中心；
- **第二级＝ support**（引子 / 副题 / 主标题之外的辅助行）：粗黑 Bold、**字号约为主标题的 0.34 倍**、字色 `visual.text_color`；
- **第三级＝ detail**（细体小字 / 落款）：细体、**字号约为主标题的 0.22 倍**、颜色浅一度。⛔ 不拉字距——中文排版基线是密排（字距 0），拉字距只会松垮（2026-08-10 v1 字墙实证+W3C 中文排版基线，旧规「字间距略拉开」作废）；疏排仅限 ≤4 字装饰性短词。

构图避让（**只有封面 P1 需要写这一句，末页与内容页不写**）：标题压在**上 1/3 区**，底部留出大片空白、不放任何文字；正方形版改为四周留匀称空白。长标题须注明「完整排下、不裁切、不省略、字号可略缩」。

> **提示词能锁「字体大类＋层级」，锁不住「具体哪一款字」**（实测：同一句提示词跨次出图，圆体会在「圆体／圆角粗黑」之间浮动）。由此推出一条硬纪律（2026-08-10 修订为实践可行版）：**封面 P1 先单独出图做风格闸门（人工确认气质），确认后以封面图 URL 当 anchor、剩余页一次性批量出完**——实测 45 张全批风格统一。⛔ 仍然禁止「中途零散补图」：补图字体气质会与前面页对不上，须以同一封面 anchor 重出或至少复核字形一致性。

> **提示词句式铁律（2026-08-10 实战翻车后立）**：图内文字指令**元指令一律放冒号前的括号内，冒号之后只留要画的文字**。
> ✅ `逐字写出这行字（行内两对直角引号照写进图，末尾不加句号）：「循证」问的不是「有没有用」`
> ⛔ `逐字写出这行字：「循证」问的不是「有没有用」——这行里的引号照写`（破折号后的说明会被整句画进主标题）
> ⛔ 外层引号包裹要画的字（`写出「xxx」`）——外层引号会被一并画进图。`check_compliance.py` 对冒号后跟破折号/分号的残留元指令会出 warn。
> 备选形态（按页型选，不改默认）：**宋体/明朝体**质感最高级、最不像 AI 出图，适合**金句页与咨询师推介页**；主标三行全用宋体时信息流缩图细横画会糊，须加大字重。**圆体**最温柔但跨次一致性最差，量产慎用。

■ 元素层（每篇替换，是"画面"的主体）：

道具：【一两个治愈系小道具，如马克杯 / 绿植 / 毛毯 / 窗光 / 打开的书】，围绕主体自然摆放、不喧宾夺主。
条件头像（**只在 P1 封面、且本篇拆解的是某咨询师署名长文时**加这一段，规格与授权口径见 §2-b「元素层 · 条件头像」）：真人照片圆形头像框（鼠尾草绿细描边、直径约画面宽 22%，居中偏左置于中下部）+ 框正下方身份行「{姓名} · 论文作者」；上面的「主体/道具」**不得与头像争焦点**（老板点名把头像放大到 36% 时，插画收到画面宽 ≤22%、置右下作陪衬）。⛔ 该加而没加 = 封面不过审。

### 内容页核心：图文双通道 + 高密度（所有内容版式先满足这条，再套下面具体版式）

内容信息图页要对齐"高密度科普文字版"的干货感，**唯一硬要求是「图文双通道」**——密度不是靠堆字，是靠**每条知识点都有自己的画面**。**下面每个版式模板开头的「【风格基底 · 取自当前用户的风格档案】」= 当前档案的 `palette` / `text_color` / `character_card` / `texture`（映射表见第 1 节）+ 下面①（②按需叠加）**。

**① 硬要求（缺了就返工）：图文共同表达足量信息**

> **密度 = 图文结合共同表达的信息量，不是字数。** 一个大隐喻 + 三四个抽象短标签（哪怕配了图标）仍是低密度——因为图在"装饰"、文字在"贴标签"，两者没合起来讲清一件事。反例：`抑郁症＝一场雨` 一朵雨云 + 3 个抽象标签「成组出现 / 至少两周 / 有周期」——雨云不承载信息，标签读完不知道"具体长啥样"。

- **图要"叙事"不要"装饰"**：每个图形元素都描绘一个读者能一眼解码的**具体情境**（一个动作、一个场景、一个对照），让"看图"本身就获取信息；不要用一个抽象大隐喻 + 几个泛标签充数。
- **抽象概念落地成具体场景/例子**：别把"成组出现""有周期"这类抽象结论配个泛图标就完事——把它画成看得见的：`成组出现`→并列画出情绪低落、失眠、没胃口、对爱好发呆等几个**具体症状小人**；`至少两周`→画一条**两周日历**几乎每天被标记；`有周期`→画一条**发作↘缓解↗复发**的情绪起伏曲线。图把抽象讲成具体，信息量才真正上去。
- **每条信息 / 每格 / 每节点都配一个各不相同、贴合含义的手绘小图标或简笔小人**（雾霾蓝灰 #A8B5C4 为主、线条清晰）——**不是装饰性小圆点**。图标承载"是什么场景"、文字承载"说什么"，图文双通道才是密度的来源。
- **信息点要足 + 用结构承载信息**：**每页信息点数按密度档位取值**（默认档 6–10 个），满版铺陈、分 **2–3 区块**组织；能用对比 / 因果 / 前后 / 分类把点之间的**关系也画出来**（关系本身也是信息，见版式菜单 ②–⑧）——覆盖情绪页"顶部留 1/3 空白"那条。

**①-b 三档版式联动（2026-07-26 老板定案配套）：低密度档必须同步换版式**

密度档位（第 2 节）决定信息点数，信息点数决定版式档。**运营要"轻一点"却仍按满版 6–10 点铺陈，出图 agent 会精分**——密度、版式、判据三样必须同档。

| 版式档 | 触发（该页信息点） | 版式怎么排 |
|---|---|---|
| **满版档** | ≥6 个（默认档就落这里） | 下面 17 种版式全适用；满版铺陈、分 **2–3 区块**；少格版式须"格内二次加密" |
| **少格档** | 3–5 个 | **只用少格版式**（② 对比图 / ④ 象限 / ③ 流程 / ⑰ 概念定义卡 / ⑯ 程度光谱）；**"格内二次加密"降级为「每格 1 图 + 1 句」**；留白明显多于满版档 |
| **大字报档** | 1–2 个 | 一个大主视觉 + 一句核心话（**≤20 字**）+ 至多一个副标注；**此时"一页只有 1–2 条 = FAIL"这条判据停用** |

> 三档共用的仍是"图文双通道"这条硬要求——低密度档只是**少铺几条**，不是让图退回装饰：那一个大主视觉照样得画成能解码的具体情境，不能是抽象大隐喻。

**② 可选设计工具（按需用、保持品牌调性一致即可，都不强制）**

- **标题风格自由**：**默认沿用品牌柔和标题**（圆润无衬线体、深灰蓝 #5A6B7B）即可；想更有海报冲击力也可以加粗、用深钢蓝黑 #2B3A4A——**但不强制粗黑**。
- **强调赭红 #A34B3A**：想突出标题关键词、或给关键结论做"红字点睛"（=被抛弃 / 危险信号 / 你很安全）时可用；不想用则整页保持柔和三色也行。
- **纸质暖框 / 箭头连接**：想要科普海报的"框感"可加纸质暖米背景 + 暖棕描边框；有因果/先后关系时用箭头 → 串联。都是加分项，不是硬指标。

> 判据：把这一页的图和字**一起读**，能否获得一个"信息完整、对得上自己"的认知？能 = 达标。若只看到一个装饰隐喻 + 几句抽象标签、或一页只有 1–2 条、图标是通用圆点 = **FAIL**。**"一页只有 1–2 条"这半条只在满版档成立**；少格档声明区间含 2 时同样停用、大字报档整条停用（见 ①-b）。**标题粗不粗、有没有红字，都不影响达标。**

> 自有数据佐证：
> 清单/自查体的收藏是普通科普的 **37 倍**，清单体的本质就是**条目多**。
> ⚠️ **别把「工具多」误判成「卖货套路」**：商品笔记堆工具确实有卖货动机，但「读者觉得这篇有料」是真实收益，
> 两件事要分开（这正是当初判错的地方）。
> **给足的同时怎么不让读者记不住**——靠**分组**，不是靠删条目。推荐按**使用时机**分三组，读者能直接对号入座：
> 「情绪上来那一刻」（急救类，30 秒内能做的 2–3 条）／「每天固定做」（练习类 2–3 条）／「长期慢慢改」（结构类 1–2 条）；
> 也可按场景或难度分，但**必须有分组标签**。
> **每条要短**：动作名一句 + 怎么做一句。**一页 2:3 竖版的物理极限约 10 条**（实测：10 条 + 3 个分组标签 + 标题副标底部条，密度拉满但不塌陷）。

> **正文只列动作名**（一行一个），详细说明放图里——发布文案有 900 字硬限，展开写必超。

| 图文面积比 | **样本卡** | ① `内容页版式`（页角色拆解要求"内容页卡"必记「图文面积比」，通常并入这一行） |
| 笔触质感（扁平 / 有无描边 / 噪点 / 纸质肌理…） | **样本卡** | ① `笔触质感` |
| 每页文字量 / 每页信息点 | **样本卡**（经 ④ 段落进 `00-overview.md` 与每篇 frontmatter） | ④ 密度五字段 |
| 封面、末页各自的文字量 | **样本卡** | ① `封面文字量` / `末页文字量`（**不进五字段**，见下 ③） |
| 总页数、内容页占比、有无过渡页 | **样本卡** | ① `整套编排` |
| **调色板 / 文字色** | **当前用户的风格档案**（`profile.visual.palette` / `text_color`）——样本卡**不直接覆盖**，但参考样本的配色可经运营拍板固化进档案（见下「⚠️ 待定」区） | 不看样本卡（除非已 PUT 更新档案成功） |
| **人物卡形象** | **当前用户的风格档案**（`profile.visual.character_card`）——同上，样本卡不直接覆盖，可经运营拍板固化 | 不看样本卡（除非已 PUT 更新档案成功） |
| **画布 2:3（1024×1536）与那行负面提示** | ⛔ **后端出图规格，不是风格**——样本卡改不了，**风格档案也改不了** | 不看样本卡 |
| 崩字防治 / 简体硬要求 / 图内无站外导流 | ⛔ **硬要求，不因样本卡放松** | 不看样本卡（见下 ④） |

**⚠️「待定：是否更新进风格档案」区怎么读（本节最容易搞反的一处）**：样本卡 ① 段末尾那块 **⚠️ 待定：是否更新进风格档案**（v1.38.0 时叫"⛔ 记录但不采用"），记的是**参考样本的配色与人物形象**——写在那儿是为了留证据说明"我们看清了它长什么样"，**它既不是待办清单、也不是已经拍板要照做的**。读到「参考样本用米黄+砖红双主色」「参考样本是短发戴眼镜男性」这类行，**先问运营要不要固化进他自己的风格档案**，按拍板结果二选一：

- **选「不更新」** → 保持现档案，参考样本的配色 / 人物**不采用**（行为与 v1.38.0 完全一致）：照旧用**当前档案**的 `palette` / `text_color` / `character_card`。
- **选「更新」** → 创作端先把档案改掉：`--get` 拿全量 → 把 `profile.visual.*` 里要改的字段替换掉 → **整份 PUT**（必须带读到的 `base_version`，**不是打补丁**）；**PUT 成功之后**，本批次及此后他所有笔记都用新配色 / 新人物，`00-overview.md` 的风格档案留痕行同步更新成新版本号。收到 **409 别重试同一份 body**——告诉运营"你的风格档案在别处被改过（v{读到的} → v{`detail.current_version`}），我重新读一遍再改"，重新 `--get` 后再来。
- ⚠️ **没 PUT 成功就不许先斩后奏**：档案还没更新，就照旧用当前档案的取值出图，别"预支"新配色——审查端是按留痕行指定的那一版档案判的，预支必判不一致。
- **把这块内容抄进提示词、却没走过上面的固化流程 = 成图直接判 FAIL**（审查端 `checklist-images.md` 有对应判据）。

> 样本卡 ④ 段的 `emoji 目标` / `引号口径` / `标题结构` 是**正文侧**参数，由 `xiaohongshu-spec.md` 消费，**不改图内文字规范**——第 2 节「图内引号要收敛」照旧生效（小标题 / 标签 / 说明句 / pill 一律不加引号，一页成对引号 ≤2 处；提示词里包裹入图文字的那对引号照写）。唯一例外是封面主/副分工，见下 ⑤。

### ② 与三层组件模板（第 3 节）的关系：背景层不动，文字层与元素层重排

第 3 节封面 / 末页的「背景层 + 文字层 + 元素层」拆分**继续成立**，样本卡只作用在其中两层：

| 层 | 有样本卡时怎么办 |
|---|---|
| **■ 背景层** | **照当前档案原样复用，一个字不改**——底色 / 肌理 / 光影取自 `visual.palette` + `visual.texture`，只出现档案 `palette` 内的颜色（默认配置示例：暖米白 #E8D8C4 纸质肌理、细腻颗粒、柔光无强阴影）。参考样本的底色 / 底纹**不带进来**（除非运营拍板固化进档案，见 ①） |
| **■ 文字层** | **按样本卡 ① `封面版式` 重排**：标题落在画面哪一区、主/副字号比、标题占画面高度的比例、文字量（封面照 ① `封面文字量`、末页照 ① `末页文字量`）——都换成样本卡实测的样子。但**字体气质与字色仍取自当前档案**（`visual.text_color`；默认配置示例：圆润无衬线体，深灰蓝 #5A6B7B / 可选深钢蓝黑 #2B3A4A / 可选赭砖红 #A34B3A 点睛） |
| **■ 元素层** | **按样本卡 ① `封面版式` + `笔触质感` 重排**：主视觉类型（单人物 / 场景物件 / 纯图形）、道具多寡、有无描边、噪点与肌理强弱，照样本卡；但**人物一旦出场，形象仍照当前档案的 `visual.character_card`**（默认配置示例：圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫） |
| **■ 比例参数** | **不动**。仍是 `竖版 2:3 构图（1024×1536）…` 那一整行（含负面提示）。理由见第 3 节那条说明：2:3 是出图后端 `/api/op/consistent-images` 的**真实画布**，声明的画布必须与真实出图一致，否则版面怎么调都白调——它是技术规格，不是可模仿的风格。**参考样本哪怕是 3:4 或 1:1，我们照样出 2:3**（换平台仍只走第 3 节那张比例参数表 / 预览页开关，与样本卡无关） |

内容页同理：每条模板开头那句 **「【风格基底 · 取自当前用户的风格档案】」照写不误**，样本卡改的是它后面的「版式：…」行与各元素的具体画面描述。

### ③ 版式档：样本卡定的档同样走 ①-b 那三档

样本卡 ④ 段的 `版式档` 字段与第 3 节 ①-b **是同一套体系、同一组取值**：`满版` / `少格` / `大字报`，分别对应 ①-b 表里的**满版档 / 少格档 / 大字报档**。

- 出图端**直接读 ④ 段的 `版式档`**，不再自行从信息点数推导（与 v1.37.0 口径一致）。
- 读到哪一档，就照 ①-b 那一档的全套规则执行：铺陈方式、少格版式「格内二次加密」是否降级、「一页只有 1–2 条 = FAIL」是否停用、「一套混用 3–5 种版式」是否停用——**规则一条不改，样本卡只负责选档，不负责改档内规则**。
- 每条提示词「要求」行的收尾四件套照旧，其中「按当前版式档的铺陈方式」这一句自然吃到样本卡定的档。
- ⚠️ **密度五字段只约束内容页 P2…P(N-1)**（v1.37.0 口径，不因样本卡变）。样本卡 ① 里的 `封面文字量` / `末页文字量` 是**另外单独记录的两项**，只用来定封面与末页的字数，**不进五字段、也不参与内容页密度**；反过来也别拿内容页的密度去撑封面。这正是样本卡要求"密度实测分角色统计、绝不把封面的十几字与内容页的几百字平均"的原因（详见 `reference-mimicry-spec.md`）。
- 形态 B（运营只给了封面）时，样本卡 ④ 会注明"内容页密度沿用默认档"——**照默认档做**，别拿封面字数去当内容页密度。

### ④ 这些硬要求不因样本卡放松（一条都不打折）

- **崩字防治**（第 2 节「崩字的真规律 = 单个文字块被迫折行」）：样本卡记录的版式若含**窄竖 pill / 窄色带 / 小徽章**，仍按高危形态处理——该处文字缩到 4 字以内，或把容器改宽改横；反复崩就按三招消因改版式。**"参考样本就是这么排的"不是保留窄容器的理由**——参考样本用排版工具做图不会崩字，我们的出图模型会。模仿到的是"视觉上的窄标签感"，不是"必须让文字在窄容器里折行"。
- **全部图内文字用简体中文、不得繁体或异体**：每条提示词的「要求」行照带，出图后照旧逐字核对。
- **图内刻度名/组名/标签名/打分句须过中文本土化自检**（口径唯一真源 `xiaohongshu-spec.md` §1「中文本土化表达」）：光杆形容词不得当概念名（⛔「强烈 9 分」→ ✓「心动 9 分」），同一篇刻度名全篇恒定。图内文字比正文更容易犯——空间挤，压缩时最先丢的就是着落点（2026-08-06 七篇返工的教训）。
- **图内不得出现任何站外导流**（微信 / 二维码 / 公众号 / 电话 / 加群）：参考样本图上印了二维码，我们也**绝不画**——这属**平台封号级**红线，运营指令与样本卡都不可覆盖（红线三层切分见 `reference-mimicry-spec.md`）。
- **只有封面 P1 守安全区**：那是小红书 feed 按 3:4 裁封面缩略图的**平台行为**，与样本卡无关，照旧执行（避让靠构图描述"标题压在上 1/4 区""底部留出大片空白不放文字"，不写像素数字）。
- **末页仍保留品牌锚句 + 危机声明小字**：即便参考样本的末页只有一句金句，我们的末页照旧带「NBDpsy · 北大硕博纯线上心理咨询」与「心理科普，非诊断治疗 · 援助热线 12356」——前者是**工作室品牌锚句**（所有运营通用，不属于个人风格档案的视觉字段）、后者是执业级合规，**样本卡与风格档案都不可覆盖**。样本卡 ① 的 `末页文字量` 按**这两行之外**的正文量对齐即可（2026-07-26 补充口径）。

### ⑤ 封面主 / 副分工被样本卡覆盖时怎么办

第 3 节那张「**主标题＝核心议题词、副标题＝场景钩子**」的分工表属**产品判断级**——按 2026-07-26 老板定案，**运营给了参考样本就照做**，可被样本卡覆盖。执行判据：

- 样本卡 ③/④ 段记了 `标题结构: 纯场景钩子`，**且 ⑤ 段「覆盖了哪些默认口径」把这条列了出来** → 封面按样本卡排，主标题可以就是场景钩子。
- ⚠️ **⑤ 段点名覆盖了发布标题结构 ＝ 视同点名封面主/副分工**（2026-07-26 v1.38.0 补充口径，堵一个无解约束）：⑤ 段通常只会写「覆盖标题结构」这一条（说的是**发布标题**），不会再单列一行「封面主/副分工」；但第 3 节那张表要求封面主标题＝核心议题词、**且与发布标题同源**——发布标题一旦被改成纯场景钩子，里面根本没有那个目标长尾关键词，「主＝议题词」与「与发布标题同源」**不可能同时成立**，出图端会卡死。所以只要 ⑤ 段列了标题结构那条，封面主/副分工**一并视为被覆盖**，按上一条走（主标题就是那句场景钩子，仍与发布标题同源；副标题按样本卡 ① `封面版式` 排），**不得静默回落到第 3 节的默认分工**。
- **⑤ 段没列 = 没被覆盖 = 照第 3 节的默认分工做**（主＝议题词、副＝场景钩子，两层不得说同一件事）。
- 代价（丢掉议题词这个记忆与搜索锚点）与对应的回撤线**已写在 `xiaohongshu-spec.md` §1，此处不重写**；出图端只照 ⑤ 段执行即可。
- ⚠️ **咨询师推介笔记的封面分工不受样本卡影响**：仍是 主＝咨询师姓名、副＝职称/最硬资质，以 `references/counselor-note-spec.md` §4 的「P1 · 照片封面」为准。

### ⑥ 与批次锚点的衔接：参考图**不是** anchor

- 参考图**绝不喂给出图后端当 anchor**。正确顺序：参考图 + 样本卡 → 写出**我们自己的 P1** 提示词（内容是我们的、版式 / 密度 / 质感照样本卡、**配色与人物卡取自当前用户的风格档案**）→ P1 经运营确认 → P1 落盘 `_shared/BATCH_ANCHOR.txt` → 后续所有页、所有重出一律以 P1 为 anchor。
- 第 4 节「第 1 张定稿后作参考图」那条**照旧成立**，只是这一批 P1 的版式来自样本卡。
- 完整的三条理由见 `reference-mimicry-spec.md`；对出图端最要命的一条是——**参考图的配色会盖掉当前档案的配色**。成图里一旦出现参考样本的配色或人物形象、而档案里并没有这套取值，审查端直接判 FAIL（说明要么误把参考图当了 anchor，要么把"⚠️ 待定：是否更新进风格档案"区当成了已经拍板要照做的——**没 PUT 进档案就不算数**）。

### ⑦ 版权护栏（图侧）

⛔ **不复刻**参考样本里的：人物形象、IP 形象、logo、字体标识、水印。我们模仿的是**版式结构与质感**，不是**具体画面与专属符号**。参考样本里的**原句一句都不许写进图内文字**（著作权 + 平台判重限流），图上文字一律由我们自己的源长文重新写。详见 `reference-mimicry-spec.md` 第六节。

### ⑧ 视频参考图（第 6 节）照旧 3:4

`## 视频参考图提示词` 那一节**不受样本卡影响**：比例仍写 **3:4**（喂 `nbdpsy-text-to-video` image2video 的规格，**同样是技术规格、不随风格档案变**），推导规则（剔除所有图内文字指令、保留当前档案的风格基底与人物卡、末尾追加「画面中无任何文字」）一字不变。样本卡改变的只是轮播页的画面结构，去文字化照第 6 节各版式的既有做法处理即可。

## 4. 一套 6–9 张如何保持风格一致

- **风格基底逐字不变**（同一批次内用同一版档案的取值，逐字不变；跨运营则各用各自档案），每页只改"画面主体"和"文字"两行。
- **第 1 张定稿后作参考图**：Gemini/GPT 支持上传参考图，把定稿的 P1 喂进去让后续页"保持同一画风与人物"，比纯文字复现更稳。
- **当前档案 `palette` 的主色 HEX 在每页都带上**，复制粘贴时不要改（页与页之间色值漂移＝整套散架）。
- 人物在多页出现时，每页都带档案 `character_card` 那一整句，避免长相漂移。

**低密度 → 高密度改写**（拆解/隐喻图最易踩的坑，演示"密度 = 图文共同表达的信息量"）：

❌ 低密度原稿——图在装饰、文字在贴标签，全页只有 3 个抽象点：

```

> 问题：雨云是纯装饰隐喻、不承载信息；3 个标签都是抽象结论，读者看完仍不知道"具体长啥样"。字不算少，但图文没合起来讲清一件事。

✅ 高密度改写——同一主题，把每个抽象点画成看得见的具体场景，图文合起来讲清"怎么判断抑郁症"：

## 6. 视频参考图提示词（去文字版 · 页对页）

每篇笔记文件末尾追加一节 `## 视频参考图提示词`，为轮播的每一页给出一条"去文字版"提示词。

> ⚠️ **视频参考图沿用 3:4，与小红书轮播的 2:3 画布无关**（2026-07-26 定案）——它喂给 `nbdpsy-text-to-video` 的 image2video（画幅按 3:4 推算 834×1112），跟着轮播改会脱钩。本节所有比例行一律写 **3:4**（`竖版 3:4` 或完整标准句 `竖版 3:4 构图（1080×1440）` 均可）；照搬第 1 节风格基底时，把基底里那句 2:3 比例一并换成本节的 3:4。

- **用途**：nbdpsy-text-to-video 图生模式用这套提示词生成"无文字同款图"，当每个镜头的首帧参考图。视频阶段会把旁白烧录成字幕——图内若再有文字，会与字幕重叠打架，所以参考图必须完全无文字。本节只产提示词，图由 nbdpsy-text-to-video 产线按需生成（该产线与出图环节同一套宿主自适应逻辑）。
- **推导规则**：拿该页的绘图提示词，**剔除所有图内文字指令**（「文字：…」「顶部大标题"…"」以及基底里"顶部留出约 1/3 空白用于放标题文字"这类为文字服务的构图指令，可改为"构图完整、留白自然"）；**保留当前档案的风格基底（`palette` 主色 HEX + `texture`）、`character_card` 人物卡、画面主体与版式氛围**；末尾追加一句**「画面中无任何文字」**。
- **页对页**：P1 对 P1、PN 对 PN，画面主体与轮播版**语义呼应**（要点卡页去文字后结构相仿；信息图页有合理例外，见下）。不同版式的去文字化各有讲究：
  - **要点卡页**：把"文字条目"改述为等量的图形元素（小圆图标竖排等），保持画面结构相仿。
  - **信息图页**（对比/流程/象限/数据/拆解）：**别保留没文字的空图表骨架**（空坐标轴、空箭头没有意义、也不适合当视频首帧）；改为回到这一页的**内核场景或隐喻**——用档案 `character_card` 人物的一个相关情绪画面、或该概念的隐喻意象（如对比页→一个人站在两条岔路前；流程页→拾级而上的台阶；数据页→人群中一个被柔光标出的身影），保留当前档案的风格基底与氛围。
  - **隐喻图页**：本就以画面为主，去掉标注即可，隐喻场景原样保留。
- **格式硬约束**：节内每页用加粗标记 `**P1**`…`**PN**` + 围栏提示词；**绝不用 `### PN` 标题**——`### PN` 是「## 配图轮播」的页数计数契约（count_xhs.py 全文数 `### P*`），在本节复用会让页数翻倍误判。
