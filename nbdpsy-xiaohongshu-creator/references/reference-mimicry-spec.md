# 参考样本模仿规格（reference mimicry）

> **这份文档解决什么**（老板 2026-07-26 定案）：运营手里有一篇（或几篇）他觉得对味的小红书图文，
> 想让我们「照着这个做」——**图片风格、信息密度、说话语气**都学过来。以前没有落点：agent 要么把参考图
> 当摆设照旧走默认口径，要么走另一个极端，把对方的配色、人物、甚至句子一起搬过来。
> 本文把「模仿」拆成**可提取、可落盘、可被审查端读取**的三段：**判形态 → 出样本卡 → 下游按样本卡执行**。
>
> **谁读这份文档**：
> - `SKILL.md` 第 0.5 步「吸收参考样本」——判形态、看图、写样本卡，模板逐字取自本文 §3；
> - `references/illustration-spec.md`——有样本卡时怎么写提示词；
> - `references/xiaohongshu-spec.md`——有样本卡时怎么写正文；
> - `nbdpsy-content-reviewer/references/checklist-note.md` / `checklist-images.md`——按样本卡判，不按默认判。
>
> **没有参考样本时，本文整篇不适用**——第 1 步照常走默认口径（v1.39.0 起"默认口径"= **当前用户的风格档案**，
> 档案里没写的项才退到 skill 内置默认值），不需要建样本卡。
>
> **⚠️ 别把样本卡和风格档案搞混（v1.39.0）**：**样本卡是批次级、一次性的**（只管这一批）；
> **风格档案是用户级、长期的**（管这个运营此后的每一批，有版本号、可回退）。
> 把样本卡的某一条变成长期口径，**是一次要运营拍板的显式动作，不是自动同步**——完整规则见 **§3.3**。

## 0. 全流程一句话

```
运营给图片路径
  → 判输入形态（A / B / C）
  → 逐张 Read 看图、分「页角色」提取
  → 写 {note_dir}/_shared/style-card.md（样本卡）
  → 归一化结果回读给运营确认一次
  → 问运营：① 段「待定」项要不要固化进他的风格档案（要 → 整份 PUT 存新版本，见 §3.3）
  → 密度五字段填进 00-overview.md → 正文与提示词按样本卡执行
  → 我们自己的 P1 出图并经运营确认 → P1 才是批次锚点
```

**输入只收图片文件路径**（agent 用 Read 工具逐张看图）。**给链接不行**——本 skill **不做站外抓取**，
运营需自己截图或把内容粘过来。

### 1.1 哪些学、哪些不学（v1.39.0：「不学」那一档改为**由运营拍板**）

> **v1.39.0 反转（老板 2026-07-26 下午定案）**：视觉基底不再是全局品牌常量，而是**每个运营各自一份的风格档案**
> （`profile.visual.*` / `profile.tone.*` / `profile.structure.*` / `profile.density.*`）。
> 下面写出来的莫兰迪三色与固定人物卡，**降级为「默认配置」的取值——是示例，不是常量**。
> 别的运营的档案可以与它**完全不同**（多号矩阵各有各的调性），照他自己那一份做就对了。
> 档案怎么读（`--get`、三层降级、`00-overview.md` 的版本留痕行）见 `SKILL.md` 开工前那一步。

| | 内容 | 处理 |
|---|---|---|
| ⚠️ **默认不学，但可被运营固化**（当前用户风格档案里的视觉资产） | **配色**与**人物卡**——即当前档案的 `profile.visual.palette` / `text_color` / `character_card`。<br>默认配置的**示例取值**：莫兰迪三色 雾霾蓝灰 `#A8B5C4` / 暖米白 `#E8D8C4` / 鼠尾草绿 `#C9D6CE`（含赭砖红 `#A34B3A`、深钢蓝黑 `#2B3A4A`、深灰蓝 `#5A6B7B` 这套完整调色板）；人物卡=圆脸、齐肩微卷短发的东亚年轻女性，穿燕麦色针织衫，神情温和平静。**这是默认配置长什么样，不是所有人的常量** | 参考样本的配色与人物形象记进样本卡 ① 段的**「⚠️ 待定：是否更新进风格档案」**区，**由运营拍板**（§3.1）：<br>· 选 **不更新** → 本批出图仍按当前档案的配色与人物卡（行为与 v1.38.0 完全一致）；<br>· 选 **更新** → 整份 `PUT` 存成档案的新版本，**此后他本人所有笔记都用新配色 / 新人物**（怎么走见 §3.3） |
| ✅ **学**（批次级，不进档案也照样生效） | 版式结构、分区数、信息密度、图文面积比、笔触质感、说话语气（人称/句长/emoji/引号/段落节奏）、开头钩子与结尾落点的形态、整套编排（页数、递进方式） | 提取进样本卡 ①②③，推导进 ④，下游直接读。**默认只对本批次生效**；要长期生效同样得走 §3.3 的固化动作 |
| **不变**（既不属"学"也不属"不学"，是技术参数） | 画布 **2:3（1024×1536）**——出图后端实际出的就是这个尺寸，**不随样本卡变、也不随风格档案变**（哪怕参考样本是 3:4 或 1:1，哪怕某个档案里写了别的比例） | 见 `illustration-spec.md` 比例参数一节 |

> **为什么配色与人物卡默认不跟着参考样本走**：它们是**跨这个运营所有笔记复用的识别系统**，某一篇跟着参考样本换掉，
> 这一批就从他的号里"掉出来"了；而版式、密度、语气是**单批可变的表达选择**，换了不伤识别。
> **但"默认不换"不等于"不能换"**——运营真想整体换个调性，正确做法不是让某一批偷偷跑偏，
> 而是**把新配色 / 新人物明确固化进他的风格档案**（§3.3），之后每一篇都稳定用新的那一套。
>
> ⚠️ **风格档案管的是视觉与语气，不管合规**：§1.2 的**法律 / 执业级**与**平台封号级**这两层红线，
> **既不能被样本卡覆盖，也不能靠"写进风格档案"绕过**。把红线项写进档案 = 无效，出图与正文照判 FAIL。

### 1.2 红线三层切分（**运营指令只能覆盖第三层**）

| 层 | 内容 | 能否被参考样本覆盖 |
|---|---|---|
| **法律 / 执业级** | **F1 公域冻结**（疗法对比「EMDR / 图式 / IFS / CBT 哪个适合你」、服药与咨询的先后顺序、用药 / 停药 / 诊断建议）；**G5 案例可反向识别**（来访隐私）；以及 G2 躯体分流、G3 不给第三人贴标签这类**撞执业资质与就医安全**的条款 | ⛔ **不可覆盖**。参考图这么写**也不照做**，在报告里单独列出并说明理由 |
| **平台封号级** | 站外导流（微信号 / 二维码 / 外链 / 加群 / 网盘）、G7 黑名单 CTA 及其谐音变体 | ⛔ **不可覆盖**。同上 |
| **产品判断级** | 术语做落点、自测句式（「对上 3 条你就是」）、恐惧钩子（「再不管就晚了」）、P4 代价显影、密度 / emoji / 引号 / 标题结构等**风格判断** | ✅ **可覆盖**（老板 2026-07-26 定案：运营给了就照做） |

**⚠️ 拿不准某条属于哪一层时的判法**：问一句「违反它会怎样」——
**吊照 / 延误就医 / 泄露来访隐私 = 第一层；封号 / 限流处罚 = 第二层；只是我们自己觉得转化不好 = 第三层**。
判不出来就**停下来问运营**，不要自行归到第三层放行。

**⚠️ 风格档案不改变这张表（v1.39.0）**：前两层**不因"运营把它写进了自己的风格档案"而放行**——
风格档案能自定义的只有**视觉与语气**（配色、人物、版式、密度、句长、emoji、引号……），
**没有一个字段能豁免合规**。运营要求把第一层 / 第二层的做法固化进档案 → **拒绝并说明理由**，
只固化那一条里合规的部分（例：可以固化"更强的钩子语气"，不能固化"站外导流句式"）。

### 1.3 覆盖必须留痕（格式写死，审查端按这一行放行）

在 `00-overview.md` 里写明一行。**下面是带占位的模板，不是可以照抄的成品**——
`< >` 里的内容**每批现填**，条款名逐字取自**本批样本卡 ⑤ 段**：

```
参考样本覆盖：按运营参考样本放开了「<⑤ 段逐条列出的条款，逐字同名>」——覆盖 checklist 判据 <对应判据号> 对应条款
```

**填法示例**（对应 §3.1 那张样本卡的 ⑤ 段，两边**列的是同一批条款、逐字同名**）：

```
参考样本覆盖：按运营参考样本放开了「标题前 10 字必须含目标长尾词」「emoji 默认区间 8–14」——覆盖 checklist 判据 0②、9 对应条款
```

- **`<对应判据号>` 怎么填**（编号照 `checklist-note.md`）：标题结构 → **0②**；密度五字段 → **6**；

- ⚠️ **被点名 ≠ 全免**：`xiaohongshu-spec.md` §1.7 D 给「术语做落点 / 自测句式 / 恐惧钩子 / P4 代价显影」四条

- 同一批次的样本卡 ⑤ 段要与这一行**列的是同一批条款**——两边对不上，以样本卡 ⑤ 为准并修正 `00-overview.md`。

## 2. 输入形态（**三种，先判形态再提取；判错了提出来的规格全是废的**）

| 形态 | 长什么样 | 能学到什么 | 提取方式 |
|---|---|---|---|
| **A · 整篇多页**（**最常见**） | 一个完整笔记的全部页：封面 + 若干内容页 + 末页 | **页角色分工 + 整套编排** | **按页角色分别拆解**，见 §2.2 |
| **B · 多篇单页** | 若干篇不同笔记，每篇只给了封面（或零散页） | **账号的稳定风格**（跨篇共性） | 提共性；只在 1 篇出现的特征**降级为「可选参考」** |
| **C · 多篇多页**（最理想） | 两三个完整笔记 | A + B 全都有 | 先按 A 拆每篇，**再跨篇取共性** |

### 2.1 判定与两条纪律

- **怎么判**：看运营给了几组图、每组是不是能拼成一篇完整笔记（有没有大标题封面、有没有带 CTA / 金句的末页）。
  一组完整 = A；多组只给单页 = B；多组完整 = C。
- **顺序即页序**：形态 A/C 时，运营给图的**顺序就是页序**。顺序不明（文件名无序、运营没说）→ **先问一句，别猜**——
  页序猜错，「整套编排」和「末页收尾方式」两项直接是错的。
- **单张样本必须提示运营**：单张能提取的只有这一篇的特征，**容易把偶然特征**（某篇特有的版式实验）**当成风格**。
  提示原话可用：「只有 1 张的话，我提出来的风格可能是这篇的偶然做法。方便的话再给 2 张，或至少给全一篇的所有页。」
  **提示后照常执行，不阻塞。** 此时样本卡里所有条目的置信度都是 `低`。
  - **单张一律按形态 B 处理**（2026-07-26 定案，别在这里犹豫）：1 张封面既拼不成完整一篇（不是 A）、
    也谈不上跨篇共性（不是 B 的原义），`样本形态` 会**没有合法取值**。**定死**：`样本形态: B` / `样本张数: 1`，
    **全部条目置信度 `低`**，**密度五字段沿用默认档**（同 §4 形态 B 那一行），并在样本卡 ④ 注明
    「参考样本只含封面，内容页密度沿用默认档」。**⛔ 绝不许拿这张封面的字数去填内容页密度。**

### 2.2 形态 A/C 的页角色拆解（**核心：绝不可把各页混在一起统计**）

先给每张图判角色——依据：**文字量、有无大标题、有无 CTA / 引导语、在序列中的位置**——再**分角色各出一份规格**：

| 角色 | 提取什么 |
|---|---|
| **封面卡** | 主 / 副标题的层级与字号比、标题位置与占画面比、有无人物、主视觉类型、**文字量**（通常 10–20 字） |
| **内容页卡** | 版式类型（对比 / 流程 / 象限 / 清单…）、分区数、**文字量与信息点数**、图文面积比、小图风格、有无格内二次加密 |
| **末页卡** | 收尾方式（行动建议 / 金句 / 推介 / 危机声明）、**文字量**、有没有 CTA 及其强度 |
| **整套编排** | 总页数、内容页占比、有无过渡页、信息递进方式（总分 / 并列 / 递进 / 故事线）、页间靠什么维持一致 |

⚠️ **密度实测必须分角色统计，绝不可把封面的 15 字与内容页的 300 字平均**——
平均出来的数字**既不像封面也不像内容页**，照它出图两头都不对（封面被灌满、内容页被掏空）。

### 2.3 与 v1.37.0「档位只约束内容页」的对齐（**这层必须讲清**）

v1.37.0 已经定过：**密度五字段只约束内容页 P2…P(N-1)**，封面 P1 与末页 PN 始终精简、不受档位管
（`SKILL.md` 第 1 步「信息密度档位」）。参考样本的分角色统计与它**天然对齐**：

> **只有「内容页卡」的密度进密度五字段**（`每页文字量` / `每页信息点` / `版式档`）；
> **封面卡与末页卡的文字量单独记录在样本卡 ① 里，不进五字段**。

两边是同一件事的两个说法——一边说"这三个字段只管内容页"，一边说"只有内容页的实测值能填这三个字段"。
所以**不需要为参考样本改动 v1.37.0 的任何口径**，照它执行即可。

### 2.4 密度实测怎么做：**agent 逐张目视数，无脚本**

⛔ **本 skill 没有、也不会有 `analyze_reference.py` 这类分析脚本，别去找、别去写。**
图内文字量**只能靠视觉模型逐张数**——参考样本是**图片**，字在像素里，`count_xhs.py` 只能数 md 文本，数不到图。
（接 OCR 理论上可行，**本次不做**。）

**目视实测的操作口径**（保证两个 agent 数出来的结果不会差一倍）：

- **只数汉字**，emoji、标点、数字与英文单词不计（与 `count_xhs.py` 的正文口径一致，便于跨端对齐）；
- **一页一个数**，给区间不给单值——如「图2–图6：118–140 字」，区间下界与上界都写出来；
- **「信息点」的数法**：**一个独立的、能单独复述的认知 = 1 个信息点**。一格里"小图 + 一句说明"讲的是同一件事 = 1 个；
  同一格里再挂一条二次说明（格内二次加密）且它是新信息 = 再 +1。标题、页码、装饰不计；
- **数完写进样本卡的「证据」列**（写"图2–图6 逐张数"），不写具体原句（原因见 §6）。

## 3. 样本卡 `_shared/style-card.md`

**落盘位置**：`{note_dir}/_shared/style-card.md`——**批次级，与 `BATCH_ANCHOR.txt` 同目录**。
一批只有一张样本卡（跨这批所有篇生效）。

**每条都必须标注两样**：

| 列 | 要求 |
|---|---|
| **证据** | 第几张图的什么位置（「图1 上部」「图2–图6 逐张数」「正文首行」）。**只写位置，不摘原文**（§6） |
| **置信度** | `高` = N≥3 张都有 / `中` = 2 张有 / `低` = 仅 1 张有。**形态 B 里只在 1 篇出现的特征一律 `低`，且在下游按"可选参考"处理，不当硬约束** |

### 3.1 完整模板（**跨 6 个文件的接口，结构必须逐字一致**）

```markdown
# 样本卡（style-card）

样本形态: A          # A 整篇多页 | B 多篇单页 | C 多篇多页（只给 1 张一律填 B，见 §2.1）
样本张数: 8
样本构成: 1 篇完整笔记（P1 封面 + P2–P7 内容页 + P8 末页）
提取日期: 2026-07-26

## ① 视觉（配色与人物卡另见本段末「待定」区）
```

### 3.2 ④ 段填写的四条硬规则（**别在这里发明新取值**）

1. **五个字段名逐字照 v1.37.0**：`信息密度档位` / `每页文字量` / `每页信息点` / `版式档` / `运营原话`，
   一个不能少、不能改名——`00-overview.md` 与每篇 post 的 frontmatter 都要有同一组值。
   ⚠️ **唯一例外是场景四**（运营既给参考图又口头指定）：④ 保留实测值、overview 与 frontmatter 填口头值，
   并靠 ④ 的注明行把两者接起来，见 **§4.1**。
2. **取值域不扩展**：`信息密度档位` 只有 `默认` | `运营指定` 两个取值——**样本卡实测出来的密度写 `运营指定`**
   （运营给参考图就是一次意图表达）。⚠️ **这是合法值，不是"上游漏填"**，审查端不得据此判缺字段。

   - 只给了参考图、没口头说密度 → `按参考样本（N 张，形态 X）实测`
   - 既给参考图、又口头指定了密度（场景四）→ **合成格式**（见 §4）：
     `"每页 300 字"（参考样本 8 张/形态 A 实测 118–140 字，已被口头覆盖）`
   - 形态 B（含单张，提取不到内容页密度）→ `—`（五字段整体沿用默认档）

   `版式档` 仍只有 `满版` / `少格` / `大字报` 三个取值，**按 SKILL.md 第 1 步的落档规则由实测信息点数落档**
   （区间取下界：实测 2–3 个 → 落 `大字报`），创作端定死、审查端直接读，不新增第四个取值。
3. **④ 段之外的三行**（`emoji 目标` / `引号口径` / `标题结构`）**不是密度五字段**，
   它们是给正文端（`xiaohongshu-spec.md`）看的语气与结构覆盖项，**不要塞进 frontmatter 的五字段区**。
4. **实测区间的上界即硬上限**（写死，别按"区间只是参考值"理解）：`每页文字量` / `每页信息点` 写成区间时，
   **上界就是审查端的硬上限**——`每页文字量: 118–140 字` → 审查端跑 `--density-max 140`，做出 141 字即超限判 major；
   `每页信息点: 6–8 个` → `--density-points 8`；写成单值（`6 个`）时上限就是那个值本身。
   所以**别为了"留点余量"把区间写宽**——上界写成 180，这批的实际上限就真是 180。
   ⚠️ 与 `版式档` 的落档规则**方向相反、不要搞混**：`版式档` 由信息点数**取下界**落档（实测 2–3 个 → `大字报`），
   而字数/信息点进硬上限是**取上界**。一个是"落哪一档"，一个是"档内不许超到哪"。

### 3.3 样本卡 → 风格档案的字段映射（v1.39.0 新增）

#### 先分清这两样东西（**混了就会出大错**）

| | **样本卡** `_shared/style-card.md` | **风格档案** `profile`（服务端） |
|---|---|---|
| 作用域 | **批次级**——只管这一批笔记 | **用户级**——这个运营此后的每一批 |
| 生命周期 | **一次性**，这批做完就留在批次目录里当证据 | **长期**，有版本号、有历史、可回退 |
| 谁写 | agent 拆解参考样本后落盘 | **只在运营明确拍板时**才被写入（`PUT`） |
| 怎么生效 | 下游读文件 | 开工前 `style_profile.py --get` 读回来 |

> ⚠️ **固化是一次显式动作，不是自动同步。**
> 写了样本卡 **≠** 档案被改了；样本卡里的任何一条，**不问运营就不许写进档案**。
> 反过来也一样：档案更新了，**不会回头改已经落盘的老样本卡**（老批次留的是它当时的证据，改了就没法复核了）。
> **绝大多数批次的正常结局是"档案一个字都不动"**——样本卡执行完这一批就结束。

#### 字段映射（**问运营"要不要固化"时，就按这张表把样本卡的条目搬进 `profile`**）

| 样本卡 | → `profile` 里的位置 | 搬什么 |
|---|---|---|
| **① 视觉** | `profile.visual.*` | 配色 → `palette`；文字色 → `text_color`；人物形象 → `character_card`；笔触质感 → `texture`；封面版式 → `cover_layout`；内容页版式 → `content_layout`（字段名以 `illustration-spec.md` 的基底块为准） |
| **② 语气** | `profile.tone.*` | 人称、句长、emoji（数量与款式）、引号口径、段落节奏——逐项搬（对应关系见 `xiaohongshu-spec.md` §1.7 B 那张表的「风格档案字段」列） |
| **③ 结构** | `profile.structure.*` | 开头钩子、标题结构、正文推进、结尾落点的**形态** |
| **④ 推导出的参数** | `profile.density.*` | **五个中文 key 原样搬，一个字都不许翻成英文**：<br>`信息密度档位` / `每页文字量` / `每页信息点` / `版式档` / `运营原话`<br>（v1.37.0 起创作端与审查端都按这五个中文 key 读写，**改名即断链**） |
| ④ 段之外的三行 | 拆开放 | `emoji 目标` / `引号口径` → `profile.tone.*`；`标题结构` → `profile.structure.*`。**它们不是密度五字段**，别塞进 `profile.density` |
| **⑤ 覆盖了哪些默认口径** | **不进档案** | ⑤ 段是**这一批**的放行清单，跟着 `00-overview.md` 的留痕行走（§1.3）。要长期放开某条默认口径，是把**新口径本身**固化进 ①②③④ 对应字段，不是把"⑤ 段"搬进去 |

- **`④` 里 `运营原话` 固化时记的是"这份档案的密度档是怎么定下来的"**，不是某一批的临时说法——
  写成 `按 2026-07-26 参考样本（8 张，形态 A）实测固化` 这种能追溯的句子，别把 `—` 或半句话搬上去。
- **样本卡里没提取到的项，不要凭空造一个塞进档案**——档案里读不到某项 = 那项没被自定义 = 下游照 skill 默认走。
  拿一个瞎编的值填进去，等于给这个运营**永久**加了一条没人知道出处的口径。

#### 怎么固化（照做，别自行发挥）

1. **先 `--get` 拿全量**，记下响应里的 **`base_version`**（认这个字段名，别去找 `version`）。
   **server 与脚本都无条件下发 `base_version`**——有档案给当前版本号、`exists:false` 时给 `0`，
   **它是"下一次 PUT 该传什么"的唯一真源，直接照抄，不要自己推、也别按 `exists` 分支去换算**；
2. 在**完整 profile** 上把运营点头的那几个字段替换掉——**其余字段原样保留**；
3. **整份 `PUT`**（`--put <完整 profile.json> --base-version {刚读到的 base_version} --source reference_sample --note "按参考样本（N 张，形态 X）固化"`）。
   带上 `--source reference_sample` 才能在历史里看出这一版是从参考样本来的（默认会落成 `manual`，来源就失真了）。
   ⚠️ **`PUT` 是整份覆盖不是打补丁**：只发被改的字段会把其余字段**清空**。改一个字段也要先 GET 拿全量再整份发；
4. **收到 409 别重试同一份 body**——说明档案在别处被改过了。按响应 `detail.current_version` 告诉运营
   「你的风格档案在别处被改过（v{你读到的} → v{current}），我重新读一遍再改」，**重新 `--get` 后从第 1 步再来**；
5. **200 之后先读响应里的 `dropped_keys`，读完才准往下走**（`--rollback` 同理）——
   server 拿上一版比出来的「这次覆盖冲掉了哪些字段」，只比两层（顶层 + 二级；顶层整段消失只报顶层名、不展开），
   **无丢弃时给 `[]` 而不是省略这个键**（首次建档也是 `[]`），可以无条件读，不用先判它在不在。
   - `[]` → 正常，进第 6 步；
   - **非空**（如 `["tone", "visual.character_card", "visual.text_color"]`）→ **停下来当场回读给运营确认**
     「这次固化会丢掉这几项——语气整段、人物卡、文字色，确定吗？」，**拿到明确答复再进第 6 步**。
   ⛔ **固化正是丢字段的高发点**：最常见的错法就是只把改过的 `visual` 发上去，把 `tone` / `structure` / `density`
   整段冲掉，而 **server 只告知、不拦截也不报错**，PUT 照样 200。运营说不是有意的 →
   **被丢字段的值从 `--version <上一版号>` 取回**——⚠️ **光重新 `--get` 救不回来**：覆盖已经生效，
   GET 拿到的正是刚存进去那份缺字段的新版。取回值 → 补进完整 profile → 整份再发一次
   （`--base-version` 用这次新 `--get` 响应里的 `base_version`）；
6. 成功后把新版本号回填两处：样本卡 ① 段那一行（`已固化进风格档案 v{新版本号}`）与
   `00-overview.md` 的风格档案留痕行。

> **不确定要不要固化时，默认"不更新"并问一句**：不更新只影响这一批（还能改），
> 更新会影响他此后每一篇（虽然能回退，但中间产出的图已经发出去了）。**可逆代价小的那一边是默认。**

## 4. 优先级链（**必须写死，三方都要有**）

```
运营的显式口头指令  >  样本卡实测  >  当前用户的风格档案  >  skill 默认口径
```

（v1.39.0 在链中间插入了「风格档案」这一层：**它比 skill 内置默认值优先，但比这一批的样本卡靠后**——
样本卡是运营为这一批专门给的材料，比他的长期档案更贴近当下意图。
**档案里读不到的项 = 那项没被自定义，继续往右退到 skill 默认。**）

| 情形 | 怎么办 |
|---|---|
| 运营既给了参考图、又口头说「每页 300 字」（**场景四**） | **听口头的**（口头是更直接的意图表达）；④ 段字段值的落法**写死在下方「场景四怎么落字段」**，照着填，别自行发挥 |
| **形态 B（只给了封面），提取不到内容页密度** | 密度五字段**沿用默认档**（`默认` / `200–400 字` / `6–10 个` / `满版` / `—`），在样本卡 ④ 注明「参考样本只含封面，内容页密度沿用默认档」。**⛔ 绝不许拿封面的字数去填内容页密度**——封面十几个字，填进去等于凭空把这批打成大字报档，整批内容页会被掏空 |
| 形态 A/C 但某几页角色判不明（如过渡页） | 该页**不计入内容页密度统计**，在样本卡 ① 的「整套编排」里记一句「有 N 页过渡页」即可 |
| 样本卡实测与 skill 默认冲突（如 emoji 6 个 vs 默认 8–14） | **听样本卡的**，并在 ⑤ 段列明"覆盖了哪一条默认口径"——⑤ 段没列 = 审查端照默认判 = 会被判 FAIL |
| **样本卡实测与当前用户的风格档案冲突**（如档案写 emoji 4 个、样本卡实测 6 个） | **听样本卡的**（它在链上更靠左），⑤ 段照常留痕。**档案不因此被改**——要改得走 §3.3 问运营 |
| 样本卡实测项落在**法律/执业级或平台封号级** | **不采纳**，在报告里单列并写明理由（§1.2）。⚠️ **不要塞进 ① 段的「⚠️ 待定：是否更新进风格档案」区**——那个区是等运营拍板要不要**固化**的，红线项根本没有"可以固化"这个选项，摆进去等于给运营一个不该有的按钮 |

**归一化结果必须回读给运营确认一次**——与第 1 步密度档位的做法一致，一句话即可：
「按参考样本执行：每页 118–140 字、6 个信息点、满版；emoji 约 6 个；标题走纯场景钩子（会放弃搜索入口）。」
确认后再开写。（**场景四的回读话术见 §4.1 末尾**——报的是口头值，不是实测值。）

**回读的同一句话里把「要不要固化」一并问掉**（别分两次打扰运营），例：
「……另外参考样本是米黄+砖红配色、人物是短发戴眼镜男性，**这批先按你现在的风格档案做**；
要不要把它们更新进你的风格档案、以后每篇都用这一套？（更新后可以随时回退到旧版本。）」
**运营没明确说"更新"就是不更新**——`PUT` 只在他点头时才发（§3.3）。

### 4.1 场景四（**既给参考图、又开口指定**）怎么落字段（2026-07-26 定死，创作端与审查端同源）

**三条一起看，缺一条下游就会判错**：

1. **样本卡 ④ 的字段值保留「实测值」**——④ 是**样本卡**，记的是"参考样本长什么样"，不是"这批最后按什么做"。
   实测 118–140 字就写 118–140 字，**不要改写成 300**（改了就把唯一一份实测证据抹掉了，
   后面没人能复核"归一化对不对"）。
2. **运营的口头值只进 `00-overview.md` 与每篇 post 的 frontmatter**——那两处是"这批实际怎么做"的落点，
   五字段填口头值（`每页文字量: 300 字`）。**这是场景四下 ④ 与 overview 唯一允许的不一致**，
   靠下面第 3 条的注明行把两者接起来。
3. **④ 段必须加一行注明 + `运营原话` 用合成格式**（逐字照抄这两行的写法）：

```markdown
## ④ 推导出的参数（**下游直接读这一段**）

信息密度档位: 运营指定
每页文字量: 118–140 字
每页信息点: 6 个
版式档: 满版
运营原话: "每页 300 字"（参考样本 8 张/形态 A 实测 118–140 字，已被口头覆盖）

每页文字量 由运营口头指定覆盖样本实测值（实测 118–140 字 → 口头 300 字）
```

- **注明行**（最后那行「由运营口头指定覆盖样本实测值……」）是**审查端识别场景四的唯一标志**：
  ④ 段有它 = 允许 `00-overview.md` 的五字段与 ④ 不一致；**没有它 = 两边必须逐字一致**，不一致就是上游填错。
  被口头覆盖了几个字段就写几行（`每页信息点` 也被口头改了就再写一行）。
- **`运营原话` 的合成格式两半都不能少**：前半是**运营真说过的那句话**（带引号原样引），
  后半是**被它覆盖掉的实测值**。留着前半，v1.37.0 那条「归一化结果与运营原话明显不符 = FAIL」的复核才有得比
  （审查端能看到运营真说过什么）；留着后半，实测证据不丢。**别只写一半。**
- **回读给运营时报口头值**：「按你说的每页 300 字做（参考样本实测是 118–140 字，以你说的为准）；
  其余按参考样本：6 个信息点、满版、emoji 约 6 个……」

## 5. 与锚点纪律的衔接（**关键技术设计，别搞反**）

**参考图不直接当整批 anchor。** 正确流程：

1. 参考图 + 样本卡 → 生成**我们自己的 P1**（内容是我们的、版式 / 密度 / 质感模仿参考样本、
   **配色与人物卡取自当前用户的风格档案**——若运营已按 §3.3 把新配色 / 新人物固化进档案，
   这里用的就是**固化后那一版**，先跑 `--get` 确认拿到的是新版本再出 P1）；
2. P1 经运营确认 → **P1 成为批次锚点**，写进 `{note_dir}/_shared/BATCH_ANCHOR.txt`（沿用 v1.37.0 的落盘步骤，
   见 `SKILL.md` 出图章节，命令与参数一个字都不改）；
3. 后续所有页、所有次重出，一律用 P1 当 anchor。

**为什么不拿参考图直接当 anchor**（三条理由，缺一都会被下游误用）：

- 参考图带着**别人的具体文字与版式**，当 anchor 会把对方的内容特征**传染到我们每一页**；
- 违反既有纪律「**锚点图自始至终只有一张**（第 1 步确认的 P1）」——一批两个锚点，风格必然分叉；
- 参考图的**配色会盖掉当前档案的视觉基底**（成图里出现**当前档案之外**的配色 / 人物 = 图审 FAIL）。
  ⚠️ 注意这条判据说的是"**当前档案之外**"，不是"参考样本的配色"——运营若已按 §3.3 把参考样本的配色固化进档案，
  那套配色**就是**当前档案的取值，此后成图用它**不判 FAIL**；判据永远对着**留痕行指定的那一版档案**比，
  不是对着莫兰迪三色比。

⚠️ 参考图**不进** `_shared/BATCH_ANCHOR.txt`、**不作** `--anchor-url` 的参数、**不上传**到出图后端。
它的全部作用在**生成 P1 提示词的那一刻**就结束了；此后一切以样本卡（文字规格）为准。

## 6. 版权与同质化护栏（**不可覆盖，属法律 / 平台层**）

- **模仿风格 ≠ 抄文案**：参考样本里的句子**一句原文都不许照搬**（著作权 + 平台判重限流）。
  样本卡里只记录**结构与特征**（「第二人称、句长 14 字、每段末挂一个 emoji」），**不摘录原句**——
  摘了下游 agent 就会顺手抄进去。**样本卡「证据」列写位置，不写原文。**
- **事实与数据仍须溯源到我们自己的源长文**：参考样本里的统计 / 结论 / 案例**一律不得采用**（既有铁律不动）。
  参考样本说"78% 的人有这个问题"，我们**不跟着写**——除非我们的源长文里本来就有这个数据与出处。
- **不复刻**：参考样本里的**人物形象、IP 形象、logo、字体标识、水印**。
  ⚠️ **固化进风格档案也不例外（v1.39.0）**：运营选了"更新人物形象"，能写进 `profile.visual.character_card` 的
  只是**一句抽象的人物设定**（"短发、戴细框眼镜、穿深色毛衣的东亚年轻男性，神情松弛"），
  **不是**对方那个具体角色的**复刻描述**（不写"和 XX 号那个 IP 一样"、不描摹其独有的角色标识 / 五官画法 / 签名画风），
  **更不许把 logo、水印、字体标识写进任何档案字段**。**换的是"我们自己的人长什么样"，不是"把别人的人搬过来"。**
  这一条属法律层，**风格档案自主不覆盖它**。
- **审查端会查**：样本卡里出现参考样本的原句摘录、或产出正文与参考样本句子高度雷同 = **FAIL**
  （见 `nbdpsy-content-reviewer/references/checklist-note.md`）。
