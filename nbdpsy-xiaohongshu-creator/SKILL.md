# 小红书图文笔记创作（从 pillar 长文拆分）

承接 `nbdpsy-seo-artical-creator` 产出的心理科普 pillar 长文，把一篇 4000+ 字的长文拆成 **5–8 条可直接发小红书的图文笔记**。每条笔记 = 一段 **~300 字正文** + 一套 **6–9 页"PPT 式"轮播插图**（每页给出"页面文字"+"中文绘图提示词"，提示词把要显示在图上的中文直接写进去，复制即可喂给 Gemini/GPT 出图）。

**项目背景一句话**：NBDpsy 是咨询师全员北大硕博的纯线上华人心理咨询工作室。官网 pillar 长文负责被搜索引擎/AI 引擎收录；小红书负责触达正在 emo、正在内耗、正在搜"怎么办"的真人。长文重信源与循证，小红书重共情与钩子——本 skill 的使命是把前者的可信内容，翻译成后者的语言，**绝不在翻译中编造新事实**。

## 三条贯穿全程的铁律（理解动机，别只背规则）

1. **不新增未验证事实**。统计数字、专家引语、出处只能沿用 pillar 原文里已核实过的内容。短文里出现的每个数字，都要能在源长文里找到。小红书没有参考文献区，但"编造一个数据被扒出来"对一个心理工作室是致命的——所以宁可少写一个数字，不可造一个。
2. **合规红线高于传播效果**。心理/健康类是小红书重点审核领域：极限词（最/第一/根治/100%/彻底）违广告法、医疗词（治疗/治愈/诊断）非医疗机构禁用、站外导流（微信/二维码/加群）直接限流封号。详见 `references/xiaohongshu-spec.md`，发布前用脚本扫一遍。
3. **发布走双轨：自动优先、人工兜底**。配图按「出图（后端一致性出图优先，宿主自适应兜底）」章节产出（凭据在位时首选后端 gpt-image 锚点法自动出图，缺凭据才由宿主自动生成或人工把每页提示词喂给 Gemini/GPT）。发布环节：若本机配了 `NBDPSY_XHS_API_KEY`（管理员发的运营接入包带此凭据），用 `scripts/publish_note.py` 经 nbdpsy-api（自建 REST 服务）自动发布——**发布前必须经运营确认账号与篇目**；没配凭据则回到人工发布，交付时把"怎么发"讲清楚。

多步任务先维护一份任务清单，每步勾掉。

> **路径约定**：以下 `{SKILL_DIR}` 指本 SKILL.md 所在目录；`{workspace}` 指内容工作区（实际路径用 `python3 {SKILL_DIR}/scripts/nbdpsy_common.py workspace` 查询）；`{note_dir}` 指一次拆分的产物目录 `{workspace}/xiaohongshu/{slug}/`。

## 完整流程（0–7 步，每步都有验证闸门）

```
0. 定位源长文               → 验证：拿到源长文的本地 md 路径（fetch_post.py 输出的 path）
1. 规划拆分                 → 验证：**素材台账每页有独立出处**→篇数由材料定（≤8，可少于 5）；每篇一个独立钩子、彼此不重叠
2. 写正文（每篇 ~300 字）    → 验证：count_xhs.py 字数达标 + 钩子/分点/CTA 齐 + 不新增未验证事实
3. 设计配图轮播（6–9 页）    → 验证：每页复用固定品牌基底 + 图中文字短 + 首页是钩子封面 + 视频参考图提示词页对页齐
4. 合规校验                 → 验证：check_compliance.py 逐篇全绿 + 危机声明每篇在位 + 语义自检过
5. 落盘 + 预览页 + 笔记审查  → 验证：一篇一文件写入 {note_dir}，含 00-overview 与 {note_dir名}-preview.html；笔记对抗审查 PASS
6. 出图（宿主自适应）+ 图审  → 验证：{note_dir}/images/post-NN/P01…PNN.png 齐全；图片对抗审查 PASS
7. 发布（自动可选）或交付     → 验证：自动=publish_note.py 轮询到 published 拿到 note_url；人工=给出文件路径 + 发布要点（首图最重要/2:3/标签/危机声明保留）
```

### 第 0 步 · 定位源长文

按输入类型三选一：

- **用户给了 slug** → `python3 {SKILL_DIR}/scripts/fetch_post.py --slug <slug>`：自动从官网公开 API 拉取全文，落到 `{workspace}/drafts/{slug}.md`（stdout 输出 JSON，`path` 字段即文件路径；本地已有同名文件直接复用缓存、不打网络。要落到别处加 `--out <目录>`）。
- **用户没给** → `python3 {SKILL_DIR}/scripts/fetch_post.py --list 10` 列最新文章（JSON 数组：slug/标题/发布时间）让用户选；`--list` 不带数字默认 10。全自动流水线中直接用上一级刚发布的 slug，无需询问。
- **用户直接给了本地文件路径** → 直接用。

拿到文件后先把全文读完——尤其是 TL;DR、各 H2、对比表、统计块、FAQ，这些是拆分的原料。

### 第 1 步 · 规划拆分 —— **按「痛点场景」分箱，不是按知识点切段**

> ⛔ **本步是整条产线的生死线**（详见 `references/xiaohongshu-spec.md` §1.5，动手前必读那一节）。
>
> **停留在现象层的笔记，读者反应是"学到了"（收藏→划走→忘记）；深挖到场景层的笔记，读者反应是"这说的就是我"（对号入座→情绪被击中→才可能付费）。付费不是被科普说服的，是被场景击中的。**

**长文是知识组织（按主题/机制分 H2），笔记必须是场景组织。**所以拆分不是切段落，是**换一套坐标系重新分箱**：

1. 先列出长文里的知识点/机制/方法（原料）。
2. 再问：**「这个知识点最能救的是哪个具体场景里的哪个人？」**
3. **一篇笔记 = 一个具体场景 ＋ 长文里能解答这个场景的那部分知识**（同一知识点可服务多个场景，不必和 H2 一一对应）。
4. 5–8 篇 = 5–8 个**互不重叠的具体场景**，不是 5–8 个知识角度。

**但"被击中"只是必要条件**：一个已经痛到极点、却被"我不好意思 / 我试过没用 / 我不知道找谁 / 我一直没约"钉住的读者，你再给他一篇更痛的场景文，他只会**更痛地划走**。所以每篇还要回答第二个问题——**它把读者往前推了哪一格？** 那一格就是它的**深挖路径（主路径，唯一）**。

**深挖路径清单（12 条 · 详情与护栏见 spec §1.5，动手前必读）**：

| 层 | 路径 | 公式（一行） |
|---|---|---|
| 认知 | **P1 痛感认领** ≤1 | 白描处境 ＋ "你不用解释" ＋ 人群/慢性度锚点 ＋ 一个今天能做的小动作 |
| 认知 | **P2 处境命名** ★主力 | 具体处境（谁+时刻+那句话/那个身体反应）＋ **计数器**（第几次了）＋ 给它一个**议题名**（不是诊断名） |
| 认知 | **P3 归因矫正** ≤1 | 你以为是 X ＋ 其实更可能是 Y（**机制，不是病名**）＋ 可自验线索 ＋ 下一步 |
| 阻力 | **P4 代价显影** ⛔ | **生产配额 = 0**。落进 P4 = 打回（改写成 P2 慢性版）。分类保留只为当废稿检测器 |
| 阻力 | **P5 去羞耻化** | 把"性格缺陷"重述为"当年的适应"（**条件式**）＋ 常见性（不编数字）＋ 一句许可 |
| 阻力 | **P6 失效归因** ≤1 | 你试过的 X ＋ 它为什么失效（机制，不贬低）＋ 什么条件下才有效 ＋ 你造不出的那部分 |
| 阻力 | **P7 价值论证** ≤1 | 免费替代品（AI/闺蜜/书）真实有效的部分 ＋ 它结构上做不到的那件事 ＋ **诚实分界：什么时候它真的够了** |
| 转化 | **P8 求助路径显影** | 怎么挑咨询师 / 自助 vs 专业的分界 / 换人不是失败（**⛔ 疗法对比与服药并行 = F1，公域冻结**） |
| 转化 | **P9 首访祛魅** ★打头阵 | 三子形态**选一个做落点**：a 过程时间线 / b **保密与记录** / c 表达门槛（"你不需要说得很惨"） |
| 转化 | **P10 可得性破解** ≤1 | 结构约束（时差/母语/本地供给）＋ 怎么绕过 ＋ 线上做不到什么（**主战场在搜索场，小红书只试水**） |
| 转化 | **P11 临门推动** ≤1 | 把"去咨询"切成一个 5 分钟的动作 ＋ 一个时间锚（**禁限时/名额，那是促销**） |
| 关系人轴 | **PX 带他进门** ≤1 | 读者 ≠ 受苦者时走这条：落点**必须是读者自己能做的动作**，绝不能是"如何让对方改变"（他者解码 = 毙） |

**选型一句话**：**看落点——"读完这篇，作者希望读者完成的那一个内在动作是什么？"（看最后三行）** 数出唯一的那一个，就是主路径；数不出唯一一个 = 选题没想清楚，返工。**不做序号遍历**（读者会跳闸），层内并列时取**客户质量更高、合规风险更低**的那条。

**配比一句话**：7 篇 = **固定 5 篇（P2×2 · P5 · P9 · P8）+ 弹性 2 篇（P1/P3/P6/P7/P10/P11/PX 中选）**，**P4 = 0、F1 不进公域**；硬约束：**转化层 ≥1 且必含 P9**、任一路径 ≤2（**P2 可到 3**）、**P3/P4 不得作次要路径**、护栏与配额按"篇内出现的任一路径元素"计（不按主路径计）。

**篇数以用户为准（1–2 篇小批量模式）**：用户明确指定篇数（「只拆 1 篇」「出 2 条」）时按用户说的来——不凑 5–8、不执行上面的固定配比。小批量选型优先级：**单篇选 P2 处境命名**（主力路径，最容易被击中；用户点名了具体场景/角度则以其为准），**两篇选 P2 + P9 首访祛魅**（一篇击中场景＋一篇降求助门槛，认知层+转化层的最小闭环）。**其余护栏一律不降**：五问、慢性度计数器、G1–G10、危机声明、合规扫描照常，P4/F1 依旧零产出。`00-overview.md` 照写（条目少而已），末尾注明**本次未覆盖的原文核心点**，方便下次从同一篇长文续拆时不撞车。

**场景深挖五问**（每篇动笔前逐题回答，答不上来 = 还没挖够，禁止开写）：
① **谁**（具体到能在脑子里看见这个人：产后 6 个月、婆婆天天在家、丈夫说你想太多的新手妈妈）→ ② **什么时刻**（凌晨三点 / 周日下午四点 / 家长会散场那一刻）→ ③ **正在发生什么冲突或代价**（睡不着 / 不敢开口 / 关系在冷掉）→ ④ **这一幕反复到第几次了**（慢性度计数器："第十七个周日"；**单点急性 → 钩来的是买止痛就走的脱落客，加计数器改写或换题**）→ ⑤ **她自己为什么解决不了**（试过什么、**机制上**为什么无效、哪一部分她一个人造不出来）——⑤ 同时必须能回答反面：**什么情况下她自助其实就够了**（诚实分界）。
> ⚠️ 旧第 ④ 问「不管它会怎样」已删除：它直接生产 P4 代价显影（本版禁产），且**恐惧不是求助的独立预测因子**——决定客户质量的是**慢性度**，不是痛感强度。

把拆分大纲写进 `00-overview.md`，每篇必须写全：序号 / **主路径（唯一）+ 次要路径（≤1，不得填 P3/P4）** / **受众（当事人 or 身边人）** / **慢性度** / **场景一句话**（含处境+冲突）/ **五问答案** / **目标长尾词（1–2 个）** / 标题 / 对应原文哪些 H2 / 核心 takeaway / 拟用统计或引语。

#### 🔍 目标长尾词（**每篇必填 1–2 个**，2026-07-26 加入）

> **为什么加这一栏**：旧规则下标题只写场景钩子（「总说自己想太多？」「i 人必看」），**一个可搜索的议题词都没有**——读者**搜**「童年情感忽视」「追逃循环」「复杂性创伤」时我们一条都命不中。推荐流曝光是平台给的、会波动；**搜索流量是长尾的、复利的**。长尾词是这条流量的抓手，所以它必须在**规划阶段**定死，而不是写标题时临时想一个。

**怎么选**：

- **来源只有一个——源长文里本篇真实覆盖的议题**（能在下面的素材台账里指到具体小节/段落）。**不许硬蹭没写过的方向**：蹭来的读者进来发现文不对题，跳出反噬权重，比没有更糟。
- **优先非诊断的议题词**（童年情感忽视 / 追逃循环 / 情绪内耗 / 职业倦怠）；诊断级术语（CPTSD / 回避型依恋）只在它**本身就是读者的搜法**时才用，且**只能作搜索入口，不得作落点、不得写成自测句式**（选词优先级见 `references/xiaohongshu-spec.md` §1「标题」，护栏见 §1.5 P2）。
- **一套 5–8 篇的长尾词彼此不重复**——重复 = 自己跟自己抢同一个搜索词，通常也说明这两篇选题撞车了。

**它要串起三处（缺一即返工）**：

| 落点 | 要求 | 自检 |
|---|---|---|
| **标题前 10 字** | 完整出现、优先占位；**字数不够砍钩子、不砍关键词** | `count_xhs.py <post.md> --title-keyword "<词>"` |
| **标签行** | 标签里必须含该长尾词（不能只有 `#心理科普` 这类泛词） | 人工核 frontmatter `hashtags` + 文末可见标签行 |
| **正文** | 自然出现（不堆砌、不硬塞）——读者搜进来，要能看到他搜的那件事被正面讲了 | 人工核 |

**标注格式**（与 `scene_path` 同一处理：`00-overview.md` 每篇一行，**同时**写进该篇 post 的 frontmatter，供审查端直接取用）：

```yaml
目标长尾词: 童年情感忽视          # 1–2 个；出处：H2「被忽视的孩子长大以后」第 1–4 段
```

#### 🎚️ 信息密度档位（**先定档位、再核算承载力**，2026-07-26 老板定案）

> **为什么要有档位**：过去每页密度写死「6–10 个信息点 / 200–400 字」，运营说「低信息密度」「每页不超过 100 字」时没有落点——agent 要么当耳旁风照旧灌满，要么自行折中，审查端还会拿旧区间把低密度页判成「密度不足」。
> **老板 2026-07-26 定案：默认每页 200–400 字，运营指明时一律按运营说的做。** 运营用的是自然语言，必须先归一化成结构化档位，才能贯通创作端（写正文 / 选版式 / 出图）与审查端（判据 6）。

**归一化表（运营自然语言 → 档位参数）**：

| 运营怎么说 | 每页文字量 | 每页信息点 | 版式档 |
|---|---|---|---|
| **不说**（默认档） | 200–400 字 | 6–10 个 | **满版档** |
| 「低信息密度」「轻一点」「简洁一些」「别太满」 | ≤120 字 | 3–4 个 | **少格档** |
| 「每页不超过 N 字」 | ≤N 字 | N≥200 → 6–10；100≤N<200 → 3–5；N<100 → 1–3 | 按信息点数落档 |
| 「一页 M 个核心观点」（M=1..10） | ≤ M×40 字 | M 个 | 按 M 落档 |
| 「一页只讲一件事」「一页一个观点」 | ≤60 字 | 1 个 | **大字报档** |

- 运营同时给了字数和观点数（如「一页表达 2–3 个核心观点，每页不超过 100 字」）→ **两个都按运营的值写，都是硬上限**。
- **落档规则（2026-07-26 主会话定案）**：`版式档` 由**创作端在归一化时就定死并写进字段**，审查端直接读、**不再自行推导**（两端各推一次必然分叉）。**声明值为区间时，按区间下界落档**——「一页 2–3 个核心观点」下界是 2 → 落 **大字报档**（字段里写 `大字报`，不带「档」字）。理由：宁可豁免不可误判——判松了最多是页面偏空，判严了会把达标产出打回返工，返工成本远高。
- 运营的表达**不在表内、或自相矛盾**（如「高密度但每页 30 字」）→ **停下来问运营**，不要自行折中、也不要挑一个执行。
- 归一化结果必须**回读给运营确认一次**（一句话即可：「按每页 ≤100 字、2–3 个核心观点执行」），确认后再开写。

⚠️ **档位只约束内容页 P2…P(N-1)**（2026-07-26 主会话补口径）：`每页文字量` / `每页信息点` / `版式档` 三项**只管内容页**；**封面 P1 与末页 PN 始终精简**（封面 = 大标题 + 一句副标题；末页按既有末页规范），**不受档位管**——封面本来就只有十几个字，把 200–400 字塞进封面这一页就废了。

**结构化字段（五个，缺一不可）**（写进 `00-overview.md` 开头，**同时**写进每篇 post 的 frontmatter，供审查端直接取用）：

```yaml
信息密度档位: 默认            # 取值只有两个：默认 | 运营指定
每页文字量: 200–400 字
每页信息点: 6–10 个
版式档: 满版                  # 取值只有三个：满版 | 少格 | 大字报；创作端定死，出图与审查都直接读
运营原话: —                   # 「运营指定」时逐字抄运营的话，供审查端复核归一化对不对
```

运营指定时的样子：

```yaml
信息密度档位: 运营指定
每页文字量: ≤100 字
每页信息点: 2–3 个
版式档: 大字报                # 区间按下界落档：2–3 个的下界是 2 → 大字报档
运营原话: "一页表达 2-3 个核心观点，每页不超过 100 字"
```

**版式档联动**（**低密度必须同步换版式，否则第 3 步出图会精分**——版面照满版排、字却只剩几十个，出来不是大片空白就是被灌水填满）：

| 版式档 | 触发 | 版式怎么做 |
|---|---|---|
| **满版档** | 每页信息点 ≥6 | 现行 17 种版式全适用；满版铺陈、分 2–3 区块；少格版式须"格内二次加密" |
| **少格档** | 每页信息点 3–5 | 只用少格版式（对比图/象限/流程/概念定义卡/程度光谱）；**格内二次加密降级为"每格 1 图 + 1 句"**；留白明显多于满版档 |
| **大字报档** | 每页信息点 1–2 | 一个大主视觉 + 一句核心话（≤20 字——这是**核心话本身**的上限；整页文字量以 `每页文字量` 字段为准，两者不是一回事）+ 至多一个副标注；**此时"一页只有 1–2 条 = FAIL"这条判据停用** |

**判据不对称（最容易做错的一条，创作端与审查端都要写明）**：

| 档位 | 下限 | 上限 |
|---|---|---|
| **默认档 200–400** | 低于 200 且达不到密度硬指标 → 判密度不足 | **400 是建议值不是上限，超了绝不判 FAIL/major**（2026-07-25 实测证伪条款继续有效，原样保留） |
| **运营指定档** | 明显低于运营给的数**且确实没讲清**（话不成句 / 图与字对不上 / 整页读完拿不到认知）→ 才判；**运营给的是上限不是目标值，做得比上限更轻不构成缺陷**（如运营要 ≤100 字，某页只有 20 字但话讲清了、图字对得上 = 达标） | **运营给的数是硬上限，超了判 FAIL（major）** |

**为什么不对称**：默认档的 400 是**我们自己的版式经验值**（而且"高密度必崩字"的推断已被 2026-07-25 实测证伪——崩字与文字总量无关），超一点不影响质量；运营指定的那个数是**产品意图**，超了等于没执行指令。两者性质不同，不能互相套用，也不能混为一谈。

#### ⛔ 素材承载力核算（**定篇数之前必做**，2026-07-25 加入）

> **这一步是为了根治「材料不够 → 图内灌水 → 删字掉字数 → 再加密 → 来回震荡」。**
> 震荡的根因不在写作，在**规划时没核算长文供不供得起**：一篇笔记要 6–9 页、每页 6–10 个信息点，
> 5–8 篇就是几百个信息点。长文供不上时，agent 面对硬指标只会重复同一个意思——那不是执行问题，是**规划超发**。

**做法：建素材台账，一页一行，写进 `00-overview.md`。**

| 篇号 | 页 | 该页要讲的那一件事 | **素材出处（长文的哪个小节/段落/数据）** |
|---|---|---|---|
| 01 | P2 | 追逃循环怎么形成 | H2「为什么越追越远」第 2–3 段 |
| 01 | P3 | 四个阶段的身体信号 | H2「身体先知道」的症状清单 |

**判据（硬性）**：
- 每一页都必须能填出**具体、独立、本篇专属**的出处。填不出、或出处与本篇其他页重复、或与其他篇已占用的出处重复 → **这一页撑不起来**，划掉。
- 某篇撑不起来的页 **≥3** → **这篇材料不足**，与相邻篇合并或直接砍掉。
- 台账填完后**篇数 = 实际撑得住的篇数**，可能少于 5——**这是正确结果，不是失败**。

#### 材料不足时的三种让步 —— **默认走 C（减页数），另两种由运营点名才切换**

台账算出撑不住时，**必须让步，不能靠重复灌水硬撑**。三个维度只能让一个，取舍如下：

| | 让步什么 | 保全什么 | 参数调整 | 适合 |
|---|---|---|---|---|
| **C · 减每篇页数（默认）** | 每篇 6–9 页 → **4–6 页** | **篇数、每页密度全保** | 页数区间改 4–6；每页仍 6–10 信息点、200–400 字 | 常规情形：覆盖面与单页质量都不牺牲，只是每篇更短 |
| **A · 减笔记数** | 篇数 5–8 → 实际撑得住的 N | 每篇页数、每页密度全保 | 篇数 = 台账实际值（可少于 5） | 运营要「宁缺毋滥」、单篇当精品打时 |
| **B · 减每页密度** | 每页 6–10 信息点 → **4–6 个**、文字 200–400 → **120–250 字** | 篇数、每篇页数全保 | 判据 6 按调整后区间判 | 运营要铺量、且接受单页更轻时；**运营已指定密度档位时本方式停用** |

**默认 C（2026-07-25 老板定案）**：不问就按 C 执行——篇数和每页密度是产量与质量的底线，
页数是三者里最可让的。**A 与 B 需要运营明确点名才切换。**

**与「信息密度档位」的优先级（2026-07-26 老板定案，三条按顺序判）**：让步方式是**材料不足被动触发**的，
密度档位是**运营主动指定**的，两者性质不同、会同时出现，所以：

1. **先定密度档位**（运营指定 or 默认），**再**按该档位算素材承载力。低密度档每页需要的材料本来就少 →
   同样一篇长文能撑住的页数/篇数更多，**可能根本不需要让步**。顺序颠倒会白砍页。
2. **运营已指定密度档位时，让步方式 B 停用**——密度是运营定的，不能再动；此时只能走 A（减篇数）或 C（默认，减页数）。
3. 让步声明行与密度档位字段**同时存在、各写各的**（一行记"材料撑不住所以让了什么"，一组字段记"运营要的密度是多少"），
   审查端两处都读，不互相覆盖。

⚠️ **无论走哪种，都必须在 `00-overview.md` 开头写明一行**，供审查端参照：
`材料让步方式：C（减页数）· 本篇长文实撑 N 篇 × 每篇 M 页 · 让步原因：⋯⋯（列出哪些页找不到独立出处）`
**审查端读到这一行后，按该方式的调整区间判，不按默认区间判 FAIL**（走 B 时尤其重要，
否则每页 4–6 个信息点会被判「密度不足」）。

**主动让步并写明 = 达标；不让步、靠重复灌水凑满 = 不达标。** 后者的返工成本远高于前者。

**返工时的铁律（老板 2026-07-25 定案）**：审查发现图内灌水/重复要删时，
**删掉的位置必须用长文里本篇还没用过的小节填回来——靠"换材料"，不靠"删字"**。
只删不换会掉回字数下限、又触发加密，来回震荡。
**若翻遍长文找不到可换的新材料 → 这就是「材料不足」的确诊信号**：
别再纠缠这一页，退回本步**按当前让步方式处理**——默认 C 就砍掉这一页（页数降到 4–6 区间内），走 A 则把该篇合并或砍掉，走 B 则把该页密度降到 4–6 个信息点——并同步修正 `00-overview.md` 的台账与那行让步说明。

⚠️ **合规护栏（YMYL 红线，十条全局硬闸见 spec §1.5「G1–G10」）**：深挖场景 ≠ 制造恐慌。**G1 最低出口律**（每篇末必须有一个今天能做、门槛低于付费的小动作）、**G2 躯体分流律**（写到胃疼/失眠/心悸必须同段落说"先排除器质性原因"）、**G3 不给第三人贴标签**（禁 NPD/PUA/回避型式给读者的父母伴侣孩子下判断）、**G4 不代读者作结论**（成因一律条件式）、**G5 案例三律**（书面同意或复合案例并明示 + 禁可反向识别组合）、**G6 危机与 CTA 分离**、**G10 不卖依赖**（收尾指向"有一天你不再需要它"）。风险提示必须在源长文有出处；高危议题（自伤/自杀/重度精神障碍）只做识别与转介（12356），**绝不暗示我们能即时接住正在发生的危机**（判据在即时性与渠道、不在能力：危机当下该走 12356/急诊，咨询预约有等待期）。**但危机题材笔记照样可以挂商业 CTA 与咨询师推介末页**——题材禁令已于 2026-07-25 取消，只保留排版分离（G6）。判据：读者看完应感到「被理解了，且知道下一步能做什么」，不是「被吓到了，必须马上花钱」。

### 第 2 步 · 写发布文案（正文 ~300 字 + 可见标签）

每篇 post 的第一个内容块就是**复制即发的"发布文案"单元**——这是用户真正粘进小红书输入框的东西。块标题用 `## 发布文案（复制这一段直接发布）`，里面依次是：① 正文主体 ② 危机声明一行 ③ **可见的 `#标签` 行**。

> **标签必须可见**：标签除了写进 frontmatter 的 `hashtags`（供机器读取），**必须同时作为可见文本 `#标签1 #标签2 …` 附在文案末尾**。frontmatter 在网页/编辑器渲染时不显示，只放 frontmatter 等于「看不到标签、也没法复制」。小红书惯例标签贴在正文末尾。

打开 `references/xiaohongshu-spec.md` 对照写。

**正文必须是三段式骨架（强制，不是建议）**：

> **① 痛点场景开头（15–20%）→ ② 科普干货主体（65–75%）→ ③ 结尾轻引导（1–2 句）**
>
> **为什么**：纯科普易涨粉、难转化（读者收藏完就走）；硬广易转化、难曝光（限流+投流拒审+读者反感）。三段式是唯一的解——它对齐小红书真实决策链路（痛点搜索 → 案例对比 → 私信咨询 → 社群成交），也符合投流过审规律（**全文绝大部分是科普干货、只有结尾一句轻引导的笔记最容易过审**；通篇引导或开头即广告的，限流与拒审风险最高）。

- **① 痛点场景开头**：**直接把第 1 步挖出的那个场景写出来**（五问的 ①②③ ——谁、什么时刻、正在发生什么），让读者对号入座（"凌晨三点又醒了，脑子里循环白天那句话"）。首句即 3 秒钩子。禁用"你是否常常感到焦虑？"这种问卷腔。**开头写不具体 = 第 1 步的场景没挖够，回去重挖，别在这里硬凑。**
- **② 科普干货主体**：笔记的价值来源——讲机制、给判据、给可执行方法，分点写。**这一段完全不谈自家服务**；干货要能独立成立（读者不点主页也有收获），数字/结论可溯源到源长文。
- **③ 结尾轻引导**：先给**一个今天能做、门槛低于付费的小动作**（G1 最低出口律，全路径适用——只共情不给出口 = 高唤起零效能，读者会关掉手机而不是求助），再 CTA（提问引评论 /「收藏不迷路」/「评论区抱抱」），再**轻**提一句"还有专业支持这条路"。**轻 = 陈述事实、给出选项，不催不促不承诺**。安全句式与反面例子见 spec §1「轻引导写法」；**结尾的最后三行 = 这篇的落点，必须能读出唯一一条主路径**（选错落点 = 主路径标注作废，返工）。品牌锚句每篇只出现一次，自然带过。
- ⛔ **结尾禁止硬广特征**：限时/优惠/立减/名额/仅剩/立即/私信我领——这些词会导致投流拒审 + 自然流限流（脚本会扫，见第 4 步）。更禁止站外导流（微信/二维码/外链，直接封号）。

其它骨架记忆点：

- **口吻**：第一人称共情 + 干货清单 + 自救指南，口语化，像朋友说话。**共情先于科普**（这是心理内容区别于普通种草文的关键）。分段与 emoji 按 spec §1.6 口径（每段 1–3 短句、emoji **每篇 ~300 字正文 8–14 个**且温和款）。
- **写完必须按排版规范重排再落盘**（`references/xiaohongshu-spec.md` §1.6「发布排版规范（手机端实际渲染）」）：小红书正文**不渲染 Markdown**——发布前 `**加粗**` 会被剥掉、到手机上没效果，所以**强调靠"金句独立成行 + 前后空行"，不靠加粗**。核心口径：首行就是场景钩子（≤1.5 行）、每段 2–3 短句、段间空一行、emoji **每篇 ~300 字正文 8–14 个**且只选温和治愈款（🌱🫧🌙☁️💭🤍🌿，禁 🔥💥❗）、破折号做解释改成换行或括号、禁花哨分隔线/装饰 bullet/满屏 emoji（营销号观感）、危机声明单独成段不点缀、标签只在文末一行。**先按三段式把内容写对，再对照 §1.6 把它排成"像有人温柔地跟你说话"而不是"像促销传单"。**
- **标题 ≤20 字，结构 =「核心议题词（目标长尾词）＋ 场景钩子」，关键词优先占位**（2026-07-26 改版，完整口径见 spec §1「标题」）：标题是这篇**唯一的搜索入口**——**前 10 字内必须完整出现第 1 步定下的目标长尾词**（feed 折叠与算法权重都偏重前 10 字：手机一屏约露 12 字、超 18 字大概率被折叠）。
  - ✅「童年情感忽视：长大后总觉得自己有问题」（议题词前置 ＋ 场景钩子在后）
  - ✅「追逃循环｜越想靠近，他越往后退」　✅「CPTSD 和创伤后应激有什么不同」
  - ❌「总说自己想太多？」「我后悔没早点知道这件事」「i 人必看」（**纯钩子、零可搜索词——旧规则的产物，现在一律返工**）
  - ⚠️ **字数不够时砍钩子、不砍关键词**（核心取舍，无例外）。只剩一个干净议题词的标题可接受；关键词被挤到 10 字之后不可接受。
  - 四类钩子（数字体/痛点体/悬念体/身份标签）保留为**后半段的可选修饰**，改后示例与「改前」对照见 spec §1 那张表。
  - **自检**：`python3 {SKILL_DIR}/scripts/count_xhs.py <post.md> --title-keyword "<目标长尾词>"` → `ok_title=true`（false 时看 `title_reason`）。
- **标签 5–10 个**：关联（精准品类如 #心理科普 #CPTSD）+ 热度（蹭当下）+ 长尾（细分/身份/地域，如 #留学生心理 #情绪内耗）。**其中必须含本篇的目标长尾词**（与标题前 10 字、正文同词，见第 1 步）。同时写进 frontmatter `hashtags` 与文案末尾可见标签行。

**字数默认 300 汉字**（用户指定值，只数正文主体、不含标签）。三段式在 300 字下的典型配比：开头 50–60 字 / 主体 200–220 字 / 结尾 30–40 字。提醒：小红书爆款正文常在 500–800 字、信息更厚更易被收藏；如想提收藏率可把默认调到 500–600，但默认遵守 300（注意：count_xhs.py 的判定区间固定按 300 基准 210–450，调高目标字数时以人工核对为准）。

**验证**：`python3 {SKILL_DIR}/scripts/count_xhs.py <post.md> --title-keyword "<本篇目标长尾词>"` 输出 JSON——`title_chars` ≤20 且**目标长尾词落在标题前 10 字内**（不满足则 `ok_title=false`，原因看 `title_reason`；不传 `--title-keyword` 时只校字数、不校关键词）；`body_chars` 只数「发布文案」区块的汉字（剔除标签行、emoji/符号不计，**排版不影响字数**），区间 210–450；`pages` 同时核轮播页数 6–9；以 `ok` 为 true 为过。⚠️ **若本次走了材料让步方式 C（减页数，4–6 页）**，自检要显式传区间：`count_xhs.py <post.md> --page-min 4 --page-max 6`——不传会按默认 6–9 判 `ok_pages=false` 误报。（走 B 减密度时页数不变、正文字数不变，命令照常不用改。）此外：**三段式在位（痛点场景开头 / 科普主体不谈服务 / 结尾轻引导 1–2 句且无硬广词）**；**排版已按 §1.6 重排**（首行即场景钩子、每段 2–3 行有空行呼吸、强调靠独立成行而非加粗、emoji **每篇 ~300 字正文 8–14 个**且温和、无花哨分隔线/满屏 emoji 的营销号观感、危机声明单独成段、标签只在文末）；发布文案块含可见标签行；第 1 步规划的钩子有落地；正文里的数字都能在源长文找到出处。

### 第 3 步 · 设计配图轮播（每篇 6–9 页）

每条笔记配一套"像 PPT 一样"的轮播图。**核心规则见 `references/illustration-spec.md`**，记忆点：

> ⚠️ **写提示词前先回读 `00-overview.md` 开头的密度五字段**（`信息密度档位` / `每页文字量` / `每页信息点` / `版式档` / `运营原话`）：**本节以下写的"满版 / 一页 6–10 信息点 / 混用 3–5 种"全部是默认档取值**，运营指定档一律以那五个字段为准（三档各怎么排见 `references/illustration-spec.md` ①-b）。**且这些取值只约束内容页 P2…P(N-1)**——封面 P1 与末页 PN 始终精简，不受档位管。

- **每页 = 一张"知识卡"**：① 页面文字 ② 中文绘图提示词。**封面/末页精简**（大标题 + 一句）；**内容页要高密度——但密度 = 图文合起来表达的信息量，不是字数**：把每条信息画成一个能看懂的**具体场景**、抽象点落成具体画面（"有周期"→情绪曲线、"至少两周"→日历、"成组出现"→并列几个症状小人），一页 6–10 个信息点满版铺开（默认档）。
- **内容页 = 图文双通道（对齐参考图，非纯文字列表）**：**硬要求只有一条——每条/每格/每节点都配一个各不相同、把该点画成具体场景的手绘小图或简笔小人**（图在叙事不在装饰、文字在说明，两者合起来才是密度），配合满版、分 2–3 区块、一页 6–10 信息点（**默认档；运营指定档按第 1 步定下的 `版式档` 取值排版，换版式见 illustration-spec ①-b**）。版式按内容选（**17 种，一套 6–9 页混用 3–5 种、别整本都对比表**——**大字报档不适用**，该档整本同形态是运营点的菜；**少格档在白名单 5 种内混用即可，不要求 3–5 种**，见 illustration-spec ①-b）——分区图标清单/对比表/流程步骤/象限/隐喻/数据占比/拆解结构/因果链/时间轴周期/自查清单/恶性循环圈/情景对话/身体地图/误区纠错/换个想法(认知重构)/程度光谱/概念定义卡；选型第一问"这页信息之间是什么关系"（映射表见 illustration-spec 第 3 节）；**套用时按金标准范例的详细度展开**——每种版式都有一条实测级完整范例在 `references/layout-gallery.md`，先抄对应范例的结构与颗粒度再替换主题内容（`〇〇` 占位换成具体内容 + 每个元素写成具体画面，别把骨架直接丢给模型）。⚠️ 隐喻图/拆解图别只放"一个大隐喻+几个抽象标签"（低密度陷阱，把每部分落成具体场景或补足信息点）。纸质暖框、粗黑标题、赭红高亮等都是**可选**设计项（标题不必粗黑，默认沿用品牌柔和标题即可）。判据与模板见 `references/illustration-spec.md` 第 1、3 节。
- **图中文字直接写进提示词**：你用的 Gemini/GPT 能渲染中文，所以把这页要显示的中文用引号写进提示词，并指定位置与层级。每个文字块（标题/分区标题/图标标注/说明）各自要短、独立成行——渲染更准、也更好扫；**信息图标注点位多、错字风险更高**，点位式短标注 ≤6 字、关键术语放大，出图后逐字核对。
- **首页 = 钩子封面**（最重要，决定点击率，不堆要点留悬念，保留柔和治愈单主体）；中间页 = 高密度信息海报（一页讲透一个点）；末页 = 行动建议 + 品牌一句话 + 危机声明。
- **全套复用固定品牌调色板与人物卡**：封面/末页/隐喻页用柔和治愈单主体基底；内容页用知识海报基底；两类页共用同一调色板（主色 #A8B5C4 / 暖米 #E8D8C4 / 鼠尾草绿 #C9D6CE；可选强调赭红 #A34B3A + 标题深色 #2B3A4A）与固定人物卡，保证 6–9 张风格一致、整个号调性统一。
- **每篇笔记末尾追加 `## 视频参考图提示词` 节**（页对页的"去文字版"提示词）：每页一条 = 该页绘图提示词**剔除所有「图内文字」指令**，保留品牌基底与人物卡，末尾追加「画面中无任何文字」。用途：nbdpsy-text-to-video 图生模式拿这套提示词出"无文字同款图"当每镜首帧——视频会把旁白烧录成字幕，图内若再有文字会和字幕打架。本 skill 只产这节提示词，不在本级出这套图（由 nbdpsy-text-to-video 产线按需生成）。**节内每页用加粗标记 `**P1**`…`**PN**` + 围栏提示词，绝不用 `### PN` 标题**——`### PN` 是配图轮播的页数计数契约，重复使用会让 count_xhs.py 把页数翻倍误判。完整规格与模板见 `references/illustration-spec.md` 第 6 节。

> **要不要末页推介咨询师**：用户说「这篇顺带推介 XX / 末页带上咨询师」时，在轮播最后**追加一页**咨询师推介页（用系统头像直接合成），内容页相应收到 6–8 页、总页数仍落 7–9。口径、提示词骨架、出图两批 anchor 见下面「科普笔记末页 · 咨询师推介页」一节与 `references/counselor-note-spec.md` §6。

**验证**：每页提示词都含品牌基底；图中文字够短；首页是钩子封面而非内页；页数落在 6–9；视频参考图提示词与轮播页一一对应且不含任何图内文字指令（**末页推介页除外**——它不进视频参考图提示词节，见 counselor-note-spec §6.7）。

### 第 6 步 · 出图（后端一致性出图优先，宿主自适应兜底）

   ```bash
   python3 {SKILL_DIR}/scripts/gen_images.py --note {note_dir}/post-01.md --cover-only
   ```
   把落盘的 `P01.png` 给运营看，确认三项（① 配色只用品牌调色板 ② 人物符合固定人物卡 ③ 竖版构图
   （后端出 2:3，判据是没被出成方图/横版）＋图中中文逐字无错）。不过 → 改提示词重跑本命令，**不要往下走**。
2. **确认通过 → 先把批次锚点落盘，再批量出全套**：把第 1 步输出 JSON 里的 `anchor_url`（那张已确认的 P1 绝对 URL）**存成文件**，此后所有出图命令一律从这个文件读——**整套所有篇、所有次重出都用它**。
   ```bash
   mkdir -p {note_dir}/_shared
   echo -n "<那个anchor_url>" > {note_dir}/_shared/BATCH_ANCHOR.txt   # 2026-07-26 定案：批次锚点必须落盘，供图审端事后审计
   ```
   > ⚠️ **这一步不能省**：`checklist-images.md` 的批次锚点审计会 `cat` 这个文件，逐篇比对
   > `images/post-NN/.gen_images_state.json` 里记录的 `anchor_url`。文件缺失 = 审查端判该项不通过。

   然后**按篇并行、并发度 10**（服务端 2026-07-25 升级后单篇内部已 10 路并发，**每篇约 50 秒**；6–8 篇一套一次全开，墙钟≈1 分钟）：
   ```bash
   # 后台并行起，每篇一个 job；日志各自落盘便于事后核对
   for f in {note_dir}/post-*.md; do
     python3 {SKILL_DIR}/scripts/gen_images.py --note "$f" \
       --anchor-url "$(cat {note_dir}/_shared/BATCH_ANCHOR.txt)" \
       > "${f%.md}-genimg.json" 2>&1 &

   wait   # 全部结束后逐篇读 *-genimg.json 核对
   ```

   > 服务端走的是 **Images API（`images.edit`）**，其参数里**没有任何 session/conversation/
   > previous_response_id 字段**，是无状态接口；风格一致性来自**每张都传同一张锚点图**。
   > 因此调用顺序、是否并发都不影响一致性。（OpenAI 另有 Responses API 的多轮图像会话是有状态的，
   > 但那条路径天然串行、且累积上下文使单篇成本约为现路径的 1.8 倍——我们不用它。）
   > 服务端侧的 `session_id` 只是它自己的产物目录标识，与 OpenAI 无关。
   >
   > **服务端已于 2026-07-25 22:25 升级，本段是升级后的口径**（旧的「逐篇串行 / ≤6 路」已作废）：
   >
   > **维度一 · 单篇内部**：服务端 `generate_batch` 已从逐页 `await` 改为**有界并发 10 路**，
   > 一篇 6–9 页**一波出完**，墙钟从约 7.5 分钟降到 **约 50 秒**。这层由服务端控制，**skill 侧无可调项、也不用调**；
   > 以后要调并发只需服务端改一个配置项，**不用动这份文档**。
   >
   > **维度二 · 按篇并行**：**并发度设为 10**（服务端确认的安全区）。账号是 **Tier 5（250 IPM）**，
   > 服务端已核算总量：10 篇 × 内部 10 路 = **100 并发 ≈ 120 张/分钟**，占 Tier 5 上限（250 IPM）的 **48%**，留一半余量给其他运营同时出图。
   > 因此 6–8 篇一套的常规批量**可以一次全开**，墙钟≈最慢那一篇≈1–2 分钟。
   >
   > **429 已由服务端兜底**：撞限额时自动指数退避重试 3 次，不再直接判该页失败。
   > 结果与 prompts 的下标对齐、失败位留空位的语义**完全不变**，`P01.png…PNN.png` 落图规则照旧。
   >
   > **观察期（当前）**：先按 10 路跑一天。若日志或返回里出现 429 相关错误，**记录下来反馈给服务端**
   > （他们已把真实限额响应头记进日志），由他们据实调整——**不要自行降并发后就不报了**，
   > 那会让服务端拿不到真实水位数据。
   >
   > 成本参考（1024×1536 medium，官方费率）：单张出图 ≈$0.048，edit 每次重传锚图额外 ≈$0.016，
   > **一篇 9 页 ≈$0.57（¥4.1）**，其中锚图重传占 ~22%。

   全部 `outcome=done` 后进入图片对抗审查（下同，原文不动）。

   ⛔ **成图有问题时的唯一正确改法（2026-07-25 老板定案，违反=返工）**：
   图审发现错字、元素画错、版式跑偏时——**改初始提示词、带上原来那张锚点图、整页重新生成**。

   | | 做法 |
   |---|---|
   | ✅ **只能这样** | 修 `post-NN.md` 里该页的提示词 → `gen_images.py --pages N --anchor-url "$(cat {note_dir}/_shared/BATCH_ANCHOR.txt)"`（**原来那个 anchor_url**，从批次锚点文件读，别手抄） |

   **锚点图自始至终只有一张**——就是第 1 步确认通过的那张 P1，整套所有页、所有次重出都用它。

## 小红书账号接入与管理（发布前的自检与运营指导）

发布走的是 nbdpsy-api，账号登录态靠 **chrome 插件**维护（登录没有 API）。用户问「怎么接入 /
怎么登录新账号 / 账号失效了 / 我有哪些号」或路线 A 发布报账号类错误时，按本节处理。

### 接入自检（用户说「帮我做接入自检 / 我配好了吗」时直接跑这个）

**一键自检**（连通性 + 身份 + 被授权账号 + 就绪，可反复跑）：

```bash
python3 {SKILL_DIR}/scripts/publish_note.py --self-check
```

读输出 JSON：`ok=true, ready=true` → 可以发布；`error` 提 `Host not allowed`/超时 → 沙盒拦网
（跑 `nbdpsy_common.py sandbox allow` 后重启 Claude）；`401` → apikey 失效找管理员重发；
`need_relogin` 非空 → 那些号要重新扫码（见下）。凭据本身是否导入用
`nbdpsy_common.py doctor` 看 `xhs_ready`（**别用 `secret get` 探测，会回显密钥**）。

**插件判据**（本机测不到浏览器装没装插件，用状态倒推）：`--self-check` 返回账号数为 0、或
全部 `cookie_status=unknown` 且从没登录过 → 大概率插件还没装/没用过，走下面「装插件」；
有号但 `invalid`/`captcha` → 插件在但登录态过期，走「重新扫码」。

### 装插件（细致指导，逐步带运营做）

`download_url`（免鉴权直接下）、`version`、`install_steps`（官方步骤数组）、`server_time`。
把步骤**翻译成人话逐条发给运营**（默认口径，以 install_steps 为准）：

1. 打开 `download_url` 下载插件包 zip，解压到一个固定文件夹（别放回收站/临时目录）。
2. Chrome 地址栏输入 `chrome://extensions` → 右上角打开「开发者模式」→「加载已解压的扩展程序」
   → 选刚才解压的文件夹。
3. 点开插件弹窗，填**两样**（缺 serverUrl 插件连不上）：
   - **serverUrl** = `https://mcp.nbdpsy.com`（本服务地址，即凭据 NBDPSY_XHS_API_BASE）
   - **apikey** = 接入包里那把（本机凭据库键名 NBDPSY_XHS_API_KEY；提醒运营别外传）
4. 进插件详情页勾选「**在无痕模式下启用**」（下一步登录用无痕窗，不勾开不了）。
5. 装好后按下面「登录新账号」扫码。

### 登录新账号 / 重新扫码（登录态过期）

1. **先**跑 `--extension-info` 记下 `server_time`（必须在扫码**之前**取，它是轮询起点）。
2. 让运营：开一个**无痕窗口**（插件账号页上有入口）打开小红书 → 手机小红书 App 扫码登录。
   登录成功后插件会自动把 cookie 推回服务端、账号自动入库。
3. 你轮询确认：`python3 {SKILL_DIR}/scripts/publish_note.py --wait-login --since <server_time>`
   （重登旧号加 `--account-id <id>`）。`done=true` 即完成；新号记得让管理员授权给这位运营
   （首次导入者自动有权）。
4. 验活兜底：`python3 {SKILL_DIR}/scripts/publish_note.py --check-cookie <账号名或id>`——
   五态里 `valid` 才算好；`invalid` 重新扫码；`captcha` 要人工过验证码；
   **`error` 是服务端基础设施失败 ≠ cookie 失效，别让运营白扫一遍，稍后重测**。

### 用某个账号打开小红书（人工运营场景）

插件的账号卡片上有「打开小红书」：它会用服务端存的该号 cookie 开一个已登录的无痕窗口
（评论互动、手动检查笔记都走这里），卡片上也有「检测」按钮 = 手动触发 cookie 验活。
告诉运营用插件操作即可，这一步没有命令行。

### 账号名跟随小红书昵称（预期行为，不是数据错乱）

每次 cookie 检测（`--check-cookie`、插件「检测」按钮或服务端后台巡检）拿到最新小红书昵称后，
会把该账号的 `name` 同步成昵称。所以运营在小红书 App 里改了账号名、检测一次后，
`--list-accounts` / `--check-cookie` 显示的名字会跟着变（不再是接入时的旧名）。
认账号别只认名字——拿不准就用账号 id 指定。

### 账号被平台处罚（禁发笔记）

对该号发布**约 1 秒即返终态 `failed`**、且 `error` 含「发布被小红书阻断 / 违反社区规范 /
禁止发笔记 / 账号异常」→ 是平台违规处罚不是技术故障（详见「路线 A · 3. 失败排障」）。
处理只有两条：**换未受限账号发，或让运营在小红书 App 内核实账号状态**。
不要重扫码（cookie 是好的）、不要改脚本重发（重发是更强的高频封号信号）。

## 咨询师推介笔记（独立场景，不从长文拆分）

除了「拆长文」，本 skill 还能给**某一位咨询师**做一条推介图文笔记（卖点是「这个人可信、可托付」，不是疗效）。取材源不同（官网咨询师公开资料，不拆 pillar），品牌基底 / 合规红线 / 出图 / 发布链路全部复用本 skill 既有能力。**完整规格见 `references/counselor-note-spec.md`**（数据字段口径、照片三铁律、文案骨架、4–6 页轮播结构、封面底图留白模板），下面只给速记。

**🔴 两条红线先记牢**：① `contracted_price`（签约价）是隐私字段，`fetch_counselor.py` 已在返回前删除，任何产物里绝不出现——对外价格只有 `price_per_session`（¥N / 次）和 `communication_price`（预沟通 ¥N / 免费），且**价格默认不上笔记不上图——生成前问运营「要不要展示价格」，明确要求才加**。② 真人照片三铁律——**照片只上 P1 封面，内页（简历卡等）一律不放**（2026-07-24 定案，内页出现人物照片＝返工）；**出图前必须拿到"咨询师本人同意用于小红书宣传"的确认**（未确认停等不出图）；**默认 AI 直出**（照片上图床后当 anchor_url 喂后端生图、只出封面这一页，会重绘人物）——**成图必须经咨询师本人过目认可后才可发布**，在意像素级真实时改走 compose_photo 本地合成备选；照片不入 git、用完提醒运营自行保管。

**🟡 推介场景与科普笔记的三点差异（2026-07-24 黄安麟篇反馈定案）**：① **骨架＝「人物直入」不是科普三段式**——开头姓名+最硬资质直入（前 10 字立住信息），**禁止痛点场景铺垫、禁止「选咨询师其实是先认识一个人」类导语**；② **危机声明不加**（正文与末页图都不放 12356——推介是人物介绍非科普内容，硬塞科普声明反而跑调；合规校验走 `check_compliance.py --no-crisis`，其余违禁词照扫）；③ **议题必展开＋埋长尾词＋写流派＋字数更长**——擅长议题逐条展开成"是什么困扰＋怎么工作"、每类嵌 ≥1 个后台真实覆盖的长尾词（原生家庭创伤→CPTSD/复杂性创伤、亲密关系→依恋修复…，绝不硬蹭），受训流派（CBT/精神动力/整合取向）写出来，正文 400–800 字，标签含核心议题长尾词。字数/页数自检 `count_xhs.py <post.md> --body-min 400 --body-max 800 --page-min 4 --page-max 6`。

**流程速记**：`fetch_counselor.py` 取材（确认 `is_accepting=true` + 输出无 `contracted_price`）→ **停等：问运营封面要不要放真人照片、要则索取照片 + 授权确认**（拿不到就 P1 走纯插画封面）→ 按 spec §3「人物直入」三部分写文案（正文 400–800 字、擅长议题逐条展开并嵌长尾词、受训流派写明、亮点逐条对齐后台资料不编造）→ `check_compliance.py --no-crisis` 全绿（推介笔记不含危机声明）→ 出图：授权照片经 `publish_note.py --upload-images` 上图床取直链，`gen_images.py --pages 1 --anchor-url <照片直链>` 单出 P1 封面，**内页常规路线 0 出图、绝不带照片 anchor** → **封面成图经咨询师本人过目认可（硬闸）** → 图审（错字 / 风格一致 / 照片只在封面）→ 沿用路线 A/B 发布（发布前确认账号）。轮播 4–6 页：P1 照片封面（人物主体+姓名钩子，**全笔记唯一带照片的页**）、P2 简历卡（纯信息图，8–10 信息点高密度）、P3 专长/风格卡（纯信息图）、PN 预约页（**本场景不放危机声明**——推介是人物介绍非科普内容）。

两条命令示例：

```bash
python3 {SKILL_DIR}/scripts/fetch_counselor.py --list            # 全部咨询师概览，选人
python3 {SKILL_DIR}/scripts/fetch_counselor.py --emp <emp_no>    # 单人详情（含 profile_sections，已删 contracted_price）
python3 {SKILL_DIR}/scripts/compose_photo.py --base <P1封面底图.png> --photo <授权照片> --out <P1成图.png> --region top   # 仅备选保真路线用
```

## 科普笔记末页 · 咨询师推介页（系统头像直出，2026-07-25 定案）

**触发**：用户说「**这篇顺带推介 XX**」「**末页带上咨询师**」「**最后一页放 XX 的推介**」「**这条笔记挂某某咨询师**」——**不是**整篇推介笔记（那走上一节），而是一篇正常科普笔记在轮播最后**追加 1 页**推介。完整规格见 `references/counselor-note-spec.md` §6，下面是速记。

**与上一节的关键区别（最容易做错，先记住）**：素材是**咨询师自己上传到系统的头像**（`avatar_url`），**上传即已授权**——**不逐次索取授权、不设「本人过目认可」闸门、不卡发布流程**（老板定案：事后有问题走下架笔记补救）。上一节「整篇推介笔记」用的是运营额外索取的照片，照片三铁律**原样不变**，两套规则别混用。判据：**照片从哪来**——运营手里来 → 上一节；`avatar_url` 来 → 本节。

**其余差异**：正文照科普笔记写（~300 字三段式，**默认一个字都不改**）；**危机声明照常在位**（放推介页**之前**那一页，天然满足 G6 分离）；合规校验走 `check_compliance.py`（**不带 `--no-crisis`**）；内容页收到 6–8 页 + 推介页 1 页 = 总 7–9 页，`count_xhs.py` 默认区间不用改。

**前置闸门只有一条**：`is_accepting=true`（停单的不推）。**笔记题材不设限——危机议题笔记同样可以挂推介末页**（2026-07-25 老板定案，原「危机相关笔记不加推介末页」的题材闸门已取消：咨询师均为持证心理咨询师、具备危机干预能力，运营点名要推介就照做）。⚠️ 取消的只是**题材否决**；**危机声明照常在位、且仍与推介页不同页**（G6 的物理分离要求保留，按 §6 页序天然满足）。

**流程速记**：

```bash
# 1. 取数 + 头像落本地（avatar_url 是相对路径，脚本自动拼绝对 URL 下载）
python3 {SKILL_DIR}/scripts/fetch_counselor.py --emp <emp_no> --avatar-out {note_dir}/photo/
# 2. 头像上图床拿直链（返回 urls[0]，7 天有效）
python3 {SKILL_DIR}/scripts/publish_note.py --upload-images {note_dir}/photo/avatar-<emp_no>.jpg
# 3. 科普内容页照旧（anchor = 已确认的 P1 封面，从批次锚点文件读）
python3 {SKILL_DIR}/scripts/gen_images.py --note {note_dir}/post-01.md --pages 1-8 \
  --anchor-url "$(cat {note_dir}/_shared/BATCH_ANCHOR.txt)"
# 4. 末页推介单出一批，anchor 换成头像直链（⛔ 不用 compose_photo 本地拼图，老板要求直接喂 AI 合成）
python3 {SKILL_DIR}/scripts/gen_images.py --note {note_dir}/post-01.md --pages 9 --anchor-url <头像直链>
```

**末页文案就四件**（别写成简历卡）：姓名（**直呼其名，绝不加「老师」**）＋ 职称/最硬资质一行（≤14 字，按后台事实不升格）＋ 擅长方向药丸 2–4 个（**各 2–6 字短词**，长尾词留给正文不进药丸）＋ 一句「怎么开始」（≤16 字陈述句，如「可以先做一次预沟通」「主页可查预约方式」；⛔ 禁「立即预约/私信我/限时」）。**价格默认不展示**——生成前问运营，明确要求才加且取实时值。品牌锚句已在原末页用过，推介页只放右下角小字「NBDpsy 心理咨询」。提示词骨架照抄 counselor-note-spec §6.5（比例参数必须写标准句，否则预览页 2:3↔1:1 切换认不出）。

**视频衔接**：推介末页**不写进**「## 视频参考图提示词」节；这篇要做视频时明确告诉 nbdpsy-text-to-video 跳过末页（`parse_note.py` 没有跳页开关，产出 shots.json 后删掉最后一镜再往下走）。

**头像取不到时**（后台没传 `avatar_url`，脚本会报错停下）：让运营先在管理后台补头像，或**本篇不做推介末页**——不要退回让 AI 编一张脸，那不是这个人。

## 红线速记（违反任一即不合格）

1. 不新增未验证事实——数字/引语只沿用源 pillar，短文里的每个数字都能在原文找到。**标题/封面里的条数数字必须等于正文实际条数**（说「5 个」就得真有 5 条，不可为凑钩子虚增）。
2. 不用「治疗/诊断/治愈/医院/医生」自我描述；不用极限词；不夸大效果。
3. 任何位置都不放站外导流（微信/二维码/加群/外链）——小红书限流封号红线。
4. 危机声明（全国统一心理援助热线 12356）每篇在位，且**单独成段、不与商业 CTA 同句同段**（G6）。**适用范围：科普笔记（拆长文）。咨询师推介笔记除外**——推介是人物介绍非科普内容，正文与末页图都不加危机声明，合规校验走 `check_compliance.py --no-crisis`（理由见 `references/counselor-note-spec.md` §3）。**科普笔记追加推介末页时不算例外**——它仍是科普笔记，危机声明照常在位（放推介页之前那一页）、校验**不带** `--no-crisis`。**危机议题笔记也可以挂推介末页**（2026-07-25 定案，题材闸门已取消）；这里保留的要求只是「声明与推介**不同页/不同屏**」，不是「危机题材整篇不许挂推介」。
5. 全套轮播图复用同一品牌基底，风格一致；图中文字短、不编造专业名词拼写。
6. **主路径唯一且已标注**（`scene_path`）；**P4 代价显影零产出**、**F1 疗法对比/服药并行零出现**；**不给读者的父母/伴侣/孩子贴标签**（NPD/PUA/回避型，G3）；**方法清单必带边界声明**（G9）。全部十条全局硬闸见 spec §1.5。
7. 账号被平台判违规（发布秒返 `failed` + 封禁语义 error）**绝不重发重试**——重发是更强的高频封号信号；只能换号发或让运营 App 内核实（见「小红书账号接入与管理·账号被平台处罚」）。
